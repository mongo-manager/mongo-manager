# ログアナライザー

データベースが遅くなったとき、その理由はログに書かれています。低速クエリ、インデックスを使わないスキャン、エラー、接続などです。ただ、手作業で読むのは大変です。ログアナライザーは、mongod または mongos のログファイルをブラウザー内で読み取って要約します。これは、mtools がコマンドラインで `mloginfo --queries` で行うこと、NoSQLBooster のログパーサーが専用ウィンドウで行うこと、Atlas の Query Insights が自社で運用するクラスターに対して行うことと同じです。

## 使い方

1. サイドバーで **ログアナライザー** を開きます。
2. ログファイルをページにドロップするか、ファイルを選択します。対応するのは、MongoDB 4.4 以降の構造化 JSON ログ、従来のテキストログ、またはそれらの gzip 圧縮ファイル（`mongod.log.gz`。複数の gzip を連結したファイルも可）で、最大 2 GB です（gzip の場合は展開後のサイズ）。ファイルはストリームとして読み取られ、進捗バーと **停止** ボタンが表示されます。1 MB を超える行（通常のログ行はそこまで長くなりません）はスキップされ、読み取れなかった行として数えられます。途中で切れた gzip ファイルはその旨が表示され、切れる前までに読み取った内容が表示されます。
3. 結果を確認します。
   - **概要:** 行数、ログ行として読み取れなかった行数、時間範囲、低速操作、エラー、警告、サーバーのバージョンとホスト。重大度とコンポーネントは、それぞれ最大 16 個と 200 個まで名前で保持されます。それ以外の行はカウントされ、その旨が表示されます（エラーと警告は常にカウントされます）。
   - **タイムライン:** 1 分あたりのログ行と低速操作（長いログでは 1 時間、1 日、1 週間、または 4 週間あたり）。時刻が 2009 年より前、または現在より 1 日以上先の行（時計の異常）はカウントされますが、範囲とタイムラインからは除外され、その件数がページに表示されます。
   - **低速操作:** 名前空間、操作、**クエリのシェイプ** ごとにまとめます。シェイプとは、値を `?` に置き換えたクエリのことで、似たクエリがまとめて数えられます。各グループには、回数、合計、平均、p95（最大 1,000 件の所要時間のサンプルから算出）、最も遅い時間、プラン（インデックスを使わないスキャンには目印が付きます）、そして返却数に対する読み取ったキーとドキュメントの数が表示されます。合計時間、回数、最も遅い順、p95 の高い順に並べ替えられます。表の上のコントロールか列見出しから操作でき、並べ替え中の列には目印が付きます。**シェイプをコピー** するか、**例** で書かれたままの行を 1 件確認できます。
   - メッセージ別の **エラーと警告**。発生回数と発生時刻も表示されます。
   - **接続:** 開始・終了した接続の数、同時接続の最大数、各クライアントとそのアプリケーション（クライアントは最大 1,000 件。それ以外の行はカウントされ、その旨が表示されます）。
4. スプレッドシートで使うには **低速操作を CSV として保存** します。アプリが保存できるのは最大 1 MB なので、非常に負荷の高いログの CSV では最も遅いシェイプが残り、行の区切りで切り詰められ、何行が除外されたかがページに表示されます。または **別のファイルを読み取る** ことができます。

## プライバシー

ファイルがブラウザーの外に出ることはありません。プラグインのページはどのアドレスにもアクセスできず、データベースからは何も読み取りません。シェイプには値が含まれません。書かれたままの行には値が含まれている可能性があるため、例を求めたときだけ表示され、どこにも送信されません。

## 権限

なし。渡されたファイルだけを読み取ります。
