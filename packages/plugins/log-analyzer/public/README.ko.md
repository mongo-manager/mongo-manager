# 로그 분석기

데이터베이스가 느려지면 그 이유는 로그에 있습니다. 느린 쿼리, 인덱스 없는 스캔, 오류, 연결이 모두 기록되어 있지만 직접 읽기에는 시간이 오래 걸립니다. 로그 분석기는 mongod 또는 mongos 로그 파일을 브라우저에서 읽고 요약해 줍니다. 명령줄에서는 mtools의 `mloginfo --queries`가, 별도 창에서는 NoSQLBooster의 로그 파서가, Atlas가 운영하는 클러스터에서는 Atlas의 Query Insights가 하는 일과 같은 종류의 작업입니다.

## 사용 방법

1. 사이드바에서 **로그 분석기**를 엽니다.
2. 페이지에 로그 파일을 놓거나 선택합니다. MongoDB 4.4 이상의 구조화된 JSON 로그, 기존 텍스트 로그, 또는 둘 다 gzip으로 압축된 파일(`mongod.log.gz`, 여러 gzip 조각을 하나로 이은 파일 포함)을 최대 2 GB까지(gzip 파일은 압축을 푼 크기 기준) 읽을 수 있습니다. 파일은 진행률 표시줄과 **중지** 버튼과 함께 스트림으로 읽힙니다. 1 MB를 넘는 줄(실제 로그 줄은 그렇게 길지 않습니다)은 건너뛰고 읽지 못한 줄로 집계하며, 중간에 잘린 gzip 파일은 잘렸다는 사실과 그 전까지 읽은 내용을 함께 알려 줍니다.
3. 찾아낸 내용을 확인합니다.
   - **요약:** 줄 수, 로그 줄로 읽지 못한 줄 수, 시간 범위, 느린 작업, 오류, 경고, 서버의 버전과 호스트. 심각도는 16개까지, 컴포넌트는 200개까지 이름으로 유지하며, 그 밖의 줄은 집계하여 알려 줍니다(오류와 경고는 항상 집계됩니다).
   - **타임라인:** 1분당 로그 줄과 느린 작업 수(더 긴 로그는 1시간, 1일, 1주 또는 4주당). 2009년 이전이거나 현재보다 하루 넘게 뒤의 시간이 찍힌 줄(시계 오류)은 집계되지만 시간 범위와 타임라인에서는 제외되며, 페이지가 그 수를 알려 줍니다.
   - **느린 작업:** 네임스페이스, 작업, **쿼리 형태**별로 묶어 보여 줍니다. 쿼리 형태는 값을 `?`로 바꾼 쿼리이므로 비슷한 쿼리가 함께 집계됩니다. 각 항목에는 횟수, 합계, 평균, p95(소요 시간 최대 1,000개의 샘플 기준), 가장 느린 시간, 플랜(인덱스 없는 스캔은 표시됨), 반환된 도큐먼트 대비 읽은 키와 도큐먼트 수가 나옵니다. 총 시간, 횟수, 가장 느림, p95 기준으로 높은 순 정렬을 표 위에서 또는 열 머리글로 선택할 수 있으며 정렬 기준 열에는 표시가 붙습니다. **형태 복사**를 누르거나 **예시**로 기록된 그대로의 줄 하나를 볼 수 있습니다.
   - **오류 및 경고:** 메시지별로 발생 횟수와 시점을 보여 줍니다.
   - **연결:** 열림과 종료 수, 동시 최대 수, 그리고 클라이언트별 애플리케이션(클라이언트 최대 1,000개이며 나머지 줄은 집계하여 알려 줍니다).
4. 스프레드시트용으로 **느린 작업을 CSV로 저장**하거나 **다른 파일 읽기**를 선택합니다. 앱은 최대 1 MB까지만 저장하므로 매우 바쁜 로그의 CSV에는 가장 느린 형태가 행 단위로 잘려 담기며, 페이지가 제외된 행 수를 알려 줍니다.

## 개인정보 보호

파일은 브라우저 밖으로 나가지 않습니다. 플러그인 페이지는 어떤 주소에도 접근할 수 없으며 데이터베이스에서 아무것도 읽지 않습니다. 형태에는 값이 들어 있지 않습니다. 값이 들어 있을 수 있는 기록된 그대로의 줄은 예시를 요청할 때만 표시되며 어디에도 전송되지 않습니다.
