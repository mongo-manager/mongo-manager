# 日志分析器

数据库变慢时，日志会告诉你原因：慢查询、没有索引的扫描、错误和连接。但手工阅读日志很慢。日志分析器会在浏览器中读取 mongod 或 mongos 日志文件并进行汇总，就像 mtools 在命令行中用 `mloginfo --queries` 做的、NoSQLBooster 的日志解析器在自己窗口中做的，以及 Atlas 的 Query Insights 为它所运行的集群做的那样。

## 使用方法

1. 在侧边栏中打开 **日志分析器**。
2. 将日志文件拖到页面上，或选择一个文件：MongoDB 4.4 及更高版本的结构化 JSON 日志、旧版文本日志，或它们的 gzip 压缩文件（`mongod.log.gz`，由多个 gzip 片段拼接成的文件也可以），最大 2 GB（gzip 文件指解压后的大小）。文件以流的方式读取，并带有进度条和 **停止** 按钮。超过 1 MB 的行（没有哪条日志行会这么长）会被跳过，并计入未读取的行；被截断的 gzip 文件会明确提示，并显示截断之前已读取的内容。
3. 查看分析结果：
   - **摘要：** 行数、无法识别为日志行的行数、时间范围、慢操作、错误、警告、服务器版本和主机。严重级别和组件分别最多按名称保留 16 个和 200 个；其余的行会被计数并说明（错误和警告始终计数）。
   - **时间线：** 每分钟的日志行和慢操作（较长的日志则按小时、天、周或四周）。时间早于 2009 年或比当前时间晚一天以上的行（时钟错误）会被计数，但不计入时间范围和时间线，页面会说明有多少行。
   - **慢操作：** 按命名空间、操作和 **查询形状** 分组，查询形状是将值替换为 `?` 的查询，因此相似的查询会合并计数。每一组显示：次数、总计、平均、p95（取自最多 1,000 个耗时样本）和最慢耗时、执行计划（没有索引的扫描会标出），以及读取的键和文档与返回数量的对比。可按总耗时、次数、最慢或 p95 从高到低排序，可使用表格上方的选项或列标题；当前排序的列会被标出。可 **复制形状**，或点击 **示例** 查看某一行的原文。
   - 按消息汇总的 **错误和警告**，包括出现次数和时间。
   - **连接：** 打开和结束的连接数、同时连接的最大数量，以及每个客户端及其应用程序（最多 1,000 个客户端；其余客户端的行会被计数并说明）。
4. 可 **将慢操作保存为 CSV** 以便在电子表格中使用（应用最多保存 1 MB，因此非常繁忙的日志的 CSV 会保留最慢的形状，并在完整的一行处截断，页面会说明有多少行未保存），或 **读取另一个文件**。

## 隐私

文件不会离开你的浏览器：插件页面不能访问任何地址，也不会读取你数据库中的任何内容。形状不包含值。日志行的原文可能包含值，只有在你要求查看示例时才会显示，并且绝不会发送到任何地方。

## 权限

无：它只读取你提供的文件。
