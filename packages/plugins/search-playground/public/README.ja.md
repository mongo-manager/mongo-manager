# 検索プレイグラウンド

Atlas Search と Vector Search は、通常のインデックスでは答えられないクエリに対応します。誤字を含む語、関連度スコア、ハイライトされた一致箇所、埋め込みがクエリに近いドキュメントなどです。インデックスが何を返すかを確かめるために `$search` や `$vectorSearch` ステージを手で書くのは手間がかかります。Atlas の Search Tester や Compass の検索インデックスビューなら数クリックで試せます。検索プレイグラウンドは、コレクションの検索インデックスに対して同じことを行います。

## 使い方

コレクションを開いて **検索** タブを選びます。コレクションの検索インデックスが、種類（全文またはベクトル）と状態とともに一覧表示されます。まだクエリできないインデックス（構築中、失敗）には印が付き、実行できません。

### 全文

- **検索語**: 検索する語。
- **対象**: インデックスがマッピングするテキストフィールドの 1 つ、または **すべてのフィールド**（動的インデックスなら全フィールド、そうでなければマッピングされたすべてのテキストフィールド）。
- **許容する誤字**: なし、1 文字、2 文字（`fuzzy`）。
- **ハイライト**: 一致した箇所を、一致した語に印を付けて表示します。
- **結果数**: 1 から 100。

### ベクトル

- **ベクトルフィールド**: インデックスのベクトルフィールドの 1 つ。次元数も表示されます。
- **ベクトル**: 貼り付けたクエリベクトル（`[0.1, 0.2, …]`、またはカンマや空白で区切った数値）、または **ドキュメントに類似**: コレクションの先頭 20 件のドキュメントの 1 つで、そのドキュメント自身のベクトルを使って類似のものを探します。数値のリスト、または float32 や int8 の値による BSON ベクトル（バイナリサブタイプ 9）が使えます。ベクトルはインデックスの次元数と一致している必要があります。
- **候補数**: MongoDB が考慮する最近傍の数（結果数以上、最大 10,000）。
- **フィルター**: インデックスのフィルターフィールドに対する JSON オブジェクト。例: `{ "year": { "$gte": 2000 } }`。

**検索** でパイプラインを実行します。各結果にはスコア、ハイライト、フィールドが表示されます。**集計で使用** を押すと、パイプラインが集計エディターに渡され、ステージを追加して保存できます。

## 必要なもの

検索インデックスは Atlas、および MongoDB Search（`mongot`）を設定し、MongoDB のドキュメントが対応として挙げるバージョンで動く自己管理の MongoDB にあります。検索が有効でない場合やコレクションに検索インデックスがない場合は、タブにその旨が表示されます。コレクションのインデックスページで作成してください。

## 安全性

アプリはあなたの権限で、読み取り専用として、検索ステージを先頭にパイプラインを実行します。書き込み、他のコレクションとの結合、コードの実行を行うものは含まれません。ハイライトはテキストとして表示され、マークアップとしては扱われません。個人データとして非表示になっているフィールドは提示されません。また、個人データが非表示のユーザーは、ルールが及ぶ範囲で検索を拒否されます（結果から非表示の値が推測される可能性があるため）。タブは検索の前にその旨を表示します。

## 権限

- **ドキュメントの読み取り:** 検索結果と、ベクトルの取得元となるドキュメント。
- **コレクション詳細の読み取り:** コレクションの検索インデックス。名前、状態、マッピングされたフィールド（非表示のものは含まれません）。
