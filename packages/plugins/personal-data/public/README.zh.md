# 个人数据查找器

个人数据查找器会找出集合中包含个人数据的字段——电子邮件地址、电话号码、银行卡号、IBAN、身份证号、IP 地址、姓名、地址、出生日期、密码和密钥——以便在任何人看到不该看的内容之前，用个人数据规则将它们隐藏。它会读取集合文档的随机样本，并根据值和名称判断找到的每个字段，同时给出可信度和原因。

该插件只读取。除掩码外不会显示任何值（`u•••@e•••.com`、`+•• ••• ••• •• 67`），也不会保存或发送到任何地方：读取值只是为了区分类型。

## 出现的位置

- **集合标签页：** 在每个集合的“文档”“聚合”等标签页旁边，会出现一个**查找个人数据**标签页。

## 使用方法

打开一个集合，再打开**查找个人数据**标签页。它一打开就会随机抽取 300 个文档作为样本（如果这么多大文档无法放进一次响应，则抽取 60 个）；**重新扫描**会重新抽取样本。

找到的每个字段为一行：

- **包含：** 它看起来像什么——电子邮件地址、电话号码、银行卡号、IBAN、身份证号、IP 地址、人名、地址、出生日期，或密码或密钥。
- **可信度：** 当它的大多数值属于该类型（或其值与名称一致）时为**高**；当有很多值属于该类型或名称表明如此时为**中**；当只有部分值属于该类型，或名称表明如此但值看起来不像时为**低**。
- **原因：** 样本中有多少个值看起来像它，以及它的名称是否表明如此。
- **示例：** 最多两个值，已掩码。

可能性较大的字段（高和中）会被预先选中；可以勾选或取消勾选任意字段。**建议为规则**会打开集合的**个人数据**部分，并将所选字段列为此插件的建议：连接的管理员在那里逐个（或一次全部）添加，此后无权查看个人数据的人看到的值将是 `***`。插件不会擅自保存任何内容。**复制列表**会复制所选字段，每行一个（`数据库.集合.字段`、包含的内容、可信度），以便发送给管理员。

## 如何识别值

- **电子邮件地址**和 **IP 地址**（IPv4 和 IPv6；`12:30:45` 这样的时间不算）。
- 符合某个卡组织号段和长度（Visa、Mastercard、Mir、American Express、Discover、UnionPay、Diners Club、JCB、Troy）且通过 Luhn 校验的**银行卡号**——单靠 Luhn 校验，每十个数字就会误判一个。
- 通过 mod-97 校验的 **IBAN**（土耳其的还要求长度为 26 个字符）。
- **身份证号：** 两位校验位正确的土耳其身份证号，以及写作 `123-45-6789` 的美国社会安全号。
- 写成一个整体的 9 到 15 位**电话号码**：带 `+` 或 `00`、带分隔符，或在 9 或 10 位数字前有前导 0。单纯的数字，或以数字形式存储的值（坐标、金额），只有在名称类似电话的字段中，且是完整的一个数字时，才会被视为电话号码。
- 按其本身的书写方式识别**密码和密钥**：bcrypt、Argon2 和 scrypt 哈希、JSON Web Token、AWS 访问密钥、GitHub 和 Stripe 令牌、私钥。
- **按名称：** `email`、`phoneNumber`、`iban`、`cardNumber`、`tckn`、`ssn`、`passportNumber`、`ipAddress`、`firstName`、`lastName`、某人的 `name`（`customer.name`）、`billingAddress`、`street`、`postalCode`、`birthDate`、`dateOfBirth`、`password`、`apiKey`、`accessToken` 及其同类，支持英语、土耳其语和应用的其他语言（`eposta`、`telefon`、`soyad`、`dogumTarihi`、`telefono`、`nachname`、`date_naissance`、`телефон`、`电话`、`電話番号`、`전화번호`……）。描述数据而非数据本身的名称不算：`emailVerified`、`phoneType`、`passwordChangedAt`、`isMobile`。

对象或数组内部的字段按个人数据规则的命名方式来命名：联系人数组中的电子邮件为 `contacts.email`。

## 示例

在 `users` 集合上：

```
字段        包含             可信度     原因                                  示例
email       电子邮件地址     高         200 个值中有 200 个；名称也表明如此   u•••@e•••.com
phone       电话号码         高         196 个值中有 196 个；名称也表明如此   +•• ••• ••• •• 67
apiToken    密码或密钥       高         名称表明如此                          ••••••••
firstName   人名             中         名称表明如此                          A•••
```

找到密码或密钥时会附带一条提示：规则只在应用中将其隐藏，而不是在数据库中——密码应存为慢速哈希，密钥应存入密钥库。名称表明是密码的字段，无论其值看起来如何，都会显示为密码。

## 关于视图

视图的读取方式与集合相同，但其数据来自源集合：规则应建议在它所读取的集合上，该集合的规则会作用于视图。在视图上，**建议为规则**不可用。

## 权限

- **读取文档**（`documents:read`）：用于抽取集合文档的样本，以及将字段建议为个人数据。

读取通过应用以已登录用户的权限和字段掩码进行：已对您隐藏的字段会以 `***` 返回，不会被当作数据，并会被标明为已隐藏。只有连接的管理员（可以管理该连接的人）才会获得建议字段；对其他人，**建议为规则**会如此说明，并提供**复制列表**以便转交。

## 设置

无。

## 限制

- 只是样本：在少数文档中包含个人数据的字段可能不会出现在样本中。每个字段读取 200 个值，数组读取 50 个元素，读取深度为六层。
- 任何规则都无法指定的字段——键中含有点号、以 `$` 开头、含有隐藏字符、前后有空格，或规则超过 512 字节——会被列出并说明原因，但无法选择。
- 一次最多建议 50 个字段：标签页会在您建议之前提示这一点，并在“个人数据”部分显示期间保持打开，因此您可以回来处理其余字段。
- “个人数据”部分只提供样本中的集合所包含的建议字段；不包含的字段会被列为未提供。
- 姓名和地址只按字段名称识别：名为 `title` 的字段中的人名不会被发现。
