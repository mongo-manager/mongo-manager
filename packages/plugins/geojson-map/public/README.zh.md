# 地图

“地图”会在它自带的地图上绘制集合中文档所在的位置：文档的 GeoJSON 形状（点、线、多边形及其集合）和旧式的 `[lng, lat]` 坐标对。相距很近的点会聚合并显示数量；点击某个形状会打开一张关于其文档的卡片。

该插件只读取数据，不会更改数据库中的任何内容。

## 出现的位置

- **集合标签页：** 在每个集合和视图中，“文档”“聚合”等标签页旁边会有一个**地图**标签页。
- **文档操作：** 在“文档”中，文档行操作菜单里的**在地图上显示**会只绘制该文档。
- **单元格值：** 在“文档”中，GeoJSON 点旁边会以 `lat, lng`（五位小数）显示其位置，例如 `41.00820, 28.97840`。

## 使用方法

打开一个集合，然后切换到**地图**标签页。系统会读取当前“文档”查询的文档并绘制其形状；地图会自动适应这些形状。

- 拖动可移动地图，滚动或使用**放大**和**缩小**可缩放，使用**适应形状**可重新查看全部内容。
- 带数字的圆圈表示相距很近的多个位置：点击即可放大。
- 点击某个点或形状可打开其卡片：显示文档的名称、若干字段，以及用于在应用中显示该文档的**打开**。
- 当文档在多个字段中包含形状时（例如 `pickup` 和 `dropoff`），**GeoJSON 字段**可将地图限制为某一个字段；**所有字段**则显示全部。
- **形状**列出已绘制的内容（文档、字段、类型）。这是用键盘浏览地图的方式：**在地图上显示**会将某个形状居中，**打开**会打开其文档。

## 按区域筛选

字段选择器旁边的三个按钮可按区域筛选文档：

- **绘制用于筛选的区域：** 点击地图添加角点；点击第一个角点、双击或按 Enter 完成。Backspace 撤销上一个角点；无论焦点在哪里，按 Esc 都会放弃。
- **绘制用于筛选的圆：** 先点击圆心，再点击边缘；移动时会显示半径，其轮廓是球面上的实际轮廓（在地图上越靠近极点越宽）。
- **按当前视图区域筛选：** 即地图当前显示的那部分世界。

使用键盘时：地图获得焦点后，方向键可移动地图，空格键会在地图中心（那里会显示一个十字）放置一个角点（或圆的圆心，然后是边缘）。再次点击正在使用的工具会将其放下；选择另一个字段会停止绘制。

区域内含有形状的文档会通过 MongoDB 的 `$geoWithin` 放入“文档”查询。每条边都沿着地图上绘制的线——会沿边添加角点，因为 MongoDB 以绕地球的最短路径连接两个角点，这条路径会向极点弯曲——并且区域可以跨越 180 度经线。它对 GeoJSON 形状和 `[lng, lat]` 坐标对同样适用，且不需要索引。Feature 内的形状按其几何体筛选，FeatureCollection 内的形状按集合的 features 筛选（只要文档的任一形状在区域内，该文档就算在内），数组中的形状按数组元素筛选。当一个字段以上述多种方式保存形状时，筛选会同时处理每一种。位于任何筛选都无法指向的键下的形状（键名含点或 `$`，或为空）会被排除，页面会在筛选之前在工具旁边说明这一点。

区域会放在正在使用的“文档”筛选条件旁边：其他条件会保留，同一字段上已有的区域（先前绘制的，或您自己写的）会被替换。与插件放入的任何查询一样，“文档”的排序和投影会被重置为无。边相交、接触或折返的多边形，或角点在同一条直线上的多边形，无法构成区域：页面会说明原因。当文档在多个字段中包含形状时，请先选择要筛选的字段；页面会在按钮旁边提示。**在地图上显示**（单个文档）没有绘制工具。

## 哪些内容会被视为位置

- 任何字段中的 GeoJSON 几何体：`Point`、`MultiPoint`、`LineString`、`MultiLineString`、`Polygon`、`MultiPolygon` 或 `GeometryCollection`。
- GeoJSON `Feature` 或 `FeatureCollection`。
- 旧式坐标对 `[lng, lat]`，与 MongoDB 的存储方式一致，经度在前，但仅限以地点命名的字段：`loc`、`location`、`coordinates`、`coords`、`position`、`pos`、`point`、`geo`、`lnglat`、`lonlat`、`center` 及其复数或相近变体。其他位置的两个数字（如版本号、尺寸）不会被当作位置。名为 `latlng` 的字段不会被读取，因为它通常纬度在前。

字段最多查找六层深度，也会查找数组内部。不是有效 GeoJSON 的形状会被整体排除。

## 示例

一个 `stores` 集合：

```json
{ "_id": 1, "name": "Kadıköy", "location": { "type": "Point", "coordinates": [29.0275, 40.9903] } }
{ "_id": 2, "name": "Beşiktaş", "loc": [29.0094, 41.0422] }
```

两者都会显示在“地图”标签页中。在“文档”中，第一个文档的 `location` 单元格会在值旁边显示 `40.99030, 29.02750`。

## 地图瓦片

默认情况下，不会加载任何地图瓦片，也不会连接任何瓦片服务器：地图会绘制经纬网格，并有提示说明管理员可以设置瓦片服务器。设置瓦片服务器后，形状会绘制在真实的地图瓦片之上。

## 权限

- **读取文档**（`documents:read`）：用于读取当前查询的文档，以及“在地图上显示”的那一个文档。

读取通过应用进行，使用已登录用户的权限和字段遮蔽。该插件无法读取其他集合。

## 设置

管理员在“插件”页面中设置这些选项。所有使用该插件的人都能看到它们，因此切勿在此放置机密信息（例如私有 API 密钥）。

- **瓦片服务器**（`tileUrl`）：栅格瓦片的 http 或 https 地址模板。`{z}`、`{x}` 和 `{y}` 会为每个瓦片填入，`{-y}` 从南向北计算行号（TMS），`{s}` 选择子域名（`a`、`b` 或 `c`），`{r}` 留空。示例：`https://tile.openstreetmap.org/{z}/{x}/{y}.png`（请先查看瓦片提供方的使用政策）。
- **瓦片署名**（`tileAttribution`）：显示在地图上的署名行，纯文本，例如 `© OpenStreetMap contributors`。为空时显示瓦片服务器的主机名。

只有瓦片服务器的主机（且仅此主机）会被加入插件框架可加载的图像来源。带有凭据的地址或不常见的主机会被拒绝。

## 限制

- 最多读取当前查询的前 1,000 个文档，按 `_id` 顺序，以符合应用 1 MB 消息限制的分页方式读取。文档更多时，摘要会显示“来自前 1,000 个文档”；请缩小“文档”筛选条件以查看其他文档。
- 每个文档最多取 50 个形状。
- 顶点超过 10,000 个的形状会被抽稀绘制（每隔 n 个点保留一个，两端保留），多部分形状最多绘制 1,000 个部分。
- “形状”列表显示前 200 行。
- 缩放最高到 19 级；适应形状到 15 级为止，以免单个点被绘制到街道级别。
- 地图使用 Web Mercator 投影：南北纬约 85 度以外的纬度会绘制在边缘。
