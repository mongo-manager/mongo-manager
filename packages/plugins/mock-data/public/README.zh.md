# 测试数据

试用索引、查询、图表或界面都需要文档——比你手动输入的更多，而且没有一条是真实的。“测试数据”会生成与你的集合结构相仿的逼真文档，并交给应用的导入向导，由你在那里检查并开始导入。NoSQLBooster 也有同样的功能，名为“Test Data Generator”。

## 如何使用

1. 打开一个集合及其**测试数据**标签页。插件会读取 100 个文档的样本并列出它们的字段（`_id` 交给服务器处理）。
2. 每个字段都会按名称和类型获得选定的**测试值**——`email` 得到电子邮件地址，`createdAt` 得到过去一年内的日期，`price` 得到价格，`status` 得到集合中已有的值之一，GeoJSON 的 `location` 得到一个点。名称绝不会改变字段的类型：以文本保存的日期得到文本日期，以字节保存的图片得到小的 PNG 图像。你可以从 100 多个分组的模板中更换任意一个：人物、互联网、位置、公司、商业、金融、日期和时间、数字、文本、标识符、真或假、其他（“此文本”、null、空）。
3. 取消勾选可排除某个字段，或添加新字段（嵌套在另一个字段中的用 `profile.phone`；像 `items[].qty` 这样的对象数组会得到一到三个元素）。
4. 选择文档数量（最多 5,000）、留空字段的比例（用于并非每个文档都有全部字段的情况）、词语的语言（应用的十种语言中的任意一种）以及**种子**：只要标签页保持打开，相同的种子会再次生成相同的文档（日期从标签页打开的时间向前推算）。不会有文档一个字段都没有。
5. 检查**预览**，然后点击**导入…**：导入向导会在该集合上打开，并以这些文档作为它的文件。在你用自己的权限在向导中开始导入之前，不会写入任何内容。**下载 JSON** 则会改为保存这些文档。

## 绝不会生成的内容

- 电子邮件和网址只使用保留的示例域名（`example.com`、`example.org`、`example.net`、`.test`）；IP 地址只使用文档专用网段；电话号码使用为虚构保留的号段（`+1 2xx-555-01xx`）或无人使用的号段（`+90 000 …`）。公司名称均为虚构。
- 任何能区分某个人或某件事物的值都不会从集合中复制：只有以类别命名的字段（状态、国家），或名称不像标识符（id、编号、代码、护照……）也不像人（所有者、客户、作者、用户……）的字段，才会提供“已有的值之一”；而且仅当它的少量短值（你可以看到这些值）在样本中每个都至少出现两次时才提供。个人的姓名、电子邮件、电话或地址则绝不会——包括 `email2` 和 `phone1`。
- 作为个人数据对你隐藏的字段会显示为已隐藏，类型未知：在你选择其他模板之前，它的测试值为文本（原因会与其控件一起读出），并且除非你在导入向导中将其包含，否则向导会将其忽略。当应用无法及时确定哪些字段对你隐藏时，所有字段都按已隐藏处理，直到你选择**重试**。
- 新字段绝不会放在文档列表之内（`items[].qty` 旁边的 `items.note`），也不含 `$` 或方括号。
- 文档按应用接收时的大小计算：一次交给向导或一次下载最多 1,000,000 个字符，按发送时计为 1.04 MB。对应用的提问选择“否”，只会留下一条简短的说明，而不是错误。
- 没有任何 IBAN、账号或银行卡号是真实的：这些模板都标明为假（`XX00 TEST …`）。

## 权限

- **读取文档：**读取集合的一份样本，以了解其字段。导入本身由应用通过它的向导完成。
