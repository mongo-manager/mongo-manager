# 데이터 사전

데이터베이스를 공유하는 팀은 각 컬렉션에 무엇이 들어 있는지 알아야 합니다. 어떤 필드가 있고, 유형은 무엇이며, 어떤 필드가 필수이고, 각각 무슨 의미인지, 컬렉션끼리 어떻게 서로를 참조하는지, 어떤 인덱스가 있는지 말입니다. 데이터 사전은 앱의 데이터 모델을 바탕으로 데이터베이스 전체에 대해 이를 정리하고 문서로 저장합니다. NoSQLBooster("Schema documentation"), Hackolade(HTML 및 PDF), DbSchema(Markdown), Dataedo도 같은 일을 합니다.

## 사용 방법

아무 컬렉션이나 열고 **데이터 사전** 탭을 여세요. 해당 컬렉션이 속한 데이터베이스 전체가 문서화됩니다.

1. 플러그인은 데이터베이스 탭이 그리는 모델을 한 번의 읽기로 가져옵니다. 컬렉션, 필드와 그 유형 및 존재 빈도, 숨김 필드, 참조가 포함됩니다.
2. 그다음 컬렉션을 하나씩 차례로 읽으며 각 컬렉션의 인덱스와 유효성 검사 규칙을 가져오고, 진행 상황을 표시합니다. 1분 동안의 읽기 한도를 다 쓰면 기다렸다가 이어서 진행합니다. 인덱스나 규칙을 읽을 수 없는 컬렉션은 그 이유를 표시하며, 나머지 컬렉션은 계속 읽습니다.
3. **Markdown**과 **HTML**은 사전을 파일로 저장하고, **Markdown 복사**는 위키나 풀 리퀘스트에 붙여 넣을 수 있도록 클립보드에 복사합니다. 100,000자보다 긴 사전은 그 한도 앞의 마지막 완전한 줄까지만 복사되며 페이지에 그 사실이 표시됩니다. 전체가 필요하면 파일로 저장하세요. 파일은 최대 1 MB입니다. 이보다 큰 사전은 들어갈 수 있는 앞쪽 컬렉션만 저장하며, 페이지와 파일 모두 몇 개가 저장되었는지 알려 줍니다. 컬렉션 하나조차 들어가지 않으면 아무것도 저장하지 않고 페이지에 그 이유를 표시합니다.

## 표시되는 내용

각 컬렉션마다 다음이 표시됩니다.

- **필드:** 경로, 유형, 존재 빈도, `$jsonSchema`의 필수 여부, 그리고 규칙이 제공하는 설명, 허용 값, 유형. 개인 데이터로 가려진 필드는 숨김으로 표시되며, 이름과 규칙상 필수 여부만 나타납니다.
- **참조:** 해당 컬렉션이 참조하는 컬렉션(어느 필드로 참조하는지 포함)과 해당 컬렉션을 참조하는 컬렉션.
- **인덱스:** 각 인덱스의 키와 고유 여부, 문서를 만료시키는지(TTL), 부분 인덱스인지 여부. 부분 인덱스의 필터는 값이 들어 있을 수 있으므로 절대 표시하지 않습니다.
- **유효성 검사:** 수준과 동작, 규칙이 없다는 사실, 또는 규칙을 읽을 수 없는 이유. `$and`로 다른 규칙과 결합된 `$jsonSchema`도 읽습니다.

뷰는 어느 컬렉션의 뷰인지 알려 줍니다. 모델이 읽을 수 없었던 컬렉션은 그 사실을 표시합니다. 페이지와 HTML 파일은 스크립트를 절대 실행하지 않습니다. 파일에서 컬렉션이나 필드의 이름, 규칙의 텍스트는 텍스트 그대로 기록되므로 링크(주소, `www.` 이름, 이메일 포함), 이미지, 태그, 깨진 표가 되는 일이 없으며, 보이지 않거나 텍스트 방향을 뒤집는 문자는 페이지에서도 제외됩니다. 허용 값은 최대 80자까지 표시합니다. 목차의 각 컬렉션 항목은 HTML과 Markdown 모두에서 해당 컬렉션으로 이동합니다.

## 권한

- **데이터베이스 읽기:** 데이터베이스의 다른 컬렉션과 그 모델.
- **컬렉션 세부 정보 읽기:** 각 컬렉션의 인덱스와 유효성 검사 규칙.
