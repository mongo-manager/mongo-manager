# 数据字典

共用同一个数据库的团队需要知道每个集合里存放了什么：有哪些字段、各是什么类型、哪些是必填、含义是什么、集合之间如何相互引用，以及有哪些索引。数据字典会根据应用自身的数据模型，为整个数据库写出这些内容，并保存为文档。NoSQLBooster（“Schema documentation”）、Hackolade（HTML 和 PDF）、DbSchema（Markdown）和 Dataedo 也提供类似功能。

## 使用方法

打开任意集合及其 **数据字典** 标签页：它会为该集合所在的整个数据库生成文档。

1. 插件通过一次读取获取数据库的模型（即“数据库”标签页所绘制的模型）：集合、字段及其类型和出现率、已隐藏的字段、引用。
2. 然后逐个集合读取其索引和验证规则，并显示进度。当本分钟的读取次数用完时，插件会等待后继续；索引或规则无法读取的集合会说明原因，其余集合仍会照常读取。
3. **Markdown** 和 **HTML** 会把字典保存为文件；**复制 Markdown** 会把它放入剪贴板，便于粘贴到 wiki 或 pull request。超过 100,000 个字符的字典会复制到该上限之前的最后一个完整行，页面会提示这一点：如需完整内容，请保存为文件。文件最大为 1 MB：超过此大小的字典只会保存能容纳的前几个集合，页面和文件都会说明保存了多少个；若连一个集合都放不下，则不会保存任何内容，页面会说明原因。

## 内容

对于每个集合：

- **字段：** 路径、类型、出现率、其 `$jsonSchema` 是否要求必填，以及规则给出的描述、允许的值和类型。作为个人数据对您隐藏的字段会列为已隐藏：只显示其名称，以及规则是否要求必填。
- **引用：** 它引用的集合（通过哪个字段）以及引用它的集合。
- **索引：** 每个索引的键，以及它是否唯一、是否让文档过期（TTL）或是否为部分索引。部分索引的过滤条件绝不显示：其中可能包含值。
- **验证：** 级别和动作、没有规则，或规则无法读取的原因。通过 `$and` 与其他规则组合的 `$jsonSchema` 也会被读取。

视图会说明它是哪个集合的视图。模型无法读取的集合会注明这一点。页面和 HTML 文件绝不会运行脚本。在文件中，集合名或字段名以及规则的文本都按纯文本写出：它们绝不会变成链接（包括地址、`www.` 名称或电子邮件）、图片、标签或损坏的表格，不显示内容或会使文本反向的字符会被去除——页面上也一样。允许的值最多显示 80 个字符。目录中每个集合的条目都会跳转到该集合，HTML 和 Markdown 中均如此。

## 权限

- **读取数据库：** 数据库的其他集合及其模型。
- **读取集合详情：** 每个集合的索引和验证规则。
