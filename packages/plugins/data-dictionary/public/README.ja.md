# データ辞書

データベースを共有するチームには、各コレクションに何が入っているかを把握する必要があります。どのフィールドがあり、どの型で、どれが必須で、何を意味し、コレクション同士がどう参照し合い、どのインデックスがあるか、ということです。データ辞書は、アプリ自身のデータモデルからデータベース全体についてこれを書き出し、ドキュメントとして保存します。NoSQLBooster（「Schema documentation」）、Hackolade（HTML と PDF）、DbSchema（Markdown）、Dataedo も同様のことができます。

## 使い方

任意のコレクションを開き、その **データ辞書** タブを開きます。そのコレクションのデータベース全体をドキュメント化します。

1. プラグインは、データベースのモデル（データベースタブが描画するもの）を 1 回の読み取りで取得します。コレクション、型と出現率を含むフィールド、非表示のフィールド、参照が含まれます。
2. 続いて、コレクションごとにインデックスと検証ルールを 1 つずつ読み取り、進行状況を表示します。この 1 分間の読み取り上限に達した場合は、待ってから続行します。インデックスやルールを読み取れなかったコレクションにはその理由が表示され、ほかのコレクションは引き続き読み取られます。
3. **Markdown** と **HTML** は辞書をファイルとして保存します。**Markdown をコピー** は、wiki やプルリクエスト用にクリップボードへコピーします。100,000 文字を超える辞書は、その手前の最後の完全な行までがコピーされ、ページにもその旨が表示されます。全体が必要な場合はファイルとして保存してください。ファイルの上限は 1 MB です。これを超える辞書は、収まる範囲の最初のコレクションだけが保存され、ページとファイルの両方に何件保存されたかが表示されます。1 件も収まらない場合は何も保存されず、ページにその理由が表示されます。

## 表示される内容

各コレクションについて、次の内容が表示されます。

- **フィールド:** パス、型、出現率、`$jsonSchema` で必須とされているかどうか、ルールが示す説明、許可される値、型。個人データとして非表示になっているフィールドは「非表示」として一覧に載り、名前と、ルールで必須とされているかどうかだけが示されます。
- **参照:** このコレクションが参照しているコレクション（どのフィールドで参照するか）と、このコレクションを参照しているコレクション。
- **インデックス:** 各インデックスのキーと、一意か、ドキュメントを期限切れにするか（TTL）、部分インデックスか。部分インデックスのフィルターは表示されません。値が含まれている可能性があるためです。
- **検証:** レベルとアクション、ルールがないこと、またはルールを読み取れなかった理由。`$and` で他のルールと組み合わされた `$jsonSchema` も読み取られます。

ビューには、どのコレクションのビューかが示されます。モデルが読み取れなかったコレクションにはその旨が表示されます。ページと HTML ファイルがスクリプトを実行することはありません。ファイルでは、コレクション名やフィールド名、ルールのテキストはテキストとして書き出されます。リンク（アドレス、`www.` で始まる名前、メールアドレスを含む）、画像、タグ、崩れた表にはなりません。何も表示されない文字や、テキストの向きを反転させる文字は取り除かれます。ページ上でも同様です。許可される値は最大 80 文字まで表示されます。目次の各コレクションの項目は、HTML でも Markdown でもそのコレクションへ移動します。

## 権限

- **データベースの読み取り:** データベースのほかのコレクションと、そのモデル。
- **コレクション詳細の読み取り:** 各コレクションのインデックスと検証ルール。
