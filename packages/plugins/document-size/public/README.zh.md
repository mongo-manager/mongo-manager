# 文档大小

“文档大小”告诉你一个集合中的文档有多大，以及字节都用在了哪里：每个大小区间有多少文档、哪些文档最大、最大的文档距 MongoDB 的 16 MB 上限有多近，以及每个字段在字节中的占比——逐个字段，也可深入对象字段。用它可以找出让文档变大的字段、持续增长的数组，或者占用比值还多的字段名。

该插件只读。它在服务器上用一条只读管道进行测量（当 MongoDB 的内存使第一条管道中止时，会再用第二条，见“限制”）：只有大小、字段名称、类型、数组长度，以及最大文档的 `_id` 会到达页面，文档本身绝不会。

## 出现位置

- **集合标签页：** 在每个集合的“文档”“聚合”等标签页旁，增加一个**文档大小**标签页。

## 使用方法

打开一个集合，然后切换到**文档大小**标签页。它一打开就会测量随机 1,000 个文档。选择**全部**可测量每个文档（大型集合可能耗时超过一次读取所允许的时间：此时标签页会提示改为测量样本）；**重新测量**会抽取新的样本。测量结果在标签页保持打开期间会一直保留——进入某个字段再返回，或切换到**全部**再切回，看到的数字都相同——直到你点击**重新测量**。

- **大小分布：** 有多少文档小于 1 KB、在 1 到 4 KB 之间，依此类推，直到 16 MB。
- **字节去了哪里：** 每个字段，占用最多的排在最前——其类型（旁边是数组的平均元素数）、占文档字节的比例、平均大小和最大大小、出现在多少个文档中，以及其名称（连同其类型的一个字节）在每个文档中的占用。字段的字节就是它在文档中占用的空间：类型、名称和值。
- **最大的文档：** 最大的十个文档，每个都显示其占 16 MB 上限的比例，并带有**打开**按钮，可在“文档”中查看（视图中没有 `_id` 的文档则没有该按钮）。

对象字段的名称是一个按钮：点击后会测量该对象自身的字段，范围是它为对象（而不是对象数组）的那些文档；摘要上方的路径可以返回，最多深入八层。在那里不显示占 16 MB 的比例，因为对象的大小与此无关。当最大的文档超过 16 MB 上限的一半时，标签页会发出警告，因为文档不能超过该上限；当字段名称占到字节的五分之一或更多时（所有字段都计算在内，包括未列出的），它会提示这一点，因为名称越短，每个文档越小。

## 示例

在一个 `orders` 集合上，随机 1,000 个文档：

```
1,000 个文档 · 平均 15 KB · 最大 9 MB · 共 14.6 MB

最大的文档为 9 MB：占 MongoDB 16 MB 限制的 56.3%

字段                          类型                    占比    平均      最大      出现于  名称占用
items                         array ≈ 12.5 个元素     78.1%   11.7 KB   8.6 MB    100%    每个 7 B
address                       object                  3.9%    606 B     900 B     99%     每个 9 B
customerReferenceIdentifier   string                  2.6%    400 B     400 B     100%    每个 29 B
```

## 个人数据

如果集合中的个人数据对你隐藏，其文档的大小会暴露被隐藏值的长度：服务器在那里不会测量任何内容，所以标签页不会发起任何请求，并会说明这一点。

## 权限

- **读取文档**（`documents:read`）：在集合上运行测量管道，并打开文档。

读取通过应用、以已登录用户的权限进行。

## 设置

无。

## 限制

- 样本：最大的文档可能不在其中；**全部**会读取每个文档。对于由大型文档组成的集合，样本是在测量完它们的大小之后才抽取的，因此 MongoDB 只需对这些大小排序。
- 列出占用最多的 50 个字段；对象数组内部的字段与其数组一起测量。
- 包含点号或以 `$` 开头的键会被列出，但不会深入。
- 每次测量是一条最长 10 秒、不使用磁盘的管道：字段名称种类极多的文档（把键当作值使用）在**全部**模式下可能超出 MongoDB 的内存；样本可以测量它们。
