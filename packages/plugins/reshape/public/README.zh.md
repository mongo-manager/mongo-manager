# 重塑

随着应用的成长，集合的结构也会变化：`fullName` 变成 `name.full`，`address` 对象变成报表用的扁平列，以文本存储的价格需要变成数字。“重塑”把这些改动构建为步骤，在您自己的文档上展示效果，并以管道的形式交给聚合——无需迁移脚本，也不会触碰集合。Studio 3T（“Reschema”）和 NoSQLBooster（“Collection re-schema tool”）也提供同样的功能。

## 使用方法

1. 打开一个集合及其**重塑**标签页。它会读取 50 个文档作为样本，以了解字段。
2. 按顺序添加**步骤**：
   - **重命名或移动：** 填写新名称；`a.b` 会将字段移入对象。
   - **展平对象：** `address.city` 变成 `address_city`（分隔符由您指定，不能包含 `.` 或 `$`）。只有被移动的键会离开对象：样本中未遇到的键仍留在对象中，非对象的值保持原样，移动后变空的对象会被移除（原本就为空的则保留）。
   - **嵌套到对象中：** 将列表中勾选的字段收集到一个新字段下（`lat`、`lng` → `location`），并替换原有内容；以相同名称结尾的两个字段会被拒绝，因为其中一个会丢失，字段与其内部的字段同样会被拒绝。
   - **转换类型：** 转换为 int、long、double、decimal、string、date、bool 或 ObjectId；无法转换的值会变为 null 或保持不变。缺失的字段仍然缺失，null 仍为 null。
   - **缺失时设默认值**（或**缺失或为 null 时**）：为缺失的字段，或缺失或为 null 的字段设置一个值——由您选择，步骤也会据此命名。
   - **删除**、**将文本拆分为列表**、**将列表合并为文本**（无法转为文本的元素，例如对象，合并时视为空）。
3. 停止编辑后，**预览**会展示相同的五个采样文档在改动前后的样子，由 MongoDB 自身运行。覆盖已存在字段的步骤会给出提示；写入文档列表内部的步骤会说明该值会设置到每个文档中；有问题的步骤会说明问题，并且不会纳入阶段；尚未填写名称的步骤视为未完成，在完成前不会纳入。
4. 最多预览并交出 48 个阶段；超过后，预览会说明为何不显示“之后”。
5. **在聚合中使用**会交出这些阶段（应用会先征求您的确认）。若要写入结果，请在聚合中添加一个指定新集合的 `$out` 阶段：聚合会显示写入将执行的操作，并在运行前征求您的确认。**复制阶段**会将它们放入剪贴板。

## 绝不会做的事

- 绝不更改集合：它只构建只读的 `$set` 和 `$unset` 阶段，自身从不构建 `$out` 或 `$merge`。
- `_id` 绝不会被重命名、移动或删除。作为个人数据对您隐藏的字段及包含它们的对象不会提供，任何会读取、移动、写入或删除其中之一的步骤——包括通过您输入的名称——都会被拒绝。如果样本仅将某字段视为值，而规则以其自身名称指向其下的字段（`profile.ssn`），则该字段会被保留；如果规则通过 `*` 指向它（`*.ssn`），则不会保留，否则将没有任何字段可用。当应用无法及时确定哪些字段被隐藏时，在点击**重试**让它确定之前，不会提供任何字段。
- 字段不能使用的名称（空、包含 `$`、`a..b`）会被拒绝，将字段移入其自身同样会被拒绝。
- 默认值或分隔符始终是一个值，绝不会被当作字段或操作符读取。

## 权限

- **读取文档：** 用于了解字段的样本，以及预览的文档，遵循您的权限，且您的隐藏字段保持隐藏。
