# 引用

“引用”展示数据库中的文档如何通过 ObjectId 相互指向。在“文档”中，它会在 `customerId` 这样的 ID 旁写出被引用文档的名称，于是一行读起来是“customer: Ada Lovelace”，而不是一串十六进制数字。它的标签页会找出集合中哪些字段保存了其他文档的 ID、这些文档位于哪些集合，以及哪些 ID 不指向任何文档。

该插件只读取，不会更改数据库中的任何内容。

## 出现的位置

- **单元格值：** 在“文档”中的 ObjectId 旁显示箭头和被引用文档的名称（`→ Ada Lovelace`）；没有文档具有该 ID 时显示 `→ 未找到`。
- **集合标签页：** 在每个集合和视图中，位于“文档”“聚合”等标签页旁的“**引用**”标签页。
- **文档操作：** 文档操作中的“**引用方**”，列出数据库中引用该文档的文档。

## ID 旁的名称

当字段名与同一数据库中某个集合同名（单数或复数，带或不带 id 后缀）时，单元格会显示名称：

- `customerId`、`customer_id` 或 `customer` → `customers`
- `categoryIds` → `categories`
- `address` → `addresses`

插件会在该集合中按 `_id` 查找页面上显示的 ID，并且只读取所找到文档的命名字段。名称取文档所含的第一个字段，依次为 `name`、`title`、`label`、`displayName`、`fullName`、`username`、`email`、`code` 和 `slug`；都没有时显示其 `_id`。如果某个字段的 ID 在与其同名的任何集合中都找不到，则不显示任何文本。

以警告样式显示的 `→ 未找到` 表示悬空引用：该字段指向某个集合，但该集合中没有具有此 ID 的文档。

## “引用”标签页

打开一个集合，再打开“**引用**”标签页。它一打开就开始查找；“**查找引用**”会重新查找。

1. 读取 200 个文档的随机采样，收集保存 ObjectId 的字段（文档自身的 `_id` 除外）。
2. 在数据库的其他集合中按 `_id` 查找这些 ID，名称与字段相近的集合优先。
3. 为找到的每个关系显示一张卡片：字段、它指向的集合、采样 ID 在其中被找到的比例，以及几个示例名称。

每张卡片上：

- “**用 $lookup 打开**”会在该集合的“聚合”标签页中放入一个关联被引用文档的 `$lookup` 阶段。在那里运行之前不会执行任何操作。
- “**显示孤立项**”会在“文档”中放入一个筛选，用于查找保存了目标集合中不存在的采样 ID 的文档。

保存的 ObjectId 在任何集合中都找不到的字段会单独列出。

## 引用方

“**引用方**”用于查找引用其所打开文档的文档。它读取数据库的模型——即其“数据库”标签页绘制的引用，依据字段名称（`customerId` → `customers`）、属于此集合 ID 的采样值，或视图或已保存管道中的 `$lookup` 得出——并针对每个引用此集合 `_id` 的字段，查询其中是否有此文档的 ID，保存它的数组也包括在内。

保存了它的每个字段对应一张卡片：集合和字段（`orders.customerId`）、文档数量（最多列出 20 个，更多时显示“20+”）及其名称。“**在 orders 中显示**”会在该集合自己的标签页里，把选中这些文档的筛选放入其“文档”查询。无法读取的字段会如实说明；其余字段仍会列出。

## 示例

一个 `orders` 集合，内含 `{ "customerId": ObjectId("652f…"), "productIds": [ObjectId("6530…"), …] }`，旁边有 `customers` 和 `products` 集合。该标签页显示两个关系：`customerId → customers` 和 `productIds → products`，各自带有找到的比例（例如“采样的 200 个 ID 中找到 196 个”）。对第一个点击“**用 $lookup 打开**”，会在“聚合”中放入以下阶段：

```json
[
  {
    "$lookup": {
      "from": "customers",
      "localField": "customerId",
      "foreignField": "_id",
      "as": "customerId_ref"
    }
  }
]
```

## 权限

- **读取文档**（`documents:read`）：读取已打开集合的采样。
- **读取同一数据库的其他集合**（`database:read`）：列出数据库的集合并在其中查找 ID；对于“**引用方**”，则用于读取数据库的模型，以及在另一个集合的“文档”查询中放入筛选。从其他集合只会读取 `_id` 和上述命名字段，绝不会读取完整文档。

读取通过应用进行，使用已登录用户的权限和字段掩码：用户无权读取的集合，插件同样不会读取；读取被拒绝的单元格会在 30 秒后重新查询。

## 设置

无。

## 限制

- 只跟踪 ObjectId。以文本、数字或 UUID 保存的 ID 不会被查找。
- 该标签页采样 200 个随机文档，保留不同 ID 最多的 8 个字段，每个字段最多 20 个 ID，总共最多 200 个 ID。
- 最多在数据库的 50 个集合中查找，一旦所有字段都达到 80% 或更高的找到比例就提前停止。视图和 `system.` 集合从不查找。
- 关系是指保存了某字段大部分采样 ID 的集合。ID 分散在多个集合中的字段只显示保存最多的那一个。
- “**引用方**”只能找到数据库模型找到的引用（它会对每个集合采样）：采样中未出现的字段不会被查询。它最多查询 20 个字段，每个字段最多列出 20 个文档。每查询一个字段就占用应用每分钟读取次数中的一次：超出后，剩余的字段不再查询，并会予以说明。
- 在单元格中，字段只与名称相近的前两个集合匹配；ID 每次查找 200 个，内存中最多保留 5,000 个名称。集合列表每隔一分钟重新读取。
- 超过 60 个字符的名称会被截短。
- 字段最多跟踪六层深度。
