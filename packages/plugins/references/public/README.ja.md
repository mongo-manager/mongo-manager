# 参照

「参照」は、データベース内のドキュメントが ObjectId を通じてどのように互いを指しているかを示します。ドキュメントでは、`customerId` のような ID の横に参照先ドキュメントの名前を書くので、行が 16 進数の羅列ではなく「customer: Ada Lovelace」のように読めます。タブでは、コレクションのどのフィールドが他のドキュメントの ID を保持しているか、それらのドキュメントがどのコレクションにあるか、どの ID がどこも指していないかを調べます。

このプラグインは読み取るだけです。データベースは何も変更しません。

## 表示される場所

- **セルの値:** ドキュメントの ObjectId の横に、矢印と参照先ドキュメントの名前（`→ Ada Lovelace`）を表示します。その ID を持つドキュメントがない場合は `→ 見つかりません` と表示します。
- **コレクションのタブ:** すべてのコレクションとビューで、ドキュメント、集計などのタブの隣に **参照** タブが表示されます。
- **ドキュメントの操作:** ドキュメントの操作にある **参照元** は、そのドキュメントを参照しているデータベース内のドキュメントを一覧表示します。

## ID の横の名前

フィールド名が同じデータベース内のコレクション名（単数形でも複数形でも、id の語尾の有無を問わない）に似ている場合、セルに名前が表示されます。

- `customerId`、`customer_id`、`customer` → `customers`
- `categoryIds` → `categories`
- `address` → `addresses`

プラグインは、ページに表示されている ID をそのコレクションで `_id` により検索し、見つかったドキュメントのうち名前に使うフィールドだけを読み取ります。名前には、ドキュメントが持つ `name`、`title`、`label`、`displayName`、`fullName`、`username`、`email`、`code`、`slug` のうち最初のものを使い、どれもなければ `_id` を表示します。ID が、同じ名前のコレクションのどこにも見つからないフィールドには、テキストは一切表示されません。

警告として表示される `→ 見つかりません` は、宙に浮いた参照を示します。フィールドはコレクションを指していますが、そのコレクションにこの ID を持つドキュメントがありません。

## 参照タブ

コレクションを開き、**参照** タブを開きます。開くとすぐに検索を始めます。**参照を検索** で再度検索します。

1. 200 件のドキュメントをランダムに読み取り、ObjectId を保持するフィールドを集めます（ドキュメント自身の `_id` は除く）。
2. それらの ID を、データベースの他のコレクションで `_id` により検索します。フィールドに名前が似たコレクションを先に調べます。
3. 見つかった関係ごとに 1 枚のカードを表示します。フィールド、指しているコレクション、サンプルの ID のうちそこで見つかった割合、いくつかの例の名前が載ります。

各カードでは次の操作ができます。

- **$lookup で開く** は、参照先のドキュメントを結合する `$lookup` ステージを、そのコレクションの集計タブに入れます。そこで実行するまで何も実行されません。
- **孤立を表示** は、対象のコレクションにないサンプルの ID を保持しているドキュメントを探すフィルターを、ドキュメントに入れます。

どのコレクションにも見つからない ObjectId を保持するフィールドは、別に一覧表示されます。

## 参照元

**参照元** は、開いているドキュメントを参照しているドキュメントを探します。データベースのモデル、つまりデータベースタブが描く参照を読み取ります。この参照は、フィールドの名前（`customerId` → `customers`）、このコレクションの ID であるサンプルの値、またはビューや保存済みパイプラインの `$lookup` から見つかります。そして、このコレクションの `_id` を参照している各フィールドに、このドキュメントの ID を保持しているかを問い合わせます。ID を含む配列も対象です。

ID を保持していたフィールドごとに 1 枚のカードが表示されます。コレクションとフィールド（`orders.customerId`）、ドキュメントの件数（最大 20 件を一覧表示し、それ以上は「20+」）、そしてその名前です。**orders で表示** は、そのコレクション自身のタブで、これらのドキュメントを選択するフィルターをドキュメントのクエリに入れます。読み取れなかったフィールドはその旨が表示され、他のフィールドは引き続き一覧表示されます。

## 例

`{ "customerId": ObjectId("652f…"), "productIds": [ObjectId("6530…"), …] }` を持つ `orders` コレクションが、`customers` と `products` のコレクションの隣にあるとします。タブには `customerId → customers` と `productIds → products` の 2 つの関係が、それぞれ見つかった割合（たとえば「サンプルの 200 件の ID のうち 196 件が見つかりました」）とともに表示されます。1 つ目で **$lookup で開く** を押すと、集計に次のステージが入ります。

```json
[
  {
    "$lookup": {
      "from": "customers",
      "localField": "customerId",
      "foreignField": "_id",
      "as": "customerId_ref"
    }
  }
]
```

## 権限

- **ドキュメントの読み取り**（`documents:read`）: 開いているコレクションのサンプルを読み取るため。
- **同じデータベースの他のコレクションの読み取り**（`database:read`）: データベースのコレクションを一覧表示し、そこで ID を検索するため。**参照元** では、データベースのモデルを読み取り、別のコレクションのドキュメントのクエリにフィルターを入れるために使います。他のコレクションから読み取るのは `_id` と上記の名前用フィールドだけで、ドキュメント全体を読み取ることはありません。

読み取りはアプリを通じて、サインイン中のユーザーの権限とフィールドのマスキングに従って行われます。ユーザーが読み取れないコレクションは、プラグインも読み取りません。読み取りが拒否されたセルは、30 秒後に再度問い合わせます。

## 設定

なし。

## 制限

- 追跡するのは ObjectId だけです。テキスト、数値、UUID として保存された ID は対象外です。
- タブはランダムな 200 件のドキュメントをサンプリングし、異なる ID が最も多い 8 個のフィールドを残し、フィールドあたり最大 20 個、合計 200 個までの ID を扱います。
- データベースのコレクションは最大 50 個まで調べ、すべてのフィールドが 80% 以上見つかった時点で早めに終了します。ビューと `system.` コレクションは調べません。
- 関係とは、フィールドのサンプルの ID の大半を保持しているコレクションのことです。ID が複数のコレクションに分散しているフィールドには、最も多く保持している 1 つだけが表示されます。
- **参照元** が見つけるのは、データベースのモデルが見つける参照です（各コレクションをサンプリングします）。サンプルに現れなかったフィールドは問い合わせません。問い合わせるのは最大 20 個のフィールドで、それぞれ最大 20 件のドキュメントを一覧表示します。問い合わせたフィールド 1 つにつき、アプリの 1 分あたりの読み取り回数のうち 1 回を使います。上限を超えると残りのフィールドは問い合わせず、その旨が表示されます。
- セルでは、フィールドは名前が似た最初の 2 つのコレクションとだけ照合されます。ID は 200 個ずつ検索され、メモリに保持される名前は最大 5,000 件です。コレクションの一覧は 1 分後に再度読み取られます。
- 60 文字を超える名前は短縮されます。
- フィールドは 6 階層の深さまで追跡します。
