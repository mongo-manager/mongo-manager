# 참조

참조는 데이터베이스의 도큐먼트들이 ObjectId를 통해 서로를 어떻게 가리키는지 보여 줍니다. 도큐먼트 화면에서 `customerId` 같은 id 옆에 참조된 도큐먼트의 이름을 표시하므로, 한 행이 16진수 문자열이 아니라 "customer: Ada Lovelace"처럼 읽힙니다. 이 플러그인의 탭은 컬렉션의 어떤 필드가 다른 도큐먼트의 id를 가지고 있는지, 그 도큐먼트가 어느 컬렉션에 있는지, 어떤 id가 아무것도 가리키지 않는지 찾아 줍니다.

플러그인은 읽기만 합니다. 데이터베이스는 아무것도 변경하지 않습니다.

## 표시되는 위치

- **셀 값:** 도큐먼트 화면의 ObjectId 옆에 화살표와 참조된 도큐먼트의 이름(`→ Ada Lovelace`)을 표시합니다. 해당 id를 가진 도큐먼트가 없으면 `→ 찾을 수 없음`을 표시합니다.
- **컬렉션 탭:** 모든 컬렉션과 뷰에서 도큐먼트, 집계 등 다른 탭 옆에 **참조** 탭이 나타납니다.
- **도큐먼트 작업:** 도큐먼트 작업의 **참조하는 도큐먼트**는 해당 도큐먼트를 참조하는 데이터베이스의 도큐먼트를 나열합니다.

## id 옆의 이름

필드 이름이 같은 데이터베이스의 컬렉션 이름과 비슷하면(단수형이든 복수형이든, id 접미사가 있든 없든) 셀에 이름이 표시됩니다.

- `customerId`, `customer_id` 또는 `customer` → `customers`
- `categoryIds` → `categories`
- `address` → `addresses`

플러그인은 페이지에 표시된 id를 해당 컬렉션에서 `_id`로 조회하고, 찾은 도큐먼트에서는 이름에 해당하는 필드만 읽습니다. 이름은 도큐먼트가 가진 `name`, `title`, `label`, `displayName`, `fullName`, `username`, `email`, `code`, `slug` 중 첫 번째 값입니다. 이 중 어느 것도 없으면 `_id`를 표시합니다. 같은 이름의 컬렉션 어디에서도 id가 발견되지 않는 필드에는 아무 텍스트도 표시하지 않습니다.

경고로 표시되는 `→ 찾을 수 없음`은 끊어진 참조를 나타냅니다. 필드가 컬렉션을 가리키지만 그 컬렉션에 이 id를 가진 도큐먼트가 없다는 뜻입니다.

## 참조 탭

컬렉션을 열고 **참조** 탭으로 이동합니다. 탭은 열리자마자 검색을 시작하며, **참조 찾기**를 누르면 다시 검색합니다.

1. 도큐먼트 200개를 무작위로 샘플링하여 ObjectId를 가진 필드를 수집합니다(도큐먼트 자체의 `_id` 제외).
2. 그 id를 데이터베이스의 다른 컬렉션에서 `_id`로 조회합니다. 필드 이름과 비슷한 이름의 컬렉션부터 조회합니다.
3. 찾은 관계마다 카드 하나를 표시합니다. 카드에는 필드, 가리키는 컬렉션, 샘플 id 중 그곳에서 찾은 비율, 몇 가지 예시 이름이 들어 있습니다.

각 카드에서 할 수 있는 작업은 다음과 같습니다.

- **$lookup으로 열기**는 참조된 도큐먼트를 조인하는 `$lookup` 스테이지를 컬렉션의 집계 탭에 넣습니다. 그곳에서 직접 실행하기 전에는 아무것도 실행되지 않습니다.
- **고아 항목 표시**는 대상 컬렉션에 없는 샘플 id 중 하나를 가진 도큐먼트를 필터로 도큐먼트 화면에 넣습니다.

어떤 컬렉션에서도 발견되지 않은 ObjectId를 가진 필드는 따로 나열됩니다.

## 참조하는 도큐먼트

**참조하는 도큐먼트**는 열려 있는 도큐먼트를 참조하는 도큐먼트를 찾습니다. 데이터베이스의 모델을 읽고(데이터베이스 탭이 그리는 참조로, 필드 이름(`customerId` → `customers`), 이 컬렉션의 id인 샘플 값, 뷰나 저장된 파이프라인의 `$lookup`에서 찾습니다), 이 컬렉션의 `_id`를 참조하는 각 필드에 대해 이 도큐먼트의 id를 조회합니다. 그 id를 담은 배열도 포함합니다.

그 id를 가진 필드마다 카드가 하나씩 표시됩니다. 컬렉션과 필드(`orders.customerId`), 도큐먼트 수(최대 20개까지 나열하며, 더 많으면 "20+"), 그리고 해당 도큐먼트의 이름이 들어 있습니다. **orders에서 보기**는 해당 도큐먼트를 선택하는 필터를 그 컬렉션의 도큐먼트 쿼리에 넣고, 그 컬렉션 자체의 탭에서 보여 줍니다. 읽을 수 없었던 필드는 그렇다고 표시되며, 나머지는 계속 나열됩니다.

## 예시

`customers`, `products` 컬렉션과 함께 있는 `orders` 컬렉션에 `{ "customerId": ObjectId("652f…"), "productIds": [ObjectId("6530…"), …] }`가 있다고 해 보겠습니다. 탭에는 `customerId → customers`와 `productIds → products`, 두 관계가 각각 찾은 비율과 함께 표시됩니다(예: "샘플 id 200개 중 196개 찾음"). 첫 번째 관계에서 **$lookup으로 열기**를 누르면 집계에 다음 스테이지가 들어갑니다.

```json
[
  {
    "$lookup": {
      "from": "customers",
      "localField": "customerId",
      "foreignField": "_id",
      "as": "customerId_ref"
    }
  }
]
```

## 권한

- **도큐먼트 읽기**(`documents:read`): 열려 있는 컬렉션의 샘플을 읽습니다.
- **같은 데이터베이스의 다른 컬렉션 읽기**(`database:read`): 데이터베이스의 컬렉션을 나열하고 그 안에서 id를 조회합니다. **참조하는 도큐먼트**에서는 데이터베이스의 모델을 읽고 다른 컬렉션의 도큐먼트 쿼리에 필터를 넣습니다. 다른 컬렉션에서는 `_id`와 위에 나열한 이름 필드만 읽으며, 도큐먼트 전체는 읽지 않습니다.

읽기는 로그인한 사용자의 권한과 필드 마스킹을 적용하여 앱을 통해 이루어집니다. 사용자가 읽을 수 없는 컬렉션은 플러그인도 읽지 않으며, 읽기가 거부된 셀은 30초 뒤에 다시 조회합니다.

## 제한

- ObjectId만 따라갑니다. 텍스트, 숫자, UUID로 저장된 id는 확인하지 않습니다.
- 탭은 무작위 도큐먼트 200개를 샘플링하고, 고유한 id가 가장 많은 필드 8개를 유지하며, 필드당 최대 id 20개, 전체 최대 id 200개를 사용합니다.
- 데이터베이스의 컬렉션을 최대 50개까지 검색하며, 모든 필드가 80% 이상 발견되면 일찍 멈춥니다. 뷰와 `system.` 컬렉션은 검색하지 않습니다.
- 관계는 필드의 샘플 id를 가장 많이 가진 컬렉션입니다. id가 여러 컬렉션에 흩어져 있는 필드에는 가장 많이 가진 컬렉션 하나만 표시됩니다.
- **참조하는 도큐먼트**는 데이터베이스의 모델이 찾는 참조를 찾습니다(모델은 각 컬렉션을 샘플링합니다). 샘플에 나타나지 않은 필드는 조회하지 않습니다. 최대 필드 20개를 조회하고 필드당 최대 도큐먼트 20개를 나열합니다. 조회하는 필드 하나는 분당 앱 읽기 한도에서 읽기 한 번에 해당합니다. 한도를 넘으면 남은 필드는 조회하지 않으며, 그렇다고 알려 줍니다.
- 셀에서는 필드를 같은 이름의 처음 두 컬렉션에만 대조합니다. id는 200개씩 조회하며, 이름은 최대 5,000개까지 메모리에 보관합니다. 컬렉션 목록은 1분 뒤에 다시 읽습니다.
- 60자를 넘는 이름은 줄여서 표시합니다.
- 필드는 6단계 깊이까지 따라갑니다.
