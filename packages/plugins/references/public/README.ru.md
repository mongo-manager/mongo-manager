# Ссылки

Плагин «Ссылки» показывает, как документы базы данных указывают друг на друга через ObjectId. В разделе «Документы» он пишет имя документа, на который указывает идентификатор, рядом с ним, например с `customerId`, поэтому строка читается как «customer: Ada Lovelace», а не как набор шестнадцатеричных цифр. Его вкладка находит, какие поля коллекции содержат идентификаторы других документов, в каких коллекциях находятся эти документы и какие идентификаторы ни на что не указывают.

Плагин только читает. Он ничего не изменяет в базе данных.

## Где он появляется

- **Значения ячеек:** рядом с ObjectId в «Документах» стрелка и имя документа, на который указывает ссылка (`→ Ada Lovelace`), или `→ не найдено`, если документа с таким идентификатором нет.
- **Вкладка коллекции:** вкладка **Ссылки** рядом с «Документами», «Агрегациями» и другими вкладками каждой коллекции и представления.
- **Действие с документом:** **Кто ссылается** в действиях документа перечисляет документы базы данных, которые на него ссылаются.

## Имена рядом с идентификаторами

Ячейка получает имя, если ее поле названо как коллекция той же базы данных, в единственном или множественном числе, с окончанием идентификатора или без него:

- `customerId`, `customer_id` или `customer` → `customers`
- `categoryIds` → `categories`
- `address` → `addresses`

Плагин ищет идентификаторы, показанные на странице, по `_id` в этой коллекции и читает у найденных документов только поля с именами. Именем служит первое из полей `name`, `title`, `label`, `displayName`, `fullName`, `username`, `email`, `code` и `slug`, которое есть в документе; если ни одного нет, показывается его `_id`. Поле, идентификаторы которого не найдены ни в одной коллекции с таким названием, не получает никакого текста.

`→ не найдено`, показанное как предупреждение, отмечает висячую ссылку: поле указывает на коллекцию, но в ней нет документа с этим идентификатором.

## Вкладка «Ссылки»

Откройте коллекцию, затем вкладку **Ссылки**. Поиск начинается сразу при открытии; **Найти ссылки** запускает его заново.

1. Она читает случайную выборку из 200 документов и собирает поля, содержащие ObjectId (кроме собственного `_id` документов).
2. Она ищет эти идентификаторы по `_id` в других коллекциях базы данных, сначала в тех, что названы как поле.
3. Она показывает по одной карточке на каждую найденную связь: поле, коллекцию, на которую оно указывает, долю идентификаторов из выборки, найденных там, и несколько примеров имен.

На каждой карточке:

- **Открыть с $lookup** помещает стадию `$lookup`, соединяющую документы, на которые указывают ссылки, на вкладку «Агрегации» коллекции. Ничего не выполняется, пока вы сами не запустите ее там.
- **Показать потерянные** помещает в «Документы» фильтр для документов, содержащих один из идентификаторов выборки, которых нет в целевой коллекции.

Поля с ObjectId, не найденными ни в одной коллекции, перечисляются отдельно.

## Кто ссылается

**Кто ссылается** ищет документы, которые ссылаются на тот, у которого оно открыто. Оно читает модель базы данных, то есть ссылки, которые рисует ее вкладка «База данных» и которые определяются по имени поля (`customerId` → `customers`), по значениям из выборки, являющимся идентификаторами этой коллекции, или по `$lookup` в представлении либо сохраненном конвейере, и запрашивает у каждого поля, ссылающегося на `_id` этой коллекции, идентификатор данного документа, в том числе в массиве, который его содержит.

Каждое поле, где он найден, представлено карточкой: коллекция и поле (`orders.customerId`), число документов (в списке до 20, «20+», если их больше) и их имена. **Показать в orders** помещает фильтр, выбирающий их, в запрос «Документов» этой коллекции, на ее собственной вкладке. Поле, которое не удалось прочитать, сообщает об этом; остальные все равно перечисляются.

## Пример

Коллекция `orders` с документом `{ "customerId": ObjectId("652f…"), "productIds": [ObjectId("6530…"), …] }` рядом с коллекциями `customers` и `products`. Вкладка показывает две связи, `customerId → customers` и `productIds → products`, каждую с долей найденных идентификаторов (например, «Найдено идентификаторов из выборки: 196 из 200»). **Открыть с $lookup** у первой помещает в «Агрегации» такую стадию:

```json
[
  {
    "$lookup": {
      "from": "customers",
      "localField": "customerId",
      "foreignField": "_id",
      "as": "customerId_ref"
    }
  }
]
```

## Разрешения

- **Чтение документов** (`documents:read`): чтобы читать выборку открытой коллекции.
- **Чтение других коллекций той же базы данных** (`database:read`): чтобы перечислять коллекции базы данных и искать в них идентификаторы; для **Кто ссылается** также чтобы читать модель базы данных и помещать фильтр в запрос «Документов» другой коллекции. Из других коллекций читаются только `_id` и перечисленные выше поля с именами, но никогда документы целиком.

Чтение идет через приложение с правами вошедшего пользователя и с маскированием полей: коллекцию, которую пользователь не вправе читать, плагин тоже не читает, а ячейка, чтение которой было отклонено, запрашивается снова через 30 секунд.

## Настройки

Нет.

## Ограничения

- Отслеживаются только ObjectId. Идентификаторы, хранящиеся как текст, числа или UUID, не проверяются.
- Вкладка берет выборку из 200 случайных документов, оставляет 8 полей с наибольшим числом различных идентификаторов, до 20 идентификаторов на поле и 200 в сумме.
- Она просматривает не более 50 коллекций базы данных и досрочно останавливается, как только каждое поле найдено на 80 % и более. Представления и коллекции `system.` никогда не просматриваются.
- Связь — это коллекция, содержащая больше всего идентификаторов поля из выборки. Если идентификаторы поля распределены по нескольким коллекциям, показывается только та, где их больше всего.
- **Кто ссылается** находит ссылки, которые находит модель базы данных (она берет выборку из каждой коллекции): поле, которого не было в выборке, не запрашивается. Запрашивается не более 20 полей, и для каждого перечисляется до 20 документов. Каждое запрошенное поле — одно из чтений, которые приложение разрешает в минуту: сверх них оставшиеся поля не запрашиваются, и об этом сообщается.
- В ячейках поле сопоставляется только с первыми двумя коллекциями, названными так же; идентификаторы ищутся по 200 за раз, а в памяти хранится до 5 000 имен. Список коллекций перечитывается через минуту.
- Имена длиннее 60 символов сокращаются.
- Поля отслеживаются на глубину до шести уровней.
