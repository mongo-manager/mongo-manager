# 유효성 검사 점검

유효성 검사 점검은 컬렉션의 유효성 검사 규칙을 낱낱이 분해하고, 도큐먼트를 규칙별로 따로 점검합니다. 규칙 전체를 위반하는 도큐먼트가 몇 개인지, 그리고 필수 필드별, 속성별, 조건별로 위반하는 도큐먼트가 몇 개인지 알려 줍니다. 많은 도큐먼트가 위반하는 규칙은 엄격하게 만들기 전에 데이터나 규칙 자체를 먼저 고쳐야 할 규칙입니다.

이 플러그인은 읽기만 합니다. 데이터베이스나 규칙에는 아무것도 변경하지 않습니다.

## 표시되는 위치

- **컬렉션 탭:** 모든 컬렉션에서 도큐먼트, 집계 및 다른 탭 옆에 **규칙 점검** 탭이 나타납니다.

## 사용 방법

컬렉션을 연 다음 **규칙 점검** 탭을 엽니다. 탭을 열면 곧바로 무작위 도큐먼트 1,000개를 점검합니다. 더 많이 점검하려면 **무작위 10,000개** 또는 **전체**를 선택하세요. **점검**을 누르면 다시 실행합니다.

탭에는 위반이 많은 규칙부터 순서대로 규칙이 나열됩니다. 각 규칙에는 점검한 도큐먼트 중 몇 개가 위반했는지 비율과 함께 표시됩니다. **도큐먼트에서 보기**는 해당 도큐먼트를 선택하는 필터를 도큐먼트 쿼리에 넣어, 거기서 살펴보고 고칠 수 있게 합니다. **규칙을 위반하는 도큐먼트 모두 보기**는 규칙 전체에 대해 같은 일을 합니다.

유효성 검사 수준과 동작도 표시됩니다. 수준이 `moderate`이면 이미 규칙을 따르는 도큐먼트만 점검하고, 동작이 `warn`이면 쓰기를 거부하는 대신 규칙 위반을 로그에 기록합니다. 둘 중 하나라도 설정되어 있으면 탭에 그렇게 안내합니다.

## 규칙을 나누는 방식

- **`$jsonSchema`:** `required`의 각 필드가 규칙 하나이고, `properties`의 각 속성이 규칙 하나입니다(점검 내용: 타입, 최솟값, 패턴 등). `true`가 아닌 `additionalProperties`는 `properties` 및 `patternProperties`와 함께 "스키마에 정의된 필드만 허용"이라는 규칙 하나가 됩니다. 그 밖의 키워드(`minProperties`, `dependencies`, `anyOf` 등)는 각각 별개의 규칙입니다. `title`과 `description`은 도큐먼트에 대해 아무것도 말하지 않으므로 제외되며, 최상위 `bsonType: "object"`도 제외됩니다.
- **쿼리 유효성 검사기:** 각 필드의 조건이 규칙 하나이고, 최상위 `$and`의 각 절도 마찬가지입니다. `$or`, `$nor`, `$expr`는 각각 규칙 하나입니다.

도큐먼트가 규칙을 충족하지 못하면 그 규칙을 위반한 것입니다. 사용하는 필터는 `{ $nor: [규칙] }`입니다.

## 예시

유효성 검사기가 `email`을 필수로 하고 `age`가 0 이상의 int라고 정의한 `customers` 컬렉션의 경우:

```
email 필수          도큐먼트 12개 (1.2%)
age  bsonType: 'int', minimum: 0     도큐먼트 3개 (0.3%)
name 필수           위반하는 도큐먼트 없음
```

첫 번째 규칙에서 **도큐먼트에서 보기**를 누르면 도큐먼트에 `{ $nor: [{ $jsonSchema: { required: ["email"] } }] }`가 들어갑니다.

## 뷰의 경우

뷰에는 자체 유효성 검사 규칙이 없습니다. 탭에서 그렇게 안내하고, 뷰가 읽어 오는 컬렉션을 알려 줍니다.

## 권한

- **도큐먼트 읽기** (`documents:read`): 읽기 전용 집계 한 번으로 규칙별 위반 도큐먼트 수를 세기 위해 필요합니다.
- **이 컬렉션의 정의 읽기** (`collection:read`): 유효성 검사 규칙을 읽기 위해 필요합니다.

읽기는 로그인한 사용자의 권한과 필드 마스킹을 적용하여 앱을 통해 이루어집니다. 값이 사용자에게 숨겨진 필드에 대해 규칙이 정의한 내용은 플러그인에 전달되지 않습니다(필드 이름은 전달됨). 그런 규칙은 점검하지 않으며 집계 수는 표시된 규칙 기준입니다. 이 플러그인은 다른 컬렉션을 읽을 수 없습니다.

## 제한 사항

- 무작위 샘플은 규칙이 얼마나 자주 위반되는지를 알려 줄 뿐, 전체에서 몇 개의 도큐먼트가 위반하는지는 알려 주지 않습니다. 정확한 수를 알려면 **전체**를 선택하세요.
- 점검은 디스크를 사용하지 않고 최대 10초 동안 실행되는 파이프라인 하나입니다. 큰 컬렉션에서는 **전체**가 시간 초과될 수 있지만 샘플은 그렇지 않습니다.
- 규칙은 최대 40개까지 집계하며, 더 있으면 탭에서 알려 줍니다.
- 규칙은 작성된 그대로 집계합니다. 다른 규칙과 함께일 때만 성립하는 규칙(예: 여러 속성에 걸친 `anyOf`)은 MongoDB가 검사하는 방식대로 전체를 하나로 집계합니다.
