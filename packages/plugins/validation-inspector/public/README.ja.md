# 検証チェック

検証チェックは、コレクションの検証ルールを分解し、ドキュメントをルールごとに個別にチェックします。ルール全体では何件のドキュメントが違反しているか、各必須フィールド、各プロパティ、各条件ごとに何件が違反しているかが分かります。多くのドキュメントが違反しているルールは、厳格にする前に、データまたはルール自体を修正する必要があるものです。

このプラグインは読み取りのみを行います。データベースにもルールにも何も変更を加えません。

## 表示される場所

- **コレクションのタブ:** すべてのコレクションで、ドキュメント、集計などのタブの隣に**ルールチェック**タブが表示されます。

## 使い方

コレクションを開き、**ルールチェック**タブを開きます。タブを開くとすぐに、ランダムな 1,000 件のドキュメントに対してチェックが実行されます。さらに多くをチェックするには**ランダムに 10,000 件**または**すべて**を選び、**チェック**で再実行できます。

タブにはルールが違反の多い順に一覧表示されます。各ルールには、チェックしたドキュメントのうち何件が違反しているかが割合とともに表示されます。**ドキュメントで表示**は、それらのドキュメントを選択するフィルターをドキュメントのクエリに設定するので、そこで確認して修正できます。**ルールに違反するものをすべて表示**は、ルール全体について同じ操作を行います。

検証レベルとアクションも表示されます。レベルが `moderate` の場合はすでにルールに適合しているドキュメントのみが検証され、アクションが `warn` の場合はルール違反時に書き込みを拒否せずログに記録します。どちらかが設定されている場合は、タブにその旨が表示されます。

## ルールの分け方

- **`$jsonSchema`:** `required` の各フィールドが 1 つのルール、`properties` の各プロパティが 1 つのルール（チェック内容: 型、最小値、パターンなど）です。`true` 以外の `additionalProperties` は、`properties` と `patternProperties` とともに「スキーマで定義されたフィールド以外は不可」という 1 つのルールになります。その他のキーワード（`minProperties`、`dependencies`、`anyOf` など）は、それぞれ独立したルールです。`title` と `description` はドキュメントについて何も述べないため除外され、最上位の `bsonType: "object"` も同様です。
- **クエリバリデーター:** 各フィールドの条件が 1 つのルールで、最上位の `$and` の各句も同様です。`$or`、`$nor`、`$expr` はそれぞれ 1 つのルールです。

ドキュメントがルールを満たさない場合、そのルールに違反しています。使用されるフィルターは `{ $nor: [ルール] }` です。

## 例

`email` を必須とし、`age` を 0 以上の int とするバリデーターを持つ `customers` コレクションの場合:

```
email は必須          12 件（1.2%）
age  bsonType: 'int', minimum: 0     3 件（0.3%）
name は必須           違反するドキュメントはありません
```

最初の項目で**ドキュメントで表示**を押すと、ドキュメントに `{ $nor: [{ $jsonSchema: { required: ["email"] } }] }` が設定されます。

## ビューについて

ビュー自体には検証ルールがありません。タブはその旨を表示し、参照元のコレクションを案内します。

## 権限

- **ドキュメントの読み取り**（`documents:read`）: ルールごとの違反ドキュメント数を、読み取り専用の集計 1 回で数えるために使います。
- **このコレクションの定義の読み取り**（`collection:read`）: 検証ルールを読み取るために使います。

読み取りは、サインインしているユーザーの権限とフィールドのマスキングに従って、アプリを通じて行われます。値がユーザーに対して非表示のフィールドについてルールが定めている内容は、プラグインには渡されません（フィールド名は渡されます）。そのようなルールはチェックされず、件数は表示されているルールのものになります。このプラグインは他のコレクションを読み取れません。

## 設定

なし。

## 制限

- ランダムサンプルから分かるのは、ルールがどれくらいの頻度で違反されているかであり、全体で何件が違反しているかではありません。正確な件数が必要な場合は**すべて**を選んでください。
- チェックは、ディスクを使わず最大 10 秒間実行される 1 つのパイプラインです。大きなコレクションでは**すべて**がタイムアウトすることがありますが、サンプルならタイムアウトしません。
- カウントされるルールは最大 40 件です。それを超える場合はタブに表示されます。
- ルールは記述されたとおりにカウントされます。別のルールと組み合わさって初めて成り立つルール（たとえばプロパティをまたぐ `anyOf`）は、MongoDB が検証するのと同じく全体として 1 つにカウントされます。
