# 时间提示

时间提示会在隐藏着日期的值上显示可读的日期。ObjectId 的前四个字节中包含它的创建时间（精确到秒），许多集合也会把时间存为 Unix 时间戳（自 1970 年以来的秒数或毫秒数）。时间提示会在“文档”中以应用的语言和您的本地时间显示这些时刻，您无需自己解码。

该插件没有自己的页面，也不会从数据库读取任何内容。它只查看应用已经在显示的值。

## 出现的位置

- **单元格的值：** 将鼠标指向“文档”中的 ObjectId 时，显示它的创建时间。
- **单元格的值：** 将鼠标指向可视为 Unix 时间的数字时，显示它的日期，并标记为 `≈`。

两者都出现在“文档”显示该值的所有位置（表格、树、卡片、文档检查器），位于其单元格或行在您将鼠标指向它或键盘焦点移到那里时显示的工具提示中：第一行是完整的值，下面是时间，前面带有插件的名称。值的旁边不会写入任何内容，文档本身也不会被添加任何内容。屏幕阅读器会将时间与值一起朗读。

## 如何使用

无需打开或设置任何内容：管理员批准并启用该插件后，所有人都能在“文档”中看到这些提示。

## 示例

例如这样的文档：

```json
{
  "_id": { "$oid": "652629f0c3e5b2a1d4f0a9b7" },
  "createdAt": 1696999920,
  "updatedAtMs": 1697003520000,
  "quantity": 3
}
```

对于位于伊斯坦布尔、应用语言为中文的用户，会显示这些工具提示：

```
_id           指向时：  ObjectId("652629f0c3e5b2a1d4f0a9b7")
                        时间提示: 2023年10月11日 07:52
createdAt     指向时：  1696999920
                        时间提示: ≈ 2023年10月11日 07:52
updatedAtMs   指向时：  1697003520000
                        时间提示: ≈ 2023年10月11日 08:52
quantity      无工具提示
```

`quantity` 没有提示：3 不在 Unix 时间的范围内。

## 哪些内容会被视为时间

- **ObjectId：** 始终如此。前八位十六进制数字是以秒为单位的创建时间。这个时间是该 id 生成的时刻，通常由插入文档的程序的驱动程序生成，不一定是插入发生的那一刻。
- **数字：** 从 1,000,000,000 起、不含 4,102,444,800 的 int、long 或 double 会被视为秒；同一范围乘以 1,000 则被视为毫秒。这涵盖 2001 年 9 月 9 日至 2099 年底。

数字只是一种猜测：处于该范围内的价格、数量或电话号码同样会得到一个日期。这就是数字提示以 `≈` 开头的原因。以真正的 BSON 日期存储的日期由应用自己显示，不需要提示。

## 格式

- 日期和时间使用应用的语言：中等长度的日期、简短的时间（例如英语为 `Oct 11, 2023, 7:52 AM`，土耳其语为 `11 Eki 2023 07:52`）。
- 时区为浏览器的本地时区。
- 应用的语言改变时，提示会以新的语言重新显示。

## 权限

- **读取文档**（`documents:read`）：应用只会向被允许读取文档的插件询问单元格的值。时间提示接收页面上的值，自己从不查询数据库。

## 设置

无。

## 限制

- 只读取 ObjectId 和普通数字。以文本（`"2023-10-11T07:52:00Z"`）或小数（`$numberDecimal`）存储的时间不会得到提示。
- 显示的最小单位是秒；不显示毫秒。
- 小于 1,000,000,000 秒（2001 年 9 月之前）或自 2100 年起的数字不会被视为时间。
- 提示跟随应用显示的值；嵌套对象内部的值，会在应用将该嵌套值显示为单元格的位置得到提示。
