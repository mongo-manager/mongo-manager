# Скрипт индексов

Скрипт индексов записывает индексы коллекции или всей базы данных в виде команд, которые создают их заново: для mongosh, для драйвера Node.js или Python либо в формате JSON. Используйте его, чтобы создать такие же индексы в другой среде, хранить их вместе с кодом или спланировать миграцию.

Плагин только читает. Ничего не выполняется: скрипт — это текст, который можно скопировать или сохранить.

## Где он появляется

- **Вкладка коллекции:** вкладка **Скрипт индексов** рядом с «Документами», «Агрегациями» и другими вкладками каждой коллекции.

## Как пользоваться

Откройте коллекцию, затем вкладку **Скрипт индексов**. Индексы коллекции читаются сразу после открытия.

- **Индексы:** **Эта коллекция** или **Вся база данных** — все ее коллекции (у представлений нет собственных индексов).
- **Скрипт для:** **mongosh** (`db.getCollection("…").createIndex(…)`), **Node.js** (`await db.collection("…").createIndex(…)`), **Python** (`create_index` из PyMongo) или **JSON** — каждый индекс в виде `{ collection, key, options }` в каноническом Extended JSON, с точностью до типа.

**Копировать** помещает скрипт в буфер обмена, **Скачать** сохраняет его (`.txt` для скриптов, `.json` для JSON).

Записывается каждый параметр индекса: имя, `unique`, `sparse`, частичный фильтр, TTL (`expireAfterSeconds`), collation, `hidden`, веса и язык текстового индекса и остальное. `createIndex` драйвера (как и в mongosh) пропускает параметры, которых не знает, например `prepareUnique`: индекс с таким параметром записывается как команда `createIndexes` (`db.runCommand(…)` в mongosh, `await db.command(…)` для Node.js), которая сохраняет все параметры. Текстовый индекс записывается с теми полями, на которых он был создан (`{ title: "text" }`), как их указывают его веса. Значения собственного типа (даты, идентификаторы, числа, двоичные данные, метки времени) записываются так, как их создает соответствующий язык. Индекс `_id` по умолчанию или кластеризованный индекс создается вместе с коллекцией и не включается.

## Пример

```
db.getCollection("orders").createIndex({ customerId: 1, createdAt: -1 }, { name: "customerId_1_createdAt_-1", unique: true })
db.getCollection("orders").createIndex({ expires: 1 }, { name: "expires_1", expireAfterSeconds: 3600 })
```

Для Python:

```
db["orders"].create_index([("customerId", 1), ("createdAt", -1)], name="customerId_1_createdAt_-1", unique=True)
```

## Разрешения

- **Чтение определения этой коллекции** (`collection:read`): чтобы получить список ее индексов.
- **Чтение других коллекций той же базы данных** (`database:read`): для режима **Вся база данных**, чтобы получить список ее коллекций и их индексов.

Чтение выполняется через приложение с правами и маскированием полей вошедшего пользователя. Значение частичного фильтра для поля, скрытого от пользователя, приходит как `"***"`: индекс с таким значением помечается в скрипте и на вкладке, поскольку скрипт не создал бы его в исходном виде.

## Параметры

Нет.

## Ограничения

- Режим **Вся база данных** читает не более 100 коллекций; если их больше, вкладка сообщает об этом. Коллекция, индексы которой не удалось прочитать, указывается с причиной на вкладке и в начале скрипта; JSON, где для этого нет места, в таком случае не копируется и не сохраняется. При превышении лимита чтений в минуту вкладка останавливается и сообщает об этом: повторите попытку через минуту.
- Поисковые индексы (Atlas Search, Vector Search) не записываются: они создаются иначе.
- Скрипты Node.js и Python начинаются со строк, которые подключают нужные им модули; сначала подключите `db` к своей базе данных. Скрипт Node.js использует await на верхнем уровне: запускайте его как ES-модуль (файл `.mjs`).
- Поля ключа приходят в виде объекта, в котором имена-числа (`"2"`) идут первыми: порядок, в котором был создан такой составной ключ, теряется, о чем сообщают вкладка и скрипт (JSON помечает индекс как `keyOrderUncertain`; индекс с датой, которую JavaScript не может хранить, — как `farDate`).
