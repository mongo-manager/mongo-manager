# インデックススクリプト

インデックススクリプトは、コレクション（またはデータベース全体）のインデックスを、再作成するコマンドとして出力します。mongosh、Node.js や Python のドライバー、または JSON に対応しています。別の環境で同じインデックスを作成したり、コードと一緒に保管したり、移行を計画したりするのに使えます。

このプラグインは読み取りのみを行います。何も実行されません。スクリプトはコピーまたは保存するためのテキストです。

## 表示される場所

- **コレクションタブ:** すべてのコレクションで、ドキュメントや集計などのタブの隣に **インデックススクリプト** タブが表示されます。

## 使い方

コレクションを開き、**インデックススクリプト** タブを開きます。開くとすぐにコレクションのインデックスを読み取ります。

- **対象:** **このコレクション**、または **データベース全体**（そのすべてのコレクション。ビューには独自のインデックスがありません）。
- **出力形式:** **mongosh**（`db.getCollection("…").createIndex(…)`）、**Node.js**（`await db.collection("…").createIndex(…)`）、**Python**（PyMongo の `create_index`）、または **JSON**。JSON では各インデックスが、型まで正確な正規の Extended JSON で `{ collection, key, options }` として出力されます。

**コピー** はスクリプトをクリップボードに入れ、**ダウンロード** は保存します（スクリプトは `.txt`、JSON は `.json`）。

インデックスのすべてのオプションが出力されます。名前、`unique`、`sparse`、部分フィルター、TTL（`expireAfterSeconds`）、照合順序、`hidden`、テキストインデックスの重みと言語などです。ドライバーの `createIndex`（mongosh のものも同様）は、`prepareUnique` のように認識できないオプションを省きます。そのようなオプションを持つインデックスは、すべてを保持する `createIndexes` コマンド（mongosh では `db.runCommand(…)`、Node.js では `await db.command(…)`）として出力されます。テキストインデックスは、重みから分かる元のフィールド（`{ title: "text" }`）で出力されます。独自の型を持つ値（日付、ID、数値、バイナリデータ、タイムスタンプ）は、各言語がそれらを作る形式で出力されます。デフォルトの `_id` インデックスやクラスター化インデックスはコレクションと同時に作成されるため、含まれません。

## 例

```
db.getCollection("orders").createIndex({ customerId: 1, createdAt: -1 }, { name: "customerId_1_createdAt_-1", unique: true })
db.getCollection("orders").createIndex({ expires: 1 }, { name: "expires_1", expireAfterSeconds: 3600 })
```

Python の場合:

```
db["orders"].create_index([("customerId", 1), ("createdAt", -1)], name="customerId_1_createdAt_-1", unique=True)
```

## 権限

- **このコレクションの定義の読み取り**（`collection:read`）: インデックスを一覧表示するため。
- **同じデータベースの他のコレクションの読み取り**（`database:read`）: **データベース全体** で、コレクションとそのインデックスを一覧表示するため。

読み取りはアプリ経由で、サインインしているユーザーの権限とフィールドマスキングのもとで行われます。ユーザーに非表示のフィールドにある部分フィルターの値は `"***"` として返されます。そのような値を含むインデックスは、スクリプトをそのままでは作成できないため、スクリプトとタブで印が付きます。

## 設定

なし。

## 制限

- **データベース全体** で読み取るコレクションは最大 100 件です。それ以上ある場合はタブに表示されます。インデックスを読み取れなかったコレクションは、理由とともにタブとスクリプトの先頭に記されます。それを記す場所のない JSON は、その場合コピーも保存もできません。アプリの 1 分あたりの読み取り上限を超えるとタブは停止してそう表示します。1 分後にもう一度お試しください。
- 検索インデックス（Atlas Search、Vector Search）は出力されません。作成方法が異なります。
- Node.js と Python のスクリプトは、使用するものを読み込む行から始まります。先に `db` をデータベースに接続してください。Node.js のスクリプトはトップレベルで await を使うため、ES モジュール（`.mjs` ファイル）として実行してください。
- キーのフィールドはオブジェクトとして返され、名前が数字（`"2"`）のものが先頭に並びます。そのような複合キーが作成された順序は失われ、タブとスクリプトの両方がそれを伝えます（JSON ではそのインデックスに `keyOrderUncertain`、JavaScript で表せない日付を含むものには `farDate` の印が付きます）。
