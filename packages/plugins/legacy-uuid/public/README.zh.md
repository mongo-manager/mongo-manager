# 旧版 UUID

在 MongoDB 拥有标准 UUID 类型（二进制子类型 4）之前，各驱动程序把 UUID 存为二进制子类型 3，且各自使用不同的字节顺序：Java 驱动程序会把字节的前后两半各自反转，C# 驱动程序（.NET 的 `Guid`）会反转前三组，Python 驱动程序则保持原顺序。因此同样的 16 个字节会被读成三个不同的 UUID，查找某个 UUID 时必须按存储它的驱动程序的顺序来写。此插件按每种顺序读取这些 UUID，判断字段是按哪种顺序写入的，并可查找以任意方式存储的 UUID。

插件只读取，不会更改数据库中的任何内容。

## 出现的位置

- **在文档中：** 指向旧版 UUID（子类型为 3 的 16 字节二进制值）时，会显示它按 Java、C# 和 Python 顺序读取的结果。
- **集合标签页：** 每个集合和视图的文档、聚合及其他标签页旁，会多出一个 **UUID** 标签页。

## 使用方法

打开一个集合，再打开 **UUID** 标签页。标签页一打开，就会读取 1,000 个文档的随机样本；**重新扫描** 会读取另一份样本。

**UUID 字段** 列出样本中包含 UUID 的每个字段（含嵌套字段和数组），以及其中旧版和标准的数量。对于旧版 UUID 字段，会指出哪个驱动程序的字节顺序能把每个值都读成格式正确的 UUID：UUID 的版本位和变体位位于固定位置，按错误的顺序读取时，几乎不会落在这些位置。同时显示该字段的第一个值按各顺序读取的结果。**在此字段中查找** 会把该字段和该驱动程序填入查找器。

**查找 UUID** 接受人们通常的写法：32 位十六进制数字（带或不带连字符、花括号），或 `UUID("…")`；还需要填写要查找的字段，以及存储方式：**以上任意一种**、标准子类型，或 Java、C#、Python 旧版顺序。它会显示各驱动程序存储该值的形式，格式与 shell 中一致（`BinData(3, "…")`、`UUID("…")`），每项都有一个复制按钮。**在文档中显示** 会在文档查询中放入一个筛选条件，用于选出包含该 UUID 的文档；选择 **以上任意一种** 时，可查找任意驱动程序的值。

## 示例

UUID `00112233-4455-6677-8899-aabbccddeeff` 在各驱动程序中的存储形式：

```
标准      UUID("00112233-4455-6677-8899-aabbccddeeff")
Java      BinData(3, "d2ZVRDMiEQD/7t3Mu6qZiA==")
C#        BinData(3, "MyIRAFVEd2aImaq7zN3u/w==")
Python    BinData(3, "ABEiM0RVZneImaq7zN3u/w==")
```

## 权限

- **读取文档**（`documents:read`）：用于读取样本，以及在文档查询中放入筛选条件。

读取通过应用并以已登录用户的权限和字段脱敏规则进行：被隐藏的值，插件无法读取为 UUID。插件无法读取其他集合。单元格渲染器只会收到二进制值的前几个字节、子类型和长度。

## 设置

无。

## 限制

- 字段是在 1,000 个文档的随机样本中找到的；很少出现的字段可能不在样本中。
- 如果某字段的值来自多个驱动程序，则不符合任何单一顺序：标签页会说明这一点。值较少时，可能有多种顺序都符合：会全部列出。
- 只有子类型为 3 或 4 的 16 字节二进制值才会被读取为 UUID。
