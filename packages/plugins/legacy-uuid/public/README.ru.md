# Устаревшие UUID

Пока в MongoDB не было стандартного типа UUID (двоичный подтип 4), драйверы хранили UUID как двоичный подтип 3, каждый в своем порядке байтов: драйвер Java переворачивал каждую половину байтов, драйвер C# (`Guid` из .NET) переворачивал первые три группы, драйвер Python сохранял порядок. Поэтому одни и те же 16 байт читаются как три разных UUID, а искомый UUID нужно записывать в порядке того драйвера, который его сохранил. Этот плагин читает их в каждом порядке, определяет, в каком порядке записано поле, и находит UUID независимо от способа хранения.

Плагин только читает. Он ничего не изменяет в базе данных.

## Где он появляется

- **В Документах:** если навести указатель на устаревший UUID (двоичное значение длиной 16 байт с подтипом 3), он показывается прочитанным в порядках Java, C# и Python.
- **Вкладка коллекции:** вкладка **UUID** рядом с вкладками «Документы», «Агрегации» и другими вкладками каждой коллекции и представления.

## Как пользоваться

Откройте коллекцию, затем вкладку **UUID**. Случайная выборка из 1000 документов читается сразу после открытия вкладки; **Сканировать снова** читает другую.

**Поля UUID** перечисляет каждое поле выборки, содержащее UUID (в том числе вложенные поля и массивы), с числом устаревших и стандартных значений. Для поля с устаревшими UUID указывается драйвер, порядок байтов которого читает каждое значение как корректный UUID: цифра версии и биты варианта UUID находятся в фиксированных местах, и при чтении в неверном порядке они почти никогда туда не попадают. Показывается первое значение поля, прочитанное в каждом порядке. **Искать в этом поле** заполняет поиск этим полем и этим драйвером.

**Найти UUID** принимает UUID в привычной записи (32 шестнадцатеричные цифры, с дефисами или фигурными скобками либо без них, или `UUID("…")`), поле для поиска и способ хранения: **Любой из них**, стандартный подтип либо устаревший порядок Java, C# или Python. Значение показывается так, как его хранил каждый драйвер, в том виде, в каком его записывает оболочка (`BinData(3, "…")`, `UUID("…")`), с кнопкой копирования для каждого. **Показать в Документах** помещает в запрос вкладки «Документы» фильтр, выбирающий документы с этим UUID; при выборе **Любой из них** находится значение любого драйвера.

## Пример

UUID `00112233-4455-6677-8899-aabbccddeeff` в том виде, в каком его хранил каждый драйвер:

```
Standard  UUID("00112233-4455-6677-8899-aabbccddeeff")
Java      BinData(3, "d2ZVRDMiEQD/7t3Mu6qZiA==")
C#        BinData(3, "MyIRAFVEd2aImaq7zN3u/w==")
Python    BinData(3, "ABEiM0RVZneImaq7zN3u/w==")
```

## Разрешения

- **Чтение документов** (`documents:read`): чтобы читать выборку и помещать фильтр в запрос вкладки «Документы».

Чтение выполняется через приложение с правами вошедшего пользователя и с маскированием полей: скрытое значение не является UUID, который плагин может прочитать. Плагин не может читать другие коллекции. Средству отображения ячеек отправляются только первые байты двоичного значения, его подтип и длина.

## Настройки

Нет.

## Ограничения

- Поля ищутся в случайной выборке из 1000 документов; редкое поле может в нее не попасть.
- При больших документах (например, журналах API) в выборку попадает лишь столько документов, сколько помещается в один ответ странице (1 MB).
- Поле, значения которого получены от нескольких драйверов, не соответствует ни одному порядку: вкладка сообщает об этом. При малом числе значений может подходить более одного порядка: называются все.
- Как UUID читаются только двоичные значения длиной 16 байт с подтипом 3 или 4.
