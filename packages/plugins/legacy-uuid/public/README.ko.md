# 레거시 UUID

MongoDB에 표준 UUID 타입(바이너리 서브타입 4)이 생기기 전에는 드라이버가 UUID를 바이너리 서브타입 3으로 저장했고, 드라이버마다 바이트 순서가 달랐습니다. Java 드라이버는 바이트의 앞뒤 절반을 각각 뒤집고, C# 드라이버(.NET의 `Guid`)는 처음 세 그룹을 뒤집고, Python 드라이버는 순서를 그대로 유지했습니다. 그래서 같은 16바이트가 서로 다른 세 UUID로 읽히며, UUID를 검색하려면 그것을 저장한 드라이버의 순서로 써야 합니다. 이 플러그인은 모든 순서로 UUID를 읽고, 필드가 어떤 순서로 기록되었는지 알려 주며, 저장된 방식과 관계없이 UUID를 찾습니다.

플러그인은 읽기만 합니다. 데이터베이스의 어떤 것도 변경하지 않습니다.

## 표시되는 위치

- **도큐먼트에서:** 레거시 UUID(서브타입 3의 16바이트 바이너리)를 가리키면 Java, C#, Python 순서로 읽은 값을 보여 줍니다.
- **컬렉션 탭:** 모든 컬렉션과 뷰의 도큐먼트, 집계 및 기타 탭 옆에 **UUID** 탭이 추가됩니다.

## 사용 방법

컬렉션을 열고 **UUID** 탭을 엽니다. 탭이 열리면 곧바로 도큐먼트 1,000개를 무작위로 샘플링해 읽습니다. **다시 스캔**을 누르면 다른 샘플을 읽습니다.

**UUID 필드**에는 샘플에서 UUID를 가진 필드가 중첩 필드와 배열까지 포함해 모두 나열되며, 레거시와 표준이 각각 몇 개인지 함께 표시됩니다. 레거시 UUID로 이루어진 필드에는 모든 값을 올바른 형식의 UUID로 읽는 바이트 순서의 드라이버 이름이 표시됩니다. UUID의 버전 자리와 변형 비트는 고정된 위치에 있어, 잘못된 순서로 읽으면 거의 그 위치에 오지 않기 때문입니다. 필드의 첫 번째 값을 각 순서로 읽은 결과도 보여 줍니다. **이 필드에서 찾기**를 누르면 찾기 입력란에 해당 필드와 그 드라이버가 채워집니다.

**UUID 찾기**는 사람들이 쓰는 형식의 UUID(하이픈이나 중괄호가 있든 없든 16진수 32자리, 또는 `UUID("…")`), 검색할 필드, 저장 방식을 받습니다. 저장 방식은 **이 중 아무거나**, 표준 서브타입, 또는 Java, C#, Python 레거시 순서 중에서 고릅니다. 각 드라이버가 저장한 값을 셸에서 쓰는 형식(`BinData(3, "…")`, `UUID("…")`)으로 보여 주며, 각 값을 복사하는 버튼이 있습니다. **도큐먼트에서 보기**를 누르면 해당 UUID를 가진 도큐먼트를 선택하는 필터가 도큐먼트 쿼리에 들어갑니다. **이 중 아무거나**를 선택하면 모든 드라이버의 값을 찾습니다.

## 예시

UUID `00112233-4455-6677-8899-aabbccddeeff`를 각 드라이버가 저장한 형태는 다음과 같습니다.

```
Standard  UUID("00112233-4455-6677-8899-aabbccddeeff")
Java      BinData(3, "d2ZVRDMiEQD/7t3Mu6qZiA==")
C#        BinData(3, "MyIRAFVEd2aImaq7zN3u/w==")
Python    BinData(3, "ABEiM0RVZneImaq7zN3u/w==")
```

## 권한

- **도큐먼트 읽기** (`documents:read`): 샘플을 읽고 도큐먼트 쿼리에 필터를 넣기 위해 필요합니다.

읽기는 앱을 통해 로그인한 사용자의 권한과 필드 마스킹을 적용해 이루어집니다. 가려진 값은 플러그인이 읽을 수 있는 UUID가 아닙니다. 플러그인은 다른 컬렉션을 읽을 수 없습니다. 셀 렌더러에는 바이너리 값의 처음 몇 바이트, 서브타입, 길이만 전달됩니다.

없음.

## 제한 사항

- 필드는 무작위 도큐먼트 1,000개의 샘플에서 찾습니다. 드물게 나타나는 필드는 샘플에 없을 수 있습니다.
- 값이 둘 이상의 드라이버에서 온 필드는 하나의 순서에도 맞지 않으며, 탭에 그렇게 표시됩니다. 값이 적으면 둘 이상의 순서가 맞을 수 있으며, 이 경우 모두 표시됩니다.
- 서브타입이 3 또는 4인 16바이트 바이너리만 UUID로 읽습니다.
