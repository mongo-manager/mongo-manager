# ストレージレポート

コレクションのドキュメントが削除されたり小さくなったりすると、WiredTiger は解放された領域をコレクションのファイル内に保持し、新しい書き込みに再利用します。ファイルはディスク上で小さくなりません。データの大部分を削除したデータベースには、何も使っていない数 GB が残っていることがあります。ストレージレポートは、データベースの各コレクションが使用している容量とそのうち空き領域がどれだけあるかを表示し、`compact` で返却できるようにします。Atlas や Compass のストレージビュー、`db.collection.stats()`、MongoDB 公式のガイダンスで説明されているとおりです。

## 使い方

任意のコレクションを開き、その **ストレージ** タブを開きます。レポートはコレクションが属するデータベース全体を対象にします。

1. プラグインは、アプリ経由（`$collStats`）で各コレクションのストレージ統計を読み取ります。対象は名前順で最大 500 件のコレクションで、シャードをまたいで合算されます。ビューは独自のストレージを持たないため、一覧には表示されません。
2. コレクションは解放可能な容量の多い順に並びます。各行には、ドキュメント数、データサイズ、ストレージサイズ（ディスク上）、インデックスサイズ、そのコレクション自身のファイルとインデックスのファイル内の空きバイト数、そしてそれがこれらのファイルに占める割合が表示されます。合計には、サイズが判明しているコレクションが集計されます。
3. ファイルの 20% 以上かつ 10 MB 以上が空いているコレクションには **コンパクト推奨** の印が付きます。それ未満であれば WiredTiger が自動的に領域を再利用するため、コンパクトのコストが得られる効果を上回ります。
4. コレクションを選ぶと、そのインデックスのサイズと空き領域が表示されます。続けて次の操作ができます。
   - **見積もり** は、コンパクトで解放できる容量を MongoDB に問い合わせます（`dryRun` 付きの `compact`。MongoDB 8.0 以降が必要で、古いサーバーや mongos 経由のサーバーではその旨が表示されます）。
   - **コンパクト…** は、アプリにコンパクトを依頼します。アプリは独自のダイアログを表示し、コンパクトの内容やサーバーが遅くなる可能性を説明します。コレクション名を入力した後にのみ実行されます。完了後、レポートは再度読み込まれます。

**更新** はレポートを再読み込みします。レポートは 1 分間に最大 2 回しか読み込まれません。30 秒以内は同じレポートが表示され、コンパクトの後は再読み込みされます。

時系列コレクションは一覧に表示されますが、ここではコンパクトされません。測定値が専用のバケットに保存されているためです。アプリが拒否する場合にも、コンパクトは提供されません。読み取り専用の接続や、個人データのルールで値が非表示になっている場合などです。

## コンパクトについて知っておくこと

- コレクションとそのインデックスのファイルを書き直します。大きなコレクションでは時間がかかることがあり、実行中はサーバーが遅くなります。終了するまでページにはコンパクト中と表示され、1 つのコレクションで同時に実行できるコンパクトは 1 つだけです。レプリカセットでは、実行先のメンバーだけがコンパクトされます。各メンバーで実行してください（セカンダリを先に）。アプリの確認メッセージは、このことと、MongoDB が見積もりを返した場合はその見積もりを伝えます。
- 接続にデータベースを管理する権限が必要で、読み取り専用の接続では実行されません。実行はすべてアプリの監査ログに記録されます。
- プラグイン自体はサーバー上で何も実行しません。アプリに依頼し、アプリがあなたに確認します。

## 個人データ

個人データのルールで値が非表示になっている場合、コレクションのサイズも非表示になります（サイズから非表示のデータ量が分かってしまうため）。その行には **非表示** と表示され、合計には含まれず、見積もりもコンパクトも提供されません。ドキュメント数は引き続き表示されます。

## 権限

- **データベースを読み取る:** データベースのコレクションのストレージ、およびタブ自身のコレクション以外のコレクションの見積もりまたはコンパクト。
- **コレクションの詳細を読み取る:** タブのコレクションの見積もりとコンパクト。
