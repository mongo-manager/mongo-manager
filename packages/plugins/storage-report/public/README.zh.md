# 存储报告

当集合中的文档被删除或变小时，WiredTiger 会把释放出的空间保留在集合的文件内部，并用于新的写入；文件在磁盘上不会变小。一个删除了大部分数据的数据库，可能占用着数 GB 无人使用的空间。存储报告会针对数据库的每个集合显示其占用的空间以及其中有多少是空闲空间，并可通过 `compact` 将其归还，这与 Atlas 和 Compass 的存储视图、`db.collection.stats()` 以及 MongoDB 官方指南所描述的一致。

## 使用方法

打开任意集合的 **存储** 标签页：它报告的是该集合所在的整个数据库。

1. 插件通过应用（`$collStats`）读取每个集合的存储统计信息，按名称最多读取前 500 个集合，并汇总各分片的数据。视图没有自己的存储，因此不会列出。
2. 集合按可回收空间从多到少排列。每一行显示其文档数、数据大小、存储大小（磁盘上）、索引大小，以及其自身文件和索引文件中的空闲字节数，还有这些空闲字节占这些文件的比例。合计汇总了大小已知的集合。
3. 当集合文件至少 20% 且至少 10 MB 为空闲时，该集合会被标记为 **值得压缩**。低于此值，WiredTiger 会自行复用这些空间，压缩的成本反而高于收益。
4. 选择一个集合即可查看其索引的大小和空闲空间，然后：
   - **估算** 向 MongoDB 询问压缩能释放多少空间（带 `dryRun` 的 `compact`，需要 MongoDB 8.0 及更高版本；较旧的服务器或位于 mongos 之后的服务器会提示无法估算）。
   - **压缩…** 请求应用对其执行压缩。应用会显示自己的对话框，说明压缩的作用以及可能拖慢服务器，并且只有在您输入集合名称后才会运行。之后会重新读取报告。

**刷新** 会重新读取报告。报告每分钟最多读取两次：半分钟内会显示同一份报告，而执行压缩后会重新读取。

时间序列集合会被列出，但不在此处压缩：其测量数据存放在其专属的桶中。凡是应用会拒绝的情况也不提供压缩，例如只读连接，或个人数据规则对您隐藏了值的地方。

## 关于压缩需要了解的事项

- 它会重写集合及其索引的文件。对大型集合可能耗时较长，并在运行期间拖慢服务器：页面会在结束前显示正在压缩，且同一集合同一时间只会运行一次压缩。在副本集上，只有其运行所在的成员会被压缩：请在每个成员上运行（先从节点）。应用的提问会说明这一点，MongoDB 给出估算时也会说明。
- 它需要连接具有管理数据库的权限，并且绝不会在只读连接上运行。每次运行都会写入应用的审计日志。
- 插件本身从不在服务器上运行任何操作：它询问应用，应用再询问您。

## 个人数据

当个人数据规则对您隐藏了值时，集合的大小也会被隐藏（它们会泄露隐藏数据的多少）：其所在行显示 **已隐藏**，不计入合计，也不提供估算或压缩。其文档数量仍会显示。

## 权限

- **读取数据库：** 数据库中各集合的存储情况，以及对标签页自身集合之外的集合进行估算或压缩。
- **读取集合详情：** 对标签页所属集合进行估算和压缩。
