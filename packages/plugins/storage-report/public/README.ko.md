# 스토리지 보고서

컬렉션의 도큐먼트가 삭제되거나 줄어들면 WiredTiger는 확보된 공간을 컬렉션 파일 안에 그대로 두고 새 쓰기에 재사용하며, 파일은 디스크에서 작아지지 않습니다. 데이터의 상당 부분을 삭제한 데이터베이스는 아무도 쓰지 않는 수 GB를 차지하고 있을 수 있습니다. 스토리지 보고서는 데이터베이스의 모든 컬렉션에 대해 차지하는 공간과 그중 여유 공간이 얼마인지 보여주고, Atlas와 Compass의 스토리지 보기, `db.collection.stats()`, MongoDB 자체 안내가 설명하는 것처럼 `compact`로 그 공간을 반환할 수 있게 해 줍니다.

## 사용 방법

아무 컬렉션이나 열고 **스토리지** 탭을 여세요. 이 탭은 컬렉션이 속한 데이터베이스 전체를 보고합니다.

1. 플러그인은 앱을 통해 모든 컬렉션의 스토리지 통계(`$collStats`)를 읽습니다. 이름순으로 처음 500개 컬렉션까지이며, 샤드 전체를 합산합니다. 뷰는 자체 스토리지가 없으므로 나열되지 않습니다.
2. 컬렉션은 회수 가능한 공간이 큰 순서로 나옵니다. 각 행에는 도큐먼트 수, 데이터 크기, 스토리지 크기(디스크 기준), 인덱스 크기, 컬렉션 파일과 인덱스 파일 안의 여유 바이트, 그리고 그것이 파일에서 차지하는 비율이 표시됩니다. 합계는 크기를 아는 컬렉션만 더합니다.
3. 파일의 20% 이상, 그리고 10 MB 이상이 비어 있으면 컬렉션에 **압축 권장** 표시가 붙습니다. 그보다 적으면 WiredTiger가 공간을 스스로 재사용하며, 압축은 얻는 것보다 비용이 더 큽니다.
4. 컬렉션을 선택하면 인덱스의 크기와 여유 공간을 볼 수 있으며, 다음을 할 수 있습니다.
   - **예상**은 압축으로 반환할 수 있는 공간을 MongoDB에 묻습니다(`dryRun`을 사용한 `compact`, MongoDB 8.0 이상. 이전 서버나 mongos를 거치는 서버는 그렇다고 알려줍니다).
   - **압축…**은 앱에 압축을 요청합니다. 앱은 압축이 하는 일과 서버를 느리게 할 수 있다는 점을 알리는 자체 대화상자를 표시하고, 컬렉션 이름을 입력한 뒤에만 실행합니다. 끝나면 보고서를 다시 읽습니다.

**새로고침**은 보고서를 다시 읽습니다. 보고서는 1분에 최대 두 번만 읽습니다. 30초 안에는 같은 보고서를 보여주며, 압축을 실행하면 다시 읽습니다.

시계열 컬렉션은 나열되지만 여기서 압축하지 않습니다. 측정값이 자체 버킷에 들어 있기 때문입니다. 앱이 거부하는 경우에도 압축은 제공되지 않습니다. 읽기 전용 연결이거나, 개인 데이터 규칙으로 값이 숨겨진 경우입니다.

## 압축에 대해 알아둘 점

- 컬렉션과 인덱스의 파일을 다시 작성합니다. 큰 컬렉션에서는 오래 걸릴 수 있고 실행하는 동안 서버가 느려집니다. 페이지는 끝날 때까지 압축 중이라고 알려 주며, 한 컬렉션에 대해 한 번에 하나의 압축만 실행됩니다. 레플리카 세트에서는 실행한 멤버만 압축됩니다. 각 멤버에서(세컨더리부터) 실행하세요. 앱의 질문이 이를 알려 주며, MongoDB가 예상치를 제공하면 그것도 알려 줍니다.
- 연결에 데이터베이스를 관리할 권한이 필요하며, 읽기 전용 연결에서는 실행되지 않습니다. 실행할 때마다 앱의 감사 로그에 기록됩니다.
- 플러그인 자체는 서버에서 아무것도 실행하지 않습니다. 앱에 요청하고, 앱이 사용자에게 묻습니다.

## 개인 데이터

개인 데이터 규칙으로 값이 숨겨진 경우 컬렉션의 크기도 숨겨집니다(크기로 숨겨진 데이터의 양을 알 수 있기 때문입니다). 해당 행에는 **숨김**이라고 표시되고 합계에 포함되지 않으며, 예상도 압축도 제공되지 않습니다. 도큐먼트 수는 그대로 표시됩니다.

## 권한

- **데이터베이스 읽기:** 데이터베이스 컬렉션들의 스토리지, 그리고 탭 자체 컬렉션이 아닌 컬렉션의 예상 또는 압축.
- **컬렉션 세부 정보 읽기:** 탭 자체 컬렉션의 예상과 압축.
