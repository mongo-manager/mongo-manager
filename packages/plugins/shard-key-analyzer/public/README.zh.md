# 分片键分析器

分片键决定分片集合的文档如何分布到各个分片，而一个糟糕的分片键很难撤销：不同的值太少，数据块就无法拆分；某个值被大量文档持有，一个分片就要承担它们的负载；值随每次插入而增长（日期、计数器、ObjectId），每次插入都会落到同一个分片。MongoDB 7.0 新增了 `analyzeShardKey`，可在分片之前评估候选键；Atlas 和 MongoDB 文档对其结果的判断标准与此相同。分片键分析器替你调用它，并将候选键并排对比。

## 使用方法

打开一个集合及其**分片键**标签页。

1. 插件会对集合的文档采样（200 个），并列出其字段。作为个人数据对你隐藏的字段不会提供；数组内部的字段、包含数组的字段（MongoDB 不允许它们出现在分片键中）、整个对象，以及以整数命名的字段（`"0"`：页面无法保持它们在键中的位置）同样不会提供。
2. 构建候选键：选择一个字段，选择**升序**或**哈希**，然后点击**添加字段**；一个候选键最多包含五个字段，其中最多一个哈希字段。点击标签可移除对应字段。
3. **分析**会通过应用、以你的身份请求 MongoDB 分析该候选键：使用 `analyzeShardKey` 及其键特征，最多采样 10,000 个文档。
4. 最多可并排放置六个候选键。对每个候选键：
   - **不同的值**——从 1,000 起为良好，从 100 起为一般，低于 100 为较差（唯一键始终为良好）；
   - **最常见的值**——持有该值的采样文档所占比例：低于 5% 为良好，低于 20% 为一般，20% 及以上为较差；
   - **单调性**——随每次插入而增长的键为较差；哈希键会将其分散，为良好；
   - 键是否唯一、采样了多少文档、其平均大小，以及最常见的五个值及其计数；
   - 一个**结论**，取以上三项中最差的一项。

点击候选键的 × 可将其移除。

## MongoDB 可能无法给出的结果

- 单机服务器无法分析：`analyzeShardKey` 需要副本集或分片集群。
- 7.0 之前的 MongoDB 没有该命令。
- MongoDB 需要一个以该键开头的索引：若没有，插件会指出需要创建的索引，点击**复制**会将 shell 命令放入剪贴板。插件不会替你创建任何内容。

## 个人数据

最常见的值就是集合自身的值。若个人数据规则对你生效于该集合，应用会拒绝此次分析（否则会泄露被隐藏的值），页面会说明原因。

## 权限

- **读取文档：** 字段所来源的采样文档，以及分析结果，其中的常见值属于数据。
