# シャードキーアナライザー

シャードキーは、シャーディングされたコレクションのドキュメントを各シャードにどう分散するかを決めるもので、不適切なキーは後から直すのが困難です。値の種類が少なければチャンクを分割できません。1 つの値が多くのドキュメントに偏れば、1 つのシャードがその負荷を負います。挿入のたびに増加する値（日付、カウンター、ObjectId）では、すべての挿入が同じシャードに集中します。MongoDB 7.0 では、シャーディングの前に候補を測定できる `analyzeShardKey` が追加されました。Atlas と MongoDB のドキュメントも、その結果を同じ基準で評価しています。シャードキーアナライザーは、これを代わりに実行し、候補を並べて比較します。

## 使い方

コレクションを開き、その**シャードキー**タブを開きます。

1. プラグインはコレクションのドキュメントをサンプリング（200 件）し、そのフィールドを提示します。個人データとして非表示になっているフィールドは提示されません。配列の内側にあるフィールド、配列を保持するフィールド（MongoDB はシャードキーでこれらを受け付けません）、オブジェクト全体、整数の名前を持つフィールド（`"0"`: ページがキー内での位置を保持できないため）も提示されません。
2. 候補を組み立てます。フィールドを選び、**昇順**または**ハッシュ**を選んで、**フィールドを追加**します。候補には最大 5 つのフィールドを含められ、ハッシュは 1 つまでです。チップを押すとフィールドを削除できます。
3. **分析**は、アプリを通じてあなたの権限で MongoDB に候補の分析を依頼します。キーの特性を指定した `analyzeShardKey` を使い、最大 10,000 件のドキュメントをサンプリングします。
4. 候補は最大 6 件を並べて表示できます。それぞれについて次を示します。
   - **一意な値** — 1,000 以上で良好、100 以上で普通、それ未満は不良（一意なキーは常に良好）。
   - **最頻値** — その値を保持するサンプリング済みドキュメントの割合。5% 未満で良好、20% 未満で普通、20% 以上は不良。
   - **単調性** — 挿入のたびに増加するキーは不良。ハッシュキーはそれを分散するため良好。
   - キーが一意かどうか、サンプリングしたドキュメント数、その平均サイズ、頻出する上位 5 つの値とその件数。
   - 上の 3 つのうち最も悪いものを示す**総合評価**。

候補の × を押すと、その候補を削除できます。

## MongoDB が答えられない場合

- スタンドアロンのサーバーでは分析できません。`analyzeShardKey` にはレプリカセットまたはシャーディングされたクラスターが必要です。
- 7.0 より前の MongoDB にはこのコマンドがありません。
- MongoDB にはキーで始まるインデックスが必要です。ない場合、プラグインは作成すべきインデックスを示し、**コピー**を押すとシェルコマンドがクリップボードに入ります。プラグインが代わりに何かを作成することはありません。

## 個人データ

最頻値は、コレクション自身の値です。個人データのルールがあなたにとってコレクションに及ぶ場合、アプリは分析を拒否し（非表示の値が明らかになるため）、ページにその理由が表示されます。

## 権限

- **ドキュメントの読み取り:** フィールドの元になるサンプリング済みドキュメントと、分析結果（頻出する値はデータです）。
