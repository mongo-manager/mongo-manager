# 数据匿名化

开发人员需要接近生产环境的数据来复现一个缺陷；团队想把一份样本交给供应商；测试环境应当看起来真实，却不包含任何人的个人数据。应用自带的匿名副本会用 `***` 替换隐藏的值。数据匿名化插件生成的数据则看起来、用起来仍像原始数据——思路与 Studio 3T 的数据脱敏、Hackolade 以及各数据库平台的脱敏功能相同：同类型的虚构值、保证关联仍然可用的哈希、在文档间打乱的值、略微平移的日期、加入噪声的数字。

## 使用方法

打开一个集合及其**匿名化**标签页。

1. 插件随机采样 100 个文档并列出其字段（对象或对象数组内部的字段会单独列出，包含它的对象本身不会列出——除非某些文档在该位置存放的是值而不是对象：此时它也会列出，并标注*非对象时*，针对这些值）。每个字段对应一种方式：
   - **保留** — 值保持原样。
   - **虚构值** — 同类型的逼真值，按字段名称和类型自动选择，或按您选择的类型生成（姓名、电子邮件、电话、街道地址、城市、邮政编码、公司、句子、UUID、日期…）：电子邮件仍是电子邮件，使用示例域名；电话号码取自不会有真实线路的号段。
   - **一致性哈希** — 在整份副本中，相同输入得到相同输出（同一个电子邮件在每个包含它的文档中哈希相同，因此仍可按它分组或关联），类型保持不变（ObjectId 仍是 ObjectId，整数仍是整数）。其密钥在标签页打开时随机生成，绝不保存：两次会话得到的哈希不同。
   - **打乱** — 该字段的值在文档之间移动：每个值都还在，但没有一个留在自己的文档中。
   - **平移日期** — 日期最多平移 ± 您指定的天数，同一文档中的所有日期平移相同的天数（同一个人的事件先后顺序得以保留）。以文本形式书写的日期保持其格式。
   - **数字噪声** — 数字最多按 ± 您指定的比例变化；整数仍是整数。
   - **Null**、**移除**、**脱敏**（`***`）。
     `_id` 只能选择保留、哈希、虚构（ObjectId 或 UUID）、打乱或移除（之后导入时会生成新的 `_id`）：不允许任何会让两个文档共用同一个 `_id` 的方式。
     涉及个人、地址或账户的字段（姓名、电子邮件、电话、街道、邮政编码、出生日期、密码、IBAN…）默认为**虚构值**；其他字段默认为**保留**。
2. **采样中没有的字段**：后面的文档中有、而采样中没有的字段，以及在采样中只出现对象的位置上出现的值，默认会被排除；您可以选择保留。
3. 预览显示 5 个文档的前后对比，并随每次更改更新。**重新生成**会重新生成虚构值、打乱结果和新的哈希密钥。
4. **生成副本**按 `_id` 顺序逐页读取最多 1,000 个文档（数量由您选择；各种类型的 `_id` 都会读取，按 MongoDB 的排序规则，数字在 ObjectId 之前），并在页面中完成匿名化。副本大小不超过应用一次消息可接收的上限（约 1 MB）：超出时会在完整文档处截断，页面会给出提示。
5. 然后：
   - **保存 NDJSON** 或 **保存 JSON** 将副本保存为文件；
   - **导入…** 会针对同一数据库的新集合（默认为 `<集合>_anonymised`）打开应用的导入向导，并以该副本作为文件：您在向导中检查、映射并开始导入。

**保存设置**将每个字段的方式保存为 JSON 文件（绝不包含哈希密钥或任何值）；**加载设置**可再次应用该文件——文件中提到而此集合没有的字段会被计数并跳过。

## 个人数据

按个人数据规则对您隐藏的字段绝不会被保留：插件对它拿到的始终只有 `***`。它可以被脱敏、虚构、设为 null 或移除；采样中没有出现的隐藏字段，无论出现在何处都会被脱敏。集合本身绝不会被修改：副本只会去往您保存或导入的位置。

## 权限

- **读取文档：** 用来生成副本的文档。
- **读取数据库：** 将副本交给导入向导，导入到该数据库的另一个集合。
