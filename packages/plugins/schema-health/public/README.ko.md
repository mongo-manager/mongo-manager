# 스키마 상태

스키마 상태는 MongoDB 문서에 설명된 스키마 안티패턴이 컬렉션에 있는지 점검합니다: 너무 커지는 도큐먼트와 배열, 깊은 중첩, 필드가 매우 많은 도큐먼트, 둘 이상의 유형을 가진 필드, 너무 많거나 사용되지 않거나 중복된 인덱스. 각 발견 항목에는 무엇이 발견되었는지, 왜 중요한지, 무엇을 해야 하는지가 표시됩니다.

이 플러그인은 읽기만 합니다. 데이터베이스의 어떤 것도 변경하지 않습니다. 제안만 하고 결정은 사용자가 합니다.

## 표시되는 위치

- **컬렉션 탭:** 모든 컬렉션과 뷰에서 도큐먼트, 집계 및 다른 탭 옆에 **상태** 탭이 표시됩니다.

## 사용 방법

컬렉션을 연 다음 **상태** 탭을 엽니다. 탭을 열면 점검이 바로 실행됩니다. 예를 들어 데이터나 인덱스를 변경한 뒤에는 **점검**으로 다시 실행할 수 있습니다.

점검은 세 단계로 읽으며, 실행되는 동안 각 단계가 표시됩니다.

1. 배열, 중첩, 필드 수, 유형을 위한 최대 1,000개의 무작위 도큐먼트 샘플
2. 서버가 측정하는 최대 10,000개의 무작위 도큐먼트 크기
3. 컬렉션의 인덱스와 사용 횟수 카운터

발견 항목은 심각도순으로 나열됩니다. **높은 위험**이 먼저, 그다음 **경고**, 그다음 **정보**입니다. 각 항목에는 해당 필드나 인덱스, 발견된 내용, 중요한 이유, 해야 할 일이 표시됩니다. 발견 항목에 해당하는 도큐먼트만 정확히 선택하는 필터를 만들 수 있으면 **도큐먼트에서 보기**가 그 필터를 도큐먼트 쿼리에 넣습니다.

**점검 항목**은 탭에서 클릭하면 펼쳐지는 섹션으로, 사용 중인 임계값과 함께 MongoDB 자체 제한을 나열합니다.

## 점검 내용

- **큰 도큐먼트:** 1 MB를 넘으면 경고, 8 MB를 넘으면 높은 위험입니다. MongoDB는 16 MB를 넘는 도큐먼트를 거부합니다.
- **큰 배열:** 샘플 도큐먼트의 배열 요소가 1,000개를 넘으면 경고, 10,000개를 넘으면 높은 위험입니다. 이런 배열은 최대 10개까지 나열됩니다.
- **깊은 중첩:** 20단계를 넘게 중첩된 도큐먼트(MongoDB의 제한은 100단계).
- **매우 많은 필드:** 필드가 200개를 넘는 샘플 도큐먼트.
- **혼합 유형:** 샘플 전체에서 null을 제외하고 둘 이상의 유형을 가진 필드(예: 대부분의 도큐먼트에서는 숫자이고 일부에서는 문자열). 이런 필드는 최대 20개까지 나열됩니다.
- **인덱스 과다:** 컬렉션의 인덱스가 20개를 넘는 경우(MongoDB는 64개까지 허용).
- **사용되지 않는 인덱스:** 서버가 사용 횟수를 세기 시작한 이후(마지막 재시작 이후) 사용이 한 번도 집계되지 않은 인덱스. `_id` 인덱스, 고유 인덱스, TTL 인덱스는 쿼리 없이도 동작하므로 사용되지 않는 인덱스로 보고되지 않습니다.
- **중복 인덱스:** 키가 다른 인덱스 키의 앞부분인 인덱스(같은 방향이거나 반대 방향). 다른 인덱스가 그 쿼리를 처리할 수 있습니다. 같은 콜레이션을 가진 표시 상태의 인덱스이며 스파스도 부분 인덱스도 아닌 경우에만 이를 대신하는 인덱스로 인정합니다.

## 예시

`orders` 컬렉션에서는 다음과 같이 보고할 수 있습니다.

```
High risk   Large array        items: up to 12,400 elements in one sampled document.
Info        Mixed types        total: number in 981 sampled documents, string in 19.
Info        Redundant index    customerId_1: its keys are the start of customerId_1_createdAt_-1's keys.
```

혼합 유형 발견 항목에서 **도큐먼트에서 보기**를 누르면 `{ "total": { "$type": "string" } }`가 도큐먼트에 입력되어, 어긋난 19개의 도큐먼트를 수정할 수 있습니다.

## 뷰에서

뷰에는 자체 인덱스가 없습니다. 뷰에서는 이 플러그인이 인덱스를 읽지 않고 인덱스에 대해 아무것도 표시하지 않습니다. 샘플과 도큐먼트 크기는 컬렉션과 똑같이 점검합니다.

## 권한

- **도큐먼트 읽기**(`documents:read`): 샘플을 읽고 도큐먼트 크기를 측정하기 위한 권한으로, 둘 다 읽기 전용 집계 파이프라인을 통해 수행됩니다.
- **이 컬렉션의 인덱스 읽기**(`collection:read`): 인덱스와 그 옵션, 사용 횟수 카운터를 나열하기 위한 권한.

읽기는 로그인한 사용자의 권한과 필드 마스킹을 적용하여 앱을 통해 수행됩니다. 이 플러그인은 다른 컬렉션을 읽을 수 없습니다.

## 설정

없음.

## 제한 사항

- 배열, 중첩, 필드 수, 유형은 1,000개의 무작위 도큐먼트 샘플로 판단하므로, 드문 문제는 샘플에 없을 수 있습니다. 다른 샘플을 보려면 점검을 다시 실행하세요.
- 크기는 10,000개의 무작위 도큐먼트 샘플로 측정합니다. 측정에는 MongoDB 4.4 이상(`$bsonSize`)이 필요합니다. 이전 서버에서도 다른 점검은 실행되며, 탭에는 크기를 측정할 수 없다고 표시됩니다.
- 도큐먼트가 크면 두 샘플 모두 작아집니다. 샘플은 앱이 페이지에 보내는 한 번의 응답(약 1 MB)에 들어가는 도큐먼트만 담고, 크기를 측정할 때 MongoDB가 디스크 없이 허용하는 것보다 많은 메모리가 필요하면 1,000개, 그다음 100개 샘플을 측정합니다. 상태 줄에는 실제로 샘플링하고 측정한 수가 표시됩니다. 도큐먼트 하나도 응답에 들어가지 않으면 측정한 크기는 그대로 표시되고, 탭에 도큐먼트를 샘플링할 수 없다고 표시됩니다.
- 사용 횟수 카운터는 서버를 다시 시작하면 처음부터 다시 시작되며, 레플리카 세트의 각 멤버가 자체적으로 셉니다. 다른 멤버에서만 사용되었거나 재시작 이전에만 사용된 인덱스는 사용되지 않는 것으로 보고될 수 있습니다. 인덱스를 삭제하기 전에 먼저 숨기고, 느려지는 쿼리가 없는지 지켜보세요.
- 각 파이프라인은 디스크를 사용하지 않고 최대 10초 동안 실행됩니다.
- 임계값은 설정이 아니라 이 플러그인의 기본값입니다. MongoDB는 Atlas에서 사용하는 값을 공개하지 않습니다.
