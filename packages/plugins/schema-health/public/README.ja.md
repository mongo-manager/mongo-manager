# スキーマの健全性

スキーマの健全性は、MongoDB のドキュメントに挙げられているスキーマのアンチパターンがコレクションにないかをチェックします。対象は、大きくなりすぎたドキュメントや配列、深いネスト、フィールドが非常に多いドキュメント、複数の型を持つフィールド、そして多すぎる・未使用・冗長なインデックスです。各検出結果には、何が見つかったか、なぜ重要か、何をすべきかが示されます。

このプラグインは読み取りのみを行います。データベースは何も変更しません。提案するだけで、判断はあなたが行います。

## 表示される場所

- **コレクションタブ:** すべてのコレクションとビューで、ドキュメントや集計などのタブの隣に**健全性**タブが表示されます。

## 使い方

コレクションを開き、**健全性**タブに切り替えます。チェックはタブを開くとすぐに実行されます。データやインデックスを変更した後などは、**チェック**でもう一度実行できます。

読み取りは 3 つのステップで行われ、実行中はそれぞれが表示されます。

1. 配列、ネスト、フィールド数、型を調べるための、最大 1,000 件のドキュメントのランダムなサンプル
2. サーバーが測定する、最大 10,000 件のランダムなドキュメントのサイズ
3. コレクションのインデックスとその使用状況カウンター

検出結果は重大度順に表示されます。**高リスク**、**警告**、**情報**の順です。それぞれに、対象のフィールドまたはインデックス、見つかった内容、重要な理由、対処方法が示されます。ある検出結果の対象ドキュメントだけをフィルターで選択できる場合は、**ドキュメントで表示**がそのフィルターを「ドキュメント」のクエリに設定します。

タブ内でクリックすると開く**チェック内容**セクションには、使用しているしきい値が、MongoDB 自体の制限とともに一覧表示されます。

## チェック項目

- **大きなドキュメント:** 1 MB 超は警告、8 MB 超は高リスクです。MongoDB は 16 MB を超えるドキュメントを拒否します。
- **大きな配列:** サンプルのドキュメントで要素が 1,000 個を超える配列は警告、10,000 個を超えると高リスクです。このような配列は最大 10 件まで表示されます。
- **深いネスト:** 20 階層を超えてネストしているドキュメント（MongoDB の上限は 100 です）。
- **非常に多いフィールド:** フィールドが 200 個を超えるサンプルのドキュメント。
- **型の混在:** サンプル全体で、null を除いて複数の型を持つフィールド（例: 大半のドキュメントでは数値、一部では文字列）。このようなフィールドは最大 20 件まで表示されます。
- **多すぎるインデックス:** コレクションのインデックスが 20 個を超える場合（MongoDB が許可するのは 64 個です）。
- **未使用のインデックス:** サーバーがカウントを開始してから（最後の再起動以降）、使用が一度もカウントされていないインデックス。`_id` インデックス、一意インデックス、TTL インデックスは、クエリがなくても機能するため、未使用として報告されることはありません。
- **冗長なインデックス:** キーが、同じ方向または逆方向で、別のインデックスのキーの先頭部分になっているインデックス。そのため、もう一方がそのクエリに対応できます。それを包含するインデックスとして数えられるのは、照合順序（collation）が同じで、スパースでも部分でもない、表示状態のインデックスだけです。

## 例

`orders` コレクションでは、チェックで次のように報告されることがあります。

```
高リスク   大きな配列       items: サンプルの 1 件のドキュメントに最大 12,400 個の要素。
情報       型の混在         total: サンプルの 981 件が number、19 件が string。
情報       冗長なインデックス   customerId_1: キーが customerId_1_createdAt_-1 のキーの先頭部分。
```

型の混在の検出結果で**ドキュメントで表示**を使うと、`{ "total": { "$type": "string" } }` が「ドキュメント」に設定され、外れた 19 件のドキュメントを修正できます。

## ビューの場合

ビューにはそれ自体のインデックスがありません。ビューでは、プラグインはインデックスを読み取らず、インデックスについても何も表示しません。サンプルとドキュメントのサイズは、コレクションと同様にチェックされます。

## 権限

- **ドキュメントの読み取り**（`documents:read`）: サンプルの読み取りとドキュメントのサイズの測定のために使用します。どちらも読み取り専用の集計パイプラインで行われます。
- **このコレクションのインデックスの読み取り**（`collection:read`）: インデックス、そのオプション、使用状況カウンターを一覧表示するために使用します。

読み取りはアプリを経由し、サインインしているユーザーの権限とフィールドマスキングが適用されます。プラグインは他のコレクションを読み取れません。

## 設定

なし。

## 制限

- 配列、ネスト、フィールド数、型は、1,000 件のドキュメントのランダムなサンプルから判断されます。まれな問題はサンプルに含まれない可能性があります。別のサンプルが必要な場合は、チェックをもう一度実行してください。
- サイズは、10,000 件のドキュメントのランダムなサンプルで測定されます。測定には MongoDB 4.4 以降が必要です（`$bsonSize`）。それより古いサーバーでも他のチェックは実行され、タブにはサイズを測定できなかったことが表示されます。
- 大きなドキュメントでは、どちらのサンプルも小さくなります。サンプルはアプリがページに返す 1 回の応答（約 1 MB）に収まるドキュメントだけを取り、サイズの測定で MongoDB がディスクなしで許可される以上のメモリを必要とする場合は、1,000 件、次に 100 件のサンプルを測定します。ステータス行には実際にサンプリング・測定した件数が表示されます。1 件も応答に収まらない場合も、測定したサイズは表示され、ドキュメントをサンプリングできなかったことがタブに表示されます。
- 使用状況カウンターはサーバーの再起動で最初からやり直しになり、レプリカセットの各メンバーがそれぞれ独自にカウントします。別のメンバーでのみ使用されたインデックスや、再起動前にのみ使用されたインデックスは、未使用として報告されることがあります。インデックスを削除する前に非表示にして、遅いクエリが出ないか確認してください。
- 各パイプラインは最長 10 秒間、ディスクを使用せずに実行されます。
- しきい値はこのプラグイン独自のデフォルト値であり、設定ではありません。MongoDB は Atlas が使用するしきい値を公開していません。
