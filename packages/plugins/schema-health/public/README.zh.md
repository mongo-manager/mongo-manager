# 模式健康度

模式健康度会检查集合中是否存在 MongoDB 文档所述的模式反模式：过大的文档和数组、嵌套过深、字段过多的文档、包含多种类型的字段，以及过多、未使用或冗余的索引。每项发现都会说明发现了什么、为何重要以及该怎么做。

插件只读取，不会更改数据库中的任何内容：它只提出建议，由您决定。

## 出现位置

- **集合标签页：** 在每个集合和视图中，“文档”“聚合”等标签页旁边会出现一个**健康**标签页。

## 使用方法

打开一个集合，然后切换到**健康**标签页。检查会在标签页打开时立即运行；**检查**会再次运行它，例如在更改数据或索引之后。

读取分为三步，运行时会逐步显示：

1. 最多 1,000 个文档的随机采样，用于检查数组、嵌套、字段数量和类型；
2. 由服务器测量的最多 10,000 个随机文档的大小；
3. 集合的索引及其使用计数器。

发现按严重程度排列：先是**高风险**，然后是**警告**，最后是**信息**。每一项都会指出相关的字段或索引、发现了什么、为何重要以及该怎么做。如果某个筛选条件能够恰好选中某项发现所涉及的文档，**在文档中显示**会将该筛选条件放入“文档”查询。

标签页中点击后展开的**检查内容**部分列出了所用的阈值，并在旁边标注 MongoDB 自身的限制。

## 检查项

- **大文档：** 超过 1 MB 为警告，超过 8 MB 为高风险。MongoDB 拒绝超过 16 MB 的文档。
- **大数组：** 采样文档中元素超过 1,000 个的数组为警告，超过 10,000 个为高风险。最多列出 10 个此类数组。
- **嵌套过深：** 嵌套超过 20 层的文档（MongoDB 的限制是 100 层）。
- **字段过多：** 字段超过 200 个的采样文档。
- **混合类型：** 在整个采样中，除 null 外包含多种类型的字段（例如多数文档中为数字，部分文档中为字符串）。最多列出 20 个此类字段。
- **索引过多：** 集合上的索引超过 20 个（MongoDB 允许 64 个）。
- **未使用的索引：** 自服务器开始计数以来（即自上次重启以来）没有被计到任何使用的索引。`_id` 索引、唯一索引和 TTL 索引绝不会被报告为未使用：它们无需查询也能发挥作用。
- **冗余索引：** 键是另一个索引的键的前缀（方向相同或相反）的索引，因此另一个索引可以服务它的查询。只有排序规则（collation）相同、既非稀疏也非部分的可见索引，才算作覆盖它的索引。

## 示例

在 `orders` 集合上，检查可能会报告：

```
高风险   大数组      items: 某个采样文档中多达 12,400 个元素。
信息     混合类型    total: 采样中 981 个文档为 number，19 个文档为 string。
信息     冗余索引    customerId_1: 其键是 customerId_1_createdAt_-1 的键的前缀。
```

对混合类型这一项使用**在文档中显示**，会将 `{ "total": { "$type": "string" } }` 放入“文档”，以便修复这 19 个异常文档。

## 关于视图

视图本身没有索引。在视图上，插件不读取索引，也不提及索引；采样和文档大小的检查与集合相同。

## 权限

- **读取文档**（`documents:read`）：用于读取采样和测量文档大小，两者都通过只读的聚合管道完成。
- **读取此集合的索引**（`collection:read`）：用于列出索引、其选项和使用计数器。

读取通过应用进行，使用已登录用户的权限和字段脱敏。插件无法读取其他集合。

## 设置

无。

## 限制

- 数组、嵌套、字段数量和类型是根据 1,000 个文档的随机采样判断的；罕见的问题可能不在采样中。再次运行检查即可获得另一份采样。
- 大小是在 10,000 个文档的随机采样上测量的。测量需要 MongoDB 4.4 或更高版本（`$bsonSize`）；在更旧的服务器上，其他检查仍会运行，标签页会说明无法测量大小。
- 使用计数器在服务器重启后会重新开始，副本集的每个成员各自计数。仅在另一个成员上使用过、或仅在重启之前使用过的索引，可能会被报告为未使用。删除索引之前请先将其隐藏，并留意是否出现慢查询。
- 每个管道最多运行 10 秒，且不使用磁盘。
- 阈值是此插件自己的默认值，而不是设置项；MongoDB 并未公布 Atlas 所使用的阈值。
