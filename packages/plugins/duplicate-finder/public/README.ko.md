# 중복 도큐먼트 찾기

중복 도큐먼트 찾기는 컬렉션에서 고유해야 하는 필드(이메일 주소, 주문 번호, 성과 이름의 조합 등)의 값을 둘 이상의 도큐먼트가 공유하는 경우를 나열합니다. 각 값에는 그 값을 공유하는 도큐먼트 수가 함께 표시되며 많은 순서로 정렬됩니다. 도큐먼트 자체도 클릭 한 번이면 볼 수 있습니다.

이 플러그인은 읽기만 합니다. 데이터베이스에서 아무것도 변경하지 않습니다.

## 표시되는 위치

- **컬렉션 탭:** 모든 컬렉션과 뷰에서 도큐먼트, 집계 및 다른 탭 옆에 **중복** 탭이 표시됩니다.

## 사용 방법

1. 컬렉션을 연 다음 **중복** 탭을 엽니다.
2. **고유해야 하는 필드**에 필드 이름을 입력하고 Enter를 누르거나, **이 컬렉션의 필드:** 아래에 추천된 필드 중 하나를 클릭합니다. 중첩 필드는 경로를 입력합니다(`address.city`). 쉼표로 구분해 여러 필드를 한 번에 입력하면 함께 추가됩니다.
3. 필드를 최대 다섯 개까지 추가해 함께 확인할 수 있습니다. 이 경우 선택한 모든 필드가 일치해야 중복으로 간주합니다.
4. 아래 옵션을 설정한 다음 **중복 찾기**를 누릅니다.

옵션은 다음과 같습니다.

- **대소문자 무시:** `Ada@Example.com`과 `ada@example.com`을 같은 값으로 간주합니다. 기본값은 꺼짐입니다.
- **필드가 없는 도큐먼트 제외:** 선택한 필드가 없거나 null인 도큐먼트는 그룹화하지 않습니다. 기본값은 켜짐이며, 끄면 해당 필드가 없는 도큐먼트가 몇 개인지 확인할 수 있습니다.
- **검색 범위:** **전체 컬렉션**(기본값) 또는 **도큐먼트 필터**에 해당하는 도큐먼트만 검색합니다.

결과에는 중복 값이 몇 개 발견되었고 관련 도큐먼트가 몇 개인지 표시됩니다. 각 행에는 값과 개수가 표시됩니다.

- **도큐먼트 나열**을 누르면 행이 펼쳐져 그 값의 도큐먼트 중 처음 20개가 표시되며, **열기**를 누르면 앱에서 해당 도큐먼트를 볼 수 있습니다.
- **표시**(또는 **모두 도큐먼트에서 보기**)를 누르면 그 값의 도큐먼트에 대한 필터가 도큐먼트 쿼리에 들어가며, 거기서 모든 도큐먼트를 페이지별로 넘겨 볼 수 있습니다.

## 예시

`email`이 고유해야 하는 `users` 컬렉션입니다. `email`을 선택하고 **대소문자 무시**를 켠 다음 **중복 찾기**를 누릅니다. 다음과 같은 행이 나타납니다.

```
ada@example.com     3 documents
```

이는 사용자 세 명이 철자(대소문자)만 다른 같은 주소를 공유한다는 뜻입니다. **표시**를 누르면 그 세 도큐먼트에 대한 필터가 도큐먼트에 들어가며, 거기서 어느 것을 남길지 결정할 수 있습니다.

두 번 입력된 사람을 찾으려면 `firstName`과 `lastName`을 함께 선택합니다. 두 필드가 모두 일치하는 도큐먼트만 그룹화됩니다.

## 동작 방식

그룹화는 서버에서 읽기 전용 집계 파이프라인 하나로 실행됩니다. 필터(그리고 제외하도록 한 경우 없는 필드)를 위한 `$match`, 선택한 필드에 대한 `$group`, 이어서 도큐먼트가 둘 이상인 그룹을 개수순으로 정렬합니다. 브라우저로는 그룹만 돌아오며 컬렉션 전체가 오는 일은 없습니다.

대소문자를 무시하면 텍스트 값은 소문자로 비교하고(`$toLower`), 다른 유형은 그대로 비교합니다.

## 권한

- **도큐먼트 읽기**(`documents:read`): 그룹화 파이프라인을 실행하고, 필드 추천을 위해 도큐먼트 몇 개를 읽고, 그룹의 도큐먼트를 나열하는 데 필요합니다.

읽기는 로그인한 사용자의 권한과 필드 마스킹을 적용해 앱을 통해 이루어집니다. 플러그인은 다른 컬렉션을 읽을 수 없습니다.

## 설정

없음.

## 제한

- 한 번에 최대 5개 필드.
- 중복 값은 공유 수가 많은 순서로 최대 200개까지 나열됩니다. 그보다 많으면 개수가 "200+"로 표시되고, 공유 수가 가장 많은 200개만 나열된다는 안내가 표시됩니다.
- 그룹은 처음 20개 도큐먼트를 나열하며, 표시를 누르면 모든 도큐먼트가 도큐먼트에 들어갑니다.
- 추천 필드는 컬렉션의 처음 50개 도큐먼트에서 가져오며(최대 12개), 다른 필드는 직접 입력할 수 있습니다.
- 도큐먼트가 크면(예: API 로그) 페이지로 가는 한 번의 응답(1 MB)에 담기는 만큼만 읽습니다. 추천은 더 적은 도큐먼트에서 나오고, 긴 값은 더 적게 나열되며(안내가 표시됩니다), 그룹을 열면 담기는 만큼의 첫 도큐먼트를 보여 줍니다.
- 값은 저장된 그대로 비교하며, 대소문자를 무시하는 경우에만 예외입니다. 텍스트로 저장된 숫자와 숫자로 저장된 같은 숫자는 서로 다른 값입니다.
- 파이프라인은 디스크를 사용하지 않고 최대 10초 동안 실행됩니다. 매우 큰 컬렉션에서는 도큐먼트 필터로 범위를 좁히세요.
