# Поиск дубликатов

Поиск дубликатов перечисляет значения, которые разделяют несколько документов коллекции в полях, которые должны быть уникальными: адрес электронной почты, номер заказа, имя и фамилия вместе. Рядом с каждым значением указано, сколько документов его разделяют, сначала самые частые, а сами документы доступны в один клик.

Плагин только читает. Он ничего не меняет в базе данных.

## Где он появляется

- **Вкладка коллекции:** вкладка **Дубликаты** рядом с вкладками «Документы», «Агрегации» и другими у каждой коллекции и представления.

## Как пользоваться

1. Откройте коллекцию, затем вкладку **Дубликаты**.
2. В поле **Поля, которые должны быть уникальными** введите имя поля и нажмите Enter либо щелкните одно из полей, предложенных под подписью **В этой коллекции:**. Для вложенного поля введите его путь: `address.city`. Несколько полей, введенных сразу через запятую, добавляются вместе.
3. Добавьте до пяти полей, чтобы проверять их вместе: тогда документы считаются дубликатами, только если совпадают все эти поля.
4. Задайте описанные ниже параметры и нажмите **Найти дубликаты**.

Параметры:

- **Игнорировать регистр:** `Ada@Example.com` и `ada@example.com` считаются одним и тем же значением. По умолчанию выключено.
- **Пропускать документы без поля:** документы, в которых выбранное поле отсутствует или равно null, не группируются. По умолчанию включено; выключите, чтобы увидеть, сколько документов не имеют этого поля.
- **Где искать:** **Вся коллекция** (по умолчанию) или только документы, прошедшие **Фильтр документов**.

В результате указано, сколько повторяющихся значений найдено и сколько документов затронуто. В каждой строке показано значение и его число:

- **Показать документы** раскрывает строку и показывает первые 20 ее документов; **Открыть** показывает один из них в приложении.
- **Показать** (или **Все в разделе «Документы»**) помещает фильтр для документов этого значения в запрос раздела «Документы», где их все можно просмотреть постранично.

## Пример

Коллекция `users`, где `email` должен быть уникальным. Выберите `email`, включите **Игнорировать регистр** и нажмите **Найти дубликаты**. Строка вида

```
ada@example.com     3 documents
```

означает, что три пользователя разделяют этот адрес в том или ином написании. **Показать** помещает в «Документы» фильтр для этих трех документов, и там вы можете решить, какие оставить.

Чтобы найти людей, внесенных дважды, выберите вместе `firstName` и `lastName`: группируются только документы, у которых совпадают оба поля.

## Как это работает

Группировка выполняется на сервере как один конвейер агрегации только для чтения: `$match` для фильтра (и для отсутствующих полей, если их пропускают), `$group` по выбранным полям, затем группы с более чем одним документом, отсортированные по числу. В браузер возвращаются только группы, но не вся коллекция.

Когда регистр игнорируется, текстовые значения сравниваются в нижнем регистре (`$toLower`); значения других типов сравниваются как есть.

## Разрешения

- **Чтение документов** (`documents:read`): чтобы выполнять конвейер группировки, читать несколько документов для подсказок полей и перечислять документы группы.

Чтение идет через приложение с правами вошедшего пользователя и маскированием полей. Плагин не может читать другие коллекции.

## Настройки

Нет.

## Ограничения

- Не более 5 полей одновременно.
- Перечисляется не более 200 повторяющихся значений, сначала самые частые. Когда их больше, число отображается как «200+», а примечание сообщает, что перечислены только 200 самых частых.
- Группа перечисляет первые 20 своих документов; «Показать» помещает все документы в раздел «Документы».
- Предлагаемые поля берутся из первых 50 документов коллекции (не более 12 подсказок); любое другое поле можно ввести вручную.
- При больших документах (например, журналах API) читается только то, что помещается в один ответ странице (1 MB): подсказки берутся из меньшего числа документов, длинных значений перечисляется меньше (об этом говорит пометка), а группа открывается первыми документами, которые помещаются.
- Значения сравниваются в точности так, как хранятся, кроме регистра, когда он игнорируется. Число, сохраненное как текст, и то же число, сохраненное как число, — разные значения.
- Конвейер работает не более 10 секунд и без использования диска. В очень большой коллекции сузьте область поиска фильтром документов.
