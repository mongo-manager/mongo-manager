# SQL в MongoDB

SQL в MongoDB превращает SQL-запрос SELECT в запрос MongoDB, который делает то же самое: `find`, где он подходит, и конвейер агрегации в остальных случаях. Результат показывается как код для mongosh и как программа для каждого официального драйвера. На вкладке SQL коллекции плагин ещё и выполняет запрос только для чтения и показывает строки.

Выполнение запроса никогда не меняет данные: этот плагин ничего не записывает.

## Где он появляется

- **Вкладка коллекции:** вкладка **SQL** рядом с «Документами», «Агрегациями» и другими вкладками каждой коллекции и представления.

## Как пользоваться

1. Откройте коллекцию, затем вкладку **SQL**. **Примеры** заполняют редактор запросами, написанными с полями этой коллекции.
2. Напишите в редакторе SELECT. По мере ввода появляются подсказки: ключевые слова, поля коллекции (в том числе вложенные пути), значения, которые поле содержит после `=` или внутри `IN (…)`, функции и имя коллекции после FROM или JOIN. Enter принимает выделенную подсказку; Tab делает то же, когда вы уже набрали её часть или перешли к ней.
3. Код MongoDB обновляется по мере ввода. **Код для** выбирает язык: mongosh, Node.js, Python, Java, Go, C#, PHP, Ruby или Rust. **Копировать код** копирует его.
4. **Выполнить** (Ctrl+Enter, на Mac Cmd+Enter) выполняет запрос здесь только для чтения и показывает до 50 строк в разделе **Результаты**. **Открыть** в строке показывает этот документ в приложении. **Очистить** убирает результаты.
5. **Форматировать** (Shift+Alt+F) раскладывает SQL: одна часть на строку, ключевые слова заглавными буквами. Смысл запроса при этом никогда не меняется.
6. **Использовать в «Документах»** помещает фильтр, проекцию и сортировку на вкладку «Документы» коллекции; **Открыть в «Агрегациях»** помещает конвейер на её вкладку «Агрегации». Там ничего не выполняется, пока вы этого не попросите.

Ошибка отмечается в своей строке, а сообщение называет строку и столбец; **Показать в редакторе** переносит курсор туда.

## Пример

```sql
SELECT name, total FROM orders
WHERE status = 'shipped' AND total > 100
ORDER BY total DESC
LIMIT 10
```

превращается в

```mongosh
db.getCollection("orders").find(
  { status: "shipped", total: { $gt: 100 } },
  { name: 1, total: 1, _id: 0 }
).sort({ total: -1 }).limit(10)
```

Сгруппированный запрос превращается в конвейер:

```sql
SELECT status, COUNT(*) AS n FROM orders GROUP BY status HAVING COUNT(*) > 5 ORDER BY n DESC
```

```mongosh
db.getCollection("orders").aggregate([
  { $group: { _id: { status: "$status" }, n: { $sum: 1 } } },
  { $match: { n: { $gt: 5 } } },
  { $project: { _id: 0, status: "$_id.status", n: "$n" } },
  { $sort: { n: -1 } }
])
```

## JOIN

Один INNER или LEFT JOIN с другой коллекцией той же базы данных переводится в `$lookup`, и «Выполнить» выполняет его здесь:

```sql
SELECT o.orderNo, c.name FROM orders o JOIN customers c ON o.customerId = c._id
```

Столбцы результата подписаны так, как записаны в SELECT (`o.orderNo`, `c.name` или имя AS). Маленькая отметка рядом с заголовком объединённого столбца называет поле коллекции, из которого он взят, например `customers.name`. Присоединённая коллекция читается с правами пользователя и маскированием полей, как и любое другое чтение.

## Какой SQL понимается

- SELECT со столбцами, `*`, псевдонимами (AS) и DISTINCT
- WHERE с `=`, `<>`, `!=`, `<`, `<=`, `>`, `>=`, IN, NOT IN, LIKE, ILIKE, BETWEEN, IS NULL, IS NOT NULL, AND, OR, NOT
- GROUP BY с COUNT, SUM, AVG, MIN, MAX и HAVING
- ORDER BY (ASC, DESC), LIMIT и OFFSET
- один INNER или LEFT JOIN … ON одно поле = другое поле
- комментарии, имена в кавычках и значения в двойных кавычках (читаются как текст, как это делает MySQL)

Всё остальное отклоняется с сообщением о том, что именно и где: CASE, подзапросы, `COUNT(DISTINCT …)`, LIKE … ESCAPE, больше одного JOIN, операторы, кроме SELECT, и сравнения с NULL (вместо них пишите IS NULL).

Некоторые правила SQL сохранены намеренно: `<>` и NOT IN исключают документы, где поле равно null или отсутствует, как это делает SQL, а целое число больше 9007199254740991 отклоняется, а не округляется.

## Импорт и экспорт файлов SQL

Импорт дампа SQL и экспорт коллекций в SQL выполняет само приложение: **SQL ↔ MongoDB** в боковой панели — страница, которая показывает, в каком подключении и какой базе данных она работает. Этот плагин ничего не импортирует и не экспортирует.

## Разрешения

- **Чтение документов** (`documents:read`): чтобы выполнять запрос в открытой коллекции и читать из неё выборку для подсказок и примеров.
- **Чтение других коллекций той же базы данных** (`database:read`): чтобы выполнять JOIN, который читает указанную в нём коллекцию. Без JOIN другие коллекции не читаются.

Чтение идёт через приложение, с правами и маскированием полей вошедшего пользователя.

## Настройки

Нет.

## Ограничения

- «Выполнить» показывает не более 50 строк. При большем LIMIT или без него показываются первые 50 и сообщается, что совпадают и другие.
- «Выполнить» читает только открытую здесь коллекцию (и ту, которую называет JOIN). Запрос, в FROM которого указана другая коллекция, переводится, но не выполняется; откройте эту коллекцию, чтобы выполнить его.
- «Использовать в „Документах“» оставляет LIMIT и OFFSET только в коде: «Документы» сами разбивают результаты на страницы.
- Подсказки полей и значений берутся из первых 100 документов коллекции, до 20 значений на поле.
- Один JOIN на запрос, в виде простого `$lookup` (localField и foreignField). JOIN никогда не читает системную коллекцию.
- Запрос, выполняемый как конвейер (сгруппированный или с JOIN), длится не более 10 секунд и не использует диск. Запуски никогда не добавляются в недавние запросы пользователя.
