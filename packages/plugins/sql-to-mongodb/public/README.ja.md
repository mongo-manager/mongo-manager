# SQL から MongoDB へ

SQL から MongoDB へは、SQL の SELECT 文を同じ処理を行う MongoDB クエリに変換します。適する場合は `find`、それ以外は集計パイプラインとなり、mongosh のコードと各公式ドライバーのプログラムとして表示されます。コレクションの SQL タブでは、クエリを読み取り専用で実行し、行も表示します。

クエリを実行してもデータは変更されません。このプラグインは何も書き込みません。

## 表示される場所

- **コレクションタブ：** すべてのコレクションとビューで、ドキュメント、集計などのタブの隣に **SQL** タブが表示されます。

## 使い方

1. コレクションを開き、**SQL** タブに切り替えます。**例**を選ぶと、そのコレクション自身のフィールドを使ったクエリがエディターに入力されます。
2. エディターに SELECT を書きます。入力に合わせて候補が表示されます。キーワード、コレクションのフィールド（ネストされたパスも）、`=` の後や `IN (…)` 内でフィールドが持つ値、関数、FROM や JOIN の後のコレクション名です。Enter で強調表示された候補を選べます。一部を入力した後や候補に移動した後は、Tab でも選べます。
3. MongoDB のコードは入力に合わせて更新されます。**コードの言語**で言語を選びます（mongosh、Node.js、Python、Java、Go、C#、PHP、Ruby、Rust）。**コードをコピー**でコードをコピーします。
4. **実行**（Ctrl+Enter、Mac では Cmd+Enter）は、クエリをここで読み取り専用で実行し、**結果**の下に最大 50 行を表示します。行の**開く**を押すと、そのドキュメントがアプリで表示されます。**クリア**は結果を空にします。
5. **整形**（Shift+Alt+F）は SQL を整えます。1 行に 1 つの句を置き、キーワードは大文字になります。クエリの意味は変わりません。
6. **ドキュメントで使用**は、フィルター、プロジェクション、ソートをコレクションのドキュメントタブに入力します。**集計で開く**は、パイプラインを集計タブに入力します。ご自身で実行するまで、そこでは何も実行されません。

間違いは該当する行に印が付き、メッセージに行と列が示されます。**エディターで表示**を押すと、カーソルがその位置に移動します。

## 例

```sql
SELECT name, total FROM orders
WHERE status = 'shipped' AND total > 100
ORDER BY total DESC
LIMIT 10
```

は次のようになります。

```mongosh
db.getCollection("orders").find(
  { status: "shipped", total: { $gt: 100 } },
  { name: 1, total: 1, _id: 0 }
).sort({ total: -1 }).limit(10)
```

グループ化したクエリはパイプラインになります。

```sql
SELECT status, COUNT(*) AS n FROM orders GROUP BY status HAVING COUNT(*) > 5 ORDER BY n DESC
```

```mongosh
db.getCollection("orders").aggregate([
  { $group: { _id: { status: "$status" }, n: { $sum: 1 } } },
  { $match: { n: { $gt: 5 } } },
  { $project: { _id: 0, status: "$_id.status", n: "$n" } },
  { $sort: { n: -1 } }
])
```

## JOIN

同じデータベース内の別のコレクションとの INNER JOIN または LEFT JOIN 1 つは `$lookup` に変換され、実行もここで行われます。

```sql
SELECT o.orderNo, c.name FROM orders o JOIN customers c ON o.customerId = c._id
```

結果の列見出しは、SELECT での記述どおりに表示されます（`o.orderNo`、`c.name`、または AS 名）。結合された列の見出しの横にある小さな印は、その列の元になったコレクションのフィールドを示します（例：`customers.name`）。結合されるコレクションも、他の読み取りと同様に、ユーザーの権限とフィールドマスクに従って読み取られます。

## 対応する SQL

- 列、`*`、エイリアス（AS）、DISTINCT を使った SELECT
- `=`、`<>`、`!=`、`<`、`<=`、`>`、`>=`、IN、NOT IN、LIKE、ILIKE、BETWEEN、IS NULL、IS NOT NULL、AND、OR、NOT を使った WHERE
- COUNT、SUM、AVG、MIN、MAX を使った GROUP BY と HAVING
- ORDER BY（ASC、DESC）、LIMIT、OFFSET
- INNER JOIN または LEFT JOIN 1 つ … ON あるフィールド = 別のフィールド
- コメント、引用符で囲んだ名前、二重引用符で囲んだ値（MySQL と同様にテキストとして解釈）

それ以外はすべて、何がどこにあるかを示すメッセージとともに拒否されます。CASE、サブクエリ、`COUNT(DISTINCT …)`、LIKE … ESCAPE、複数の JOIN、SELECT 以外の文、NULL との比較（代わりに IS NULL を使用）が該当します。

一部の SQL ルールは意図的に維持されています。`<>` と NOT IN は、SQL と同様にフィールドが null または存在しないドキュメントを除外します。9007199254740991 を超える整数は、丸められずに拒否されます。

## SQL ファイルのインポートとエクスポート

SQL ダンプのインポートとコレクションの SQL エクスポートは、アプリ自体の機能です。サイドバーの **SQL ↔ MongoDB** で、使用する接続とデータベースが表示されます。このプラグインはインポートもエクスポートも行いません。

## 権限

- **ドキュメントの読み取り**（`documents:read`）：開いているコレクションでクエリを実行し、候補や例のためにサンプルを読み取ります。
- **同じデータベースの他のコレクションの読み取り**（`database:read`）：JOIN を実行するため、指定されたコレクションを読み取ります。JOIN がなければ、他のコレクションは読み取られません。

読み取りはすべて、サインインしているユーザーの権限とフィールドマスクに従って、アプリを通じて行われます。

## 設定

なし。

## 制限

- 実行は最大 50 行を表示します。それより大きい LIMIT や LIMIT なしの場合は、先頭の 50 行を表示し、他にも一致があることを示します。
- 実行が読み取るのは、ここで開いているコレクション（と JOIN で指定されたコレクション）のみです。FROM が別のコレクションを指すクエリは変換されますが実行されません。実行するにはそのコレクションを開いてください。
- ドキュメントで使用は、LIMIT と OFFSET をコード内にのみ残します。ドキュメントでは結果が自動的にページ分割されます。
- フィールドと値の候補は、コレクションの先頭 100 件のドキュメントから取得され、フィールドごとに最大 20 個の値です。
- 1 つのクエリにつき JOIN は 1 つで、単純な `$lookup`（localField と foreignField）として扱われます。JOIN がシステムコレクションを読み取ることはありません。
- パイプラインとして実行されるクエリ（グループ化または結合）は最大 10 秒間で、ディスクを使用しません。実行はユーザーの最近のクエリには追加されません。
