Primeiros passos

Instalação

Use qualquer uma destas opções. Cada versão também traz todos os arquivos com somas de verificação SHA-256, para máquinas isoladas da rede (air-gapped).

  • npm (Node.js 24 ou posterior): npx @mongo-manager/app
  • npm offline: npm install --global ./mongo-manager-<version>.tgz
  • Binário autônomo: baixe o arquivo para o seu sistema e execute-o; o Node.js não é necessário.
  • Docker: docker compose -f deploy/docker-compose.yml up -d

MongoDB compatível: 6.0 e posteriores. Servidores mais antigos são recusados ao conectar, com uma mensagem que informa isso.

Primeira execução

O modo local (o padrão) é para uma pessoa em um computador: o Mongo Manager escuta em 127.0.0.1:4321 e abre o navegador. Não há login: ele abre a partir de um link de uso único. Iniciado em um terminal, ele imprime o link na linha seguinte ao seu endereço; em qualquer outro lugar (um serviço, um contêiner, um log), ele imprime o caminho de um arquivo que o abre, e somente a sua conta pode lê-lo. Seu navegador então continua autenticado enquanto mantiver os dados deste site (no máximo seis meses após o último uso; o Safari os remove após uma semana sem visita), e o mesmo vale para o app instalado — exceto um web app do Safari em um Mac, que mantém dados próprios e não pode receber um link: use o Mongo Manager em uma aba do Safari nesse caso. Outro programa ou conta no computador que abrir o endereço recebe apenas uma página explicando como abri-lo. Quando o link tiver sido usado ou o seu navegador o tiver esquecido, execute mongo-manager open para obter um novo; em um terminal ele também imprime o link, para um navegador que não consegue abrir o arquivo (um navegador snap ou Flatpak no Linux). Em um computador compartilhado, use o modo equipe. 

mongo-manager
mongo-manager open             # a new link for a running Mongo Manager (--no-open prints it)

O modo equipe adiciona usuários, funções e login com autenticação em dois fatores. A primeira inicialização imprime um token de configuração de uso único no terminal (executado como serviço ou em um contêiner, ele fica em setup-token na pasta de dados); abra a página e insira-o para criar o primeiro administrador. 

mongo-manager --auth

Sua primeira conexão

  1. Escolha Adicionar conexão e cole ou digite uma string de conexão no primeiro campo, como localhost:27017 ou um endereço mongodb+srv:// (o mongodb:// pode ser omitido). O formulário se preenche sozinho: a linha abaixo do campo diz o que foi entendido, e o nome acompanha o host até você digitar um. Servidor, autenticação, TLS, SSH e o restante ficam em Opções avançadas; Salvar e conectar salva a conexão e a abre.
  2. Escolha Testar conexão. Ela mostra a versão do MongoDB e a topologia.
  3. Salve. A conexão aparece na árvore à esquerda.

Métodos de login

Além de nome de usuário e senha (SCRAM), uma conexão pode entrar com um certificado X.509, LDAP (PLAIN), chaves AWS IAM, OIDC ou Kerberos. Escolha o método em Opções avançadas → Autenticação.

  • MONGODB-OIDC (MongoDB Atlas, Enterprise): cada pessoa entra com o provedor de identidade indicado pelo servidor — nenhuma senha é armazenada. Na primeira vez que você abre a conexão, uma caixa de diálogo oferece Entrar: a página do provedor abre nesta aba e leva você de volta. Onde o redirecionamento dele não alcança o Mongo Manager, escolha Usar um código e insira o código exibido no provedor. Registre o endereço …/oidc/callback deste servidor no provedor ou informe outro em Endereço de redirecionamento. Hosts permitidos são os hosts para os quais o seu login pode ser enviado (vazio: o Atlas e este computador). A página da conexão mostra se você está autenticado e permite sair. Uma identidade de carga de trabalho (Azure, GCP, Kubernetes) entra como a máquina em que o Mongo Manager é executado: no modo equipe, somente onde um administrador permitiu.
  • Kerberos (GSSAPI): informe o principal e, quando seus servidores exigirem, o nome do serviço, o realm e a canonicalização do nome do host. Ele entra com o ticket Kerberos da conta sob a qual o Mongo Manager é executado — a sua em seu próprio computador, a do servidor no modo equipe, onde fica desativado a menos que um administrador o permita. Ele exige o pacote opcional kerberos do pacote npm (veja Implantação).

Criptografia no cliente

Em Opções avançadas → Criptografia, uma conexão pode usar a criptografia de campos no cliente (CSFLE) ou o Queryable Encryption. Ela exige o pacote opcional mongodb-client-encryption do pacote npm.

  • Provedores de chave: uma chave mestra local de 96 bytes (Gerar uma nova chave cria uma; guarde uma cópia, ou os dados não poderão ser descriptografados), AWS KMS, Azure Key Vault, Google Cloud KMS ou KMIP. As credenciais deles são mantidas lacradas e nunca mais exibidas. O key vault é a coleção em que as chaves de dados ficam (encryption.__keyVault por padrão).
  • Modo: Leitura e gravação descriptografa as leituras e criptografa as gravações (MongoDB Enterprise ou Atlas); Somente descriptografar lê os valores criptografados já descriptografados e não grava documentos (MongoDB Community). A análise de consultas usa a biblioteca crypt_shared (o caminho dela ou, no modo equipe, o do servidor) ou o mongocryptd neste computador.
  • Os campos criptografados vêm das opções de coleção do servidor — o encryptedFields do Queryable Encryption, um validador $jsonSchema do CSFLE — a menos que a conexão forneça seus próprios mapas. A visualização de documentos marca os campos criptografados com um cadeado.
  • A seção Criptografia da conexão (para os administradores dela) lista as chaves de dados, cria novas e as rotaciona (reencapsulando-as sob uma chave mestra), e cria coleções do Queryable Encryption: cada campo com seu tipo e se pode ser consultado por igualdade ou intervalo, com uma chave de dados criada para cada um.
  • Quem não pode ver dados pessoais vê os valores criptografados como estão armazenados e não pode gravar documentos em uma conexão assim. As cópias movem os valores criptografados como estão armazenados; uma coleção do Queryable Encryption não pode ser copiada.

Início e próximos passos

O Início é um painel de widgets que você adiciona, remove, redimensiona e move com Personalizar painel; ele é salvo para você no servidor. O widget Próximos passos sugere até cinco coisas a fazer, calculadas pelo próprio app a partir do seu trabalho recente: alertas disparados, tarefas que falharam no último dia, sincronizações em tempo real e backups agendados que precisam de você, um índice sugerido para o banco de dados que você usou por último (a partir das consultas lentas dele, quando você pode monitorar o servidor) e lugares que você abriu recentemente e que não estão abertos agora. Cada um é um link que executa a ação — um índice abre a caixa de diálogo usual Criar índice com a chave preenchida, e nada é criado até você confirmar ali. Dispense um com o seu ✕ (Desfazer o traz de volta); a dispensa é mantida com o seu painel, e um novo evento do mesmo tipo volta como um novo passo. Mostrar novamente os passos dispensados, no menu do widget, traz todos de volta.

Onde um provedor de IA está configurado, o menu do widget oferece Ordenar com IA; ele fica desativado até você ativá-lo. A IA então coloca os passos em ordem e redige os títulos, apenas a partir de fatos: o tipo de cada passo, nomes (conexão, banco de dados, coleção, nomes de campos de um índice) e contagens — nunca um valor, um documento ou o texto de um erro. Um passo cuja conexão tem a política de IA "desativada", ou "somente local" com um provedor que não se sabe responder a partir da rede local, não é enviado e mantém seu lugar. A IA não pode adicionar um passo nem mudar o que um passo faz: sob cada título que ela dá, as próprias palavras do app dizem o que o passo faz, e os títulos não contêm números (uma contagem ficaria desatualizada; a linha do app a informa). Os passos só são reordenados quando mudam (outro tipo de passo, outro lugar) ou quando você escolhe Reordenar com IA — nunca porque uma contagem mudou ou o tempo passou. Cada ordenação é contabilizada no histórico de IA (como "Próximos passos", sem suas palavras) e no log de auditoria (quantos passos, nunca seus nomes). Um índice sugerido só é oferecido onde você pode criar índices.

Consultas

Abra uma coleção e digite um filtro como { status: 'A', qty: { $lt: 30 } }; depois pressione Enter. Opções adiciona projeção, ordenação, ignorar, limite, collation, hint e um limite de tempo. Consultas recentes lista o que você executou nessa coleção, e a estrela guarda a consulta como favorita, com um nome e tags.

Uma coleção abre com os documentos mais recentes primeiro: a ordenação { _id: -1 } aparece em Opções e na coluna _id, onde pode ser alterada ou removida, e o botão de redefinir volta a ela. Uma view ou uma série temporal mantém a própria ordem. Para abrir as coleções na ordem em que estão gravadas, desative “Abrir as coleções com os documentos mais recentes primeiro” em Preferências.

Um valor na barra pode ser um parâmetro, escrito {{name}}: { status: {{status}}, qty: { $gte: {{min}} } }. Um campo para cada um aparece abaixo da barra, e Buscar executa a consulta com os valores informados ali: 18 é um número, "18" uma string, ISODate("2026-01-01") uma data, e qualquer outro texto é uma string como digitado. Um favorito salvo a partir da barra mantém seus parâmetros, com os valores informados como padrões; ao abri-lo, ele os preenche e executa, ou aguarda um valor onde um parâmetro não tem nenhum. Dentro de aspas, de uma expressão regular ou de um comentário, {{name}} é texto simples. Quem não pode ver os dados pessoais de uma conexão nunca recebe os padrões de outro usuário.

Chips abaixo da barra sugerem condições: as que você executou recentemente na coleção e as que uma pequena amostra dela sugere (um valor comum, como status = "paid", ou um campo que muitos documentos não têm); escolher uma a adiciona ao filtro e a executa. A amostra é coletada quando a página está ociosa ou a barra é usada, e nunca em uma visualização (ela executaria o pipeline da visualização). Acima dos resultados, cada condição do filtro em uso é um chip próprio: removê-la (o X dela, ou Delete no chip) executa o filtro sem ela, e Desfazer a traz de volta. O texto na barra a acompanha somente enquanto for o filtro em uso; um filtro que você ainda está editando é deixado como está. O painel abaixo da barra mostra a consulta em uso, parte por parte; o seu Executar a executa novamente e a estrela dele a salva como favorita.

Na tabela, clique no nome de uma coluna para ordenar por ela: crescente, depois decrescente, depois sem ordenação. Shift + clique adiciona a coluna à ordenação. A ordenação é gravada em Opções e executada com o filtro na barra, de modo que a barra sempre mostra o que é executado. Arraste a borda de uma coluna (ou foque nela e use as setas) para mudar a largura, e clique duas vezes na borda para que a coluna volte a se dimensionar sozinha; as larguras são mantidas para cada coleção, para você, neste navegador. O menu de uma coluna a ordena, copia o nome dela ou a oculta. Uma coluna cujos valores estão ocultos de você (dados pessoais) nunca é ordenada.

Gráfico, ao lado de Tabela, Cartões e JSON, desenha os resultados da consulta como barras, uma linha, pontos ou uma pizza: escolha o campo ao longo do eixo X, uma contagem, soma ou média de um campo numérico e um campo que divide os resultados em séries. Ele lê até os primeiros 1.000 documentos correspondentes (somente os campos desenhados) e avisa quando há mais; uma tabela com os mesmos números está disponível para leitores de tela. Os campos ocultos de você não são oferecidos e nunca são representados em gráficos. Copiar nome, nos menus de bancos de dados, coleções e colunas, e ao lado de um campo em Esquema, copia o nome simples.

Editar um documento mostra exatamente quais campos mudam antes de qualquer coisa ser gravada; somente esses campos são salvos. Na tabela, clique duas vezes em um valor (ou pressione Enter nele) para editá-lo no próprio local; ele mantém o seu tipo.

Atualizar vários documentos e Excluir vários documentos mostram uma prévia antes de executar: quantos documentos correspondem e alguns deles. Em uma atualização, cada amostra mostra o que muda nela, calculado pelo MongoDB em uma leitura que não grava nada; um documento em que a atualização falharia (um $inc em texto, um caminho através de um array) é marcado. Caminhos posicionais ($[]), índices de array e $pull com uma condição não têm prévia nas amostras, e a prévia informa isso. Os valores pessoais permanecem mascarados nas amostras, antes e depois.

Coleções

Nova coleção pode definir uma collation padrão (um idioma, sua força, ordenação numérica e o restante das opções do MongoDB) para uma coleção, uma coleção limitada (capped) ou de séries temporais ou uma visualização; o MongoDB a fixa na criação. Uma coleção ou coleção limitada também pode manter pré-imagens e pós-imagens do change stream desde o início. Depois, o item Editar coleção… do menu da coleção ativa ou desativa essas imagens (após uma confirmação que a nomeia), mostra a collation dela e leva à aba Validação, onde as regras permanecem. O cabeçalho da coleção informa a collation e se as imagens são mantidas.

Desempenho

A aba Desempenho de uma conexão exibe o servidor em gráficos ao vivo: operações por segundo, conexões, rede e memória, amostradas a cada 2 segundos enquanto a aba está aberta. Abaixo ficam as operações em execução mais lentas, que você pode filtrar por banco de dados ou coleção, tipo, tempo de execução, espera por um bloqueio e conexões ociosas, e pausar; e as coleções que levaram mais tempo. Editores e administradores podem abri-la; o menu "…" de uma operação mostra o comando dela e, para administradores da conexão, Encerrar operação, que pergunta antes. O próprio MongoDB precisa permitir que a conta leia o status do servidor: conceda a ela a função clusterMonitor, ou a aba informa o que está faltando.

A seção Profiler mostra o nível do profiler, o slowms e a taxa de amostragem de cada banco de dados; um administrador da conexão pode alterá-los com o lápis na linha do banco de dados. O nível 2 (todas as operações) pergunta antes e volta sozinho à configuração anterior após 30 minutos. Consultas lentas lista as operações lentas do profiler e do próprio log do servidor (que funciona mesmo com o profiler desativado), das mais recentes às mais antigas, com o plano, as chaves e os documentos examinados e o comando; uma que lê muito mais documentos do que retorna é sinalizada, e Abrir no Explain a abre na coleção dela.

Na aba Dados pessoais da conexão, um administrador da conexão pode listar os campos que contêm dados pessoais (por exemplo crm.users.email ou *.*.**.phone); a própria aba Dados pessoais de uma coleção lista e adiciona somente os campos dessa coleção, sendo o nome do campo tudo que um novo exige, e mostra as regras mais amplas da conexão que a alcançam. Um usuário com a concessão Não pode ver dados pessoais vê os valores como *** no profiler, nas consultas lentas e nas operações, e não pode usar o shell. No modo local (sem contas), as regras ocultam os valores de você também, em todos os lugares — documentos, exportações, o contexto da IA — e o shell permanece fechado enquanto eles estiverem ocultos; Ocultá-los de mim também na aba da conexão desativa isso para a conexão.

Sugestões de índices lê as consultas lentas de um banco de dados e propõe um índice para cada consulta que fez varredura, pela regra igualdade–ordenação–intervalo, a menos que um índice já a atenda; também lista índices que não foram usados desde que o servidor iniciou ou que são o início de outro índice. Somente nomes de campos são usados. Criar índice abre a caixa de diálogo usual com a chave preenchida: nada é criado até você confirmar ali.

No cabeçalho da conexão, enquanto Desempenho está aberto, escolha Ao vivo (os últimos 5 minutos) ou um período armazenado de 1 hora, 24 horas ou 7 dias. Um administrador da conexão ativa Gravar histórico de métricas no menu Histórico de métricas ao lado (o mesmo menu exclui o que foi armazenado, após perguntar): o servidor então amostra essa conexão uma vez por minuto e mantém 7 dias (somente números). Enquanto está desativado, o servidor nunca se conecta a essa conexão por conta própria. Em um mongos, a aba mostra a visão geral do sharding: shards, o balanceador, os roteadores e a chave e a distribuição de chunks de cada coleção fragmentada, com tamanhos e chunks jumbo sob demanda. Nada ali altera o cluster.

Em um conjunto de réplicas, a mesma aba lista cada membro: qual é o primário, quais estão inativos, quantos segundos cada secundário está atrás do primário (âmbar acima de 10 s, vermelho acima de 60 s), o atraso do commit da maioria e a janela do oplog, com um gráfico do atraso nos últimos minutos. Um conjunto sem primário é mostrado em vermelho: ele não pode aceitar gravações até que um seja eleito.

Agregações

A aba Agregações de uma coleção constrói um pipeline estágio por estágio. Adicione um estágio, escolha o operador dele (digite no campo do operador para encontrar um estágio pelo nome ou pelo que ele faz — "join" encontra $lookup — com as setas e Enter; ao lado da lista, o que o estágio faz e um exemplo do valor dele; cada um começa de um modelo, com um link para o manual do MongoDB) e edite o valor; a saída de cada estágio é exibida em prévia sobre uma amostra da coleção (os primeiros 1000 documentos, ou uma amostra aleatória) enquanto você digita. Os estágios podem ser desativados, reordenados com arrastar e soltar ou Alt+Seta para cima e Alt+Seta para baixo, ou editados de uma vez como texto.

Executar transmite o resultado inteiro (até 10 000 documentos) com um botão Parar; Calcular total o conta somente quando solicitado. Um pipeline que termina em $out ou $merge nunca tem prévia: ele é executado uma vez, após uma confirmação que nomeia o destino, e substituir uma coleção pede o nome dela. Os pipelines podem ser salvos com a coleção (no modo equipe, opcionalmente compartilhados), exportados como um programa para Node.js, Python, Java, Go, C#, PHP, Ruby ou Rust (a string de conexão é lida de MONGODB_URI, nunca escrita no código) ou transformados em uma visualização.

O pipeline de uma visualização é alterado da mesma forma: Editar pipeline na visualização (na visão geral ou no menu dela) o abre na aba Agregações da coleção que ela lê, marcado como o da visualização, com uma prévia de cada estágio. Atualizar visualização grava os estágios ativados de volta na visualização, após uma confirmação que a nomeia. Um pipeline com um estágio que o construtor não consegue ler não é aberto (salvá-lo perderia esse estágio); um usuário de quem os dados pessoais são ocultados não pode alterar uma visualização cuja definição ele vê mascarada.

Consultas

A página Consultas (Consultas na barra lateral, a paleta de comandos ou Ctrl / ⌘ + Shift + L; o endereço dela é /library) pesquisa os favoritos, os pipelines salvos, os snippets de shell e o histórico de consultas de uma conexão por nome, tag, texto da consulta, tipo ou coleção. Ela abre na conexão em que você estava trabalhando, ou na primeira, e mantém o que você pesquisou quando você volta a ela. Abrir um item leva à coleção dele: um find é executado em Documentos, um pipeline preenche os cartões de Agregações (após perguntar, quando a aba já tem algum). O histórico mantém os finds e as agregações que você executou, os últimos 200 por coleção e 2000 no total, cada um uma vez com quantas vezes foi usado; as entradas podem ser removidas uma a uma ou limpas. Favoritos e pipelines salvos podem ser renomeados, ter as tags alteradas, compartilhados e excluídos na página Consultas, e fixados: as consultas fixadas são somente suas (até 50 por conexão), listadas primeiro na página Consultas e no widget Consultas do Início. A paleta de comandos lista os favoritos, os pipelines salvos e os snippets de shell de cada conexão aberta em uma aba, cada conexão sob o próprio nome, com a que você está usando primeiro. Quando o modo equipe inicia, o histórico do modo local é excluído (nenhum usuário da equipe poderia vê-lo ou limpá-lo); o log informa quantas entradas foram removidas. Os favoritos e os pipelines salvos do modo local permanecem, para os administradores da conexão.

Shell avançado

A aba de shell de uma conexão executa um mongosh real, e o terminal dela é onde o código é digitado: use um banco de dados, execute finds e agregações, escreva scripts. Enter executa o código quando ele está completo; enquanto um colchete, uma string ou uma instrução está aberto (após ., um operador, if (…)), ele continua na linha seguinte após ..., e Shift+Enter sempre adiciona uma linha. Ctrl+Enter executa o código como está. Código de muitas linhas pode ser colado no terminal: ele é exibido linha por linha e só é executado quando você pressiona Enter. Um script é executado como o mongosh executa o que é digitado — use, show e it cada um por si, depois cada instrução em sequência; um erro o interrompe ali e informa quantas instruções não foram executadas. print() e printjson() escrevem no terminal; cls o limpa, junto com os resultados, e exit encerra o shell.

Seta para cima e seta para baixo percorrem as linhas do que está sendo digitado e depois o histórico; Ctrl+R pesquisa o histórico (Ctrl+R novamente para correspondências mais antigas, Escape para sair). Ctrl+C interrompe um comando em execução ou limpa a linha — ou copia, quando há saída selecionada. Alt+B e Alt+F (ou Ctrl+Seta para a esquerda e Ctrl+Seta para a direita) movem por palavra. O histórico de cada usuário é mantido por conexão, criptografado, e pode ser limpo.

O shell está disponível para os administradores da conexão e para um editor a quem um administrador o conceda. Ele é executado em um sandbox que não contém nenhuma credencial e só alcança os servidores da própria conexão; em uma conexão somente leitura, ele recusa gravações, e quem não é administrador não pode executar administração de cluster ou de usuários.

A página do shell informa onde ele é executado — a conexão e o banco de dados em que o shell está (ele acompanha use) — e o estado dele: conectando, conectado, em execução (com o tempo decorrido) ou fechado. O cabeçalho dele tem Parar enquanto um comando é executado, Limpar a tela e os resultados (Ctrl+L, também durante a execução de um comando, ou cls; um aviso informa, e o Desfazer dele, ou Trazer os resultados de volta no cartão Resultados vazio, os devolve), e um menu para salvar o que está digitado (ou o último código executado) como snippet, limpar o histórico (os resultados vão junto) ou reiniciar o shell (a sessão termina e uma nova começa; as variáveis e os resultados exibidos são perdidos). O terminal adota o tema claro ou escuro do app ou um próprio, e colore o código. Uma barra na parte inferior lista as teclas. Um shell permanece aberto enquanto a página dele estiver aberta, por mais tempo que fique sem uso. Quando ele fecha (o seu login terminou ou ele passou de um limite de ociosidade ou de duração definido pelo servidor), a página informa o motivo; Enter abre um novo; um comando ainda em execução quando a conexão cai termina na tela assim que ela é restabelecida.

Ao digitar, Tab oferece preenchimentos — as coleções do banco de dados após db. (inclusive uma criada no shell), os métodos do que uma cadeia retorna, operadores após $ e nomes de campos amostrados da coleção. Shift+Tab, ou Escape e depois Tab, sai do terminal.

Ao lado do terminal, o cartão Resultados mostra o último resultado como uma tabela, uma árvore ou texto; Mais busca o próximo lote de um cursor, e o histórico de resultados no cabeçalho dele escolhe um resultado anterior, cada um nomeado pelo comando de que veio (mantido somente na memória); Limpar esvazia o cartão; o Desfazer do aviso, ou Trazer os resultados de volta no cartão vazio, devolve os resultados até o shell reiniciar ou o histórico dele ser limpo. O cartão pode ser alargado; em uma tela estreita, o terminal e os resultados são duas abas. Várias abas de shell podem ficar abertas juntas, cada uma com a própria sessão. Um cursor de um find ou de uma agregação simples abre na visualização da coleção dele — um find começando no seu skip, o limite dele como tamanho da página — e os documentos exibidos são exportados como JSON ou CSV.

O código pode ser salvo como snippet — privado ou compartilhado com a equipe — com parâmetros escritos {{name}}. Abrir um snippet (a partir da página Consultas ou da paleta de comandos) pede os parâmetros dele e coloca o código preenchido no terminal; nada é executado até você pressionar Enter. Seus próprios snippets são editados na página Consultas: o nome, as tags, o código e os parâmetros dele (uma linha acompanha cada {{name}} enquanto você digita), verificados como um novo snippet; um snippet compartilhado continua compartilhado, e o log de auditoria registra que o código dele mudou, nunca o código.

O terminal funciona com um leitor de tela: o modo leitor de tela vem ativado por padrão, e Conta → Preferências o desativa ou o ativa novamente, inclusive nos shells abertos.

Explain

"Por que está lento?" em Documentos ou Agregações abre a seção Explain sobre essa consulta ou esse pipeline. Ela mostra o plano que o MongoDB escolheu como uma árvore (as setas percorrem a árvore), o que cada estágio leu e retornou, os planos rejeitados e avisos em palavras: uma varredura da coleção inteira, uma ordenação feita em memória, um filtro que lê muito mais do que retorna, um join em um campo sem índice. Quando um índice ajudaria, o Explain sugere um (campos de igualdade, depois a ordenação, depois intervalos) e "Criar este índice" o cria em segundo plano. Um pipeline que grava não é explicado, porque explicar o executa.

Validação

A seção Validação edita as regras que todo documento inserido ou atualizado deve seguir, com o nível e a ação de validação. "Gerar a partir de uma amostra" escreve um $jsonSchema a partir dos documentos da coleção; "Testar nos documentos existentes" conta quantos falhariam, com exemplos, antes de você salvar. Salvar pergunta antes e informa quando documentos que violam as regras teriam as atualizações recusadas; "Restaurar as regras anteriores" recoloca o que o último salvamento substituiu enquanto a aba estiver aberta. Uma gravação que as regras recusam informa quais delas não foram atendidas (um campo ausente, um tipo errado, um mínimo), e o relatório de uma importação ou de uma cópia também; o valor que falhou nunca é repetido.

Esquema

A aba Esquema de uma coleção analisa uma amostra aleatória (100, 1.000 ou 10.000 documentos): cada campo com a frequência com que está presente, seus tipos e um histograma ou seus valores mais comuns. Exportar transforma a análise em um esquema do Mongoose, um validador JSON Schema do MongoDB ou uma interface TypeScript, para copiar ou baixar. Um campo conta como obrigatório quando todos os documentos amostrados o têm.

As barras de um campo — seus intervalos e seus valores mais comuns — e seus tipos são botões: escolher um adiciona essa condição ao filtro de Documentos da coleção (ao lado das condições já digitadas, ou com $and quando o campo já tem uma), a executa e mostra os documentos. Um valor truncado na análise é exibido, mas não oferecido. Um campo que contém lugares — pontos GeoJSON ou pares de coordenadas sob um nome como location ou coords — os mostra em um mapa desenhado sem nenhuma rede (o contorno do mundo do Natural Earth, em domínio público): arraste ou use as setas para mover; Ctrl e a roda, dois dedos, ou + e − para ampliar; os lugares também são listados como uma tabela; e Filtrar por esta área adiciona um $geoWithin da área em exibição. Campos com dados pessoais nunca são desenhados.

Modelo de dados

A seção Modelo de um banco de dados desenha as coleções dele e as referências entre elas. Ler o modelo amostra cada coleção (100 a 1.000 documentos, no máximo 50 coleções) em busca dos campos dela — o nível superior e um nível abaixo, os mais profundos somente quando parecem referências — e encontra referências de três maneiras: um campo nomeado a partir de uma coleção (userId ou user_id → users, tagIds → tags), valores ObjectId amostrados encontrados como o _id de outra coleção (no máximo dez valores por campo, sessenta contagens pequenas no total) e os estágios $lookup e $graphLookup de visualizações e dos pipelines salvos que você pode abrir. Uma linha contínua foi encontrada por nome ou valores, uma tracejada somente por $lookup, uma pontilhada une uma visualização à sua origem. Uma linha termina em um pé de galinha ("muitos") no campo que contém a referência — muitos documentos podem conter o mesmo id — e em uma barra ("um") na coleção a que se refere, com um pé de galinha também ali para um array de referências. Um campo é marcado com PK (a chave, _id), UQ (um índice único somente dele) ou IX (em um índice); os índices são lidos somente pelos nomes das chaves deles.

Arraste o diagrama ou use as setas para movê-lo, + e − para ampliar, 0 para ajustá-lo. A roda rola a página até o diagrama receber o foco (clique nele ou use Tab até ele); então a roda o move e Ctrl / ⌘ e a roda ampliam (Shift e a roda o movem a qualquer momento). Clique em uma coleção, ou use Tab até ela e pressione Enter, para ver os links dela e abri-la. A visualização Lista mostra o mesmo modelo como uma lista: cada coleção abre seus campos e links, e um link vai até a coleção a que se refere. Exportar salva o diagrama como PNG ou SVG (nas cores do tema em uso e no seu idioma), o modelo como JSON e o modelo como o erDiagram do Mermaid (salvo como .mmd ou copiado) para um README, uma wiki ou um pull request que o desenhe, onde um campo único é escrito UK, como o Mermaid o nomeia. Somente nomes, tipos e contagens são exibidos; nenhum valor sai do servidor. Quem pode ler documentos pode ler o modelo; os campos ocultos de você como dados pessoais são exibidos somente pelo nome e seus valores nunca são lidos. Um usuário do MongoDB com permissão somente para algumas coleções vê essas.

Ler um modelo custa ao servidor uma amostra por coleção: até 50 coleções vezes o tamanho da amostra, mais no máximo sessenta contagens pequenas. O servidor limita o total de documentos que um modelo lê (MM_MODEL_MAX_DOCS, 20.000 por padrão): com muitas coleções, cada amostra é reduzida, e a seção informa isso. Em um banco de dados de produção movimentado, leia-o quando o servidor estiver tranquilo ou com uma amostra menor.

Índices de busca

No MongoDB Atlas, ou no MongoDB 8.0 ou posterior com o processo de busca (mongot), a aba Índices também lista os índices do Atlas Search e do Vector Search de uma coleção: cada um com seu tipo, seu status (pendente, em construção, pronto, com falha e o motivo) e o que ele abrange, verificado novamente a cada poucos segundos enquanto um está sendo construído. Criar índice de busca recebe a definição como JSON ou, para um índice vetorial, um formulário guiado: o campo com os embeddings, as dimensões e a similaridade deles e os campos pelos quais filtrar. Uma definição pode ser editada e um índice descartado, após uma confirmação que o nomeia. Em outros lugares, a aba informa o que a busca exige.

Tarefas em segundo plano

A criação de um índice e a duplicação de uma coleção são executadas em segundo plano, de modo que uma operação longa nunca encontre um timeout. Você pode sair da página, ou fechar a aba, enquanto elas são executadas. O botão Tarefas em segundo plano na barra superior mostra cada tarefa: com uma barra e números quando o MongoDB informa o progresso (criações de índice), ou Ainda em execução e o tempo decorrido quando não informa (cópias). Você é avisado quando as suas próprias tarefas terminam e pode cancelá-las ali.

Se o servidor reiniciar durante uma cópia, a cópia é abandonada e a coleção pela metade é removida; o destino nunca fica parcialmente preenchido. A criação de um índice pode continuar dentro do MongoDB; a aba Índices a mostra.
