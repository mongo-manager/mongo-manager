Erste Schritte

Installation

Verwenden Sie eine dieser Möglichkeiten. Jedes Release enthält außerdem alle Dateien mit SHA-256-Prüfsummen für Rechner ohne Netzwerkanbindung.

  • npm (Node.js 24 oder neuer): npx @mongo-manager/app
  • Offline-npm: npm install --global ./mongo-manager-<version>.tgz
  • Eigenständige Binärdatei: Laden Sie die Datei für Ihr System herunter und führen Sie sie aus; Node.js ist nicht erforderlich.
  • Docker: docker compose -f deploy/docker-compose.yml up -d

Unterstützt werden MongoDB 6.0 und neuer. Ältere Server werden beim Verbinden abgelehnt, mit einer Meldung, die darauf hinweist.

Erster Start

Der Lokale Modus (Standard) ist für eine Person an einem Computer gedacht: Mongo Manager lauscht auf 127.0.0.1:4321 und öffnet Ihren Browser. Es gibt keine Anmeldung: Die Anwendung wird über einen einmaligen Link geöffnet. Wird sie in einem Terminal gestartet, gibt sie den Link in der Zeile nach ihrer Adresse aus; an anderer Stelle (Dienst, Container, Protokoll) gibt sie den Pfad einer Datei aus, die sie öffnet und die nur Ihr Konto lesen kann. Ihr Browser bleibt danach angemeldet, solange er die Daten dieser Website behält (höchstens sechs Monate nach der letzten Verwendung; Safari entfernt sie nach einer Woche ohne Besuch), ebenso die installierte App – mit Ausnahme einer Safari-Web-App auf einem Mac, die eigene Daten führt und keinen Link erhalten kann: Verwenden Sie Mongo Manager dort in einem Safari-Tab. Ein anderes Programm oder Konto auf dem Computer, das die Adresse öffnet, erhält nur eine Seite, die erklärt, wie die Anwendung geöffnet wird. Ist der Link verbraucht oder hat Ihr Browser ihn vergessen, erzeugt mongo-manager open einen neuen; in einem Terminal gibt der Befehl den Link auch aus, für einen Browser, der die Datei nicht öffnen kann (ein Snap- oder Flatpak-Browser unter Linux). Verwenden Sie auf einem gemeinsam genutzten Computer den Teammodus. 

mongo-manager
mongo-manager open             # a new link for a running Mongo Manager (--no-open prints it)

Der Teammodus ergänzt Benutzer, Rollen und die Anmeldung mit Zwei-Faktor-Authentifizierung. Beim ersten Start gibt die Anwendung im Terminal ein einmaliges Einrichtungstoken aus (läuft sie als Dienst oder in einem Container, steht es in setup-token im Datenordner); öffnen Sie die Seite und geben Sie es ein, um den ersten Administrator anzulegen. 

mongo-manager --auth

Ihre erste Verbindung

  1. Wählen Sie Verbindung hinzufügen und fügen Sie in das erste Feld eine Verbindungszeichenfolge ein oder geben Sie sie ein, etwa localhost:27017 oder eine mongodb+srv://-Adresse (mongodb:// darf entfallen). Das Formular füllt sich selbst: Die Zeile unter dem Feld sagt, was erkannt wurde, und der Name folgt dem Host, bis Sie einen eigenen eingeben. Server, Authentifizierung, TLS, SSH und alles Weitere finden Sie unter Erweiterte Optionen; Speichern und verbinden speichert die Verbindung und öffnet sie.
  2. Wählen Sie Verbindung testen. Der Test zeigt die MongoDB-Version und die Topologie.
  3. Speichern Sie. Die Verbindung erscheint links in der Baumansicht.

Anmeldeverfahren

Neben Benutzername und Passwort (SCRAM) kann sich eine Verbindung mit einem X.509-Zertifikat, LDAP (PLAIN), AWS-IAM-Schlüsseln, OIDC oder Kerberos anmelden. Wählen Sie das Verfahren unter Erweiterte Optionen → Authentifizierung.

  • MONGODB-OIDC (MongoDB Atlas, Enterprise): Jede Person meldet sich beim vom Server genannten Identitätsanbieter an – es wird kein Passwort gespeichert. Beim ersten Öffnen der Verbindung bietet ein Dialog Anmelden an: Die Seite des Anbieters öffnet sich in diesem Tab und leitet Sie zurück. Kann ihre Weiterleitung Mongo Manager nicht erreichen, wählen Sie Stattdessen einen Code verwenden und geben Sie den beim Anbieter angezeigten Code ein. Registrieren Sie die Adresse …/oidc/callback dieses Servers beim Anbieter oder geben Sie unter Weiterleitungsadresse eine andere an. Zulässige Hosts sind die Hosts, an die Ihre Anmeldung gesendet werden darf (leer: Atlas und dieser Computer). Die Seite der Verbindung zeigt, ob Sie angemeldet sind, und meldet Sie ab. Eine Workload-Identität (Azure, GCP, Kubernetes) meldet sich stattdessen als die Maschine an, auf der Mongo Manager läuft: im Teammodus nur dort, wo ein Administrator es erlaubt hat.
  • Kerberos (GSSAPI): Geben Sie den Principal an sowie, wenn Ihre Server es benötigen, Dienstnamen, Realm und Kanonisierung des Hostnamens. Die Anmeldung erfolgt mit dem Kerberos-Ticket des Kontos, unter dem Mongo Manager läuft – auf Ihrem eigenen Computer Ihres, im Teammodus das des Servers; dort ist sie deaktiviert, solange ein Administrator sie nicht erlaubt. Sie benötigt das optionale Paket kerberos des npm-Pakets (siehe Bereitstellung).

Clientseitige Verschlüsselung

Unter Erweiterte Optionen → Verschlüsselung kann eine Verbindung die clientseitige Verschlüsselung auf Feldebene (CSFLE) oder Queryable Encryption verwenden. Sie benötigt das optionale Paket mongodb-client-encryption des npm-Pakets.

  • Schlüsselanbieter: ein lokaler 96-Byte-Hauptschlüssel (Neuen Schlüssel erzeugen erstellt einen; bewahren Sie eine Kopie auf, sonst lassen sich die Daten nicht entschlüsseln), AWS KMS, Azure Key Vault, Google Cloud KMS oder KMIP. Ihre Zugangsdaten werden versiegelt gespeichert und nie wieder angezeigt. Der Key Vault ist die Collection, in der die Datenschlüssel liegen (standardmäßig encryption.__keyVault).
  • Modus: Lesen und Schreiben entschlüsselt beim Lesen und verschlüsselt beim Schreiben (MongoDB Enterprise oder Atlas); Nur entschlüsseln liest verschlüsselte Werte entschlüsselt und schreibt keine Dokumente (MongoDB Community). Die Abfrageanalyse verwendet die Bibliothek crypt_shared (ihr Pfad, im Teammodus der des Servers) oder mongocryptd auf diesem Computer.
  • Verschlüsselte Felder stammen aus den Collection-Optionen des Servers – dem encryptedFields von Queryable Encryption, einem CSFLE-$jsonSchema-Validator –, sofern die Verbindung nicht eigene Zuordnungen angibt. Die Dokumentansicht kennzeichnet verschlüsselte Felder mit einem Schloss.
  • Der Abschnitt Verschlüsselung der Verbindung (für ihre Administratoren) listet die Datenschlüssel auf, erstellt neue und rotiert sie (durch erneutes Verpacken unter einem Hauptschlüssel) und erstellt Queryable-Encryption-Collections: jedes Feld mit seinem Typ und der Angabe, ob es per Gleichheit oder Bereich abgefragt werden kann, jeweils mit einem erzeugten Datenschlüssel.
  • Wem personenbezogene Daten verborgen sind, sieht verschlüsselte Werte so, wie sie gespeichert sind, und kann auf einer solchen Verbindung keine Dokumente schreiben. Kopien übertragen verschlüsselte Werte unverändert; eine Queryable-Encryption-Collection lässt sich nicht kopieren.

Start und nächste Schritte

Der Start ist ein Dashboard aus Widgets, die Sie mit Dashboard anpassen hinzufügen, entfernen, in der Größe ändern und verschieben; es wird für Sie auf dem Server gespeichert. Das Widget Nächste Schritte schlägt bis zu fünf Dinge vor, die die App selbst aus Ihrer letzten Arbeit ermittelt: ausgelöste Warnungen, Aufträge, die am letzten Tag fehlgeschlagen sind, Live-Synchronisierungen und geplante Backups, die Sie brauchen, ein Index für die zuletzt verwendete Datenbank (aus ihren langsamen Abfragen, sofern Sie ihren Server beobachten dürfen) und zuletzt geöffnete Orte, die jetzt nicht geöffnet sind. Jeder Vorschlag ist ein Link, der die Aktion ausführt – ein Index öffnet den gewohnten Dialog „Index erstellen“ mit ausgefülltem Schlüssel, und erst nach Ihrer dortigen Bestätigung wird etwas aufgebaut. Blenden Sie einen Vorschlag mit seinem ✕ aus (Rückgängig bringt ihn zurück); das Ausblenden wird mit Ihrem Dashboard gespeichert, und ein neues Ereignis derselben Art kommt als neuer Schritt wieder. Ausgeblendete Schritte wieder anzeigen im Menü des Widgets bringt alle zurück.

Ist ein KI-Anbieter eingerichtet, bietet das Menü des Widgets Mit KI ordnen an; die Funktion ist ausgeschaltet, bis Sie sie einschalten. Die KI ordnet die Schritte dann und formuliert ihre Titel, ausschließlich aus Fakten: Art des Schritts, Namen (Verbindung, Datenbank, Collection, Feldnamen eines Index) und Anzahlen – nie ein Wert, ein Dokument oder ein Fehlertext. Ein Schritt, dessen Verbindung die KI-Richtlinie „aus“ hat oder „nur lokal“ mit einem Anbieter, von dem nicht bekannt ist, dass er aus dem lokalen Netzwerk antwortet, wird nicht gesendet und behält seinen Platz. Die KI kann keinen Schritt hinzufügen und nicht ändern, was ein Schritt tut: Unter jedem von ihr vergebenen Titel sagt die App mit eigenen Worten, was der Schritt tut, und die Titel enthalten keine Zahlen (eine Anzahl würde veralten; die Zeile der App nennt sie). Die Schritte werden nur neu geordnet, wenn sie sich ändern (andere Art von Schritt, anderer Ort) oder wenn Sie Mit KI neu ordnen wählen – nie, weil sich eine Anzahl geändert hat oder Zeit vergangen ist. Jede Anordnung wird im KI-Verlauf gezählt (als „Nächste Schritte“, ohne ihre Wörter) und im Audit-Protokoll (wie viele Schritte, nie ihre Namen). Ein vorgeschlagener Index wird nur angeboten, wo Sie Indizes erstellen dürfen.

Abfragen

Öffnen Sie eine Collection und geben Sie einen Filter wie { status: 'A', qty: { $lt: 30 } } ein, dann drücken Sie Enter. Optionen ergänzt Projektion, Sortierung, Überspringen, Limit, Collation, Hint und ein Zeitlimit. Letzte Abfragen listet auf, was Sie in dieser Collection ausgeführt haben, und der Stern speichert die Abfrage mit Namen und Tags als Favorit.

Eine Collection öffnet sich mit den neuesten Dokumenten zuerst: Die Sortierung { _id: -1 } steht in Optionen und an der Spalte _id, wo Sie sie ändern oder entfernen; die Schaltfläche zum Zurücksetzen stellt sie wieder her. Eine View oder eine Zeitreihe behält ihre eigene Reihenfolge. Um Collections in ihrer gespeicherten Reihenfolge zu öffnen, schalten Sie „Collections mit den neuesten Dokumenten zuerst öffnen“ unter Präferenzen aus.

Ein Wert in der Leiste kann ein Parameter sein, geschrieben {{name}}: { status: {{status}}, qty: { $gte: {{min}} } }. Für jeden erscheint unter der Leiste ein Feld, und Suchen führt die Abfrage mit den dort angegebenen Werten aus: 18 ist eine Zahl, "18" eine Zeichenfolge, ISODate("2026-01-01") ein Datum und jeder andere Text eine Zeichenfolge, wie eingegeben. Ein aus der Leiste gespeicherter Favorit behält seine Parameter, wobei die angegebenen Werte ihre Standardwerte sind; beim Öffnen werden sie eingesetzt und die Abfrage wird ausgeführt, oder sie wartet auf einen Wert, wo ein Parameter keinen hat. In Anführungszeichen, in einem regulären Ausdruck oder in einem Kommentar ist {{name}} einfacher Text. Wer die personenbezogenen Daten einer Verbindung nicht sehen darf, erhält nie die Standardwerte eines anderen Benutzers.

Chips unter der Leiste schlagen Bedingungen vor: solche, die Sie zuletzt in der Collection ausgeführt haben, und solche, die eine kleine Stichprobe nahelegt (ein häufiger Wert wie status = "paid" oder ein Feld, das vielen Dokumenten fehlt); die Auswahl fügt sie dem Filter hinzu und führt ihn aus. Die Stichprobe wird gezogen, sobald die Seite im Leerlauf ist oder die Leiste verwendet wird, und nie bei einem View (sie würde die Pipeline des Views ausführen). Über den Ergebnissen ist jede Bedingung des verwendeten Filters ein eigener Chip: Das Entfernen (sein Kreuz oder Delete auf dem Chip) führt den Filter ohne sie aus, und Rückgängig bringt sie zurück. Der Text in der Leiste folgt nur, solange er der verwendete Filter ist; ein Filter, den Sie noch bearbeiten, bleibt unverändert. Das Panel unter der Leiste zeigt die verwendete Abfrage Teil für Teil; sein Ausführen führt sie erneut aus, und sein Stern speichert sie als Favorit.

Klicken Sie in der Tabelle auf den Namen einer Spalte, um danach zu sortieren: aufsteigend, dann absteigend, dann ohne Sortierung. Shift + Klick fügt die Spalte der Sortierung hinzu. Die Sortierung wird in Optionen geschrieben und läuft mit dem Filter in der Leiste, sodass die Leiste immer zeigt, was ausgeführt wird. Ziehen Sie den Rand einer Spalte (oder fokussieren Sie ihn und verwenden Sie die Pfeiltasten), um die Breite zu ändern, und doppelklicken Sie auf den Rand, damit sich die Spalte wieder selbst anpasst; die Breiten werden pro Collection für Sie in diesem Browser gespeichert. Das Menü einer Spalte sortiert sie, kopiert ihren Namen oder blendet sie aus. Eine Spalte, deren Werte vor Ihnen verborgen sind (personenbezogene Daten), wird nie sortiert.

Diagramm neben Tabelle, Karten und JSON zeichnet die Ergebnisse der Abfrage als Balken, Linie, Punkte oder Kreis: Wählen Sie das Feld für die X-Achse, die Anzahl, Summe oder den Durchschnitt eines Zahlenfelds und ein Feld, das die Ergebnisse in Reihen aufteilt. Es liest bis zu die ersten 1.000 passenden Dokumente (nur die gezeichneten Felder) und sagt, wenn es mehr gibt; für Screenreader steht eine Tabelle mit denselben Zahlen bereit. Vor Ihnen verborgene Felder werden nicht angeboten und nie dargestellt. Namen kopieren in den Menüs von Datenbanken, Collections und Spalten sowie neben einem Feld in Schema kopiert den reinen Namen.

Beim Bearbeiten eines Dokuments wird genau angezeigt, welche Felder sich ändern, bevor etwas geschrieben wird; nur diese Felder werden gespeichert. Doppelklicken Sie in der Tabelle auf einen Wert (oder drücken Sie darauf Enter), um ihn direkt zu bearbeiten; er behält seinen Typ.

Mehrere Dokumente aktualisieren und Mehrere Dokumente löschen zeigen vor der Ausführung eine Vorschau: wie viele Dokumente passen, und einige davon. Bei einer Aktualisierung zeigt jede Stichprobe, was sich darin ändert, von MongoDB in einem Lesevorgang berechnet, der nichts schreibt; ein Dokument, bei dem die Aktualisierung fehlschlagen würde (ein $inc auf Text, ein Pfad durch ein Array), wird markiert. Positionspfade ($[]), Array-Indizes und $pull mit einer Bedingung werden in Stichproben nicht in der Vorschau gezeigt, und die Vorschau weist darauf hin. Personenbezogene Werte bleiben in den Stichproben maskiert, davor und danach.

Collections

Neue Collection kann für eine Collection, eine Capped oder Time-Series-Collection oder einen View eine Standard-Collation festlegen (eine Sprache, ihre Stärke, numerische Sortierung und die übrigen MongoDB-Optionen); MongoDB legt sie bei der Erstellung fest. Eine Collection oder Capped Collection kann außerdem von Anfang an Pre- und Post-Images von Change Streams aufbewahren. Später schaltet das Menü der Collection Collection bearbeiten… diese Images ein oder aus (nach einer Bestätigung, die sie nennt), zeigt ihre Collation und führt zum Tab Validierung, wo die Regeln bleiben. Die Kopfzeile der Collection nennt ihre Collation und ob Images aufbewahrt werden.

Leistung

Der Tab Leistung einer Verbindung stellt den Server live dar: Operationen pro Sekunde, Verbindungen, Netzwerk und Arbeitsspeicher, alle 2 Sekunden abgetastet, solange der Tab geöffnet ist. Darunter stehen die langsamsten laufenden Operationen, die Sie nach Datenbank oder Collection, Art, Laufzeit, Warten auf eine Sperre und Leerlaufverbindungen filtern und anhalten können, sowie die Collections mit der meisten Zeit. Bearbeiter und Administratoren können ihn öffnen; das Menü „…“ einer Operation zeigt ihren Befehl und für Verbindungsadministratoren Operation beenden, was zuvor nachfragt. MongoDB selbst muss dem Konto das Lesen des Serverstatus erlauben: Geben Sie ihm die Rolle clusterMonitor, sonst sagt der Tab, was fehlt.

Der Abschnitt Profiler zeigt für jede Datenbank Profiler-Level, slowms und Abtastrate; ein Verbindungsadministrator kann sie mit dem Stift in der Zeile der Datenbank ändern. Level 2 (jede Operation) fragt zuvor nach und kehrt nach 30 Minuten von selbst zur vorherigen Einstellung zurück. Langsame Abfragen listet langsame Operationen aus dem Profiler und aus dem eigenen Protokoll des Servers (das auch bei ausgeschaltetem Profiler funktioniert) auf, neueste zuerst, mit Plan, den geprüften Schlüsseln und Dokumenten und dem Befehl; eine Operation, die weit mehr Dokumente liest, als sie zurückgibt, wird markiert, und In Explain öffnen öffnet sie in ihrer Collection.

Im Tab Personenbezogene Daten der Verbindung kann ein Verbindungsadministrator die Felder auflisten, die personenbezogene Daten enthalten (zum Beispiel crm.users.email oder *.*.**.phone); der eigene Tab Personenbezogene Daten einer Collection listet und ergänzt nur die Felder dieser Collection, wobei für ein neues nur der Feldname verlangt wird, und zeigt die weiter gefassten Regeln der Verbindung, die sie erreichen. Ein Benutzer mit der Berechtigung Kann personenbezogene Daten nicht sehen sieht deren Werte als *** im Profiler, in langsamen Abfragen und in Operationen und kann die Shell nicht verwenden. Im Lokalen Modus (ohne Konten) verbergen die Regeln die Werte auch vor Ihnen, überall – Dokumente, Exporte, Kontext der KI – und die Shell bleibt geschlossen, solange sie verborgen sind; Auch vor mir verbergen im Tab der Verbindung schaltet das für die Verbindung ab.

Index-Vorschläge liest die langsamen Abfragen einer Datenbank und schlägt für jede Abfrage mit Scan nach der Regel Gleichheit–Sortierung–Bereich einen Index vor, sofern nicht bereits ein Index sie bedient; außerdem listet es Indizes auf, die seit dem Serverstart nicht verwendet wurden oder den Anfang eines anderen Index bilden. Es werden nur Feldnamen verwendet. Index erstellen öffnet den gewohnten Dialog mit ausgefülltem Schlüssel: Erst nach Ihrer dortigen Bestätigung wird etwas aufgebaut.

Wählen Sie in der Kopfzeile der Verbindung, solange Leistung geöffnet ist, Live (die letzten 5 Minuten) oder einen gespeicherten Zeitraum von 1 Stunde, 24 Stunden oder 7 Tagen. Ein Verbindungsadministrator schaltet Metrikverlauf aufzeichnen im Menü Metrikverlauf daneben ein (dasselbe Menü löscht nach Rückfrage das Gespeicherte): Der Server tastet diese Verbindung dann einmal pro Minute ab und bewahrt 7 Tage auf (nur Zahlen). Solange die Funktion aus ist, verbindet sich der Server nie von selbst mit dieser Verbindung. Auf einem mongos zeigt der Tab die Sharding-Übersicht: Shards, den Balancer, die Router sowie Schlüssel und Chunk-Verteilung jeder Sharded Collection, mit Größen und Jumbo-Chunks auf Anforderung. Nichts davon verändert den Cluster.

Bei einem Replica Set listet derselbe Tab jedes Mitglied auf: welches der Primärknoten ist, welche ausgefallen sind, wie viele Sekunden jeder Sekundärknoten hinter dem Primärknoten liegt (bernsteinfarben über 10 s, rot über 60 s), den Rückstand des Majority Commit und das Oplog-Fenster, mit einem Diagramm des Rückstands über die letzten Minuten. Ein Set ohne Primärknoten wird rot dargestellt: Es kann keine Schreibvorgänge annehmen, bis einer gewählt ist.

Aggregationen

Der Tab Aggregationen einer Collection baut eine Pipeline Stage für Stage auf. Fügen Sie eine Stage hinzu, wählen Sie ihren Operator (geben Sie im Feld des Operators etwas ein, um eine Stage über ihren Namen oder ihre Wirkung zu finden – „join“ findet $lookup – mit Pfeiltasten und Enter; neben der Liste stehen, was die Stage tut, und ein Beispiel für ihren Wert; jede beginnt mit einer Vorlage, mit Link zum MongoDB-Handbuch) und bearbeiten Sie ihren Wert; die Ausgabe jeder Stage wird während der Eingabe an einer Stichprobe der Collection (die ersten 1000 Dokumente oder eine zufällige Stichprobe) in der Vorschau gezeigt. Stages lassen sich deaktivieren, per Drag-and-drop oder mit Alt+Auf und Alt+Ab umsortieren oder alle auf einmal als Text bearbeiten.

Ausführen streamt das gesamte Ergebnis (bis zu 10 000 Dokumente) mit einer Schaltfläche Stoppen; Gesamtzahl berechnen zählt es nur auf Anforderung. Eine Pipeline, die mit $out oder $merge endet, wird nie in der Vorschau gezeigt: Sie läuft einmal, nach einer Bestätigung, die das Ziel nennt, und das Ersetzen einer Collection verlangt deren Namen. Pipelines lassen sich mit der Collection speichern (im Teammodus optional geteilt), als Programm für Node.js, Python, Java, Go, C#, PHP, Ruby oder Rust exportieren (die Verbindungszeichenfolge wird aus MONGODB_URI gelesen, nie in den Code geschrieben) oder in einen View umwandeln.

Die Pipeline eines Views wird auf dieselbe Weise geändert: Pipeline bearbeiten am View (in seiner Übersicht oder seinem Menü) öffnet sie im Tab Aggregationen der Collection, die er liest, als die des Views gekennzeichnet, mit einer Vorschau jeder Stage. View aktualisieren schreibt die aktivierten Stages in den View zurück, nach einer Bestätigung, die ihn nennt. Eine Pipeline mit einer Stage, die der Builder nicht lesen kann, wird nicht geöffnet (beim Speichern ginge diese Stage verloren); ein Benutzer, vor dem personenbezogene Daten verborgen sind, kann einen View nicht ändern, dessen Definition er maskiert sieht.

Abfragen

Die Seite Abfragen (Abfragen in der Seitenleiste, die Befehlspalette oder Ctrl / ⌘ + Shift + L; ihre Adresse ist /library) durchsucht die Favoriten, gespeicherten Pipelines, Shell-Snippets und den Abfrageverlauf einer Verbindung nach Name, Tag, Abfragetext, Art oder Collection. Sie öffnet sich bei der Verbindung, an der Sie gearbeitet haben, sonst bei der ersten, und behält Ihre Suche, wenn Sie zu ihr zurückkehren. Das Öffnen eines Eintrags führt zu seiner Collection: Ein Find läuft in Dokumente, eine Pipeline füllt die Aggregationskarten (nach Rückfrage, wenn der Tab schon welche hat). Der Verlauf bewahrt die ausgeführten Finds und Aggregationen auf, die letzten 200 pro Collection und 2000 insgesamt, jede einmal mit der Anzahl ihrer Verwendungen; Einträge lassen sich einzeln entfernen oder leeren. Favoriten und gespeicherte Pipelines lassen sich auf der Seite Abfragen umbenennen, neu mit Tags versehen, teilen und löschen sowie anheften: Angeheftete Abfragen gehören Ihnen allein (bis zu 50 pro Verbindung) und stehen zuerst auf der Seite Abfragen und im Widget Abfragen auf dem Start. Die Befehlspalette listet die Favoriten, gespeicherten Pipelines und Shell-Snippets jeder in einem Tab geöffneten Verbindung auf, jede unter ihrem eigenen Namen, die, an der Sie arbeiten, zuerst. Beim Start des Teammodus wird der Verlauf des Lokalen Modus gelöscht (kein Teambenutzer könnte ihn sehen oder leeren); das Protokoll nennt, wie viele Einträge entfielen. Favoriten und gespeicherte Pipelines des Lokalen Modus bleiben für Verbindungsadministratoren erhalten.

Erweiterte Shell

Der Shell-Tab einer Verbindung führt eine echte mongosh aus, und ihr Terminal ist der Ort, an dem Code eingegeben wird: eine Datenbank wählen, Finds und Aggregationen ausführen, Skripte schreiben. Enter führt den Code aus, sobald er vollständig ist; solange eine Klammer, eine Zeichenfolge oder eine Anweisung offen ist (nach ., einem Operator, if (…)), geht er in der nächsten Zeile nach ... weiter, und Shift+Enter fügt immer eine Zeile hinzu. Strg+Enter führt den Code so aus, wie er ist. Mehrzeiliger Code lässt sich ins Terminal einfügen: Er wird Zeile für Zeile angezeigt und läuft erst, wenn Sie Enter drücken. Ein Skript läuft so, wie mongosh Eingegebenes ausführt – use, show und it jeweils für sich, dann jede Anweisung der Reihe nach; ein Fehler stoppt es an dieser Stelle und nennt, wie viele Anweisungen nicht liefen. print() und printjson() schreiben ins Terminal; cls leert es und die Ergebnisse, und exit beendet die Shell.

Auf und Ab wechseln zwischen den Zeilen des Eingegebenen, dann durch den Verlauf; Strg+R durchsucht den Verlauf (erneut Strg+R für ältere Treffer, Escape zum Verlassen). Strg+C stoppt einen laufenden Befehl oder leert die Zeile – oder kopiert, wenn Ausgabe markiert ist. Alt+B und Alt+F (oder Strg+Links und Strg+Rechts) bewegen wortweise. Der Verlauf jedes Benutzers wird pro Verbindung verschlüsselt aufbewahrt und lässt sich leeren.

Die Shell steht Verbindungsadministratoren zur Verfügung und einem Bearbeiter, dem ein Administrator sie gewährt. Sie läuft in einer Sandbox, die keine Zugangsdaten enthält und nur die eigenen Server der Verbindung erreichen kann; auf einer schreibgeschützten Verbindung lehnt sie Schreibvorgänge ab, und ein Nicht-Administrator kann keine Cluster- oder Benutzerverwaltung ausführen.

Die Shell-Seite nennt, wo sie läuft – die Verbindung und die Datenbank, auf der die Shell steht (sie folgt use) – und ihren Zustand: verbindet, verbunden, läuft (mit der bisherigen Laufzeit) oder geschlossen. Ihre Kopfzeile enthält Stoppen, solange ein Befehl läuft, Leeren des Bildschirms und der Ergebnisse (Strg+L, auch während ein Befehl läuft, oder cls; ein Hinweis meldet es, und sein Rückgängig oder Ergebnisse wiederherstellen auf der leeren Karte Ergebnisse bringt sie zurück) sowie ein Menü, um das Eingegebene (oder den zuletzt ausgeführten Code) als Snippet zu speichern, den Verlauf zu leeren (die Ergebnisse gehen damit) oder die Shell neu zu starten (die Sitzung endet und eine neue beginnt; Variablen und die angezeigten Ergebnisse gehen verloren). Das Terminal übernimmt das helle oder dunkle Design der App oder ein eigenes und färbt den Code ein. Eine Leiste unten listet die Tasten auf. Eine Shell bleibt geöffnet, solange ihre Seite geöffnet ist, wie lange sie auch nicht verwendet wird. Wenn sie sich schließt (Ihre Anmeldung endete, oder sie überschritt ein vom Server festgelegtes Leerlauf- oder Lebensdauerlimit), nennt die Seite den Grund; Enter öffnet eine neue; ein Befehl, der beim Abbruch der Verbindung noch lief, wird nach der Wiederverbindung auf dem Bildschirm zu Ende geführt.

Beim Tippen bietet Tab Vervollständigungen an – die Collections der Datenbank nach db. (auch eine in der Shell erstellte), die Methoden dessen, was eine Kette zurückgibt, Operatoren nach $ und aus der Collection per Stichprobe ermittelte Feldnamen. Shift+Tab oder Escape und dann Tab verlässt das Terminal.

Neben dem Terminal zeigt die Karte Ergebnisse das letzte Ergebnis als Tabelle, Baum oder Text; Mehr holt den nächsten Stapel eines Cursors, und der Ergebnisverlauf in ihrer Kopfzeile wählt ein früheres Ergebnis, jeweils nach dem Befehl benannt, aus dem es stammt (nur im Arbeitsspeicher aufbewahrt); Leeren leert die Karte; das Rückgängig des Hinweises oder Ergebnisse wiederherstellen auf der leeren Karte bringt die Ergebnisse zurück, bis die Shell neu startet oder ihr Verlauf geleert wird. Die Karte lässt sich verbreitern; auf einem schmalen Bildschirm sind Terminal und Ergebnisse zwei Tabs. Mehrere Shell-Tabs können gleichzeitig geöffnet sein, jeder mit eigener Sitzung. Ein Cursor eines einfachen Find oder einer Aggregation öffnet sich in der Ansicht seiner Collection – ein Find beginnend bei seinem Überspringen, sein Limit als Seitengröße –, und die angezeigten Dokumente lassen sich als JSON oder CSV exportieren.

Code lässt sich als Snippet speichern – privat oder mit dem Team geteilt – mit Parametern, geschrieben {{name}}. Das Öffnen eines Snippets (von der Seite Abfragen oder der Befehlspalette) fragt nach seinen Parametern und setzt den ausgefüllten Code ins Terminal; nichts läuft, bis Sie Enter drücken. Ihre eigenen Snippets bearbeiten Sie auf der Seite Abfragen: Name, Tags, Code und Parameter (eine Zeile folgt jedem {{name}} während der Eingabe), geprüft wie ein neues Snippet; ein geteiltes Snippet bleibt geteilt, und das Audit-Protokoll vermerkt, dass sich sein Code geändert hat, nie den Code.

Das Terminal funktioniert mit einem Screenreader: Sein Screenreader-Modus ist standardmäßig an, und Konto → Präferenzen schaltet ihn aus oder wieder ein, auch in geöffneten Shells.

Explain

„Warum ist es langsam?“ in Dokumente oder Aggregationen öffnet den Abschnitt Explain für diese Abfrage oder Pipeline. Er zeigt den von MongoDB gewählten Plan als Baum (Pfeiltasten bewegen sich darin), was jede Stage gelesen und zurückgegeben hat, die verworfenen Pläne und Warnungen in Worten: einen Scan der gesamten Collection, eine Sortierung im Arbeitsspeicher, einen Filter, der weit mehr liest, als er zurückgibt, einen Join über ein Feld ohne Index. Wenn ein Index helfen würde, schlägt Explain einen vor (Gleichheitsfelder, dann die Sortierung, dann Bereiche), und „Diesen Index erstellen“ baut ihn im Hintergrund. Eine Pipeline, die schreibt, wird nicht erklärt, weil das Erklären sie ausführt.

Validierung

Der Abschnitt Validierung bearbeitet die Regeln, denen jedes eingefügte oder aktualisierte Dokument genügen muss, mit Validierungslevel und -aktion. „Aus Stichprobe generieren“ schreibt ein $jsonSchema aus den Dokumenten der Collection; „An vorhandenen Dokumenten testen“ zählt vor dem Speichern, wie viele fehlschlagen würden, mit Beispielen. Das Speichern fragt zuvor nach und sagt, wenn Dokumente, die die Regeln verletzen, bei Aktualisierungen abgelehnt würden; „Vorherige Regeln wiederherstellen“ stellt wieder her, was das letzte Speichern ersetzt hat, solange der Tab geöffnet ist. Ein von den Regeln abgelehnter Schreibvorgang nennt, welche er nicht erfüllt hat (ein fehlendes Feld, ein falscher Typ, ein Minimum), ebenso der Bericht eines Imports oder einer Kopie; der fehlgeschlagene Wert wird nie wiederholt.

Schema

Der Tab Schema einer Collection analysiert eine zufällige Stichprobe (100, 1.000 oder 10.000 Dokumente): jedes Feld mit der Häufigkeit seines Vorkommens, seinen Typen und einem Histogramm oder seinen häufigsten Werten. Exportieren wandelt die Analyse in ein Mongoose-Schema, einen MongoDB-JSON-Schema-Validator oder ein TypeScript-Interface um, zum Kopieren oder Herunterladen. Ein Feld gilt als erforderlich, wenn jedes Dokument der Stichprobe es hat.

Die Balken eines Felds – seine Bereiche und häufigsten Werte – und seine Typen sind Schaltflächen: Die Auswahl fügt diese Bedingung dem Dokumente-Filter der Collection hinzu (neben bereits eingegebenen Bedingungen oder mit $and, wenn das Feld schon eine hat), führt ihn aus und zeigt die Dokumente. Ein in der Analyse gekürzter Wert wird angezeigt, aber nicht angeboten. Ein Feld mit Orten – GeoJSON-Punkten oder Koordinatenpaaren unter einem Namen wie location oder coords – zeigt sie auf einer Karte, die ohne jedes Netzwerk gezeichnet wird (die Weltumrisse von Natural Earth, gemeinfrei): Ziehen oder Pfeiltasten verschieben sie; Ctrl und Mausrad, zwei Finger oder + und − zoomen; die Orte sind auch als Tabelle aufgelistet; und Auf diesen Bereich filtern fügt ein $geoWithin des sichtbaren Bereichs hinzu. Felder mit personenbezogenen Daten werden nie gezeichnet.

Datenmodell

Der Abschnitt Modell einer Datenbank zeichnet ihre Collections und die Referenzen zwischen ihnen. Modell lesen zieht aus jeder Collection eine Stichprobe (100 bis 1.000 Dokumente, höchstens 50 Collections) für ihre Felder – die oberste Ebene und eine darunter, tiefere nur, wenn sie wie Referenzen aussehen – und findet Referenzen auf drei Wegen: ein nach einer Collection benanntes Feld (userId oder user_id → users, tagIds → tags), per Stichprobe gefundene ObjectId-Werte als _id einer anderen Collection (höchstens zehn Werte pro Feld, insgesamt sechzig kleine Zählungen) sowie die Stages $lookup und $graphLookup von Views und von den gespeicherten Pipelines, die Sie öffnen dürfen. Eine durchgezogene Linie wurde über Namen oder Werte gefunden, eine gestrichelte nur über $lookup, eine gepunktete verbindet einen View mit seiner Quelle. Eine Linie endet in einem Krähenfuß („viele“) an dem Feld, das die Referenz hält – viele Dokumente können dieselbe ID halten – und in einem Strich („eins“) an der Collection, auf die sie verweist, dort ebenfalls in einem Krähenfuß bei einem Array von Referenzen. Ein Feld wird mit PK (der Schlüssel, _id), UQ (ein eindeutiger Index allein darauf) oder IX (in einem Index) markiert; Indizes werden nur anhand der Namen ihrer Schlüssel gelesen.

Ziehen Sie das Diagramm oder verwenden Sie die Pfeiltasten, um es zu bewegen, + und − zum Zoomen, 0 zum Einpassen. Das Mausrad scrollt die Seite, bis das Diagramm den Fokus hat (klicken Sie darauf oder wechseln Sie per Tab hinein); dann bewegt das Mausrad es, und Ctrl / ⌘ und Mausrad zoomen (Shift und Mausrad bewegen es jederzeit). Klicken Sie auf eine Collection oder wechseln Sie per Tab zu ihr und drücken Sie Enter, um ihre Verknüpfungen zu sehen und sie zu öffnen. Die Ansicht Liste zeigt dasselbe Modell als Liste: Jede Collection öffnet ihre Felder und Verknüpfungen, und eine Verknüpfung führt zur Collection, auf die sie zeigt. Exportieren speichert das Diagramm als PNG oder SVG (in den Farben des verwendeten Designs und Ihrer Sprache), das Modell als JSON und das Modell als erDiagram von Mermaid (als .mmd gespeichert oder kopiert) für eine README, ein Wiki oder einen Pull Request, der es zeichnet, wobei ein eindeutiges Feld UK geschrieben wird, wie Mermaid es nennt. Es werden nur Namen, Typen und Anzahlen gezeigt; kein Wert verlässt den Server. Wer Dokumente lesen darf, darf das Modell lesen; vor Ihnen als personenbezogene Daten verborgene Felder werden nur mit Namen gezeigt, und ihre Werte werden nie gelesen. Ein MongoDB-Benutzer, dem nur einige Collections erlaubt sind, sieht diese.

Das Lesen eines Modells kostet den Server eine Stichprobe pro Collection: bis zu 50 Collections mal Stichprobengröße, plus höchstens sechzig kleine Zählungen. Der Server begrenzt die Dokumente, die ein Modell insgesamt liest (MM_MODEL_MAX_DOCS, standardmäßig 20.000): Bei vielen Collections wird jede Stichprobe kleiner, und der Abschnitt sagt es. Lesen Sie es auf einer ausgelasteten Produktionsdatenbank, wenn der Server ruhig ist, oder mit einer kleineren Stichprobe.

Suchindizes

Auf MongoDB Atlas oder MongoDB 8.0 und neuer mit dem Suchprozess (mongot) listet der Tab Indizes zusätzlich die Atlas-Search- und Vector-Search-Indizes einer Collection auf: jeweils mit Art, Status (ausstehend, wird aufgebaut, bereit, fehlgeschlagen mit Grund) und dem, was er abdeckt, alle paar Sekunden erneut geprüft, solange einer aufgebaut wird. Suchindex erstellen nimmt die Definition als JSON entgegen, bei einem Vektorindex ein geführtes Formular: das Feld mit den Embeddings, ihre Dimensionen und Ähnlichkeit sowie die Felder zum Filtern. Eine Definition lässt sich bearbeiten und ein Index verwerfen, nach einer Bestätigung, die ihn nennt. Anderswo sagt der Tab, was die Suche benötigt.

Hintergrundaufträge

Das Erstellen eines Index und das Duplizieren einer Collection laufen im Hintergrund, sodass ein langer Vorgang nie in ein Timeout läuft. Sie können die Seite verlassen oder den Tab schließen, während sie laufen. Die Schaltfläche Hintergrundaufträge in der oberen Leiste zeigt jeden Auftrag: mit Balken und Zahlen, wenn MongoDB den Fortschritt meldet (Index-Builds), oder mit Läuft noch und der bisherigen Zeit, wenn nicht (Kopien). Sie werden benachrichtigt, wenn Ihre eigenen Aufträge enden, und können sie dort abbrechen.

Startet der Server während einer Kopie neu, wird die Kopie abgebrochen und ihre halb fertige Collection entfernt; das Ziel bleibt nie halb gefüllt zurück. Ein Index-Build kann in MongoDB weiterlaufen; der Tab Indizes zeigt ihn.
