监视变更

“监视”部分会实时显示 MongoDB 对数据所做的变更：每一次插入、更新、替换和删除，并可按需显示新建索引等模式变更。该功能基于 MongoDB 的变更流。不会存储任何内容：数据流在打开时开始，只显示此后发生的变更。

入口位置

  • 集合标签页 → 监视：该集合的变更。
  • 数据库标签页 → 监视：该数据库中所有集合的变更。
  • 连接标签页 → 监视：该连接下所有数据库的变更。
  • 命令面板（Ctrl+K）：“Watch changes…”会打开当前标签页的“监视”部分。

变更流需要副本集、分片集群或负载均衡部署（MongoDB Atlas 始终属于其中之一）。独立服务器无法监视，该部分会给出说明。开发时使用单节点副本集即可：启动 mongod --replSet rs0，并运行一次 rs.initiate()。视图无法监视：视图的“监视”部分会提供该视图所读取的集合。尚不存在的集合可以监视，创建后其变更便会出现。

谁可以监视

凡有权读取该连接中文档的用户，均可在所有范围内监视。连接所用的数据库用户需要对被监视对象拥有 changeStream 和 find 权限（内置的 read 角色同时具备二者）。 system.users 等凭据集合仅向该连接的管理员显示。

数据流

数据流上方的状态栏显示其状态：实时、已暂停、落后（落后超过两秒，并显示落后多少）、重新连接中或已结束，以及已收到的变更数量和速率。最新的变更位于顶部。每一行显示变更的类型（以文字和颜色表示）、数据库和连接数据流中的集合、文档的 _id、更新所涉及的字段名，以及变更发生的时间（悬停时显示精确时间）。向下滚动时，新变更会收在“新事件”按钮之后，不会打乱正在阅读的内容。系统保留最近 2,000 条变更，更早的会从列表中移出。

选择一条变更，即可在右侧查看：已更改的字段、插入和替换时的完整文档，或以 JSON 表示的事件。“打开文档”会打开该集合的“文档”部分，并按该文档的 _id 筛选。“复制为 EJSON”会以 Extended JSON 复制该变更。

暂停、继续和重新连接

暂停会停止列表更新，且不会丢失位置：MongoDB 在服务器端保留这些变更。继续时，选择“追赶”可查看暂停期间发生的变更，选择“从现在开始”则跳过这些变更。数据流工具栏上的空格键可暂停和继续。已暂停的数据流在切换部分或标签页时保持暂停，直到关闭其标签页；正在运行的数据流在离开其部分几秒后停止。

与应用的连接断开时，数据流会自动重新连接。两分钟内，数据流会从浏览器收到的最后一条变更之后继续，不会遗漏也不会重复，并会提示这一点；已暂停的数据流恢复后仍处于暂停状态。如果无法再从该位置继续（例如在一次非常大的突发之后），则会从服务器所在位置继续，并提示可能缺少部分变更；超过两分钟后，则从当前时刻重新开始，并提示这一点。数据流继续时所用的位置（MongoDB 的恢复令牌）保留在服务器上。

筛选

各个标签用于选择变更的类型：插入、更新、替换和删除。“包含模式更改”会加入创建或删除集合和索引以及选项更改等变更。“更新后显示完整文档”会在每次更新后读取文档，每次更新需额外读取一次。

“编辑筛选”接受针对每个变更事件的 $match，写法与查询相同，例如：

  • { 'updateDescription.updatedFields.status': 'paid' }：将 status 设为 paid 的更新。
  • { 'fullDocument.total': { $gt: 1000 } }：大额订单的插入和替换。
  • { 'documentKey._id': ObjectId('…') }：单个文档。
  • { 'ns.coll': 'orders' }：在数据库或连接数据流中指定某一个集合。

筛选最大 12 KB，最多嵌套 20 层。在服务器上运行 JavaScript 的操作符（$where、$function、$accumulator）一律不予接受。更改任何筛选都会使数据流从现在重新开始，数据流会提示这一点。

查看变更前的值

MongoDB 会报告更新更改了哪些字段及其新值。若还要查看变更前的值，请为该集合开启前镜像；之后数据流会在更新时显示完整的变更前后对比，在删除时显示删除前的文档。在集合的“监视”页面上，有权更改集合选项（例如验证规则）的用户在前后镜像关闭时会看到 开启前后镜像；页面会说明其开销，然后运行同一条命令（会记入审计）。也可以在 Shell 中执行： 

db.runCommand({ collMod: 'orders', changeStreamPreAndPostImages: { enabled: true } })

前镜像会按服务器变更流设置所规定的时长保存在服务器的存储中，因此在繁忙的集合上会占用磁盘空间。没有前镜像时，数据流显示更新后的值、被移除的字段名，以及数组被缩短的方式。

录制、回放和告警

录制到文件（位于筛选中，供有权从该连接导出的用户使用）会在服务器上保存数据流的事件，内容与发送给您的完全一致（已脱敏的部分保持脱敏），每行一个事件。录制文件属于用户自己的传输文件：占用个人的传输空间，最大 64 MB（达到后录制停止而数据流继续，“监视”页面会提示），并在数据流结束后按传输文件的保留时间保存。重新连接后继续录制会开始新文件。服务器重启会结束录制：已写入磁盘的内容会保留，作为已完成的录制。文件是否脱敏，以其事件发送时的状态为准：如果在数据流期间脱敏设置发生变化（个人值现在对该用户隐藏或不再隐藏，或规则已更改），文件会在此处结束，并以新的标记开始新文件，录制列表中会同时显示两者。工具栏上的 录制会列出该连接下属于用户自己的录制：回放会取代实时数据流显示其中一个（列表和详情相同）——先显示前 500 个事件，之后每次选择加载更多事件再显示 500 个，最多 5,000 个（其余内容在文件中）；下载可获取文件（NDJSON）；录制也可以删除。其他任何人（包括管理员）都无法读取。如果该连接上的个人值现在已对用户隐藏（录制时未脱敏），或其规则已更改（录制时已脱敏），则不再提供该录制。

匹配时触发告警会通知应用的告警（watch.matched 事件）：有事件通过了数据流的筛选，最多每 10 秒一次，内容包括匹配数量和最后一个事件的类型，绝不包含任何值。该功能在数据流运行期间有效。

个人数据

对于无权查看个人数据的用户，每条变更中的个人字段均显示为 ***：文档、其键、变更前的值和更新后的值，均按字段路径处理，包括数组位置。针对隐藏字段的筛选会被拒绝，并且在数据库和连接数据流中，此类用户只能按变更类型、命名空间和时间进行筛选。数据流的导出包含当时显示的内容，隐藏的值同样显示为 ***。

限制和设置

  • 每个浏览器窗口 3 个实时数据流，每个用户 5 个，服务器上共 50 个（MM_WATCH_MAX_FEEDS）。
  • 大于 256 KB 的文档不会在数据流中发送；“打开文档”可显示该文档。
  • 每个数据流每秒最多有 200 条变更到达浏览器；超过时，数据流会显示落后多少并随后赶上。
  • MM_WATCH=0 会在服务器上关闭监视功能。
  • 数据流的启动和停止会记入审计日志，包含筛选的指纹，但绝不包含其值。

数据流结束的情形

  • 集合被删除或重命名：数据流结束；“从现在重新开始”会重新监视同名集合。
  • 服务器的历史记录（oplog）已不再覆盖数据流所处的位置，例如离开很长时间之后：请从现在重新开始。
  • 访问权限、连接或其设置发生了变化：数据流结束并说明原因。
