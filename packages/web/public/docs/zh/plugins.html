构建插件

插件可以为 Mongo Manager 添加视图、操作或页面，例如集合中地点的地图、图表、重复项查找器、SQL 转换器。本指南面向插件开发者，涵盖插件由哪些文件组成、插件可以向应用请求哪些内容、应用强制执行的规则，以及如何打包、测试和发布插件。管理员在 插件页面安装并批准插件；批准模型请参阅安全。该页面列出全部插件，并可按状态筛选：已启用的、需要管理员处理的（等待批准、已更改或已损坏）、已停用的；也可按来源筛选，或通过搜索按名称、描述、ID、版本、所请求的权限或所添加的内容查找。

什么是插件

插件是一个由静态文件组成的文件夹：一个 HTML 页面及其脚本、样式、图片和字体，外加一个名为 mongo-manager-plugin.json 的清单，用于说明插件添加了什么、允许做什么。应用在沙箱框架中显示该页面，页面只通过消息与应用通信：页面请求文档，应用以当前登录用户的身份作答，沿用该用户的权限和应用的脱敏规则。

  • 没有服务器代码。插件的任何部分都不会在服务器上运行。服务器只负责存储插件文件、检查文件，并将其提供给框架。
  • 没有网络。页面无法从任何地址获取数据，包括其来源服务器。页面没有 Cookie、没有存储，也无法访问应用的页面。浏览器仍留有两条出路：只有强制执行策略中 webrtc 指令的浏览器才会阻止 WebRTC，而基于 Chromium 的浏览器（Chrome、Edge）自 149 版起会忽略该指令，Firefox 也不可依赖，因此在这些浏览器上，插件仍可通过 WebRTC 发送其读取到的内容；此外，预取提示（dns-prefetch、preconnect）可以触发域名解析。框架会要求浏览器不要预取，扫描也会将这两者标记为高风险，但扫描只是在文件文本中查找已知模式：为绕过扫描而编写的代码无法被发现。请只批准信任的插件。
  • 未经批准不运行。只有管理员批准了插件的确切文件及其所请求的权限后，插件才会运行。文件的任何更改都需要重新批准。
  • 更改需经用户确认。可以更改文档的插件需要提出请求；应用在自己的对话框中显示更改内容，由用户决定。插件准备的查询或管道会放入用户自己的编辑器，在用户运行之前不会执行任何操作。

Mongo Manager 自带多个插件（地图、图表、模式健康度、重复项查找器、值搜索、引用、文档差异、SQL 转 MongoDB、时间提示、二进制预览、数据字典、本地时间、日志分析器、测试数据、重塑、匿名化、搜索试验场、分片键分析器、存储报告、验证检查、旧版 UUID、日期筛选、索引脚本、过期（TTL）、个人数据查找器、文档大小）。它们运行在同一个沙箱中，通过同一个桥接通信，并以同样的方式扫描；由于是应用自带的代码，批准它们时从不要求输入其 ID（参阅版本与批准）。可以通过 MM_PLUGINS=0 为整个服务器关闭插件功能（参阅部署）。

快速开始

从入门模板开始：在插件页面的构建自己的插件下，选择下载入门模板（.zip）（它也是 Mongo Manager 源代码中的 packages/plugins/starter 文件夹）。它是一个完整的纯 JavaScript 插件，无需构建步骤，也没有依赖项：包含一个集合标签页和一个侧边栏页面，用于列出集合中的文档。

  1. 将其解压，或复制该文件夹，放入自己的新仓库。
  2. 在 mongo-manager-plugin.json 中修改 id、name、 author 和 repository。ID 必须唯一：它决定插件在每台服务器上的文件夹名称。
  3. 在 main.js 和 style.css 中编写页面。
  4. 在自己的服务器上试用： node scripts/pack.mjs --folder ~/.mongo-manager/plugins，然后点击 插件 → 重新扫描，查看扫描结果并批准。参阅在自己的服务器上测试。
  5. 用 node scripts/pack.mjs 打包，它会生成 <id>-<version>.tgz，将该文件附加到 GitHub 发布版本。参阅在 GitHub 上发布。

入门模板还包含面向 AI 编码助手的说明文件（CLAUDE.md、 AGENTS.md、GEMINI.md 和 .github/copilot-instructions.md）；参阅借助 AI 助手构建。

文件与文件夹结构

hello-documents/
  mongo-manager-plugin.json   the manifest (required, at the top)
  index.html                  the entry page every contribution opens
  main.js                     the page's script (an ES module)
  style.css                   the page's styles
  README.md                   shown to administrators on the plugin's details page
  README.tr.md, README.zh.md  the same in another language of the app (optional)
  scripts/pack.mjs            packaging (not part of the plugin: left out of the archive)
  CLAUDE.md, AGENTS.md, ...   AI assistant files (left out of the archive)

应用对插件所含文件的规则如下：

  • 文件总数最多 500 个，总大小最多 25 MB；清单最大 64 KB。
  • 每个路径都必须是相对的普通路径：每一段以字母、数字、_ 或 - 开头，仅包含字母、数字、.、_ 和 -，每段最多 100 个字符；最多 16 层深，总长度最多 240 个字符。不允许隐藏文件或文件夹（名称以 . 开头）、空格、设备名称（con、nul、 com1……），也不允许 __proto__、constructor 或 prototype。
  • 只能包含文件和文件夹：链接、联接点和特殊文件会使插件无法使用。
  • 不允许两个路径仅在字母大小写上不同。
  • 提供文件时，类型取自其扩展名：html、js、 mjs、css、json、map、txt、 svg、png、jpg、jpeg、gif、 webp、avif、ico、woff、woff2、 ttf、otf。其他扩展名的文件只会作为字节提供，永远不会运行。

清单

mongo-manager-plugin.json 会被严格检查：未知字段、类型错误或超出范围的值都会使插件无法使用，插件页面会指出哪个字段有误。供人阅读的文本（名称、标题、备注）不得包含控制字符，也不得包含隐藏或反转文本的字符。 

{
  "id": "hello-documents",
  "name": { "en": "Hello documents", "tr": "Merhaba belgeler" },
  "version": "0.1.0",
  "description": { "en": "Lists the documents of a collection.", "tr": "Bir koleksiyonun belgelerini listeler." },
  "entry": "index.html",
  "permissions": ["documents:read"],
  "contributes": {
    "collectionTabs": [{ "id": "list", "title": { "en": "Hello", "tr": "Merhaba" }, "icon": "table" }],
    "sidebarPanels": [{ "id": "page", "title": { "en": "Hello documents" }, "icon": "puzzle" }]
  },
  "settings": {},
  "author": { "name": "Your Name", "url": "https://example.com" },
  "homepage": "https://example.com/hello-documents",
  "repository": "https://github.com/your-name/hello-documents",
  "license": "MIT",
  "publishedAt": "2026-10-11",
  "changelog": [
    { "version": "0.1.0", "date": "2026-10-11", "notes": { "en": "First release.", "tr": "İlk sürüm." } }
  ]
}
字段 必填 规则
id 是 小写字母和数字，以短横线分隔（geojson-map），最多 64 个字符。必须与插件的文件夹名称一致。不能使用 Mongo Manager 自带插件的 ID，也不能使用读起来像应用保留名称的 ID（见下文）。
name 是 本地化文本，最多 60 个字符：{ "en": "...", "tr": "..." }。不得包含不可见字符（零宽字符、标签字符、变体选择符；表情符号自带的除外），也不得使用读起来像应用自身消息的名称：Mongo Manager（或以此开头的名称）、MongoDB、 System、Session、Security、Admin、Server、 Update 及类似名称，应用的任何语言均在此列，按读起来的样子比较，不区分大小写、空格、重音和形近字母。每个单词中的字母必须全为拉丁字母或全不是（不得混用希腊字母和西里尔字母），括号内不得出现读起来像 ID 的内容（(value-search)；(beta) 可以）。应用显示插件的消息和提问时，会在其名称旁标注其 ID。
version 是 语义化版本：major.minor.patch，可带预发布标识 （1.2.0-beta.1），最多 64 个字符。
description 否 本地化文本，最多 300 个字符。
entry 是 每个贡献点打开的页面：指向插件中某个 .html 文件的普通路径。
permissions 否 可取 documents:read、documents:write、collection:read、 database:read 中的任意项，每项至多出现一次。默认：无。参阅 权限。
contributes 否 collectionTabs、documentActions、sidebarPanels 和 cellRenderers：每个列表最多 5 项，列表内 ID 唯一。参阅 贡献点。
settings 否 最多 10 项，以键标识（以字母开头，后接字母和数字，最多 32 个字符）： { "type": "url" | "text" | "boolean", "title": 最多 60 个字符的本地化文本 }。 值由管理员设置；页面通过上下文读取。
author 否 { "name": 最多 80 个字符的文本, "url": https 地址（可选） }。
homepage、repository 否 带主机名的 https:// 地址，最多 300 个字符，不得含凭据、空格或反斜杠。
license 否 SPDX 表达式，最多 40 个字符：MIT、Apache-2.0 OR MIT。
publishedAt 否 真实存在的日期，格式 YYYY-MM-DD，范围在 1900 年至 2100 年之间。
changelog 否 最多 50 条 { "version", "date": "YYYY-MM-DD", "notes": 最多 1000 个字符的本地化文本 }；每个版本至多出现一次，且不得晚于清单的 version。

本地化文本是一个对象，其中 en 必填，另外可按需包含应用支持的其他语言：tr、zh（简体中文）、ja、es、 pt（巴西葡萄牙语）、ko、de、fr 和 ru；读者所用语言缺失时显示英文。贡献点的格式为 { "id", "title": 最多 40 个字符的本地化文本, "icon" }：其 ID 以小写字母开头，后接小写字母、数字和短横线，最多 32 个字符；图标取 map、chart、table、file、image、 globe、layers、puzzle、book、wand、 shapes、scroll、code、calendar、 hourglass、shield、fingerprint、ruler 之一（均为应用自带图标：插件不能自带图标）。单元格渲染器则为 { "id", "match" }，并可带可选的 "display"：inline（默认）或 tooltip。

url 类型的设置必须是不含凭据的 https 地址（仅限本机时可用明文 http：localhost、127.0.0.1 或 [::1]）；其协议、主机和端口会加入框架允许加载的图片来源（对于地图瓦片：开头的 {s}. 表示任意子域名，仅限用在由两段或更多段组成的名称之前，不适用于 IP 地址）。图片地址可能携带数据：插件可以将其读取到的内容发送给该服务器，批准界面和设置中都会对此作出说明。text 类型的设置最多 500 个字符。插件的每个用户都能读取其设置：切勿要求填写机密信息。服务器会用自己的密钥加密存储这些设置，与其他所有已保存的值一样。

贡献点

每个贡献点都打开同一个入口页面。页面通过地址的片段 #<kind>=<id>（例如 #collectionTab=list）以及上下文中的 contribution 得知自己是哪一个贡献点。

类型 出现位置及打开方式
collectionTabs 每个集合的一个标签页，位于应用自带标签页之后，视图上同样有。框架填满该标签页。其 place 为该集合，并带有用户在“文档”中设置的 filter。每次显示该标签页时页面都会重新加载，除非页面通过 ui.keepOpen 要求保持打开：此时当该集合标签页的其他部分显示时，页面仍保持已加载状态（不可见时，页面可以读取但不能执行操作：not_visible）。
documentActions “文档”中某个文档的操作菜单里的一项，仅对已获 documents:read 批准的插件显示。它会打开一个显示该页面的对话框；place.documentId 为该文档的 _id。插件放入查询或管道（ui.useQuery、ui.useQueryIn、ui.useAggregation）后，对话框随即关闭。
sidebarPanels 侧边栏中的一项，打开自己的页面，即位于 /plugin/<id>/<contribution> 的工作区标签页。在某个集合的标签页处于活动状态时点击，页面会在该集合上打开 （/plugin/<id>/<contribution>/<connection>/<db>/<collection>）， place 指明该集合；从其他位置打开时 place 为 null。通过链接打开的页面在读取该集合之前会询问用户，用户也可以不选择集合而继续。其他标签页显示时，该页面仍保持已加载状态；不可见时，页面仍可读取但不能执行操作（not_visible）。
cellRenderers 在“文档”显示值的各处（表格、树、卡片、文档页面、变更流详情）附加的一段简短文本，例如 ObjectId 的创建日期：显示在值旁边 （"display": "inline"，默认）或显示在工具提示中（"display": "tooltip"），当鼠标悬停或焦点位于其单元格或行上时，工具提示显示在完整值下方，并标有插件名称。工具提示中的文本为纯文本，其 tone 不起作用；屏幕阅读器会连同值一并朗读。插件在值旁边和工具提示中各说一段文本：每个位置采用第一个作出回答的渲染器。页面运行在隐藏的框架中，每个插件一个，仅对已获 documents:read 批准的插件运行，且自身从不显示。match 取 geojson、string、number、date、 object、objectId、binary（不含 UUID）之一。参阅 单元格渲染器。

单元格渲染器

应用通过 cells.render 消息向隐藏框架询问其所显示的值，每批最多 200 个。使用 kit 时，通过 client.onCells 作答： 

client.onCells((renderer, values, locale, paths, place) =>
  values.map((v) => (typeof v?.$oid === 'string' ? { text: createdAt(v.$oid, locale), tone: 'info' } : null)),
)
  • renderer 为贡献点的 ID，values 为规范 Extended JSON 格式的值，locale 为应用的语言，paths 为各值的字段路径（或 null），place 为值所属的集合（或 null）。
  • binary 值只发送开头部分，绝不发送完整内容： { "$binaryHead": { "base64", "subType", "length" } }，包含其前 2,048 个字节，足以判断图片的类型和大小。
  • 按值的顺序，每个值答复一项：{ "text", "tone" }；无文本时为 null；要稍后再次被询问时为 { "retry": true }。长度不一致的列表会被忽略。
  • 文本以纯文本显示（值旁边最多 80 个字符，工具提示中最多 200 个字符），其中的控制字符和隐藏字符会被移除。 tone 取 neutral、info、success、 warning、danger 之一。
  • 答复必须在 3 秒内给出；否则保留原始值，并在 30 秒后再次询问该值。答复按值、语言和插件设置分别缓存：插件设置更改后会重新询问；超过一分钟的答复会在下次显示该值时重新请求，新答复到来之前沿用旧答复（重新请求失败时也继续沿用）。binary 值的答复按其长度、子类型和开头部分的哈希缓存。
  • 渲染器在作答前可以先读取数据（例如引用其他文档）：它传入请求中给定的 place，即 { place, filter, ... }，并且只能在该处读取。其上下文中的 place 为 null。

上下文

context.get 返回页面所处的位置以及应有的外观。请首先调用它；当某个集合处于打开状态时，应用需要检查它是否为视图，因此响应最多可能需要 3 秒。 

{
  "plugin": { "id": "hello-documents", "version": "0.1.0" },
  "contribution": { "kind": "collectionTab", "id": "list" },
  "locale": "en",
  "theme": "dark",
  "accent": "emerald",
  "place": {
    "connectionId": "6650...",
    "connectionName": "Production",
    "db": "shop",
    "coll": "orders",
    "view": false,
    "documentId": null,
    "filter": { "status": "open" }
  },
  "settings": { "tileUrl": "https://tile.example.org/{z}/{x}/{y}.png" }
}
  • kind 为 collectionTab、documentAction、 sidebarPanel 或 cellRenderer。
  • locale 为应用的语言：en、tr、zh、ja、es、pt、ko、de、fr、ru。
  • theme 为 light 或 dark。
  • accent 为用户的强调色：emerald、indigo、 violet、ocean 或 rose。其他任何值均按 emerald 处理。
  • 页面在未打开任何集合的情况下被打开时（侧边栏页面、单元格渲染器），place 为 null。connectionName 可能为 null。view 对视图为 true：视图只能读取，不能写入，也没有索引。documentId 是文档操作所针对的文档，采用规范 Extended JSON 格式，否则为 null。filter 对集合标签页是“文档”中的筛选条件，否则为 {}。两者都属于数据：没有 documents:read 的插件得到的是 null 和 {}。
  • hidden 列出个人数据规则在该集合中对用户隐藏的字段路径，每条路径是一组键的列表（[["contact", "phone"]]；"*" 表示一个键， "**" 表示任意数量的键，可位于任意深度），仅包含名称，且仅提供给具有 documents:read 的插件，否则为 []；应用未能及时判断（3 秒）时为 null。此类字段的值会以 "***" 形式到达：切勿将其当作该字段的类型。
  • settings 包含管理员设置的值；未设置的设置项不存在。

当用户更改语言、主题或强调色时，应用会发送 context.changed，其中带有 locale、theme 和 accent（即 kit 的 client.onContext）。请立即应用：页面不应显示与当前设置不符的主题或语言。对于可以读取文档的插件，当其页面已加载期间“文档”的筛选条件发生变化时，同样会发送 context.changed，已调用 ui.keepOpen 的集合标签页即使不可见，也会收到用户设置的每一次筛选。请再次调用 context.get 以获取新的 place。

桥接 API

协议

页面与应用通过 postMessage 交换纯 JSON。kit （packages/plugins/kit/src/client.ts）和入门模板的 main.js 均已实现该协议；若自行编写，规则如下：

  1. 只读取 event.source 为 window.parent 且 mm 为 1 的消息。
  2. 页面加载完成后，应用会向其问候： { "mm": 1, "type": "hello", "token": "..." }。保留第一个令牌。在此之前不要发送任何内容。
  3. 请求的格式为 { "mm": 1, "id": 1, "method": "documents.find", "params": { ... }, "token": "..." }， 以 '*' 为目标发送到 window.parent（框架的源是不透明的）。ID 为数字或最多 64 个字符的字符串；应用会忽略不带令牌的请求。
  4. 应答带有相同的 ID：{ "mm": 1, "id": 1, "result": ... } 或 { "mm": 1, "id": 1, "error": { "code": "...", "message": "..." } }。
  5. 用户更改相关设置时，应用会发送 { "mm": 1, "type": "context.changed", "locale", "theme", "accent" }（对具有 documents:read 的插件，还会在“文档”的筛选条件变化时发送），并向单元格渲染器询问 { "mm": 1, "id": "h1", "method": "cells.render", "params": { ... } }，其应答为 { "mm": 1, "id": "h1", "token", "result": [...] }。

页面不得离开其所在地址。如果页面加载了另一个页面（链接、表单或 location 的更改），应用会关闭桥接并移除框架，用户必须重新打开该插件。请将所有内容保持在同一个页面中。 

import { createClient, askMessage, AskError } from './kit/client'

const client = createClient()                       // requests time out after 15 s ("timeout")
client.onContext((locale, theme, accent) => restyle(locale, theme, accent))
client.onReady(async () => {
  const context = await client.ask('context.get')
  if (!context.place) return showNoCollection()
  try {

限制

  • 消息在任一方向上最大为 1 MB；更大的应答会以 too_large 失败。请求更少的文档，或投影更少的字段；也可以在 documents.find、documents.findIn 或 documents.aggregate 中传入 fit: true：应用会按顺序返回一个应答所能容纳的尽可能多的完整文档，并用 cut: true 表示省略了其余文档（此时 hasMore 或 truncated 为 true）。抽样可以直接使用收到的文档；分页读取则从收到的最后一个文档之后继续。如果连一个文档都放不下，仍然返回 too_large。
  • 同时最多有 8 个请求在等待（too_many）。
  • 每个框架每分钟最多 60 次读取（documents.find、.get、 .aggregate、.findIn、collections.list、 database.model），此外另有 120 次定义读取 （indexes.list、validation.get）：包含 50 个集合的数据字典需要 1 次模型读取和 100 次定义读取。
  • 紧接着在插件页面中点击之后。ui.copy、 ui.useQuery、ui.useAggregation、ui.importSql、 ui.exportSql、ui.openDocument、ui.download、 ui.importDocuments 和 documents.update 仅在用户于插件自己的页面中的点击或按键仍然有效时才会被接受：框架必须拥有焦点，因此在应用其他位置的点击从不算数。请在点击处理函数中直接调用它们，先于任何 await；否则它们会以 no_activation 失败。对 ui.copy、ui.use…、SQL 页面或 ui.openDocument 的每次尝试，无论是否被拒绝，都计入该方法的限额：反复尝试并等待点击的插件会耗尽当前这一分钟的限额（too_many）；documents.update 则由一次只能有一个提问以及两次拒绝的规则限制。框架无需点击也可以获得焦点，因此若 ui.copy、 ui.download 或 ui.importDocuments 是在应用其他位置的点击或按键后 5 秒内（浏览器激活状态持续的时间）发出的，应用不会听信插件的一面之词：它会询问用户，并注明插件及其意图（多少个字符及文本的开头，隐藏字符会明确拼出；文件的名称和大小；为哪个集合导入多少个文档），并在用户点击应用自己的复制、保存或打开后才执行；插件的应答会等待此结果（用户关闭提示时返回 declined，无人应答时返回 unanswered，已有一个在等待时返回 busy）。应用为插件提出的每个问题（上述这些、更改、放入的阶段）在 150 秒后结束，即使鼠标仍指向它；kit 对这些请求等待 180 秒，因此页面听到的是应用的答复，而不是自己的超时。
  • 可见时。从单元格渲染器，或在其他标签页显示期间保持加载的页面发出的 documents.update、ui.openDocument 及上述各方法，会以 not_visible 失败。

沙箱

页面加载在带有 sandbox="allow-scripts" 的 iframe 中，来自一个已签名并经加密的地址，该地址标明了插件、其版本、其已批准的文件以及用户的会话（即票据：页面必须在 10 分钟内加载完成，其他文件在会话持续期间均可加载，最长 12 小时；原地续期的会话，例如在另一个标签页登录或更改密码，会被沿用；退出登录后，该地址不再提供任何内容，浏览器也不会保留其任何文件）。提供的每个文件都会对照其已批准的 SHA-256 进行检查。其策略（Content-Security-Policy）以及 X-DNS-Prefetch-Control: off 如下： 

default-src 'none'; script-src <its files>; style-src <its files>;
img-src <its files> data: blob: <the origins of its url settings>; font-src <its files>;
connect-src 'none'; webrtc 'block'; frame-ancestors 'self'; base-uri 'none'; form-action 'none';
sandbox allow-scripts

这对代码意味着：

  • 完全没有网络。不能向任何地址发出请求，包括插件自己的文件：请将数据放入脚本模块（data.js），而不是要加载的 .json 文件。也不要使用 WebRTC 或预取提示：并非所有浏览器都会阻止它们，而且扫描会将其标记为高风险。
  • 没有内联代码或样式。脚本和样式只能来自插件的文件。不得有内联 <script>、<style> 元素、style 属性、内联事件处理程序或 eval。在脚本中设置属性（el.style.width = '40px'）是可行的。
  • 不透明的源。没有 Cookie，没有 localStorage，没有 IndexedDB：它们都会失败。请将状态保存在内存中；管理员选择的设置来自清单的 settings。
  • 没有弹窗、对话框、表单或下载。window.open、 alert、confirm 和表单提交都不起作用。请用 ui.copy 复制；通过应用自己的导入和导出将文件交给用户。
  • 无法触及应用。页面无法读取应用的页面、会话或存储，只能与应用交换消息。
  • 字体和图片是自己的文件（或 data: 和 blob: 图片）。

安全扫描

每个插件的文件在被发现或安装时，都会在管理员批准之前进行扫描。扫描逐行读取脚本（.js、.mjs、.cjs）、标记（.html、.htm、.svg）和样式（.css）文件，包括注释，并列出每项发现的严重程度、规则、文件、行号和摘录。标记文件还会被整体读取，因此跨越多行的 <script> 标签或内联处理程序同样能被发现。打包进插件的库与你自己的代码一样会被扫描。扫描是一种启发式方法：它在文本中查找已知模式，因此为躲避扫描而编写的代码（例如用片段拼出名称）无法被发现，扫描结果干净并不能证明安全。存在高风险发现的插件，只有管理员输入其 ID 以接受风险之后才能被批准；这一点由服务器强制执行，审计日志会记录扫描的各项计数以及是否接受了风险。请避免所有高风险发现，并将中等风险发现控制在自己能够解释的范围内。

  • 向 setTimeout 和 setInterval 传入函数。只通过 window.parent.postMessage 与应用通信。

界面与主题

插件应当看起来像应用的一部分：采用用户所选主题和强调色下的颜色、字体和间距。Mongo Manager 自带的插件使用 packages/plugins/kit 中的插件 kit：

  • kit/src/ui.css：应用的设计令牌（--ds-surface、 --ds-fg、--ds-accent……），涵盖浅色、深色及每种强调色，以及组件（mm-btn、mm-table、mm-empty、 mm-callout……）。其字体是 @fontsource 软件包中的文件：请将它们随插件一起打包，或删除 @font-face 规则以使用系统字体。
  • kit/src/ui.ts：applyLook(theme, accent) 设置 html.dark 和 html[data-accent]；h(tag, props, ...children) 构建元素，其中的文本始终是文本；此外还有 icon、button、segmented、 switchControl、chip、badge、pageHeader、 emptyState、skeleton、callout、table、 valueView、describeValue、formatNumber、 statusLine、setBusy、serialAsk。
  • kit/src/client.ts：createClient、AskError、 askMessage。

kit 是 TypeScript 代码，需要打包使用：将 kit/src 复制到自己的项目中，用 Vite（或其他打包工具）构建为不含内联脚本的相对路径，如同自带插件的 vite.config.ts：base: './'、modulePreload: { polyfill: false }、 assetsInlineLimit: 0。打包的应是构建产物，而不是源代码。入门模板则自带一份用纯 JavaScript 和 CSS 编写的简短客户端和配色副本。 

import './kit/ui.css'
import { createClient } from './kit/client'
import { applyLook, h, pageHeader, emptyState, button } from './kit/ui'

const client = createClient()
client.onContext((locale, theme, accent) => applyLook(theme, accent))
client.onReady(async () => {
  const context = await client.ask('context.get')
  applyLook(context.theme, context.accent)
  document.body.append(
    h('div', { class: 'mm-page' },
      pageHeader({ icon: 'table', title: 'Hello', description: context.place?.coll ?? '' }),
      emptyState({ icon: 'search', title: 'Nothing yet', action: button({ label: 'Load', variant: 'primary' }) }),
    ),
  )
})

请针对页面出现的位置进行设计：集合标签页很宽，文档操作是对话框，侧边栏页面填满工作区。没有内容可显示时显示空状态，place 为 null 时同样如此；读取时显示骨架屏；遇到拒绝时使用应用的措辞。请使用按钮和真正的控件，使页面可通过键盘操作。

版本与批准

  • 批准针对的是确切的文件：即其摘要，由每个文件的路径和 SHA-256 计算得出的 SHA-256。管理员在批准前可以看到它。
  • 已上传的插件或插件文件夹中任何文件的任何更改（新版本、修正 README 中的错别字）都会使其停用，直到管理员再次批准。每次发布都请提升 version 并添加更新日志条目，使管理员知道自己批准的是什么。
  • 上传一个 ID 已安装的插件会将其替换；只有文件与已批准的完全一致时，它才会保持启用。只要新清单仍以相同类型声明这些设置，其设置就会保留。
  • 手动放置的插件文件夹由手动管理：上传相同 ID 的插件会被拒绝，在应用中删除它只是让应用不再记录它，而不会删除该文件夹。
  • 只有 Mongo Manager 自带的插件才会在更新后保留其批准，并且仅限于它们已启用且更新未请求新权限的情况；此时不会要求管理员做任何操作，插件详情页会说明它保留了批准。由管理员手动批准的更新会注明其由管理员批准。

在 GitHub 上发布

在设置为允许此功能的服务器上（MM_PLUGINS_GITHUB=1；默认关闭），管理员可以直接从公开的 GitHub 仓库安装插件。在插件页面中，他们粘贴下列地址之一：

  • https://github.com/<owner>/<repo>、…/releases 或 …/releases/latest，对应最新发布版本；
  • https://github.com/<owner>/<repo>/releases/tag/<tag>，对应指定的发布版本。 标签可以包含斜杠（最多 4 段）。

应用只与 github.com、api.github.com、 objects.githubusercontent.com 和 release-assets.githubusercontent.com 通信，使用 https，仅限公网地址，并且不发送服务器的任何信息（不含 Cookie、令牌或凭据）。它最多跟随 4 次重定向，且仅限在这些主机之间，最多读取发布版本说明 5 MB，整个安装过程限时 4 分钟。插件安装后处于停用状态并附有扫描结果，与上传一样等待批准。它会记住自己的来源（仓库、发布版本和归档），并显示在其详情页上。

  1. 提升 version，添加 changelog 条目，并设置 publishedAt。
  2. 运行 node scripts/pack.mjs。
  3. 创建 GitHub 发布版本（例如标签 v0.1.0），并将 hello-documents-0.1.0.tgz 作为附件。不要附加其他 .tgz 或 .tar.gz 文件。
  4. 将其标记为最新发布版本。把 pack.mjs 打印的摘要放入发布说明，以便管理员将其与应用显示的内容比对。

  1. 在开启插件的情况下（默认）运行 Mongo Manager，并以管理员身份登录。找到其数据目录：除非 MM_DATA_DIR 另有指定，否则为 ~/.mongo-manager。

  5. 每次更改后，重新复制，点击重新扫描并再次批准（文件已更改），然后重新打开标签页、页面或对话框。试用多种语言、两种主题、一个视图、一个没有文档的集合，以及不带集合打开的侧边栏页面。
