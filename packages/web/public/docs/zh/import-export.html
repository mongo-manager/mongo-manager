导入和导出

文件在计算机与集合之间以后台任务的方式传输：可以关闭对话框，并在任务列表中跟踪进度。可从集合的工具栏、侧边栏中集合的菜单或命令面板打开。SQL 转储则不同：它们在文件与整个数据库之间传输，位于单独的页面（参见 SQL 导入和导出）。

格式

  • CSV 和 TSV（逗号、分号、制表符或竖线分隔；UTF-8、UTF-16、Latin-1、Windows-1252、Windows-1254 或 ISO-8859-9 编码）。
  • JSON：一个文档数组，或单个文档。
  • NDJSON：每行一个文档，采用 Extended JSON，因此每种 BSON 类型都能原样还原。
  • Excel 工作簿（.xlsx），一次处理一个工作表。
  • 以上任一种格式经 gzip（.gz）压缩后的文件。

导入

  1. 选择文件、将文件拖放到对话框上，或粘贴文本。
  2. 检查读取方式：格式、分隔符、编码、首行是否为字段名，以及工作簿的工作表。除非字节顺序标记另有指示或选择了其他编码，否则文件按 UTF-8 读取。当字节在该编码下不是文本时，会建议看起来匹配的编码（没有字节顺序标记的 UTF-16、含土耳其语字母的 Windows-1254，否则为 Windows-1252），点击一次即可用该编码重新读取文件；猜测的结果绝不会自动应用，因为错误的编码会写入错误的字符。在所选编码下仍不是文本的行会被拒绝，绝不会用替换字符写入。
  3. 映射字段：每个字段的去向（a.b 表示嵌套，a[0] 表示数组元素）、类型，以及空值或无法转换的值将变成什么。类型根据前一千条记录给出建议；带前导零或前导 + 的值保持为文本，以便编码和电话号码保留原样。对之后的每条记录、对您选择的类型以及对常量，规则都相同：编码绝不会被读作数字，数字也不会被读作会变成另一个数字的双精度浮点数（0.30000000000000004 是双精度浮点数；12345678901234567 不是）：此类值将按无法转换的值处理。不带时区的日期按 UTC 读取。CSV 中字段数比表头多或少的行（字段中有未加引号的逗号）属于行错误，并按原样写入被拒绝记录文件；仅含空格的行不算记录。在每个字段下方，会按所选类型写出的形式显示其前几个样本，或显示无法转换的原因。
  4. 可以按需添加常量字段：每个文档中相同的值，可以是导入时间，也可以是字符串、数字（Int32、Int64、Double、Decimal128）、日期、ObjectId、布尔值、JSON 或 null。常量按与文件中的值相同的规则转换，无法转换时会在导入开始前被拒绝。
  5. 选择模式，也可以先进行试运行。对于 Upsert 和合并，如果没有任何索引以某个键字段开头，对话框会发出警告：这样每条记录都要通过扫描集合来查找。

模式

  • 插入：每条记录都成为一个新文档；_id 已存在的记录会失败。
  • Upsert：键字段（默认为 _id）相同的文档会被该记录替换；否则插入该记录。
  • 合并：记录的字段会写入键字段相同的文档；记录中没有的字段会保留，子文档内部也是如此。“仅更新”会跳过不匹配任何文档的记录。字段名含点或以 $ 开头的记录无法合并（会被当作路径解读）；这类记录请使用 Upsert。

选择“跳过并继续”时，失败的记录会被计数并列出；选择“停止导入”时，第一个失败之前的记录会被写入，导入随即停止。试运行会读取、转换并检查整个文件，不写入任何内容。报告会统计发生的情况，按映射字段显示有多少值转换成功、多少失败，列出最初的几个失败，并提供原始格式的被拒绝记录文件，便于修正后重新导入。如果该文件会超出存储限制，则不会保留，报告中会说明。键字段按值匹配，不能以 $ 开头。

导出

可以导出所应用的查询、整个集合或管道的结果。CSV 和 Excel 使用所选并排序的列。从侧边栏、命令面板或未显示任何文档的集合打开时，对话框会根据 100 个文档的样本建议列（个人字段会被标记：对无权查看的用户，它们会写成 ***）。数组可以写成其 JSON 文本，也可以每个元素一列（tags.0、tags.1……，列数与前面文档中最长的数组相同，最多为所设数量；超出的元素会在报告中指明），或者将各元素用所选的分隔符连接。如果一个都不选，则前几个文档的字段（最多 1,000 个或 8 MiB，最多 500 列）将作为列，在一个文档中是值而在另一个文档中是子文档的字段，会成为一个保存完整值的列。报告会以路径指明没有任何列包含的内容。CSV 文本如果（在任何空格之后）以 =、+、-、@、制表符或换行符开头，会加上前导 '，使电子表格绝不会将其作为公式运行；如果文件将由其他程序读取或用于重新导入，可关闭此功能。JSON 和 NDJSON 保留每个字段和每种类型。Excel 最多容纳 1 048 575 行，每个单元格最多 32 767 个字符：更长的单元格会被截断并在报告中计数，更大的导出会被拒绝，并建议改用 CSV 或 NDJSON。任务完成后，从任务列表下载文件；列表会说明文件保留到何时（默认 24 小时， MM_TRANSFER_TTL_HOURS），过期后必须重新运行导出。

SQL 导入和导出

SQL 导入和导出随内置的 SQL → MongoDB 插件提供。在管理员于插件中批准并启用它之前，该页面、它的侧边栏入口、命令面板中的命令以及下文的数据库菜单项都不会显示，服务器也会拒绝 SQL 导入和导出，包括将集合导出为 SQL 以及助手发起的 SQL 导出。

SQL 不从集合导入或导出：“文档”工具栏和集合的导出对话框都不提供该功能。它有单独的页面，即侧边栏中的 SQL ↔ MongoDB。该页面始终显示其所处理的连接和数据库。两者都在顶部选择，并保存在页面地址中（/sql/import/<connection>/<database> 或 /sql/export/…），因此重新加载或分享链接都会打开同一位置。在侧边栏的树中，数据库的菜单提供“导入 SQL 转储…”和“导出为 SQL…”，会在该数据库上打开此页面。在命令面板中，“SQL ↔ MongoDB”会打开上次离开时的页面，“导出为 SQL”会针对当前标签页所在的数据库打开导出。导入和导出每次都只处理一个数据库。查看其他标签页或该页面的另一部分时，该页面保持打开：准备好的文件或正在运行的任务不会丢失，仍在运行的导出在返回时会再次显示。在已准备文件或导入正在运行时，关闭页面或离开应用会先询问。当任务的进度显示在可见的页面上时，其结束情况会直接在那里说明，不会另有通知。

导入 SQL 转储（SQL → MongoDB）

  1. 选择或拖放 MySQL（mysqldump）、PostgreSQL（pg_dump）或 SQLite（.dump）文件，纯文本或经 gzip（.gz）压缩均可。只读取表定义和行；文件中的任何内容都不会被运行。其他语句会列为已跳过。
  2. 检查转储中包含的表：每个表会显示其列、行数、主键和几行样本。选择要导入的表，并为每个表命名其目标集合；名称会标记为新建或已存在。插入时，多个表可以进入同一个集合；在 Upsert 和合并中，每个表进入各自的集合，因为两个表中键相同的行会互相替换。
  3. 选择选项。“将主键作为 _id”会使单列主键成为文档的 _id；复合键则保持为字段。模式为插入、Upsert 或合并，与文件导入相同（Upsert 和合并按 _id 匹配，因此没有单列主键的表无法使用它们）。当某一行无法写入时，选择“跳过并继续”或“停止导入”。
  4. 可以进行试运行：它会读取并检查每个所选的行，不写入任何内容。然后开始导入。导入作为后台任务运行，在与表单分开的单独页面上跟踪：先显示进度，然后显示报告，“停止”可结束导入。被停止、失败或被中断的导入会说明这一点，并报告其结束前已写入的内容。

导入的目标是已有的数据库，或在页面上命名的新数据库，绝不能是 admin、local 或 config。仅大小写与已有数据库不同的新名称会被拒绝，MongoDB 同样会拒绝。选择另一个数据库会保留已准备的文件（试运行会被放弃，因为它说明的是其运行所在的数据库）；选择另一个连接会先询问，无论通过何种方式提出（列表、树、面板、插件、浏览器的后退），因为所读取的文件属于该连接，拒绝则保持页面原状。这需要在该连接上具有写入文档和运行后台任务的权限，并且连接和服务器都不能处于只读状态。

导入和导出逐步进行，而不是一个很长的页面：顶部的步骤（导入为文件、表、选项、进度；导出为集合、选项、进度）显示当前所处的位置。在选择文件之后经过的步骤可以返回，已选内容会保留；“选择其他文件”会用另一个文件重新开始。试运行说明的是它检查过的内容：更改表、集合、选项或数据库会使其失效（仍在运行的试运行会被停止）。导入一旦开始运行，其输入便无法更改：页面会保留到导入结束，之后“导入另一个文件”会重新开始。

导出为 SQL（MongoDB → SQL）

选择数据库（绝不能是 admin、local 或 config），然后选择要导出的集合、视图和时间序列集合：开始时默认全选，最多 500 个。一个后台任务会将它们写入一个 SQL 文件，每个对象对应一条 CREATE TABLE 及其 INSERT；该文件不会自行创建数据库或模式，因此可加载到所选的数据库中。当两个表名会冲突时（例如仅大小写不同的名称），其中一个会被改为唯一名称，报告中会说明。选项包括方言（PostgreSQL、MySQL 或 SQLite）、每条 INSERT 的行数（1 到 1000）、每个表一个事务以及 gzip 压缩；使用 MySQL 时，嵌套值可以写成 LONGTEXT（同样的 JSON 文本）而不是 JSON，以兼容旧工具，例如 4.7 之前的 phpMyAdmin。MySQL 的 decimal 列采用前几个文档的值所写的小数位数（234.20：两位；超过两个的尾随零属于填充，因此从 DECIMAL(65,30) 列读回的值保留其自身的小数位），绝不会让每个金额都带 30 个零。之后出现小数位更多的值时，会用 ALTER TABLE … MODIFY 加宽该列（MySQL 会先提交其之前的行，因此事务在其之后重新开始）。如果某个值与之前的值合在一起无法放入任何 decimal 列（小数位超过 30 位或总位数超过 65 位），则会写成 NULL 并计数，绝不会被四舍五入。列来自每个集合的前几个文档：仅在后面的文档中出现的字段会被省略，报告按表列出它们，并列出因过大或不是 SQL 类型而被写成 NULL 的值。应用写出的文件在导入时会还原为其中所含的文档：其 CHAR(24) 列还原为 ObjectId，其 "sub.a" 列还原为嵌套字段（其中的 NULL 还原为文档没有的字段），其字节还原为二进制。进度、报告和下载显示在单独的页面上；“停止”会结束正在运行的导出，“重新导出”会返回选项。

导出为 SQL 需要该连接的导出权限。无权查看个人数据的用户，在值被隐藏的位置得到 ***，与任何导出一样。

复制、比较和同步

可将集合（整个集合、所应用的查询、在复制对话框中输入的筛选条件，或管道的结果，即聚合构建器中的“复制结果…”）或数据库中所选的集合复制到同一连接或另一个连接。第一步显示源的预估大小；选择或输入目标时，对话框会立即检查：目标是否存在及其包含多少文档、所选模式会对其产生什么影响、您在那里的角色，以及复制会拒绝的任何情况。数据库复制运行期间，任务列表会显示每个集合各自的进度。插入、Upsert 和合并的工作方式与导入相同，并保留失败之前已写入的内容；“替换目标”会在暂存集合中构建副本，仅在所有文档都已写入后才将其就位：被拒绝的文档、失败或取消都会让目标保持原样。验证器在文档加载之后设置，与 MongoDB 自带的复制一致，因此验证器设置之前存储的文档也会被复制；但如果目标的用户无权更改验证器（readWrite 角色），则会先设置验证器，报告中会说明。索引、验证器和集合选项（固定、排序规则、时间序列、聚簇）也可以复制；数据库复制最后按依赖顺序创建其视图，其视图可以逐个选择。加密（可查询加密）集合及其元数据集合不会被复制。在同一连接上、没有需要脱敏的内容时，由 MongoDB 自行复制（$out 或 $merge），数据不会经过 Mongo Manager。

经过 Mongo Manager 的复制，会按 Node.js MongoDB 驱动读取的方式写入每个文档：已弃用的 BSON 类型 undefined 和 DBPointer 分别变为 null 和 DBRef 文档。由 MongoDB 自行完成的复制会保留它们。

摘要会在写入任何内容之前，显示每个目标、其是否存在，以及将如何复制。会删除目标文档的 TTL 索引需要确认。当源有个人字段规则而目标没有时，复制需要确认个人值将在目标上可见；目标的管理员也可以改为添加这些规则。个人字段的发现方式与查询相同，包括通过视图以及管道移动或查找的字段。如果源上的个人字段对您隐藏，复制会在其位置保存 ***，并且始终是匿名的；“匿名复制”会为所有人写入 ***。个人的 _id 无法以脱敏方式复制。当目标与源无法区分时，摘要会说明它可能就是源本身。

比较会按 _id 顺序读取两侧，并统计仅在源中、仅在目标中、不同和相同的文档数，附带样本和逐字段差异。筛选条件适用于两侧，并且可以忽略所选字段。当任一侧的个人字段对您隐藏时，两侧都按 *** 比较，且个人的 _id 无法比较。同步会应用已完成的比较：插入缺失的文档并替换不同的文档，但绝不会覆盖在读取之后被更改的文档。与复制一样，当目标缺少源的个人字段规则时，需要确认。删除目标中多余的文档默认关闭，需要输入目标的名称，当源没有读取到任何文档时会被拒绝，并且一旦要删除的数量超过比较所发现的数量加上一个余量（该数量的 10%，至少 100），就会停止。使用筛选条件时，源中仍存在但已不再匹配筛选条件的目标文档会被保留，绝不会删除，并在报告中计数。当个人字段规则发生变化、您失去对任一连接的访问权限，或个人字段对您隐藏时，报告会被撤回。

已保存的设置

映射、导出设置和复制设置可以按名称保存，并在此集合或其他集合上再次加载。它们与已保存的查询一样加密存储。

文件会保留什么，不能保留什么

  • CSV 和 Excel 保存文本、数字、布尔值和日期。文档中超出这些的类型（ObjectId、Long、Decimal128、二进制、嵌套文档和数组）会以文本或其 Extended JSON 形式导出，而重新读回的 CSV 会按其映射所指定的类型还原。如需文件能完全原样还原，请导出 JSON 或 NDJSON（Extended JSON）。
  • SQL 导出会将文档展平为列；本应用生成的转储在读回时会还原其 ObjectId、嵌套字段和二进制值，来自其他来源的转储则按其列所指定的类型读取。
  • 日期与 MongoDB 一样保留毫秒：SQL 转储中的微秒会被丢弃。MySQL 的 0000-00-00（“无日期”）读作 null。SQL 转储中长于 Decimal128 所能容纳（34 位数字）的整数会以文本形式精确保留。
  • 在 Excel 中，显示为日期的单元格会按所写的日期和时间以 UTC 读取（因为单元格不含时区）；只显示一天中时间的单元格读作文本，HH:MM:SS（带有格式显示的秒的小数部分），如果同时包含日期，则读作日期和时间。时长（[h]:mm）读作文本，其小时数可超过一天。
  • 导出是边走边读取集合，而不是某一时刻的快照：这期间写入的文档可能包含在内，也可能不包含。
  • 停止、失败或被取消的导入会保留其已写入的内容；其报告会说明记录有多少条。如果再次以插入方式运行，这些记录会被写入两次：请使用带键的 Upsert 或合并，或先将它们删除。上传的文件在每次运行后都会被删除；再次运行需要重新上传。
  • 合并会设置记录中的字段，保留其他字段；记录中的空子文档不会更改已存储的内容，仅在新文档中才会创建。“仅更新”对 Upsert 和合并同样适用。
  • 被拒绝的记录会以源的格式和分隔符返回，其中不是文本的字节显示为 �，以便找到并修正该行。

限制和安全

  • 文件在服务器上保留 24 小时，并有每个用户的存储限制；管理员可以更改这两项（参见 部署）。
  • 出于安全原因被拒绝的内容：启用宏的和受密码保护的工作簿、旧的 .xls 文件、解压后膨胀过多的文件、带 DTD 的 XML，以及以 $ 开头、含点或名为 __proto__ 的字段名（除非允许使用不常见的名称）。经 gzip 压缩的工作簿会在首次读取时解压一次，之后按工作簿的大小计算；其内容的膨胀不得超过普通工作簿。
  • 无权查看个人数据的用户导出的文件中，个人值用 *** 代替，不能映射或匹配个人字段，并且在存在个人字段的位置不能替换整个文档。在个人字段规则更改之前生成的文件不能再下载；请重新导出。
  • 仅当管理员为该连接允许时，查看者才能导出。
  • 导入和导出任务只对本人和管理员显示。预览会截断显示较长的值；很宽的文件会按较少的行采样。
