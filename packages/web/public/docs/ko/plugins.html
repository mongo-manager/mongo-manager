플러그인 만들기

플러그인은 Mongo Manager에 보기, 동작 또는 페이지를 추가합니다. 컬렉션에 있는 장소의 지도, 차트, 중복 검색기, SQL 변환기 등이 그 예입니다. 이 가이드는 플러그인을 만드는 사람을 위한 것입니다. 플러그인을 구성하는 파일, 플러그인이 앱에 요청할 수 있는 모든 것, 앱이 적용하는 규칙, 그리고 패키징, 테스트, 게시 방법을 다룹니다. 관리자는 플러그인 페이지에서 플러그인을 설치하고 승인합니다. 승인 모델은 보안을 참조하세요. 이 페이지에서는 모든 플러그인을 볼 수 있으며, 활성화된 플러그인, 관리자 조치가 필요한 플러그인(승인 대기 중, 변경됨, 손상됨), 비활성화된 플러그인, 특정 출처, 그리고 이름, 설명, ID, 버전, 요청하는 권한 또는 추가하는 항목으로 검색한 결과로 목록을 좁힐 수 있습니다.

플러그인이란

플러그인은 정적 파일로 이루어진 폴더입니다. HTML 페이지와 그 스크립트, 스타일, 이미지, 글꼴, 그리고 플러그인이 추가하는 것과 할 수 있는 일을 기술하는 매니페스트 mongo-manager-plugin.json으로 구성됩니다. 앱은 이 페이지를 샌드박스 프레임에 표시하며, 페이지는 메시지로만 앱과 통신합니다. 페이지가 도큐먼트를 요청하면 앱은 로그인한 사용자로서 그 사용자의 권한과 앱의 마스킹을 적용하여 응답합니다.

  • 서버 코드 없음. 플러그인의 어떤 것도 서버에서 실행되지 않습니다. 서버는 플러그인 파일을 저장하고, 검사하고, 프레임에 제공할 뿐입니다.
  • 네트워크 없음. 페이지는 페이지를 제공한 서버를 포함해 어떤 주소에서도 가져올 수 없습니다. 쿠키도, 스토리지도, 앱 페이지에 대한 접근도 없습니다. 브라우저 쪽에는 두 가지 우회로가 남아 있습니다. WebRTC는 정책의 webrtc 지시문을 적용하는 브라우저에서만 차단됩니다. Chromium 기반 브라우저(Chrome, Edge)는 버전 149 기준으로 이를 무시하며, Firefox도 믿어서는 안 됩니다. 따라서 이러한 브라우저에서는 플러그인이 읽은 내용을 WebRTC로 외부에 보낼 수 있습니다. 또한 프리페치 힌트(dns-prefetch, preconnect)로 이름 조회를 일으킬 수 있습니다. 프레임은 브라우저에 프리페치하지 않도록 요청하며 스캔은 둘 다 높음 위험으로 표시하지만, 스캔은 파일 텍스트에서 알려진 패턴을 찾을 뿐이므로 이를 피하도록 작성된 코드는 발견되지 않습니다. 신뢰하는 플러그인만 승인하세요.
  • 승인 없이는 아무것도 없음. 플러그인은 관리자가 정확한 파일과 요청한 권한을 승인한 후에만 실행됩니다. 파일이 변경될 때마다 새로 승인해야 합니다.
  • 변경은 사용자를 거침. 도큐먼트를 변경할 수 있는 플러그인은 요청을 보내며, 앱이 자체 대화 상자에 변경 내용을 표시하고 사용자가 결정합니다. 플러그인이 준비한 쿼리나 파이프라인은 사용자의 편집기에 입력되며, 사용자가 실행하기 전에는 아무것도 실행되지 않습니다.

Mongo Manager는 자체 플러그인을 여러 개 제공합니다(Map, Charts, Schema health, Duplicate finder, Value search, References, Document diff, SQL to MongoDB, Time hints, Binary preview, Data dictionary, Local time, Log analyzer, Test data, Reshape, Anonymiser, Search playground, Shard key analyzer, Storage report, Validation check, Legacy UUIDs, Date filters, Index script, Expiry (TTL), Personal data finder, Document size). 이들은 같은 샌드박스에서 실행되고, 같은 브리지로 통신하며, 직접 만든 플러그인과 같은 방식으로 스캔됩니다. 다만 앱 자체의 코드이므로 승인할 때 ID를 입력하라는 요청이 없습니다 (버전 및 승인 참조). MM_PLUGINS=0으로 서버 전체에서 플러그인을 끌 수 있습니다(배포 참조).

빠른 시작

스타터 템플릿에서 시작하세요. 플러그인 페이지의 나만의 플러그인 만들기 아래에서 스타터 다운로드(.zip)를 선택합니다(Mongo Manager 소스 코드의 packages/plugins/starter 폴더이기도 합니다). 빌드 단계나 의존성이 없는 순수 JavaScript로 작성된 완전한 플러그인이며, 컬렉션의 도큐먼트를 나열하는 컬렉션 탭과 사이드바 페이지로 구성됩니다.

  1. 압축을 풀거나 폴더를 복사하여 새 저장소에 넣습니다.
  2. mongo-manager-plugin.json에서 id, name, author, repository를 변경합니다. ID는 고유해야 합니다. 모든 서버에서 플러그인 폴더의 이름이 되기 때문입니다.
  3. main.js와 style.css에 페이지를 작성합니다.
  4. 자체 서버에서 시험합니다. node scripts/pack.mjs --folder ~/.mongo-manager/plugins를 실행한 다음 플러그인 → 다시 스캔을 선택하고, 스캔 결과를 확인한 뒤 승인합니다. 자체 서버에서 테스트를 참조하세요.
  5. node scripts/pack.mjs로 패키징하면 <id>-<version>.tgz가 생성됩니다. 이 파일을 GitHub 릴리스에 첨부합니다. GitHub에 게시를 참조하세요.

스타터에는 AI 코딩 어시스턴트용 지침 파일(CLAUDE.md, AGENTS.md, GEMINI.md, .github/copilot-instructions.md)도 들어 있습니다. AI 어시스턴트로 만들기를 참조하세요.

파일 및 폴더 구성

hello-documents/
  mongo-manager-plugin.json   the manifest (required, at the top)
  index.html                  the entry page every contribution opens
  main.js                     the page's script (an ES module)
  style.css                   the page's styles
  README.md                   shown to administrators on the plugin's details page
  README.tr.md, README.zh.md  the same in another language of the app (optional)
  scripts/pack.mjs            packaging (not part of the plugin: left out of the archive)
  CLAUDE.md, AGENTS.md, ...   AI assistant files (left out of the archive)

플러그인에 들어 있는 파일에 대한 앱의 규칙은 다음과 같습니다.

  • 전체 500개 파일, 25MB 이하이며, 매니페스트는 64KB 이하입니다.
  • 모든 경로는 상대 경로이며 단순해야 합니다. 각 부분은 문자, 숫자, _ 또는 -로 시작하고 문자, 숫자, ., _, -만 포함하며 최대 100자입니다. 깊이는 최대 16단계, 전체 길이는 최대 240자입니다. 숨김 파일이나 폴더(.로 시작하는 이름), 공백, 장치 이름(con, nul, com1...), __proto__, constructor, prototype은 사용할 수 없습니다.
  • 파일과 폴더만 허용됩니다. 링크, 정션, 특수 파일이 있으면 플러그인을 사용할 수 없게 됩니다.
  • 대소문자만 다른 두 경로는 허용되지 않습니다.
  • 파일은 확장자에 따른 유형으로 제공됩니다: html, js, mjs, css, json, map, txt, svg, png, jpg, jpeg, gif, webp, avif, ico, woff, woff2, ttf, otf. 그 외는 바이트로만 제공되며 실행되지 않습니다.

매니페스트

mongo-manager-plugin.json은 엄격하게 검사됩니다. 알 수 없는 필드, 잘못된 유형, 범위를 벗어난 값이 있으면 플러그인을 사용할 수 없게 되며, 플러그인 페이지에 어느 필드가 잘못되었는지 표시됩니다. 사람이 읽는 텍스트(이름, 제목, 노트)에는 제어 문자나 텍스트를 숨기거나 뒤집는 문자를 넣을 수 없습니다. 

{
  "id": "hello-documents",
  "name": { "en": "Hello documents", "tr": "Merhaba belgeler" },
  "version": "0.1.0",
  "description": { "en": "Lists the documents of a collection.", "tr": "Bir koleksiyonun belgelerini listeler." },
  "entry": "index.html",
  "permissions": ["documents:read"],
  "contributes": {
    "collectionTabs": [{ "id": "list", "title": { "en": "Hello", "tr": "Merhaba" }, "icon": "table" }],
    "sidebarPanels": [{ "id": "page", "title": { "en": "Hello documents" }, "icon": "puzzle" }]
  },
  "settings": {},
  "author": { "name": "Your Name", "url": "https://example.com" },
  "homepage": "https://example.com/hello-documents",
  "repository": "https://github.com/your-name/hello-documents",
  "license": "MIT",
  "publishedAt": "2026-10-11",
  "changelog": [
    { "version": "0.1.0", "date": "2026-10-11", "notes": { "en": "First release.", "tr": "İlk sürüm." } }
  ]
}
필드 필수 규칙
id 예 소문자와 숫자를 대시로 구분한 형식(geojson-map)이며 최대 64자입니다. 플러그인의 폴더 이름과 같아야 합니다. Mongo Manager와 함께 제공되는 플러그인의 ID나 앱이 예약한 이름처럼 읽히는 ID(아래 참조)는 사용할 수 없습니다.
name 예 현지화된 텍스트이며 최대 60자입니다: { "en": "...", "tr": "..." }. 보이지 않는 문자 (폭 없는 문자, 태그, 변형 선택자 등. 이모지 자체에 포함된 것은 허용)는 사용할 수 없으며, 앱 자체 메시지처럼 읽히는 이름도 안 됩니다. Mongo Manager(또는 그것으로 시작하는 이름), MongoDB, System, Session, Security, Admin, Server, Update 등이 해당하며, 앱의 모든 언어에서 읽히는 대로 비교하고 대소문자, 공백, 악센트, 비슷하게 생긴 문자는 무시합니다. 각 단어에서 문자는 모두 라틴 문자이거나 모두 아니어야 하며(그리스 문자와 키릴 문자를 함께 쓸 수 없음), 괄호 안에 ID처럼 읽히는 내용을 넣을 수 없습니다((value-search)는 안 되고 (beta)는 괜찮음). 앱은 플러그인의 메시지와 질문을 표시할 때 이름 옆에 ID를 함께 표시합니다.
version 예 유의적 버전: major.minor.patch, 선택적으로 프리릴리스 (1.2.0-beta.1)를 붙일 수 있으며 최대 64자입니다.
description 아니요 현지화된 텍스트이며 최대 300자입니다.
entry 예 모든 기여 지점이 여는 페이지로, 플러그인의 .html 파일에 대한 단순 경로입니다.
permissions 아니요 documents:read, documents:write, collection:read, database:read 중 임의의 것을 각각 최대 한 번 지정합니다. 기본값: 없음. 권한을 참조하세요.
contributes 아니요 collectionTabs, documentActions, sidebarPanels, cellRenderers: 각각 최대 5개의 목록이며 목록 안에서 ID는 고유해야 합니다. 기여 지점을 참조하세요.
settings 아니요 키(문자로 시작하고 이후 문자와 숫자, 최대 32자)별로 최대 10개: { "type": "url" | "text" | "boolean", "title": localized text of at most 60 }. 값은 관리자가 설정하며 페이지는 컨텍스트에서 읽습니다.
author 아니요 { "name": text of at most 80, "url": an https address (optional) }.
homepage, repository 아니요 호스트가 있는 https:// 주소이며 최대 300자입니다. 자격 증명, 공백, 백슬래시는 포함할 수 없습니다.
license 아니요 SPDX 표현식이며 최대 40자입니다: MIT, Apache-2.0 OR MIT.
publishedAt 아니요 실제로 존재하는 날짜로, YYYY-MM-DD 형식이며 1900년에서 2100년 사이여야 합니다.
changelog 아니요 최대 50개 항목 { "version", "date": "YYYY-MM-DD", "notes": localized text of at most 1000 }. 각 버전은 최대 한 번만 나올 수 있으며 매니페스트의 version보다 이후 버전은 없어야 합니다.

현지화된 텍스트는 en(필수)과 선택적으로 앱의 다른 언어 중 원하는 것을 가진 객체입니다: tr, zh(중국어 간체), ja, es, pt(브라질 포르투갈어), ko, de, fr, ru. 읽는 사람의 언어가 없으면 영어가 표시됩니다. 기여 항목은 { "id", "title": localized text of at most 40, "icon" } 형식이며, ID는 소문자로 시작하고 이후 소문자, 숫자, 대시를 사용해 최대 32자입니다. 아이콘은 map, chart, table, file, image, globe, layers, puzzle, book, wand, shapes, scroll, code, calendar, hourglass, shield, fingerprint, ruler 중 하나입니다 (앱 자체 아이콘이며 플러그인은 아이콘을 가져오지 않습니다). 셀 렌더러는 대신 { "id", "match" } 형식이며, 선택적 "display"로 inline(기본값) 또는 tooltip을 지정할 수 있습니다.

url 설정은 자격 증명이 없는 https 주소여야 합니다(일반 http는 이 컴퓨터, 즉 localhost, 127.0.0.1, [::1]에만 허용). 해당 주소의 스킴, 호스트, 포트는 프레임이 불러올 수 있는 이미지에 추가됩니다(지도 타일의 경우 앞의 {s}.는 모든 하위 도메인이 되며, 두 부분 이상으로 된 이름 앞에서만 가능하고 IP 주소 앞에서는 불가). 이미지 주소에는 데이터가 실릴 수 있습니다. 즉 플러그인이 읽은 내용을 해당 서버로 보낼 수 있으며, 승인 화면과 설정에 이 점이 표시됩니다. text 설정은 최대 500자입니다. 플러그인의 모든 사용자가 설정을 읽을 수 있으므로 비밀 정보는 절대 요구하지 마세요. 서버는 다른 모든 저장 값과 마찬가지로 설정을 서버 키로 암호화하여 저장합니다.

기여 지점

모든 기여 지점은 같은 진입 페이지를 엽니다. 페이지는 주소의 프래그먼트 #<kind>=<id>(예: #collectionTab=list)와 컨텍스트의 contribution에서 자신이 어느 것인지 알 수 있습니다.

종류 표시 위치 및 여는 방법
collectionTabs 뷰를 포함한 모든 컬렉션에서 앱 자체 탭 뒤에 나오는 탭입니다. 프레임이 탭을 가득 채웁니다. place는 해당 컬렉션이며 사용자가 설정한 도큐먼트 filter가 함께 전달됩니다. 탭이 표시될 때마다 페이지가 다시 로드되지만, ui.keepOpen으로 유지를 요청한 경우에는 해당 컬렉션 탭의 다른 섹션이 표시되는 동안에도 로드된 상태로 남습니다(화면에 보이지 않을 때는 읽을 수는 있지만 동작할 수는 없음: not_visible).
documentActions 도큐먼트의 동작 메뉴에 있는 항목이며, documents:read 승인을 받은 플러그인에만 표시됩니다. 페이지가 있는 대화 상자가 열리며, place.documentId는 해당 도큐먼트의 _id입니다. 플러그인이 쿼리나 파이프라인을 입력하면(ui.useQuery, ui.useQueryIn, ui.useAggregation) 대화 상자가 닫힙니다.
sidebarPanels 사이드바에 있는 항목으로, 자체 페이지를 엽니다. 워크스페이스 탭은 /plugin/<id>/<contribution>에 있습니다. 컬렉션 탭이 활성 상태일 때 클릭하면 페이지가 해당 컬렉션에서 열리며 (/plugin/<id>/<contribution>/<connection>/<db>/<collection>) place가 그 컬렉션을 가리킵니다. 그 외의 위치에서는 place가 null입니다. 링크로 열린 페이지는 해당 컬렉션을 읽기 전에 사용자에게 묻고, 사용자는 컬렉션 없이 계속 진행할 수 있습니다. 다른 탭이 표시되는 동안에도 페이지는 로드된 상태로 유지되며, 화면에 보이지 않을 때는 여전히 읽을 수는 있지만 동작할 수는 없습니다(not_visible).
cellRenderers 도큐먼트가 값을 표시하는 모든 곳(표, 트리, 카드, 도큐먼트 페이지, 변경 스트림 세부 정보)에서 값에 대한 짧은 텍스트를 보여 줍니다. 예를 들어 ObjectId가 생성된 날짜를 값 옆에 ("display": "inline", 기본값) 또는 툴팁("display": "tooltip")으로 표시합니다. 툴팁은 해당 셀이나 행에 마우스를 올리거나 포커스하면 전체 값 아래에 플러그인 이름과 함께 표시됩니다. 툴팁의 텍스트는 일반 텍스트이며 tone은 사용되지 않습니다. 스크린 리더는 값과 함께 읽습니다. 플러그인은 값 옆에 텍스트 하나, 툴팁에 텍스트 하나를 제공할 수 있으며, 각 위치에 응답하는 첫 번째 렌더러가 사용됩니다. 페이지는 플러그인당 하나씩 숨겨진 프레임에서 실행되며 documents:read 승인을 받은 플러그인에만 해당하고, 스스로 표시되지 않습니다. match는 geojson, string, number, date, object, objectId, binary(UUID 제외) 중 하나입니다. 셀 렌더러를 참조하세요.

셀 렌더러

앱은 표시하는 값에 대해 최대 200개씩 묶어 cells.render 메시지로 숨겨진 프레임에 묻습니다. 키트를 사용하는 경우 client.onCells로 응답하세요. 

client.onCells((renderer, values, locale, paths, place) =>
  values.map((v) => (typeof v?.$oid === 'string' ? { text: createdAt(v.$oid, locale), tone: 'info' } : null)),
)
  • renderer는 기여 항목의 ID, values는 표준 Extended JSON 형식의 값, locale은 앱의 언어, paths는 각 값의 필드 경로(또는 null), place는 값이 속한 컬렉션(또는 null)입니다.
  • binary 값은 전체가 아닌 앞부분만 전송됩니다: { "$binaryHead": { "base64", "subType", "length" } }이며 처음 2,048바이트를 담습니다. 이미지의 종류와 크기를 알아내기에 충분합니다.
  • 값마다 순서대로 항목 하나로 응답합니다: { "text", "tone" }, 텍스트가 없으면 null, 나중에 다시 묻도록 하려면 { "retry": true }. 길이가 다른 목록은 무시됩니다.
  • 텍스트는 일반 텍스트로 표시되며 값 옆에는 최대 80자, 툴팁에는 최대 200자이고 제어 문자와 숨은 문자는 제거됩니다. tone은 neutral, info, success, warning, danger 중 하나입니다.
  • 응답은 3초 이내에 와야 하며, 그렇지 않으면 일반 값이 그대로 남고 30초 후에 해당 값을 다시 묻습니다. 응답은 값, 언어, 플러그인 설정별로 보관됩니다. 설정이 바뀌면 다시 묻고, 1분이 지난 응답은 해당 값이 다음에 표시될 때 다시 요청되며 새 응답이 올 때까지(다시 묻는 데 실패하면 계속) 이전 응답이 유지됩니다. binary 값의 응답은 길이, 하위 유형, 앞부분의 해시를 키로 보관됩니다.
  • 렌더러는 응답하기 전에 읽을 수 있습니다(예: 다른 도큐먼트에 대한 참조). 이때 요청에서 받은 place를 { place, filter, ... } 형태로 전달하며, 그곳에서만 읽을 수 있습니다. 렌더러 컨텍스트의 place는 null입니다.

컨텍스트

context.get은 페이지의 위치와 표시 방식을 알려 줍니다. 가장 먼저 호출하세요. 컬렉션이 열려 있으면 앱이 뷰인지 확인하는 동안 응답에 최대 3초가 걸릴 수 있습니다. 

{
  "plugin": { "id": "hello-documents", "version": "0.1.0" },
  "contribution": { "kind": "collectionTab", "id": "list" },
  "locale": "en",
  "theme": "dark",
  "accent": "emerald",
  "place": {
    "connectionId": "6650...",
    "connectionName": "Production",
    "db": "shop",
    "coll": "orders",
    "view": false,
    "documentId": null,
    "filter": { "status": "open" }
  },
  "settings": { "tileUrl": "https://tile.example.org/{z}/{x}/{y}.png" }
}
  • kind는 collectionTab, documentAction, sidebarPanel, cellRenderer 중 하나입니다.
  • locale은 앱의 언어입니다: en, tr, zh, ja, es, pt, ko, de, fr, ru.
  • theme은 light 또는 dark입니다.
  • accent는 사용자의 강조 색상입니다: emerald, indigo, violet, ocean, rose. 그 밖의 값은 emerald로 취급하세요.
  • place는 페이지가 컬렉션 없이 열렸을 때(사이드바 페이지, 셀 렌더러) null입니다. connectionName은 null일 수 있습니다. view는 뷰이면 true이며, 읽을 수는 있지만 쓸 수 없고 인덱스가 없습니다. documentId는 도큐먼트 동작의 도큐먼트를 표준 Extended JSON으로 나타내며, 그 외에는 null입니다. filter는 컬렉션 탭의 도큐먼트 필터이며, 그 외에는 {}입니다. 둘 다 데이터이므로 documents:read가 없는 플러그인은 각각 null과 {}를 받습니다.
  • hidden은 개인 데이터 규칙에 따라 컬렉션에서 사용자에게 숨겨지는 필드 경로를 키 목록으로 나열합니다([["contact", "phone"]], "*"는 키 하나, "**"는 모든 깊이의 임의 개수 키). 이름만 제공되며, documents:read가 있는 플러그인에만 해당합니다. 그 외에는 []이고, 앱이 제때(3초) 알 수 없었다면 null입니다. 이러한 필드의 값은 "***"로 전달되므로 이를 필드의 유형으로 착각하지 마세요.
  • settings는 관리자가 설정한 값을 담고 있으며, 설정되지 않은 항목은 없습니다.

사용자가 언어, 테마, 강조 색상을 변경하면 앱은 locale, theme, accent와 함께 context.changed를 보냅니다(키트의 client.onContext). 즉시 적용하세요. 페이지가 다른 테마나 언어를 표시해서는 안 됩니다. 도큐먼트를 읽을 수 있는 플러그인은 페이지가 로드된 동안 도큐먼트 필터가 바뀔 때도 context.changed를 받습니다. ui.keepOpen을 호출한 컬렉션 탭은 화면에 보이지 않는 동안 사용자가 설정하는 모든 필터를 전달받습니다. 새 place가 필요하면 context.get을 다시 호출하세요.

브리지 API

프로토콜

페이지와 앱은 postMessage로 일반 JSON을 주고받습니다. 키트 (packages/plugins/kit/src/client.ts)와 스타터의 main.js가 이를 구현합니다. 직접 작성하는 경우 따라야 할 규칙은 다음과 같습니다.

  1. event.source가 window.parent이고 mm이 1인 메시지만 읽습니다.
  2. 페이지가 로드되면 앱이 인사를 보냅니다: { "mm": 1, "type": "hello", "token": "..." }. 첫 토큰을 보관하세요. 그 전에는 아무것도 보내지 않습니다.
  3. 요청은 { "mm": 1, "id": 1, "method": "documents.find", "params": { ... }, "token": "..." } 형식이며, 대상 '*'로 window.parent에 게시합니다(프레임의 출처는 불투명). ID는 숫자이거나 최대 64자의 문자열이며, 앱은 토큰이 없는 요청을 무시합니다.
  4. 응답에는 같은 ID가 담깁니다: { "mm": 1, "id": 1, "result": ... } 또는 { "mm": 1, "id": 1, "error": { "code": "...", "message": "..." } }.
  5. 앱은 사용자가 변경할 때마다 { "mm": 1, "type": "context.changed", "locale", "theme", "accent" }를 보내고(documents:read가 있는 플러그인에는 도큐먼트 필터도 보냄), 셀 렌더러에는 { "mm": 1, "id": "h1", "method": "cells.render", "params": { ... } }로 묻습니다. 이에 대한 응답은 { "mm": 1, "id": "h1", "token", "result": [...] }입니다.

페이지는 자신의 주소를 벗어나서는 안 됩니다. 다른 페이지를 로드하면(링크, 폼, location 변경) 앱이 브리지를 닫고 프레임을 제거하며, 사용자가 플러그인을 다시 열어야 합니다. 모든 것을 한 페이지 안에서 처리하세요. 

import { createClient, askMessage, AskError } from './kit/client'

const client = createClient()                       // requests time out after 15 s ("timeout")
client.onContext((locale, theme, accent) => restyle(locale, theme, accent))
client.onReady(async () => {
  const context = await client.ask('context.get')
  if (!context.place) return showNoCollection()
  try {
    const { documents, hasMore } = await client.ask('documents.find', { filter: context.place.filter, limit: 100 })
    show(documents, hasMore)
  } catch (e) {
    showError(askMessage(e, context.locale))         // the app's code, in the user's language
  }
})

ui.importDocuments
없음		 { ndjson } → true 해당 컬렉션에서. 이 도큐먼트를 파일로 하여 앱의 가져오기 마법사를 엽니다. 한 줄에 JSON 객체 하나이며 최대 1,000,000자이고, 전체 메시지는 JSON으로 최대 1MB입니다(따옴표나 백슬래시는 두 번 계산됩니다). 사용자가 직접 확인하고 매핑한 다음 자신의 권한으로 가져오기를 시작합니다. 페이지에서 클릭한 직후에만 가능하며 ui.use… 메서드와 함께 집계됩니다. 앱의 다른 곳을 누른 직후에는 먼저 묻습니다. 앱에서 대화 상자가 열려 있는 동안은 busy, 사용자가 도큐먼트를 쓰고 거기서 작업을 실행할 수 없거나 시스템 데이터베이스인 경우 not_permitted, 뷰에서는 read_only입니다.

documents.find, documents.findIn, ui.useQuery의 필터, 프로젝션, 정렬과 documents.aggregate에서는 연산자 $where, $function, $accumulator, $out, $merge, $lookup, $graphLookup, $unionWith가 모든 깊이에서 거부됩니다(위에서 설명한 최상위 일반 $lookup은 예외). ui.useAggregation의 스테이지는 사용자가 자신의 권한으로 실행하므로 다른 컬렉션을 읽을 수 있지만, $where, $function, $accumulator, $out, $merge는 절대 포함할 수 없습니다. 읽기는 즉시 실행되며, ui.useQuery와 ui.useAggregation은 작업을 사용자에게 넘기기만 합니다.

제한

  • 메시지는 양방향 모두 최대 1MB이며, 더 큰 응답은 too_large로 실패합니다. 도큐먼트를 더 적게 요청하거나 프로젝션하는 필드를 줄이세요.
  • 동시에 대기할 수 있는 요청은 최대 8개입니다(too_many).
  • 프레임당 분당 최대 60회 읽기(documents.find, .get, .aggregate, .findIn, collections.list, database.model)이며, 이와 별도로 정의 읽기 120회 (indexes.list, validation.get)가 허용됩니다. 컬렉션 50개의 데이터 사전은 모델 1회와 정의 100회입니다.
  • 플러그인 페이지에서 클릭한 직후. ui.copy, ui.useQuery, ui.useAggregation, ui.importSql, ui.exportSql, ui.openDocument, ui.download, ui.importDocuments, documents.update는 플러그인 자체 페이지에서 사용자의 클릭이나 키 입력이 유효한 동안에만 받아들여집니다. 프레임에 포커스가 있어야 하므로 앱의 다른 곳에서 클릭한 것은 인정되지 않습니다. 이들은 클릭 핸들러에서 다른 것을 기다리기 전에 바로 호출하세요. 그렇지 않으면 no_activation으로 실패합니다. ui.copy, ui.use…, SQL 페이지, ui.openDocument에 대한 모든 시도는 거부되었더라도 해당 메서드의 제한에 집계됩니다. 클릭을 기다리며 계속 시도하는 플러그인은 그 분의 한도를 소진합니다 (too_many). documents.update는 한 번에 하나의 질문과 두 번의 거절로 제한됩니다. 프레임은 클릭 없이도 포커스를 가질 수 있으므로, 앱의 다른 곳에서 클릭하거나 키를 누른 후 5초(브라우저의 활성화가 유지되는 시간) 이내에 요청된 ui.copy, ui.download, ui.importDocuments는 플러그인의 말만으로 실행되지 않습니다. 앱이 사용자에게 플러그인과 요청 내용(문자 수와 텍스트의 시작 부분(숨은 문자는 풀어서 표시), 파일 이름과 크기, 어느 컬렉션에 몇 개의 도큐먼트인지)을 밝히며 묻고, 앱 자체의 복사, 저장, 열기 클릭으로 실행합니다. 플러그인의 응답은 그때까지 대기합니다(사용자가 닫으면 declined, 응답이 없으면 unanswered, 하나가 대기 중이면 busy). 앱이 플러그인을 위해 하는 모든 질문(이러한 요청, 변경, 입력된 스테이지)은 포인터가 가리키고 있더라도 150초 후에 종료됩니다. 키트는 이러한 요청을 180초 동안 기다리므로, 페이지는 자체 타임아웃이 아니라 앱의 응답을 받게 됩니다.
  • 화면에 보일 때. documents.update, ui.openDocument 및 위의 메서드는 셀 렌더러나 다른 탭이 표시되는 동안 유지된 페이지에서는 not_visible로 실패합니다.

오류

코드 의미
bad_params 매개변수가 없거나, 유형이 잘못되었거나, 범위를 벗어났거나, 거부된 연산자를 포함합니다.
not_permitted 플러그인이 해당 권한에 대해 승인되지 않았거나, 사용자가 이 작업을 할 수 없습니다.
unknown_method 해당 메서드가 없습니다.
unavailable 이 위치에서는 메서드가 제공되지 않습니다.
no_collection 페이지가 컬렉션 없이 열렸습니다.
not_visible 프레임이 화면에 보이지 않습니다(셀 렌더러, 백그라운드 페이지).
no_activation 플러그인 페이지에서 클릭하거나 키를 누른 직후가 아닙니다.
too_many 대기 중인 요청이 너무 많거나 최근 1분 동안 요청이 너무 많습니다.
too_large 1MB를 초과하는 메시지이거나, 사용자에게 표시하기에 너무 긴 변경입니다.
busy 이 프레임의 파이프라인이 아직 실행 중이거나, 사용자의 응답을 기다리는 질문이 있습니다.
declined 사용자가 거절했습니다.
unanswered 사용자가 앱의 질문에 제때 응답하지 않았으며 아무것도 실행되지 않았습니다. 거절로 집계되지 않습니다.
blocked 사용자가 두 번 거절했으므로 플러그인을 다시 열어야 합니다.
read_only 뷰이거나 앱이 읽기 전용으로 실행 중입니다.
not_found 해당 도큐먼트가 없습니다.
timeout 제때 응답이 없습니다(키트 클라이언트가 15초 후에 설정).
failed 그 밖의 모든 경우이며, 앱은 내부 오류를 전달하지 않습니다.

서버 자체의 거부도 소문자로 전달됩니다. 예를 들어 forbidden, conflict(그 사이에 도큐먼트가 변경됨), validation_error가 있습니다. 키트의 askMessage(error, locale)는 일반적인 코드를 읽는 사람의 언어로 된 문장으로 바꿔 줍니다.

권한

관리자는 플러그인이 나열한 권한에 대해 플러그인을 승인하며, 권한 이름은 플러그인 페이지에 표시되는 대로입니다. 필요한 최소한의 권한만 요청하세요. 권한 하나하나가 관리자가 거부할 이유가 됩니다.

권한 관리자에게 표시되는 내용 허용하는 것
documents:read 도큐먼트 읽기 documents.find, .get, .aggregate. 도큐먼트 동작과 셀 렌더러는 이 권한이 있어야만 제공됩니다.
documents:write 도큐먼트 변경(변경할 때마다 확인) documents.update이며, 변경할 때마다 사용자가 확인합니다. 이 권한을 요청하면 항상 그 자체로 중간 수준의 스캔 결과가 됩니다.
collection:read 이 컬렉션의 인덱스 읽기 indexes.list.
database:read 같은 데이터베이스의 다른 컬렉션 읽기(이름과 도큐먼트) collections.list, documents.findIn, 일반 $lookup.

권한이 없는 플러그인도 페이지를 표시하고, 컨텍스트와 설정을 읽고, ui.* 메서드를 사용할 수 있습니다. 권한은 사용자 자신의 권한을 넘을 수 없습니다. 컬렉션을 읽을 수 없는 사용자는 플러그인을 통해서도 읽을 수 없습니다.

샌드박스

페이지는 sandbox="allow-scripts"가 지정된 iframe에서 로드되며, 플러그인, 버전, 승인된 파일, 사용자 세션을 명시한 서명된 주소에서 봉인되어 제공됩니다(티켓: 페이지는 10분 이내에 로드되어야 하며, 다른 파일은 세션이 유지되는 동안, 최대 12시간. 다른 탭에서의 로그인이나 비밀번호 변경으로 제자리에서 갱신된 세션은 그대로 따라감. 로그아웃하면 주소는 더 이상 아무것도 제공하지 않고 브라우저는 그 파일을 하나도 보관하지 않음). 제공되는 모든 파일은 승인된 SHA-256과 대조하여 확인됩니다. 정책(Content-Security-Policy)은 X-DNS-Prefetch-Control: off와 함께 다음과 같습니다. 

default-src 'none'; script-src <its files>; style-src <its files>;
img-src <its files> data: blob: <the origins of its url settings>; font-src <its files>;
connect-src 'none'; webrtc 'block'; frame-ancestors 'self'; base-uri 'none'; form-action 'none';
sandbox allow-scripts

코드에 미치는 영향은 다음과 같습니다.

  • 네트워크 전혀 없음. 플러그인 자체 파일을 포함해 어떤 주소에도 요청할 수 없습니다. 불러올 .json 파일 대신 데이터를 스크립트 모듈(data.js)에 넣으세요. WebRTC나 프리페치 힌트도 사용하지 마세요. 모든 브라우저가 차단하는 것은 아니며 스캔이 이를 높음 위험으로 표시합니다.
  • 인라인 코드나 스타일 없음. 스크립트와 스타일은 플러그인 파일에서만 제공됩니다. 인라인 <script>, <style> 요소, style 속성, 인라인 이벤트 핸들러, eval을 사용할 수 없습니다. 스크립트에서 속성을 설정하는 것(el.style.width = '40px')은 동작합니다.
  • 불투명한 출처. 쿠키, localStorage, IndexedDB를 사용할 수 없으며 실패합니다. 상태는 메모리에 보관하세요. 관리자가 선택하는 설정은 매니페스트의 settings에서 가져옵니다.
  • 팝업, 대화 상자, 폼, 다운로드 없음. window.open, alert, confirm, 폼 제출은 아무 일도 하지 않습니다. 복사는 ui.copy로 하고, 파일은 앱 자체의 가져오기 및 내보내기를 통해 사용자에게 전달하세요.
  • 앱에 대한 접근 없음. 페이지는 앱의 페이지, 세션, 스토리지를 읽을 수 없습니다. 앱과 메시지를 주고받을 수만 있습니다.
  • 글꼴과 이미지는 자체 파일(또는 data: 및 blob: 이미지)이어야 합니다.

보안 스캔

모든 플러그인의 파일은 발견되거나 설치될 때 관리자가 승인하기 전에 스캔됩니다. 스캔은 스크립트 (.js, .mjs, .cjs), 마크업 (.html, .htm, .svg), 스타일(.css) 파일을 주석을 포함해 줄 단위로 읽고, 각 결과를 심각도, 규칙, 파일, 줄, 발췌문과 함께 나열합니다. 마크업 파일은 전체를 한꺼번에도 읽으므로 여러 줄에 걸친 <script> 태그나 인라인 핸들러도 발견됩니다. 플러그인에 번들된 라이브러리도 직접 작성한 코드와 똑같이 스캔됩니다. 스캔은 휴리스틱입니다. 텍스트에서 알려진 패턴을 찾을 뿐이므로 이를 피하도록 작성된 코드(예: 조각을 이어 붙여 만든 이름)는 발견되지 않으며, 깨끗한 스캔 결과가 안전을 증명하지는 않습니다. 높음 결과가 있는 플러그인은 관리자가 위험을 감수하겠다는 뜻으로 플러그인 ID를 입력해야만 승인할 수 있습니다. 이는 서버가 강제하며, 감사 로그에는 스캔 건수와 위험 수락 여부가 기록됩니다. 높음 결과는 모두 피하고, 중간 결과는 설명할 수 있는 것만 남기세요.

통과하는 방법:

  • 텍스트는 textContent, append('text') 또는 키트의 h() 헬퍼로 쓰고, 요소는 document.createElement로 만드세요. 요소를 비우려면 replaceChildren()를 사용하세요. 이들은 표시되지 않으며, 마크업을 할당하거나 덧붙이는 것 (innerHTML = 또는 innerHTML +=)은 항상 표시됩니다.
  • 핸들러는 마크업이 아니라 addEventListener로 연결하세요.
  • setTimeout과 setInterval에는 함수를 전달하세요. 앱에는 window.parent.postMessage로만 접근하세요.
  • 모든 파일을 NUL 바이트 없이 UTF-8로 저장하세요(UTF-16은 불가).
  • 사용하지 않더라도 외부와 통신하는 코드를 포함하지 마세요. 라이브러리가 무엇을 가져오는지 확인하세요. 최소화되지 않은 빌드를 선호하거나 README에서 minified 결과를 설명하고, 큰 데이터를 base64 문자열에 넣지 마세요.
  • 주석도 스캔된다는 점을 기억하세요. eval(이나 innerHTML =를 언급하는 주석도 스캔 결과가 됩니다.
  • 남아 있는 각 스캔 결과가 안전한 이유를 README에 쓰세요. 어느 라이브러리인지, 어느 줄인지, 왜 실행되지 않는지 또는 샌드박스가 왜 막는지를 적습니다.

스크립트, 마크업, 스타일 파일만 스캔됩니다. 매니페스트는 documents:write(항상 중간 결과) 여부를 확인하기 위해 읽습니다. 따라서 플러그인이 도큐먼트를 변경하는 경우에만 요청하세요. 파일 하나에서 한 규칙의 결과는 최대 10개, 전체 결과는 최대 200개(가장 심각한 것 먼저)까지만 나열되지만, 건수에는 항상 모든 결과가 포함됩니다. 모든 패턴은 선형 시간에 실행되므로 어떤 파일에서든 스캔이 빠르게 끝납니다. 스캔 자체가 실패해도 플러그인은 손상됨으로 표시되지 않습니다. 스캔이 없는 상태가 되며(Mongo Manager와 함께 제공되는 플러그인이 아닌 경우) 높음 결과가 있을 때와 같이 ID를 입력해야만 승인할 수 있습니다. Mongo Manager와 함께 제공되는 플러그인의 스캔도 표시되지만, 승인할 때 ID를 요구하지 않습니다.

UI 및 테마

플러그인은 앱의 일부처럼 보여야 합니다. 사용자의 테마와 강조 색상에 맞는 색상, 서체, 간격을 사용해야 합니다. Mongo Manager 자체 플러그인은 packages/plugins/kit의 플러그인 키트를 사용합니다.

  • kit/src/ui.css: 라이트와 다크, 각 강조 색상에 대한 앱의 디자인 토큰 (--ds-surface, --ds-fg, --ds-accent...)과 컴포넌트 (mm-btn, mm-table, mm-empty, mm-callout...). 글꼴은 @fontsource 패키지의 파일입니다. 플러그인과 함께 번들하거나, 시스템 글꼴을 쓰려면 @font-face 규칙을 제거하세요.
  • kit/src/ui.ts: applyLook(theme, accent)는 html.dark와 html[data-accent]를 설정하고, h(tag, props, ...children)는 텍스트가 항상 텍스트로 처리되는 요소를 만듭니다. 그 외에 icon, button, segmented, switchControl, chip, badge, pageHeader, emptyState, skeleton, callout, table, valueView, describeValue, formatNumber, statusLine, setBusy, serialAsk가 있습니다.
  • kit/src/client.ts: createClient, AskError, askMessage.

키트는 번들하여 사용하도록 만들어진 TypeScript입니다. kit/src를 프로젝트에 복사하고, 자체 제공 플러그인의 vite.config.ts처럼 인라인 스크립트가 없는 상대 경로로 Vite(또는 다른 번들러)로 빌드하세요: base: './', modulePreload: { polyfill: false }, assetsInlineLimit: 0. 소스가 아니라 빌드 출력을 패키징하세요. 반면 스타터는 클라이언트와 색상의 짧은 사본을 순수 JavaScript와 CSS로 담고 있습니다. 

import './kit/ui.css'
import { createClient } from './kit/client'
import { applyLook, h, pageHeader, emptyState, button } from './kit/ui'

const client = createClient()
client.onContext((locale, theme, accent) => applyLook(theme, accent))
client.onReady(async () => {
  const context = await client.ask('context.get')
  applyLook(context.theme, context.accent)
  document.body.append(
    h('div', { class: 'mm-page' },
      pageHeader({ icon: 'table', title: 'Hello', description: context.place?.coll ?? '' }),
      emptyState({ icon: 'search', title: 'Nothing yet', action: button({ label: 'Load', variant: 'primary' }) }),
    ),
  )
})

페이지가 표시되는 위치에 맞게 설계하세요. 컬렉션 탭은 넓고, 도큐먼트 동작은 대화 상자이며, 사이드바 페이지는 워크스페이스를 가득 채웁니다. 표시할 것이 없고 place가 null이면 빈 상태를, 읽는 동안에는 스켈레톤을, 거부된 경우에는 앱의 표현을 사용하세요. 페이지가 키보드로 동작하도록 버튼과 실제 컨트롤을 사용하세요.

언어

앱은 영어, 터키어, 중국어 간체, 일본어, 스페인어, 브라질 포르투갈어, 한국어, 독일어, 프랑스어, 러시아어를 지원합니다. context.locale은 en, tr, zh, ja, es, pt, ko, de, fr, ru 중 하나입니다. 플러그인은 가능한 한 많은 언어를 지원해야 하며 영어는 항상 지원해야 합니다.

  • 매니페스트의 모든 현지화된 텍스트에 en 외에 지원하는 각 언어를 넣으세요.
  • 페이지에서는 언어별 표에 문구를 보관하고 context.locale로 선택하며(없는 언어는 영어), document.documentElement.lang은 문구가 실제로 쓰인 언어로 설정하며(영어로 대체했다면 en, 올바른 글리프가 표시되도록 중국어와 포르투갈어는 zh-CN과 pt-BR), 숫자도 같은 언어로 서식을 지정하고, context.changed에서 다시 렌더링하세요.
  • 셀 렌더러는 각 배치가 요청된 locale로 응답합니다.
  • 숫자와 날짜는 해당 언어에 맞게 서식을 지정하세요(Intl.NumberFormat, Intl.DateTimeFormat).
  • 각 언어마다 README.md 옆에 README.<language>.md (README.tr.md, README.zh.md, …)를 추가하고, 릴리스 노트도 각 언어로 작성하세요.

  3. 사용 방법을 예시와 함께 단계별로.
  4. 각 권한과 그것이 필요한 이유.
  5. 설정이 있다면 그 설정.
  6. 제한: 읽는 도큐먼트 수, 처리하지 않는 것.
  7. 남아 있는 각 스캔 결과와 그것이 안전한 이유.

릴리스 노트는 매니페스트의 changelog에 최신 항목부터 버전당 항목 하나씩, 날짜와 함께 영어와 지원하는 각 언어로 작성합니다. 세부 정보 페이지에 이 내용이 표시되며, 업데이트 후에는 지난 버전 이후의 버전이 새 항목으로 표시됩니다.

버전 및 승인

  • 승인은 정확한 파일에 대한 것입니다. 파일의 다이제스트, 즉 모든 파일의 경로와 SHA-256에 대한 SHA-256이 기준입니다. 관리자는 승인하기 전에 이를 확인합니다.
  • 업로드된 플러그인이나 플러그인 폴더의 어떤 파일이든 변경되면(새 버전, README의 오타 수정 포함) 관리자가 다시 승인할 때까지 비활성화됩니다. 관리자가 무엇을 승인하는지 알 수 있도록 릴리스마다 version을 올리고 changelog 항목을 추가하세요.
  • ID가 이미 설치된 플러그인을 업로드하면 교체됩니다. 파일이 승인된 파일과 완전히 같을 때만 활성화된 상태로 유지됩니다. 새 매니페스트가 같은 유형으로 설정을 계속 선언하는 동안은 설정이 유지됩니다.
  • 직접 배치한 플러그인 폴더는 직접 관리합니다. 같은 ID의 업로드는 거부되며, 앱에서 제거하면 폴더를 삭제하지 않고 플러그인만 잊습니다.
  • Mongo Manager와 함께 제공되는 플러그인만 업데이트 후에도 승인이 유지되며, 활성화되어 있고 업데이트가 새 권한을 요청하지 않는 동안에만 해당합니다. 이때는 관리자에게 아무것도 요청하지 않으며, 플러그인의 세부 정보 페이지에 승인이 유지되었다고 표시됩니다. 관리자가 직접 승인한 업데이트에는 관리자가 승인했다고 표시됩니다.

패키징

플러그인은 gzip으로 압축한 tar 아카이브(.tgz)로 전달되며, 파일은 아카이브의 루트에 있고 mongo-manager-plugin.json도 그 안에 있어야 합니다. 모든 것을 담은 최상위 폴더 하나 (npm pack의 package/처럼)는 허용되며 제거됩니다. 아카이브에는 일반 파일만 들어 있어야 합니다(폴더는 암시됨). 링크, 장치, 특수 항목, 단순하지 않은 경로, 중복된 경로는 거부되며, 압축 해제 후 최대 500개 파일과 25MB, 업로드는 최대 30MB입니다.

GitHub에 게시

관리자는 이를 허용하도록 설정된 서버에서(MM_PLUGINS_GITHUB=1, 기본적으로 꺼져 있음) 공개 GitHub 저장소에서 플러그인을 바로 설치할 수 있습니다. 플러그인 페이지에서 다음 주소 중 하나를 붙여 넣습니다.

  • https://github.com/<owner>/<repo>, …/releases 또는 …/releases/latest: 최신 릴리스용;
  • https://github.com/<owner>/<repo>/releases/tag/<tag>: 특정 릴리스용. 태그에는 슬래시가 포함될 수 있습니다(최대 4개 부분).

주소에는 그 외의 것이 없어야 합니다: 쿼리, 프래그먼트, 포트, 자격 증명 불가. 이름이 바뀐 저장소는 따라갑니다. 릴리스 자체의 페이지 주소가 해당 저장소를 가리키기 때문입니다. 앱은 해당 릴리스의 플러그인 아카이브, 즉 이름이 .tgz 또는 .tar.gz로 끝나는 유일한 에셋을 다운로드합니다. 그러한 에셋이 없거나 여러 개인 릴리스는 거부됩니다. 태그와 에셋 이름은 인쇄 가능한 ASCII여야 합니다. 에셋은 해당 저장소의 릴리스에 속해야 하며, 선언된 크기와 실제로 읽은 크기 모두 업로드 한도(30MB)를 넘으면 안 됩니다.

앱은 github.com, api.github.com, objects.githubusercontent.com, release-assets.githubusercontent.com과만, https로, 공개 주소로만 통신하며 서버의 어떤 정보(쿠키, 토큰, 자격 증명)도 보내지 않습니다. 리디렉션은 최대 4번, 위 호스트 사이에서만 따라가고, 릴리스 설명은 최대 5MB까지 읽으며, 전체 설치에 4분을 허용합니다. 플러그인은 스캔과 함께 비활성화된 상태로 설치되며, 업로드와 마찬가지로 승인을 기다립니다. 출처(저장소, 릴리스, 아카이브)를 기억하며 세부 정보 페이지에 표시됩니다.

설치에 실패하면 플러그인 페이지에 이유가 표시됩니다: 저장소에 게시된 릴리스가 없음, GitHub의 속도 제한에 도달함, GitHub가 거부함(저장소가 공개가 아님), 서버에서 GitHub에 접근할 수 없음, 리디렉션이 허용되지 않은 호스트로 향함, 리디렉션이 너무 많음, 릴리스에 아카이브가 없거나 여러 개임, 아카이브가 해당 저장소의 릴리스에 없음.

  1. version을 올리고, changelog 항목을 추가하고, publishedAt을 설정합니다.
  2. node scripts/pack.mjs를 실행합니다.
  3. GitHub 릴리스를 만들고(예: 태그 v0.1.0) hello-documents-0.1.0.tgz를 에셋으로 첨부합니다. 다른 .tgz나 .tar.gz 파일은 첨부하지 마세요.
  4. 최신 릴리스로 표시합니다. 관리자가 앱에 표시되는 값과 비교할 수 있도록 pack.mjs가 출력한 다이제스트를 릴리스 노트에 넣으세요.

GitHub 설치는 MM_PLUGINS_GITHUB=1을 설정하지 않으면 꺼져 있습니다. 서버가 GitHub에 접근할 수 없거나 프록시를 통해서만 접근할 수도 있습니다(설치는 GitHub에 직접 연결하며 HTTP 프록시 설정을 사용하지 않음). 이 경우 관리자는 .tgz를 다운로드하여 플러그인 업로드로 업로드합니다.

다른 사람이 찾을 수 있도록 Awesome Mongo Manager(github.com/mongo-manager/awesome-mongo-manager)에 플러그인을 올리세요. 그곳에서 README에 한 줄을 추가하는 풀 리퀘스트를 엽니다. 목록의 검사는 최신 릴리스를 내려받아 GitHub에서 설치할 때처럼 앱 자체의 코드로 검사하며, 이후 목록 관리자가 플러그인을 읽어 본 뒤 목록에 올립니다.

자체 서버에서 테스트

  1. 플러그인을 켠 상태(기본값)로 Mongo Manager를 실행하고 관리자로 로그인합니다. 데이터 디렉터리를 찾으세요. MM_DATA_DIR이 달리 지정하지 않는 한 ~/.mongo-manager입니다.
  2. 플러그인을 <data-dir>/plugins/<id>에 복사합니다: node scripts/pack.mjs --folder ~/.mongo-manager/plugins. 폴더 이름은 ID와 같아야 하며 숨김 파일이 없어야 합니다(그래서 스크립트는 플러그인의 파일만 복사합니다). ~/는 모든 셸에서 홈 폴더이며, cmd와 PowerShell에서는 ~\이거나 따옴표 안에 넣어야 합니다(bash와 zsh는 따옴표 없는 백슬래시를 버리며, 그러면 스크립트가 남은 것을 거부합니다). 스크립트는 복사할 수 있는 파일과 폴더(스크립트, 숨김 파일, 링크, 파이프, 소켓 없음)만 있고 그 위나 안에 마운트된 파일 시스템이 없는, 이 플러그인의 폴더만 교체하며, 새 복사본을 교체해 넣으므로 중간에 멈춰도 폴더는 원래대로 남습니다. 대상이 플러그인 자체 폴더이거나, 그 안에 있거나, 그것을 포함하는 경우 (심볼릭 링크, 정션, 공유로 경로가 가리키는 경우에도) 거부하며, 이때 아무것도 쓰지 않습니다.
  3. 플러그인을 열고 다시 스캔을 클릭합니다. 사용할 수 없는 플러그인은 이유(매니페스트 필드, 경로)를 표시합니다. 세부 정보를 열어 관리자처럼 스캔 결과, 권한, README를 읽어 보세요.
  4. 승인 및 활성화를 클릭한 다음 컬렉션을 열고 모든 기여 지점을 시험합니다.
  5. 변경할 때마다 다시 복사하고 다시 스캔을 클릭한 뒤(파일이 변경되었으므로) 다시 승인하고, 탭, 페이지 또는 대화 상자를 다시 여세요. 여러 언어, 두 가지 테마, 뷰, 도큐먼트가 없는 컬렉션, 컬렉션 없이 열린 사이드바 페이지를 시험하세요.
  6. 마지막으로, 사용자가 하는 것처럼 깨끗한 서버에서 플러그인 업로드로 .tgz 자체를 업로드하세요.

브라우저의 개발자 도구는 프레임 안에서도 동작합니다. 콘솔에서 플러그인의 프레임을 선택하면 오류와 메시지를 볼 수 있습니다. 콘솔의 정책 위반은 페이지가 샌드박스에서 금지된 것을 시도했다는 뜻입니다.

AI 어시스턴트로 만들기

스타터에는 이 페이지의 모든 내용을 AI 코딩 어시스턴트에게 가르치는 지침 파일이 들어 있습니다. 매니페스트 규칙, 브리지 메서드와 권한, 샌드박스, 스캔, 언어, README, 패키징, 게시가 포함됩니다. 이 파일들을 플러그인 저장소의 최상위에 두세요. pack.mjs는 아카이브에서 이를 제외합니다. 플러그인 페이지는 스타터를 .zip으로 저장하며, 이미 가지고 있는 플러그인에 추가할 수 있도록 AI 어시스턴트용 지침 아래에서 각 파일도 따로 저장합니다. Copilot용 파일은 저장소의 .github 폴더에 넣을 수 있도록 copilot-instructions.md로 저장됩니다.

  • CLAUDE.md: Claude Code.
  • AGENTS.md: OpenAI Codex 및 AGENTS.md를 읽는 다른 에이전트.
  • GEMINI.md: Gemini CLI.
  • .github/copilot-instructions.md: GitHub Copilot.

어시스턴트에게 플러그인이 해야 할 일을 요청하세요. 스캔과 아래 체크리스트를 통과하는 코드로 응답해야 합니다. 게시하기 전에 작성된 내용을 읽어 보세요. 관리자가 신뢰하는 사람은 바로 당신입니다.

게시 전 체크리스트

  • ID가 고유하고 폴더 이름과 같습니다. 버전을 올렸고 오늘 날짜의 changelog 항목이 있습니다.
  • 모든 현지화된 텍스트에 en과 tr이 있습니다. 페이지가 locale과 context.changed를 따릅니다.
  • 권한은 동작하는 최소한이며, README가 각 권한이 필요한 이유를 설명합니다.
  • 스캔에 높음 결과가 없고, README가 그 밖의 모든 결과를 설명합니다.
  • 텍스트는 textContent 또는 h()로 작성하며, 텍스트로 마크업을 만들지 않습니다.
  • 네트워크에 접근하지 않고(fetch, WebRTC, 프리페치 힌트 없음), 스토리지를 사용하지 않고, 팝업을 열지 않고, 페이지를 벗어나지 않습니다.
  • 인라인 스크립트, 스타일, 이벤트 핸들러가 없고, 모든 경로가 상대 경로입니다(./main.js).
  • 모든 파일이 NUL 바이트 없이 UTF-8로 저장되어 있습니다.
  • 페이지가 테마와 강조 색상을 따르며 키보드로 동작합니다.
  • place가 null인 경우, 뷰, 빈 컬렉션, 그리고 마주칠 수 있는 각 오류 코드를 처리합니다.
  • 클릭이 필요한 호출은 클릭 핸들러에서 바로 이루어집니다.
  • 큰 읽기에는 한도가 있습니다: limit, 프로젝션, 한 번에 하나의 파이프라인.
  • README.md와 번역본이 플러그인을 설명하며, license, author, repository가 설정되어 있습니다.
  • .tgz를 깨끗한 서버에 업로드하여 스캔하고, 승인하고, 시험했습니다.
  • GitHub 릴리스에는 <id>-<version>.tgz라는 이름의 플러그인 아카이브가 정확히 하나만 있습니다.
