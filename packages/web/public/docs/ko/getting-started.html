시작하기

설치

다음 중 하나를 사용하세요. 각 릴리스는 모든 파일을 SHA-256 체크섬과 함께 제공하므로 인터넷에 연결되지 않은 환경에서도 확인할 수 있습니다.

  • npm(Node.js 24 이상): npx @mongo-manager/app
  • 오프라인 npm: npm install --global ./mongo-manager-<version>.tgz
  • 독립 실행형 바이너리: 사용 중인 시스템에 맞는 파일을 내려받아 실행하세요. Node.js가 필요 없습니다.
  • Docker: docker compose -f deploy/docker-compose.yml up -d

지원하는 MongoDB: 6.0 이상. 이보다 오래된 서버는 연결할 때 그 사실을 알리는 메시지와 함께 거부됩니다.

처음 실행

로컬 모드(기본값)는 한 컴퓨터에서 한 사람이 사용하는 방식입니다. Mongo Manager는 127.0.0.1:4321에서 요청을 받고 브라우저를 엽니다. 로그인은 없으며, 일회용 링크로 열립니다. 터미널에서 시작하면 주소 다음 줄에 링크를 출력하고, 그 외의 환경(서비스, 컨테이너, 로그)에서는 앱을 여는 파일의 경로를 출력하며 이 파일은 사용자 계정만 읽을 수 있습니다. 이후 브라우저는 이 사이트의 데이터를 보관하는 동안 계속 로그인된 상태로 유지되고(마지막 사용 후 최대 6개월, Safari는 방문하지 않으면 일주일 후 삭제), 설치한 앱도 마찬가지입니다. 단, Mac의 Safari 웹 앱은 자체 데이터를 따로 보관하며 링크를 전달할 수 없으므로 그곳에서는 Safari 탭에서 Mongo Manager를 사용하세요. 같은 컴퓨터의 다른 프로그램이나 계정이 이 주소를 열면 여는 방법을 안내하는 페이지만 표시됩니다. 링크를 이미 사용했거나 브라우저가 잊어버렸다면 mongo-manager open을 실행해 새 링크를 받으세요. 터미널에서는 파일을 열 수 없는 브라우저(Linux의 snap 또는 Flatpak 브라우저)를 위해 링크도 함께 출력합니다. 여러 사람이 함께 쓰는 컴퓨터에서는 팀 모드를 사용하세요. 

mongo-manager
mongo-manager open             # a new link for a running Mongo Manager (--no-open prints it)

팀 모드는 사용자, 역할, 2단계 로그인을 추가합니다. 처음 시작하면 터미널에 일회용 설정 토큰을 출력합니다(서비스나 컨테이너로 실행한 경우 데이터 폴더의 setup-token에 있습니다). 페이지를 열고 이 토큰을 입력해 첫 관리자를 만드세요. 

mongo-manager --auth

첫 연결

  1. 연결 추가를 선택하고 첫 번째 필드에 연결 문자열을 붙여넣거나 입력하세요. 예: localhost:27017 또는 mongodb+srv:// 주소(mongodb://는 생략할 수 있습니다). 양식이 자동으로 채워집니다. 필드 아래의 줄에 인식한 내용이 표시되며, 이름을 직접 입력하기 전까지는 호스트를 따라갑니다. 서버, 인증, TLS, SSH 등은 고급 옵션에 있고, 저장 후 연결은 연결을 저장하고 엽니다.
  2. 연결 테스트를 선택하세요. MongoDB 버전과 토폴로지가 표시됩니다.
  3. 저장하세요. 연결이 왼쪽 트리에 나타납니다.

로그인 방식

사용자 이름과 비밀번호(SCRAM) 외에도 연결은 X.509 인증서, LDAP(PLAIN), AWS IAM 키, OIDC 또는 Kerberos로 로그인할 수 있습니다. 방식은 고급 옵션 → 인증에서 선택하세요.

  • MONGODB-OIDC(MongoDB Atlas, Enterprise): 각 사용자가 서버가 지정한 ID 제공업체로 로그인하며 비밀번호는 저장되지 않습니다. 연결을 처음 열면 대화 상자에 로그인이 표시되고, 제공업체 페이지가 이 탭에서 열린 뒤 다시 돌아옵니다. 제공업체의 리디렉션이 Mongo Manager에 도달할 수 없는 환경에서는 대신 코드 사용을 선택하고 제공업체에 표시된 코드를 입력하세요. 이 서버의 …/oidc/callback 주소를 제공업체에 등록하거나, 리디렉션 주소에 다른 주소를 지정하세요. 허용된 호스트는 로그인 정보를 보낼 수 있는 호스트입니다(비어 있으면 Atlas와 이 컴퓨터). 연결 페이지에 로그인 여부가 표시되며 여기서 로그아웃할 수도 있습니다. 워크로드 ID (Azure, GCP, Kubernetes)는 대신 Mongo Manager가 실행되는 머신으로 로그인합니다. 팀 모드에서는 관리자가 허용한 경우에만 사용할 수 있습니다.
  • Kerberos (GSSAPI): 주체(principal)를 지정하고, 서버에서 필요하면 서비스 이름, 영역 (realm), 호스트 이름 정규화도 지정하세요. Mongo Manager를 실행하는 계정의 Kerberos 티켓으로 로그인합니다. 자신의 컴퓨터에서는 본인 계정이고, 팀 모드에서는 서버의 계정이며 관리자가 허용하지 않으면 꺼져 있습니다. npm 패키지의 선택 사항인 kerberos 패키지가 필요합니다(배포 참조).

클라이언트 측 암호화

고급 옵션 → 암호화에서 연결에 클라이언트 측 필드 수준 암호화(CSFLE) 또는 Queryable Encryption을 사용할 수 있습니다. npm 패키지의 선택 사항인 mongodb-client-encryption 패키지가 필요합니다.

  • 키 제공업체: 로컬 96바이트 마스터 키(새 키 생성으로 만들 수 있으며, 사본을 보관하지 않으면 데이터를 복호화할 수 없습니다), AWS KMS, Azure Key Vault, Google Cloud KMS 또는 KMIP. 자격 증명은 봉인되어 보관되며 다시 표시되지 않습니다. 키 볼트는 데이터 키가 저장되는 컬렉션입니다(기본값은 encryption.__keyVault).
  • 모드: 읽기 및 쓰기는 읽을 때 복호화하고 쓸 때 암호화합니다(MongoDB Enterprise 또는 Atlas). 복호화만은 암호화된 값을 복호화해서 읽고 도큐먼트는 쓰지 않습니다 (MongoDB Community). 쿼리 분석은 crypt_shared 라이브러리(그 경로, 팀 모드에서는 서버의 경로) 또는 이 컴퓨터의 mongocryptd를 사용합니다.
  • 암호화된 필드는 연결이 자체 맵을 지정하지 않는 한 서버의 컬렉션 옵션에서 가져옵니다. Queryable Encryption의 encryptedFields, CSFLE의 $jsonSchema 유효성 검사기 등입니다. 도큐먼트 보기에서는 암호화된 필드에 자물쇠 표시가 붙습니다.
  • 연결의 암호화 섹션(관리자용)에서는 데이터 키를 나열하고, 새 키를 만들고, 키를 교체(마스터 키로 다시 래핑)하고, Queryable Encryption 컬렉션을 만들 수 있습니다. 각 필드의 유형과 동등 또는 범위로 쿼리할 수 있는지를 지정하며, 각 필드마다 데이터 키가 생성됩니다.
  • 개인 데이터가 숨겨진 사용자는 암호화된 값을 저장된 그대로 보며, 해당 연결에는 도큐먼트를 쓸 수 없습니다. 복사는 암호화된 값을 저장된 그대로 옮기며, Queryable Encryption 컬렉션은 복사할 수 없습니다.

홈과 다음 단계

홈은 대시보드 사용자 지정으로 위젯을 추가, 제거, 크기 조정, 이동할 수 있는 대시보드이며, 서버에 사용자별로 저장됩니다. 다음 단계 위젯은 최근 작업을 바탕으로 앱이 스스로 계산한 할 일을 최대 다섯 개 제안합니다. 발생 중인 알림, 지난 하루 동안 실패한 작업, 확인이 필요한 실시간 동기화와 예약 백업, 마지막으로 사용한 데이터베이스에 제안되는 인덱스(서버를 감시할 수 있는 경우 느린 쿼리 기준), 최근에 열었지만 지금은 열려 있지 않은 항목이 대상입니다. 각 항목은 바로 실행하는 링크입니다. 인덱스 제안은 키가 채워진 기존 인덱스 만들기 대화 상자를 열며, 거기서 확인하기 전에는 아무것도 생성되지 않습니다. ✕로 항목을 닫을 수 있고(실행 취소로 되돌립니다), 닫은 상태는 대시보드와 함께 저장되며 같은 종류의 새 이벤트는 새 단계로 다시 나타납니다. 위젯 메뉴의 닫은 단계 다시 표시는 모두 되돌립니다.

AI 제공업체가 설정되어 있으면 위젯 메뉴에 AI로 정렬이 나타나며, 켜기 전까지는 꺼져 있습니다. 켜면 AI가 단계의 순서를 정하고 제목을 작성하는데, 사실 정보만 사용합니다. 각 단계의 종류, 이름(연결, 데이터베이스, 컬렉션, 인덱스의 필드 이름), 개수만 사용하며 값, 도큐먼트, 오류 텍스트는 절대 사용하지 않습니다. 연결의 AI 정책이 "꺼짐"이거나 "로컬 전용"인데 제공업체가 로컬 네트워크에서 응답하는 것으로 알려지지 않은 경우, 해당 단계는 전송되지 않고 제자리를 유지합니다. AI는 단계를 추가하거나 단계의 동작을 바꿀 수 없습니다. AI가 만든 각 제목 아래에는 앱 자체 문구로 단계가 하는 일이 표시되며, 제목에는 숫자가 들어가지 않습니다(개수는 시간이 지나면 맞지 않게 되므로 앱의 줄에서 알려 줍니다). 단계는 바뀔 때(다른 종류의 단계, 다른 위치) 또는 AI로 다시 정렬을 선택할 때만 다시 정렬되며, 개수가 변했거나 시간이 지났다는 이유로 정렬되지 않습니다. 정렬할 때마다 AI 기록에 ("다음 단계"로, 문구 없이) 그리고 감사 로그에(단계 수만, 이름은 없이) 기록됩니다. 제안된 인덱스는 인덱스를 만들 수 있는 곳에서만 제공됩니다.

쿼리

컬렉션을 열고 { status: 'A', qty: { $lt: 30 } } 같은 필터를 입력한 다음 Enter를 누르세요. 옵션에서는 프로젝션, 정렬, 건너뛰기, 제한, 콜레이션, 힌트, 시간 제한을 추가할 수 있습니다. 최근 쿼리는 해당 컬렉션에서 실행한 쿼리를 나열하며, 별표를 누르면 이름과 태그를 붙여 쿼리를 즐겨찾기로 보관합니다.

바의 값은 {{name}} 형태의 매개변수일 수 있습니다: { status: {{status}}, qty: { $gte: {{min}} } }. 바 아래에 각 매개변수의 필드가 나타나며, 찾기는 거기에 입력한 값으로 쿼리를 실행합니다. 18은 숫자, "18"은 문자열, ISODate("2026-01-01")은 날짜이고, 그 밖의 텍스트는 입력한 그대로 문자열입니다. 바에서 저장한 즐겨찾기는 매개변수를 유지하며, 입력한 값이 기본값이 됩니다. 즐겨찾기를 열면 값이 채워진 채 실행되고, 기본값이 없는 매개변수가 있으면 값을 기다립니다. 따옴표, 정규식, 주석 안에서는 {{name}}이 일반 텍스트입니다. 연결의 개인 데이터를 볼 수 없는 사용자는 다른 사용자의 기본값을 받지 않습니다.

바 아래의 칩은 조건을 제안합니다. 해당 컬렉션에서 최근 실행한 조건, 그리고 컬렉션의 작은 샘플에서 제안되는 조건(status = "paid" 같은 흔한 값, 또는 많은 도큐먼트에 없는 필드)입니다. 칩을 선택하면 필터에 추가되고 실행됩니다. 샘플은 페이지가 유휴 상태가 되었거나 바를 사용할 때 한 번 가져오며, 뷰에서는 가져오지 않습니다(뷰의 파이프라인이 실행되기 때문입니다). 결과 위에는 사용 중인 필터의 각 조건이 별도의 칩으로 표시됩니다. 칩을 제거하면(칩의 x 표시 또는 칩에서 Delete) 그 조건 없이 필터가 실행되고, 실행 취소로 되돌립니다. 바의 텍스트는 사용 중인 필터일 때만 따라 바뀌며, 아직 편집 중인 필터는 그대로 둡니다. 바 아래의 패널은 사용 중인 쿼리를 부분별로 보여 주며, 패널의 실행은 다시 실행하고 별표는 즐겨찾기로 저장합니다.

테이블에서 열 이름을 클릭하면 그 열로 정렬합니다. 오름차순, 내림차순, 정렬 없음 순서로 바뀝니다. Shift + 클릭은 정렬에 열을 추가합니다. 정렬은 옵션에 기록되고 바의 필터와 함께 실행되므로, 바에는 항상 실행되는 내용이 표시됩니다. 열의 가장자리를 끌거나(또는 포커스를 두고 화살표 키를 사용) 너비를 바꾸고, 가장자리를 두 번 클릭하면 열이 다시 자동으로 크기를 맞춥니다. 너비는 컬렉션별로, 사용자별로 이 브라우저에 저장됩니다. 열 메뉴에서는 정렬, 이름 복사, 숨기기를 할 수 있습니다. 값이 숨겨진 열(개인 데이터)은 정렬되지 않습니다.

테이블, 카드, JSON 옆의 차트는 쿼리 결과를 막대, 선, 점, 원형으로 그립니다. X축에 놓을 필드, 숫자 필드의 개수·합계·평균, 결과를 계열로 나누는 필드를 선택하세요. 일치하는 처음 1,000개 도큐먼트까지 (그려지는 필드만) 읽으며 더 있으면 그렇게 알려 주고, 같은 수치의 표가 스크린 리더용으로 제공됩니다. 숨겨진 필드는 제안되지 않으며 차트에 그려지지 않습니다. 데이터베이스, 컬렉션, 열의 메뉴와 스키마의 필드 옆에 있는 이름 복사는 일반 이름을 복사합니다.

도큐먼트를 편집하면 쓰기 전에 어떤 필드가 바뀌는지 정확히 표시되며, 바뀐 필드만 저장됩니다. 테이블에서는 값을 두 번 클릭하거나(또는 값에서 Enter를 눌러) 그 자리에서 편집할 수 있으며, 유형은 유지됩니다.

여러 도큐먼트 업데이트와 여러 도큐먼트 삭제는 실행 전에 미리 보기를 제공합니다. 일치하는 도큐먼트 수와 일부 도큐먼트가 표시됩니다. 업데이트의 경우 각 샘플에 바뀌는 내용이 표시되는데, 아무것도 쓰지 않는 읽기 작업으로 MongoDB가 계산한 것입니다. 업데이트가 실패할 도큐먼트(텍스트에 대한 $inc, 배열을 통과하는 경로)는 표시됩니다. 위치 경로($[]), 배열 인덱스, 조건이 있는 $pull은 샘플에서 미리 보지 않으며, 미리 보기에서 그렇게 알려 줍니다. 개인 값은 샘플에서 전후 모두 마스킹된 상태로 유지됩니다.

컬렉션

새 컬렉션에서는 컬렉션, 캡 컬렉션, 시계열 컬렉션, 뷰에 기본 콜레이션(언어, 강도, 숫자 정렬 및 MongoDB의 나머지 옵션)을 설정할 수 있으며, MongoDB는 생성할 때 이를 고정합니다. 컬렉션 또는 캡 컬렉션은 처음부터 변경 스트림의 사전 및 사후 이미지를 보관하게 할 수도 있습니다. 이후에는 컬렉션 메뉴의 컬렉션 편집에서 (이름을 밝히는 확인 후) 이 이미지를 켜거나 끌 수 있고, 콜레이션을 확인하고, 규칙이 있는 유효성 검사 탭으로 이동합니다. 컬렉션 머리글에는 콜레이션과 이미지 보관 여부가 표시됩니다.

성능

연결의 성능 탭은 서버를 실시간으로 차트로 보여 줍니다. 초당 작업 수, 연결, 네트워크, 메모리를 탭이 열려 있는 동안 2초마다 샘플링합니다. 아래에는 가장 느리게 실행 중인 작업이 있으며, 데이터베이스나 컬렉션, 종류, 실행 시간, 잠금 대기, 유휴 연결로 필터링하고 일시 중지할 수 있습니다. 시간이 가장 오래 걸린 컬렉션도 표시됩니다. 편집자와 관리자가 열 수 있으며, 작업의 "…" 메뉴에는 해당 명령이 표시되고 연결 관리자는 작업 종료를 사용할 수 있는데 먼저 확인을 요청합니다. MongoDB 자체에서 계정이 서버 상태를 읽을 수 있어야 합니다. clusterMonitor 역할을 부여하세요. 그렇지 않으면 탭에 부족한 항목이 표시됩니다.

프로파일러 섹션에는 각 데이터베이스의 프로파일러 수준, slowms, 샘플 비율이 표시되며, 연결 관리자는 데이터베이스 행의 연필 아이콘으로 변경할 수 있습니다. 수준 2(모든 작업)는 먼저 확인을 요청하고 30분 후 이전 설정으로 자동으로 돌아갑니다. 느린 쿼리는 프로파일러와 서버 자체 로그(프로파일러가 꺼져 있어도 작동)에서 가져온 느린 작업을 최신순으로 나열하며, 플랜, 검사한 키와 도큐먼트, 명령이 표시됩니다. 반환하는 것보다 훨씬 많은 도큐먼트를 읽는 작업은 표시되며, 실행 계획 분석에서 열기는 해당 컬렉션에서 실행 계획 분석을 엽니다.

연결의 개인 데이터 탭에서 연결 관리자는 개인 데이터를 담은 필드를 나열할 수 있습니다(예: crm.users.email 또는 *.*.**.phone). 컬렉션 자체의 개인 데이터 탭은 그 컬렉션의 필드만 나열하고 추가하며(새 필드에는 필드 이름만 입력하면 됩니다), 그 컬렉션에 적용되는 연결의 더 넓은 규칙을 표시합니다. 개인 데이터를 볼 수 없음 권한이 부여된 사용자는 프로파일러, 느린 쿼리, 작업에서 해당 값이 ***로 표시되며 셸을 사용할 수 없습니다. 로컬 모드(계정 없음)에서는 규칙이 도큐먼트, 내보내기, AI의 컨텍스트 등 모든 곳에서 본인에게도 값을 숨기며, 숨겨져 있는 동안 셸은 닫혀 있습니다. 연결 탭의 나에게도 숨기기를 끄면 해당 연결에서는 이 동작이 해제됩니다.

인덱스 제안은 데이터베이스의 느린 쿼리를 읽고, 스캔이 발생한 각 쿼리에 대해 동등–정렬–범위 규칙에 따라 인덱스를 제안합니다. 이미 그 쿼리를 처리하는 인덱스가 있으면 제안하지 않습니다. 또한 서버가 시작된 이후 사용되지 않았거나 다른 인덱스의 앞부분인 인덱스도 나열합니다. 필드 이름만 사용합니다. 인덱스 만들기는 키가 채워진 기존 대화 상자를 열며, 거기서 확인하기 전에는 아무것도 생성되지 않습니다.

성능이 열려 있는 동안 연결의 머리글에서 실시간(최근 5분) 또는 저장된 1시간, 24시간, 7일 구간을 선택하세요. 연결 관리자는 옆의 지표 기록 메뉴에서 지표 기록 저장을 켭니다(같은 메뉴에서 확인 후 저장된 내용을 삭제할 수도 있습니다). 그러면 서버가 해당 연결을 1분에 한 번 샘플링하고 7일간 보관합니다(숫자만). 꺼져 있는 동안 서버는 해당 연결에 스스로 접속하지 않습니다. mongos에서는 탭에 샤딩 개요가 표시됩니다. 샤드, 밸런서, 라우터, 각 샤드 컬렉션의 키와 청크 분포이며, 크기와 점보 청크는 요청 시 표시됩니다. 여기서는 클러스터에 아무것도 변경되지 않습니다.

레플리카 세트에서는 같은 탭에 모든 멤버가 나열됩니다. 프라이머리가 어느 멤버인지, 어느 멤버가 다운인지, 각 세컨더리가 프라이머리보다 몇 초 뒤처졌는지(10초 초과는 황색, 60초 초과는 적색), 과반수 커밋 지연, oplog 윈도우, 그리고 최근 몇 분간의 지연 차트가 표시됩니다. 프라이머리가 없는 세트는 빨간색으로 표시되며, 하나가 선출될 때까지 쓰기를 받을 수 없습니다.

집계

컬렉션의 집계 탭에서는 파이프라인을 스테이지 단위로 만듭니다. 스테이지를 추가하고 연산자를 선택하세요 (연산자 필드에 입력하면 이름이나 기능으로 스테이지를 찾을 수 있으며, 예를 들어 "join"은 $lookup을 찾습니다. 화살표 키와 Enter를 사용하며, 목록 옆에 스테이지의 기능과 값의 예시가 표시됩니다. 각 스테이지는 템플릿에서 시작하고 MongoDB 매뉴얼 링크가 있습니다). 그리고 값을 편집하세요. 입력하는 동안 각 스테이지의 출력이 컬렉션의 샘플(처음 1000개 도큐먼트 또는 무작위 샘플)로 미리 표시됩니다. 스테이지는 비활성화하거나, 끌어서 놓기 또는 Alt+위쪽 화살표와 Alt+아래쪽 화살표로 순서를 바꾸거나, 텍스트로 한꺼번에 편집할 수 있습니다.

실행은 전체 결과를(최대 10 000개 도큐먼트) 중지 버튼과 함께 스트리밍하며, 총계 계산은 요청할 때만 개수를 셉니다. $out 또는 $merge로 끝나는 파이프라인은 미리 보지 않습니다. 대상을 밝히는 확인 후 한 번 실행되며, 컬렉션을 대체할 때는 컬렉션 이름을 입력해야 합니다. 파이프라인은 컬렉션과 함께 저장하거나(팀 모드에서는 선택적으로 공유), Node.js, Python, Java, Go, C#, PHP, Ruby, Rust용 프로그램으로 내보내거나(연결 문자열은 코드에 기록되지 않고 MONGODB_URI에서 읽습니다), 뷰로 만들 수 있습니다.

뷰의 파이프라인도 같은 방식으로 변경합니다. 뷰(개요 또는 메뉴)의 파이프라인 편집은 뷰가 읽는 컬렉션의 집계 탭에서 뷰의 것으로 표시된 파이프라인을 열고 각 스테이지를 미리 보여 줍니다. 뷰 업데이트는 (뷰의 이름을 밝히는 확인 후) 활성화된 스테이지를 뷰에 다시 기록합니다. 빌더가 읽을 수 없는 스테이지가 있는 파이프라인은 열리지 않습니다(저장하면 그 스테이지를 잃게 됩니다). 개인 데이터가 숨겨진 사용자는 정의가 마스킹되어 보이는 뷰를 변경할 수 없습니다.

쿼리 페이지

쿼리 페이지(사이드바의 쿼리, 명령 팔레트 또는 Ctrl / ⌘ + Shift + L, 주소는 /library)에서는 연결의 즐겨찾기, 저장된 파이프라인, 셸 스니펫, 쿼리 기록을 이름, 태그, 쿼리 텍스트, 종류, 컬렉션으로 검색합니다. 작업하던 연결에서 열리고, 없으면 첫 번째 연결에서 열리며, 돌아오면 검색한 내용을 유지합니다. 항목을 열면 해당 컬렉션으로 이동합니다. find는 도큐먼트에서 실행되고, 파이프라인은 집계 카드를 채웁니다(탭에 이미 내용이 있으면 먼저 확인합니다). 기록에는 실행한 find와 집계가 컬렉션당 최근 200개, 전체 2000개까지 보관되며, 각각 한 번씩만 표시되고 사용 횟수가 함께 나옵니다. 항목은 하나씩 제거하거나 모두 지울 수 있습니다. 즐겨찾기와 저장된 파이프라인은 쿼리 페이지에서 이름 변경, 태그 변경, 공유, 삭제, 고정할 수 있습니다. 고정한 쿼리는 본인만 볼 수 있으며(연결당 최대 50개) 쿼리 페이지와 홈의 쿼리 위젯에서 맨 앞에 나열됩니다. 명령 팔레트에는 탭에 열려 있는 모든 연결의 즐겨찾기, 저장된 파이프라인, 셸 스니펫이 연결 이름별로 나열되고, 작업 중인 연결이 맨 앞에 나옵니다. 팀 모드가 시작되면 로컬 모드의 기록은 삭제됩니다(팀 사용자는 이를 보거나 지울 수 없기 때문입니다). 로그에 삭제된 항목 수가 기록됩니다. 로컬 모드의 즐겨찾기와 저장된 파이프라인은 연결 관리자를 위해 유지됩니다.

고급 셸

연결의 셸 탭은 실제 mongosh를 실행하며, 터미널에 코드를 입력합니다. 데이터베이스를 사용하고, find와 집계를 실행하고, 스크립트를 작성할 수 있습니다. Enter는 코드가 완성되었을 때 실행합니다. 괄호, 문자열, 문장이 열려 있는 동안(., 연산자, if (…) 뒤)에는 ... 뒤의 다음 줄에서 이어지며, Shift+Enter는 항상 줄을 추가합니다. Ctrl+Enter는 코드를 있는 그대로 실행합니다. 여러 줄의 코드를 터미널에 붙여넣을 수 있으며, 한 줄씩 표시되고 Enter를 눌러야 실행됩니다. 스크립트는 mongosh가 입력한 내용을 실행하는 방식으로 실행됩니다. use, show, it은 각각 따로, 그다음 각 문장이 차례로 실행됩니다. 오류가 나면 거기서 멈추고 실행되지 않은 문장 수를 알려 줍니다. print()와 printjson()은 터미널에 출력하고, cls는 터미널과 결과를 지우며, exit는 셸을 종료합니다.

위쪽과 아래쪽 화살표는 입력한 줄 사이를 이동한 다음 기록을 탐색합니다. Ctrl+R은 기록을 검색합니다 (다시 Ctrl+R을 누르면 더 오래된 일치 항목, Escape로 종료). Ctrl+C는 실행 중인 명령을 중지하거나 줄을 지우며, 출력이 선택되어 있으면 복사합니다. Alt+B와 Alt+F(또는 Ctrl+왼쪽, Ctrl+오른쪽)는 단어 단위로 이동합니다. 각 사용자의 기록은 연결별로 암호화되어 보관되며 지울 수 있습니다.

셸은 연결 관리자와, 관리자가 허용한 편집자가 사용할 수 있습니다. 셸은 자격 증명이 없고 해당 연결의 서버에만 접근할 수 있는 샌드박스에서 실행되며, 읽기 전용 연결에서는 쓰기를 거부하고 관리자가 아닌 사용자는 클러스터 또는 사용자 관리를 실행할 수 없습니다.

셸 페이지에는 실행 위치, 즉 연결과 셸이 있는 데이터베이스(use를 따라갑니다)와 상태가 표시됩니다. 상태는 연결 중, 연결됨, 실행 중(실행된 시간 포함), 닫힘입니다. 머리글에는 명령이 실행되는 동안의 중지, 화면과 결과 지우기(Ctrl+L, 명령 실행 중에도 가능, 또는 cls. 알림이 이를 알려 주며, 알림의 실행 취소 또는 빈 결과 카드의 결과 복원으로 되돌립니다), 그리고 입력한 내용(또는 마지막으로 실행한 코드)을 스니펫으로 저장하거나, 기록을 지우거나(결과도 함께 지워짐), 셸을 다시 시작하는(세션이 끝나고 새 세션이 시작되며 변수와 표시된 결과는 사라집니다) 메뉴가 있습니다. 터미널은 앱의 밝은 테마 또는 어두운 테마, 혹은 자체 테마를 따르며 코드에 색을 입힙니다. 아래쪽 바에 키가 나열됩니다. 셸은 페이지가 열려 있는 동안 사용하지 않아도 계속 열려 있습니다. 셸이 닫히면(로그인이 종료되었거나, 서버가 정한 유휴 또는 수명 제한을 넘은 경우) 페이지에 이유가 표시되고, Enter를 누르면 새 셸이 열립니다. 연결이 끊긴 동안 실행 중이던 명령은 연결이 복구되면 화면에서 마무리됩니다.

입력하면 Tab으로 자동 완성이 제안됩니다. db. 뒤에는 데이터베이스의 컬렉션(셸에서 만든 것 포함), 체인이 반환하는 것의 메서드, $ 뒤에는 연산자, 그리고 컬렉션에서 샘플링한 필드 이름입니다. Shift+Tab 또는 Escape 다음 Tab으로 터미널에서 나갑니다.

터미널 옆의 결과 카드는 마지막 결과를 테이블, 트리 또는 텍스트로 표시합니다. 더 보기는 커서의 다음 배치를 가져오고, 머리글의 결과 기록에서는 이전 결과를 선택할 수 있으며 각 결과는 만들어 낸 명령 이름으로 표시됩니다(메모리에만 보관). 지우기는 카드를 비우고, 알림의 실행 취소 또는 빈 카드의 결과 복원은 셸을 다시 시작하거나 기록을 지우기 전까지 결과를 되돌립니다. 카드는 넓힐 수 있으며, 좁은 화면에서는 터미널과 결과가 두 개의 탭이 됩니다. 여러 셸 탭을 함께 열 수 있고, 각각 자체 세션을 가집니다. 단순한 find 또는 집계의 커서는 해당 컬렉션 보기에서 열리며(find는 건너뛰기 위치에서 시작하고 제한이 페이지 크기가 됩니다), 표시된 도큐먼트는 JSON 또는 CSV로 내보낼 수 있습니다.

코드는 {{name}} 형태의 매개변수와 함께 비공개 또는 팀과 공유하는 스니펫으로 저장할 수 있습니다. 스니펫을 열면(쿼리 페이지 또는 명령 팔레트에서) 매개변수를 묻고 채워진 코드를 터미널에 넣으며, Enter를 누르기 전에는 아무것도 실행되지 않습니다. 본인의 스니펫은 쿼리 페이지에서 편집합니다. 이름, 태그, 코드, 매개변수(입력하는 동안 각 {{name}}마다 행이 따라옵니다)를 새 스니펫과 같은 방식으로 검사합니다. 공유 스니펫은 계속 공유되며, 감사 로그에는 코드가 변경되었다는 사실만 기록되고 코드는 기록되지 않습니다.

터미널은 스크린 리더와 함께 작동합니다. 스크린 리더 모드는 기본으로 켜져 있으며, 계정 → 환경설정에서 끄거나 다시 켤 수 있고 열려 있는 셸에도 적용됩니다.

실행 계획 분석

도큐먼트 또는 집계의 "왜 느린가요?"는 해당 쿼리나 파이프라인에 대해 실행 계획 분석 섹션을 엽니다. MongoDB가 선택한 플랜을 트리로 보여 주고(화살표 키로 이동), 각 스테이지가 읽고 반환한 양, 거부된 플랜, 그리고 경고를 문장으로 표시합니다. 컬렉션 전체 스캔, 메모리 내 정렬, 반환하는 것보다 훨씬 많이 읽는 필터, 인덱스가 없는 필드에 대한 조인 등입니다. 인덱스가 도움이 될 때는 실행 계획 분석이 인덱스를 제안하고(동등 필드, 그다음 정렬, 그다음 범위), "이 인덱스 생성"은 백그라운드에서 만듭니다. 쓰기를 수행하는 파이프라인은 분석하면 실행되므로 분석하지 않습니다.

유효성 검사

유효성 검사 섹션에서는 삽입되거나 업데이트되는 모든 도큐먼트가 따라야 하는 규칙을 유효성 검사 수준 및 동작과 함께 편집합니다. "샘플에서 생성"은 컬렉션의 도큐먼트로 $jsonSchema를 작성하고, "기존 도큐먼트로 테스트"는 저장하기 전에 몇 개가 실패할지를 예시와 함께 셉니다. 저장할 때 먼저 확인을 요청하며, 규칙을 위반하는 도큐먼트의 업데이트가 거부될 수 있으면 그렇게 알려 줍니다. "이전 규칙 복원"은 탭이 열려 있는 동안 마지막 저장으로 바뀐 내용을 되돌립니다. 규칙에 의해 거부된 쓰기는 어떤 규칙을 충족하지 못했는지(필수 필드 누락, 잘못된 유형, 최솟값 등) 알려 주며, 가져오기나 복사의 보고서도 마찬가지입니다. 실패한 값은 절대 반복해서 표시하지 않습니다.

스키마

컬렉션의 스키마 탭은 무작위 샘플(100, 1,000 또는 10,000개 도큐먼트)을 분석합니다. 각 필드의 존재 빈도, 유형, 히스토그램 또는 가장 흔한 값이 표시됩니다. 내보내기는 분석 결과를 Mongoose 스키마, MongoDB JSON Schema 유효성 검사기 또는 TypeScript 인터페이스로 변환해 복사하거나 내려받게 합니다. 샘플링한 모든 도큐먼트에 있는 필드는 필수로 간주합니다.

필드의 막대(범위와 가장 흔한 값)와 유형은 버튼입니다. 하나를 선택하면 해당 조건이 컬렉션의 도큐먼트 필터에 추가되고(이미 입력한 조건 옆에, 또는 필드에 조건이 있으면 $and로), 실행되어 도큐먼트가 표시됩니다. 분석에서 잘린 값은 표시되지만 선택할 수 없습니다. 위치를 담은 필드(GeoJSON 점, 또는 location이나 coords 같은 이름 아래의 좌표 쌍)는 네트워크 없이 그려지는 지도에 표시됩니다(세계 윤곽은 퍼블릭 도메인인 Natural Earth). 끌거나 화살표 키로 이동하고, Ctrl과 휠, 두 손가락, 또는 +와 −로 확대·축소하며, 위치는 테이블로도 나열되고, 이 영역으로 필터링은 보이는 영역의 $geoWithin을 추가합니다. 개인 데이터가 있는 필드는 절대 그려지지 않습니다.

데이터 모델

데이터베이스의 모델 섹션은 컬렉션과 그 사이의 참조를 그려 줍니다. 모델 읽기는 각 컬렉션을 샘플링해(도큐먼트 100~1,000개, 컬렉션 최대 50개) 필드를 읽습니다. 최상위와 그 아래 한 단계만 읽으며, 더 깊은 필드는 참조처럼 보일 때만 읽습니다. 참조는 세 가지 방법으로 찾습니다. 컬렉션 이름을 딴 필드(userId 또는 user_id → users, tagIds → tags), 샘플링한 ObjectId 값이 다른 컬렉션의 _id로 존재하는 경우(필드당 값 최대 열 개, 작은 카운트 전체 예순 개), 그리고 뷰와 열 수 있는 저장된 파이프라인의 $lookup, $graphLookup 스테이지입니다. 실선은 이름이나 값으로 찾은 것, 파선은 $lookup만으로 찾은 것, 점선은 뷰를 원본에 연결합니다. 선은 참조를 담은 필드에서는 까마귀 발 모양("다수")으로 끝나며 (여러 도큐먼트가 같은 id를 가질 수 있기 때문), 참조 대상 컬렉션에서는 막대("하나")로 끝나고, 참조 배열이면 그쪽도 까마귀 발입니다. 필드에는 PK(키, _id), UQ(해당 필드만의 고유 인덱스), IX(인덱스에 포함)가 표시됩니다. 인덱스는 키 이름만 읽습니다.

다이어그램을 끌거나 화살표 키로 이동하고, +와 −로 확대·축소하고, 0으로 맞춤 보기를 합니다. 다이어그램에 포커스가 있기 전(클릭하거나 Tab으로 이동)에는 휠이 페이지를 스크롤하며, 포커스가 있으면 휠이 다이어그램을 이동하고 Ctrl / ⌘와 휠은 확대·축소합니다(Shift와 휠은 언제든 이동). 컬렉션을 클릭하거나 Tab으로 이동해 Enter를 누르면 링크를 보고 열 수 있습니다. 목록 보기는 같은 모델을 목록으로 표시합니다. 각 컬렉션을 열면 필드와 링크가 나오고, 링크를 누르면 가리키는 컬렉션으로 이동합니다. 내보내기는 다이어그램을 PNG 또는 SVG(사용 중인 테마의 색상과 사용자의 언어로)로, 모델을 JSON으로, 모델을 Mermaid의 erDiagram(.mmd로 저장하거나 복사)으로 저장합니다. Mermaid 형식은 다이어그램을 그려 주는 README, 위키, 풀 리퀘스트용이며, 고유 필드는 Mermaid의 표기에 따라 UK로 기록됩니다. 이름, 유형, 개수만 표시되며 어떤 값도 서버를 떠나지 않습니다. 도큐먼트를 읽을 수 있는 사용자는 모델을 읽을 수 있습니다. 개인 데이터로 숨겨진 필드는 이름만 표시되며 값은 읽지 않습니다. 일부 컬렉션만 허용된 MongoDB 사용자는 해당 컬렉션만 봅니다.

모델을 읽으면 서버가 컬렉션마다 한 번씩 샘플링합니다. 최대 컬렉션 50개 곱하기 샘플 크기, 그리고 작은 카운트 최대 예순 개입니다. 서버는 모델 하나가 전체적으로 읽는 도큐먼트 수에 상한을 둡니다 (MM_MODEL_MAX_DOCS, 기본값 20,000). 컬렉션이 많으면 각 샘플이 작아지며 섹션에 그렇게 표시됩니다. 부하가 큰 프로덕션 데이터베이스에서는 서버가 한가할 때, 또는 더 작은 샘플로 읽으세요.

검색 인덱스

MongoDB Atlas, 또는 검색 프로세스(mongot)가 있는 MongoDB 8.0 이상에서는 인덱스 탭에 컬렉션의 Atlas Search 및 Vector Search 인덱스도 나열됩니다. 각 인덱스의 종류, 상태(대기 중, 빌드 중, 준비됨, 이유와 함께 실패), 대상 범위가 표시되며, 빌드 중인 인덱스가 있으면 몇 초마다 다시 확인합니다. 검색 인덱스 만들기는 정의를 JSON으로 받고, 벡터 인덱스의 경우 안내 양식을 제공합니다. 임베딩이 있는 필드, 차원 수, 유사도, 필터링할 필드입니다. 정의는 편집할 수 있고 인덱스는 (이름을 밝히는 확인 후) 삭제할 수 있습니다. 그 밖의 환경에서는 검색에 필요한 것을 탭에서 알려 줍니다.

백그라운드 작업

인덱스 빌드와 컬렉션 복제는 백그라운드에서 실행되므로 오래 걸려도 시간 초과가 발생하지 않습니다. 실행 중에 페이지를 떠나거나 탭을 닫아도 됩니다. 상단 바의 백그라운드 작업 버튼에 각 작업이 표시됩니다. MongoDB가 진행률을 보고하는 경우(인덱스 빌드)에는 막대와 숫자로, 그렇지 않은 경우(복사)에는 아직 실행 중과 지금까지의 시간이 표시됩니다. 본인의 작업이 끝나면 알려 주며, 여기서 취소할 수도 있습니다.

복사 중에 서버가 다시 시작되면 복사는 중단되고 절반만 만들어진 컬렉션은 제거됩니다. 대상이 절반만 채워진 상태로 남지 않습니다. 인덱스 빌드는 MongoDB 내부에서 계속될 수 있으며, 인덱스 탭에 표시됩니다.
