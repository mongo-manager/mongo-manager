가져오기 및 내보내기

파일은 백그라운드 작업으로 컴퓨터와 컬렉션 사이를 이동하므로, 대화 상자를 닫고 작업 목록에서 진행 상황을 확인할 수 있습니다. 컬렉션의 도구 모음, 사이드바의 컬렉션 메뉴 또는 명령 팔레트에서 여세요. SQL 덤프는 다릅니다. 파일과 데이터베이스 전체 사이에서 이동하며 별도의 페이지가 있습니다(SQL 가져오기 및 내보내기 참조).

형식

  • CSV 및 TSV(쉼표, 세미콜론, 탭 또는 파이프 구분, UTF-8, UTF-16, Latin-1, Windows-1252, Windows-1254 또는 ISO-8859-9 인코딩).
  • JSON: 도큐먼트 배열 하나 또는 도큐먼트 하나.
  • NDJSON: 줄마다 도큐먼트 하나이며 Extended JSON 형식이므로 모든 BSON 유형이 원래대로 복원됩니다.
  • Excel 통합 문서(.xlsx), 한 번에 시트 하나.
  • 위 형식 모두 gzip(.gz)으로 압축할 수 있습니다.

가져오기

  1. 파일을 선택하거나, 대화 상자에 끌어다 놓거나, 텍스트를 붙여넣으세요.
  2. 읽는 방식을 확인하세요. 형식, 구분 기호, 인코딩, 첫 행이 필드 이름인지 여부, 통합 문서의 시트입니다. 바이트 순서 표시(BOM)가 다르게 지정하거나 다른 인코딩을 선택하지 않는 한 파일은 UTF-8로 읽습니다. 바이트가 해당 인코딩의 텍스트가 아니면 비슷해 보이는 인코딩을 제안하고(바이트 순서 표시가 없는 UTF-16, 튀르키예어 문자는 Windows-1254, 그 외에는 Windows-1252) 한 번 클릭하면 그 인코딩으로 파일을 다시 읽습니다. 추측은 절대 자동으로 적용되지 않습니다. 잘못된 추측은 잘못된 글자를 기록하기 때문입니다. 선택한 인코딩에서도 텍스트가 아닌 행은 대체 문자로 기록되지 않고 거부됩니다.
  3. 필드를 매핑하세요. 각 필드가 들어갈 위치(a.b는 중첩, a[0]은 배열 요소), 유형, 빈 값이나 변환할 수 없는 값이 어떻게 처리될지입니다. 유형은 처음 천 개의 레코드에서 제안됩니다. 앞에 0이 붙은 값이나 +로 시작하는 값은 텍스트로 유지되므로 코드와 전화번호가 그대로 보존됩니다. 같은 규칙이 이후의 모든 레코드, 사용자가 선택한 유형, 상수에도 적용됩니다. 코드는 숫자로 읽지 않으며, 다른 숫자가 되어 버리는 double로도 읽지 않습니다(0.30000000000000004는 double이지만 12345678901234567은 아닙니다). 이런 값은 변환할 수 없는 값으로 처리됩니다. 시간대가 없는 날짜는 UTC로 읽습니다. 헤더보다 필드가 많거나 적은 CSV 행(필드 안의 따옴표 없는 쉼표 등)은 행 오류이며, 원래 모습 그대로 거부된 레코드 파일로 이동합니다. 공백만 있는 줄은 레코드가 아닙니다. 각 필드 아래에는 처음 몇 개의 샘플이 선택한 유형으로 기록될 모습으로, 또는 그럴 수 없는 이유와 함께 표시됩니다.
  4. 원하면 상수 필드를 추가하세요. 모든 도큐먼트에 같은 값이 들어가며, 가져오기 시각 또는 문자열, 숫자 (Int32, Int64, Double, Decimal128), 날짜, ObjectId, 불리언, JSON, null 중 하나입니다. 상수는 파일의 값과 같은 규칙으로 변환되며, 변환할 수 없으면 가져오기가 시작되기 전에 거부됩니다.
  5. 모드를 선택하고 원하면 먼저 시험 실행을 하세요. 업서트와 병합에서는 키 필드로 시작하는 인덱스가 없으면 대화 상자가 경고합니다. 그러면 각 레코드를 컬렉션 스캔으로 찾게 됩니다.

모드

  • 삽입: 모든 레코드가 새 도큐먼트가 됩니다. _id가 이미 있는 레코드는 실패합니다.
  • 업서트: 키 필드(기본값은 _id)가 같은 도큐먼트는 레코드로 교체되며, 없으면 레코드가 삽입됩니다.
  • 병합: 레코드의 필드가 키 필드가 같은 도큐먼트에 기록됩니다. 레코드에 없는 필드는 하위 도큐먼트 안에서도 그대로 남습니다. "업데이트만"은 일치하는 것이 없는 레코드를 제외합니다. 필드 이름에 점이 있거나 $로 시작하는 레코드는 병합할 수 없습니다(경로로 읽히기 때문). 이 경우에는 업서트를 사용하세요.

"건너뛰고 계속"을 선택하면 실패한 레코드는 개수가 집계되고 목록에 나열됩니다. "가져오기 중지"를 선택하면 첫 번째 실패 이전의 레코드는 기록되고 가져오기는 거기서 멈춥니다. 시험 실행은 전체 파일을 읽고, 변환하고, 검사하지만 아무것도 쓰지 않습니다. 보고서에는 일어난 일의 개수, 매핑된 필드별로 변환된 값과 변환되지 않은 값의 수, 처음 몇 개의 실패가 표시되며, 거부된 레코드를 원래 형식의 파일로 제공하므로 수정해서 다시 가져올 수 있습니다. 그 파일이 저장소 한도를 넘으면 보관되지 않으며 보고서에 그렇게 표시됩니다. 키 필드는 값으로 일치시키며 $로 시작할 수 없습니다.

내보내기

적용한 쿼리, 컬렉션 전체 또는 파이프라인의 결과를 내보냅니다. CSV와 Excel은 선택하고 순서를 정한 열을 사용합니다. 사이드바, 명령 팔레트 또는 표시된 도큐먼트가 없는 컬렉션에서 열면 대화 상자가 도큐먼트 100개 샘플에서 열을 제안합니다(개인 필드는 표시되며, 볼 수 없는 사용자에게는 ***로 기록됩니다). 배열은 JSON 텍스트로, 요소당 한 열로(tags.0, tags.1… 처음 도큐먼트들 중 가장 긴 배열만큼, 설정한 수까지이며 그 이후 요소는 보고서에 이름이 표시됨), 또는 선택한 구분 기호로 이은 요소로 기록됩니다. 아무것도 선택하지 않으면 처음 도큐먼트들(최대 1,000개 또는 8 MiB, 최대 500열)의 필드가 열이 되며, 한 도큐먼트에서는 값이고 다른 도큐먼트에서는 하위 도큐먼트인 필드는 전체 값을 담은 하나의 열이 됩니다. 보고서에는 어떤 열에도 담기지 않은 항목이 경로와 함께 표시됩니다. 공백 뒤를 포함해 =, +, -, @, 탭 또는 줄 바꿈으로 시작하는 CSV 텍스트에는 앞에 '가 붙어 스프레드시트가 수식으로 실행하지 않습니다. 다른 프로그램이나 다시 가져오기에서 읽을 파일이라면 이 옵션을 끄세요. JSON과 NDJSON은 모든 필드와 모든 유형을 유지합니다. Excel은 최대 1 048 575행과 셀당 32 767자까지 담을 수 있습니다. 더 긴 셀은 잘리고 보고서에 집계되며, 더 큰 내보내기는 거부되고 CSV 또는 NDJSON을 사용하라고 안내합니다. 작업이 끝나면 작업 목록에서 파일을 내려받으세요. 파일이 언제까지 보관되는지 표시되며(기본 24시간, MM_TRANSFER_TTL_HOURS), 만료되면 내보내기를 다시 실행해야 합니다.

SQL 가져오기 및 내보내기

SQL 가져오기와 내보내기는 함께 제공되는 SQL → MongoDB 플러그인의 기능입니다. 관리자가 플러그인에서 승인하고 켜기 전까지 이 페이지, 사이드바 항목, 명령 팔레트의 명령, 아래의 데이터베이스 메뉴 항목은 표시되지 않으며, 서버도 SQL 가져오기와 내보내기를 거부합니다. 컬렉션을 SQL로 내보내기와 어시스턴트의 SQL 내보내기도 마찬가지입니다.

SQL은 컬렉션에서 가져오거나 내보내지 않습니다. 도큐먼트 도구 모음도 컬렉션의 내보내기 대화 상자도 이를 제공하지 않습니다. 사이드바의 SQL ↔ MongoDB라는 별도의 페이지가 있습니다. 이 페이지는 항상 작업 중인 연결과 데이터베이스를 표시합니다. 둘 다 위쪽에서 선택하며 페이지 주소 (/sql/import/<connection>/<database> 또는 /sql/export/…)에 저장되므로, 새로 고침하거나 공유한 링크를 열어도 같은 위치가 열립니다. 사이드바 트리에서 데이터베이스 메뉴의 "SQL 덤프 가져오기…"와 "SQL로 내보내기…"는 해당 데이터베이스로 이 페이지를 엽니다. 명령 팔레트에서는 "SQL ↔ MongoDB"가 마지막으로 두었던 위치로 페이지를 열고, "SQL로 내보내기"는 현재 탭의 데이터베이스에서 내보내기를 엽니다. 가져오기와 내보내기 모두 한 번에 데이터베이스 하나에서 작동합니다. 다른 탭이나 이 페이지의 다른 부분을 보는 동안에도 페이지는 열려 있으므로, 준비 중인 파일이나 실행 중인 작업이 사라지지 않으며, 아직 실행 중인 내보내기는 돌아오면 다시 표시됩니다. 파일이 준비되었거나 가져오기가 실행 중일 때 페이지를 닫거나 앱을 떠나면 먼저 확인을 요청합니다. 작업의 진행 상황이 화면에 보이는 페이지에 있는 동안에는 종료 결과가 그곳에 표시되며 별도의 알림은 없습니다.

SQL 덤프 가져오기(SQL → MongoDB)

  1. MySQL(mysqldump), PostgreSQL(pg_dump) 또는 SQLite(.dump) 파일을 선택하거나 끌어다 놓으세요. 일반 파일이거나 gzip(.gz)으로 압축된 파일이어도 됩니다. 테이블 정의와 행만 읽으며, 파일의 어떤 것도 실행되지 않습니다. 그 밖의 문은 건너뜀으로 나열됩니다.
  2. 덤프에 들어 있는 테이블을 확인하세요. 각 테이블에 열, 행 수, 기본 키, 몇 개의 샘플 행이 표시됩니다. 가져올 테이블을 선택하고 각각이 들어갈 컬렉션 이름을 지정하세요. 이름에는 새 컬렉션인지 기존 컬렉션인지 표시됩니다. 삽입할 때는 여러 테이블을 하나의 컬렉션에 넣을 수 있습니다. 업서트와 병합에서는 키가 같은 두 테이블의 행이 서로를 교체하게 되므로 각 테이블이 자체 컬렉션으로 들어갑니다.
  3. 옵션을 선택하세요. "기본 키를 _id로"는 단일 열 기본 키를 도큐먼트의 _id로 만들며, 복합 키는 필드로 남습니다. 모드는 파일의 경우와 같이 삽입, 업서트, 병합입니다(업서트와 병합은 _id로 일치시키므로 단일 열 기본 키가 없는 테이블에는 사용할 수 없습니다). 행을 쓸 수 없을 때는 "건너뛰고 계속" 또는 "가져오기 중지"를 선택하세요.
  4. 원하면 시험 실행을 하세요. 선택한 모든 행을 읽고 검사하지만 아무것도 쓰지 않습니다. 그런 다음 가져오기를 시작하세요. 가져오기는 백그라운드 작업으로 실행되며, 양식과는 별도의 페이지에서 진행 상황과 보고서를 확인합니다. "중지"로 끝낼 수 있습니다. 중지되었거나 실패했거나 중단된 가져오기는 그렇게 표시되며 끝나기 전에 쓴 내용을 보고합니다.

가져오기는 기존 데이터베이스 또는 페이지에서 이름을 지정한 새 데이터베이스로 들어가며, 절대 admin, local, config로는 들어가지 않습니다. 기존 데이터베이스와 대소문자만 다른 새 이름은 MongoDB가 거부하듯이 거부됩니다. 다른 데이터베이스를 선택해도 준비 중인 파일은 유지됩니다(시험 실행은 실행된 데이터베이스에 대한 것이므로 폐기됩니다). 다른 연결은 어떤 방법으로 요청하든(목록, 트리, 팔레트, 플러그인, 브라우저의 뒤로 가기) 먼저 확인을 요청합니다. 읽은 파일이 해당 연결에 속하기 때문이며, 거절하면 페이지는 그대로 유지됩니다. 연결에서 도큐먼트를 쓰고 백그라운드 작업을 실행할 권한이 필요하며, 연결과 서버가 읽기 전용이면 안 됩니다.

가져오기와 내보내기는 긴 페이지 하나가 아니라 한 단계씩 진행됩니다. 위쪽의 단계(가져오기는 파일, 테이블, 옵션, 진행 상황. 내보내기는 컬렉션, 옵션, 진행 상황)에 현재 위치가 표시됩니다. 파일 이후에 지나간 단계로는 돌아갈 수 있으며 선택한 내용은 유지됩니다. "다른 파일 선택"은 다른 파일로 처음부터 다시 시작합니다. 시험 실행은 검사한 내용에 대한 것이므로, 테이블, 컬렉션, 옵션 또는 데이터베이스를 바꾸면 폐기됩니다(실행 중인 시험 실행은 중지됩니다). 가져오기가 실행되기 시작하면 입력한 내용은 바꿀 수 없으며, 끝날 때까지 페이지가 유지되고 그 후 "다른 파일 가져오기"로 다시 시작합니다.

SQL로 내보내기(MongoDB → SQL)

데이터베이스(절대 admin, local, config는 안 됨)를 선택한 다음 내보낼 컬렉션, 뷰, 시계열 컬렉션을 선택하세요. 처음에는 모두 선택되어 있으며 최대 500개입니다. 백그라운드 작업 하나가 이를 하나의 SQL 파일에 기록하며, 각각에 대해 CREATE TABLE과 INSERT가 있습니다. 파일은 자체 데이터베이스나 스키마를 만들지 않으므로 선택한 데이터베이스에 로드됩니다. 두 테이블 이름이 충돌하면(예: 대소문자만 다른 이름) 하나가 고유하게 바뀌며 보고서에 그렇게 표시됩니다. 옵션은 SQL 방언(PostgreSQL, MySQL, SQLite), INSERT당 행 수(1~1000), 테이블당 트랜잭션 하나, gzip 압축입니다. MySQL에서는 phpMyAdmin 4.7 이전 같은 오래된 도구를 위해 중첩 값을 JSON 대신 LONGTEXT(같은 JSON 텍스트)로 기록할 수 있습니다. MySQL decimal 열은 처음 도큐먼트들의 값이 기록된 소수 자릿수를 사용합니다 (234.20: 두 자리. 끝의 0이 두 개를 넘으면 채움이므로, DECIMAL(65,30) 열에서 다시 읽은 값은 자체 소수 자릿수를 유지합니다). 모든 금액에 0이 30개씩 붙는 일은 없습니다. 이후 값의 소수 자릿수가 더 많으면 열이 ALTER TABLE … MODIFY로 넓어집니다(MySQL은 그 앞의 행을 커밋하므로 그 뒤에서 트랜잭션이 다시 시작됩니다). 앞의 값들과 함께 어떤 decimal 열도 담을 수 없는 값, 즉 소수 자릿수가 30자리를 넘거나 전체가 65자리를 넘는 값은 NULL로 기록되고 집계되며, 반올림되지 않습니다. 열은 각 컬렉션의 처음 도큐먼트들에서 가져옵니다. 이후 도큐먼트에서만 보이는 필드는 제외되며, 보고서에 테이블별로 나열되고, 너무 크거나 SQL 유형이 아니어서 NULL로 기록된 값도 표시됩니다. 이 앱이 작성한 파일은 담고 있던 도큐먼트로 다시 가져옵니다. CHAR(24) 열은 ObjectId로, "sub.a" 열은 중첩 필드로(거기서 NULL은 도큐먼트에 없던 필드로), 바이트는 바이너리로 복원됩니다. 진행 상황, 보고서, 다운로드는 별도의 페이지에 표시됩니다. "중지"는 실행 중인 내보내기를 끝내고, "다시 내보내기"는 옵션으로 돌아갑니다.

SQL로 내보내려면 연결의 내보내기 권한이 필요합니다. 개인 데이터를 볼 수 없는 사용자는 다른 내보내기와 마찬가지로 값이 숨겨진 곳에 ***를 받습니다.

복사, 비교, 동기화

컬렉션(컬렉션 전체, 적용한 쿼리, 복사 대화 상자에 입력한 필터, 또는 파이프라인의 결과 - 집계 빌더의 "결과 복사…")이나 데이터베이스의 선택한 컬렉션을 같은 연결 또는 다른 연결로 복사합니다. 첫 단계에서 원본의 예상 크기를 보여 줍니다. 대상을 선택하거나 입력하는 즉시 대화 상자가 확인합니다. 존재하는지와 도큐먼트가 몇 개인지, 선택한 모드가 대상에 어떤 영향을 주는지, 거기서의 역할, 복사가 거부할 사항입니다. 데이터베이스 복사가 실행되는 동안 작업 목록에 각 컬렉션이 자체 진행 상황과 함께 표시됩니다. 삽입, 업서트, 병합은 가져오기와 같이 작동하며 실패 이전에 쓴 내용을 유지합니다. "대상 대체"는 스테이징 컬렉션에 복사본을 만들고 모든 도큐먼트가 기록된 경우에만 제자리에 놓습니다. 거부된 도큐먼트, 실패, 취소가 있으면 대상은 원래대로 남습니다. 유효성 검사기는 MongoDB 자체 복사와 마찬가지로 도큐먼트를 로드한 뒤에 설정되므로 그 이전에 저장된 도큐먼트도 복사됩니다. 단, 대상 사용자가 유효성 검사기를 변경할 수 없는 경우(readWrite 역할)에는 먼저 설정되며 보고서에 그렇게 표시됩니다. 인덱스, 유효성 검사기, 컬렉션 옵션(캡, 콜레이션, 시계열, 클러스터형)도 복사할 수 있습니다. 데이터베이스 복사는 뷰를 마지막에 의존성 순서대로 만들며, 뷰는 하나씩 선택할 수 있습니다. 암호화된(Queryable Encryption) 컬렉션과 그 메타데이터 컬렉션은 복사되지 않습니다. 한 연결 안에서 마스킹할 것이 없으면 MongoDB가 스스로($out 또는 $merge) 복사하며 데이터는 Mongo Manager를 거치지 않습니다.

Mongo Manager를 거치는 복사는 Node.js MongoDB 드라이버가 읽는 대로 각 도큐먼트를 씁니다. 더 이상 사용되지 않는 BSON 유형인 undefined와 DBPointer는 각각 null과 DBRef 도큐먼트로 도착합니다. MongoDB가 스스로 하는 복사는 이를 그대로 유지합니다.

요약에는 아무것도 쓰기 전에 각 대상, 존재 여부, 복사되는 방식이 표시됩니다. 대상 도큐먼트를 삭제하는 TTL 인덱스는 확인이 필요합니다. 원본에는 있지만 대상에는 없는 개인 필드 규칙이 있으면, 개인 값이 거기서 보이게 된다는 확인이 복사에 필요합니다. 대상의 관리자는 대신 규칙을 추가할 수 있습니다. 개인 필드는 쿼리가 찾는 방식과 같이 뷰를 통해, 그리고 파이프라인이 옮기거나 조회하는 필드를 통해 찾습니다. 원본에서 개인 필드가 본인에게 숨겨져 있으면 복사본에는 그 자리에 ***가 들어가며 항상 익명입니다. "익명 복사"는 모든 사용자에 대해 ***를 씁니다. 개인 _id는 마스킹된 채로 복사할 수 없습니다. 대상이 원본과 구별되지 않으면 요약에 그것이 원본 자체일 수 있다고 표시됩니다.

비교는 양쪽을 _id 순서로 읽고, 원본에만 있는 도큐먼트, 대상에만 있는 도큐먼트, 다른 도큐먼트, 같은 도큐먼트의 수를 샘플 및 필드별 차이와 함께 셉니다. 필터는 양쪽에 적용되며 선택한 필드는 무시할 수 있습니다. 어느 한쪽에서 개인 필드가 본인에게 숨겨져 있으면 양쪽 모두 ***로 비교되며, 개인 _id는 비교할 수 없습니다. 동기화는 끝난 비교를 적용합니다. 누락된 도큐먼트를 삽입하고 다른 도큐먼트를 교체하지만, 읽은 뒤에 변경된 도큐먼트는 절대 덮어쓰지 않습니다. 복사와 마찬가지로, 대상에 원본의 개인 필드 규칙이 없으면 확인이 필요합니다. 대상의 여분 도큐먼트 삭제는 기본적으로 꺼져 있고, 대상의 이름을 입력해야 하며, 원본에서 읽히는 도큐먼트가 없으면 거부되고, 비교에서 찾은 수에 여유분(그 수의 10%, 최소 100)을 더한 수보다 더 많이 삭제하게 되면 중지됩니다. 필터가 있으면 원본에는 여전히 있지만 더 이상 필터와 일치하지 않는 대상 도큐먼트는 삭제되지 않고 유지되며 보고서에 집계됩니다. 개인 필드 규칙이 바뀌거나, 어느 한 연결에 대한 접근 권한을 잃거나, 개인 필드가 본인에게 숨겨지면 보고서는 철회됩니다.

저장된 설정

매핑, 내보내기 설정, 복사 설정은 이름을 붙여 저장하고 이 컬렉션이나 다른 컬렉션에서 다시 불러올 수 있습니다. 저장된 쿼리와 마찬가지로 암호화되어 저장됩니다.

파일이 보존하는 것과 보존하지 못하는 것

  • CSV와 Excel은 텍스트, 숫자, 불리언, 날짜를 담습니다. 그 밖의 도큐먼트 유형(ObjectId, Long, Decimal128, 바이너리, 중첩 도큐먼트, 배열)은 텍스트나 Extended JSON으로 내보내지며, CSV를 다시 읽으면 매핑이 지정하는 유형을 가집니다. 정확하게 복원되는 파일이 필요하면 JSON 또는 NDJSON(Extended JSON)으로 내보내세요.
  • SQL 내보내기는 도큐먼트를 열로 평면화합니다. 이 앱이 만든 덤프는 ObjectId, 중첩 필드, 바이너리 값과 함께 다시 읽히며, 다른 곳에서 만든 덤프는 열이 지정하는 유형으로 읽힙니다.
  • 날짜는 MongoDB와 같이 밀리초를 유지합니다. SQL 덤프의 마이크로초는 버려집니다. MySQL의 0000-00-00("날짜 없음")은 null로 읽힙니다. Decimal128이 담을 수 있는 자릿수(34자리)보다 긴 SQL 덤프의 정수는 텍스트로 정확하게 유지됩니다.
  • Excel에서 날짜를 표시하는 셀은 UTC로, 기록된 그대로의 날짜와 시간으로 읽힙니다(셀에 시간대가 없기 때문). 시각만 표시하는 셀은 텍스트 HH:MM:SS로 읽히고(서식이 표시하는 소수 초 포함), 날짜도 있으면 날짜와 시간으로 읽힙니다. 기간([h]:mm)은 텍스트로 읽히며 시간은 하루를 넘겨 셉니다.
  • 내보내기는 한 순간의 스냅샷이 아니라 진행하면서 컬렉션을 읽습니다. 그동안 기록된 도큐먼트는 포함될 수도, 포함되지 않을 수도 있습니다.
  • 중지되었거나 실패했거나 취소된 가져오기는 이미 쓴 내용을 유지하며, 보고서에 그 레코드 수가 표시됩니다. 삽입으로 다시 실행하면 그 레코드가 두 번 기록됩니다. 키를 지정한 업서트나 병합을 사용하거나 먼저 제거하세요. 업로드한 파일은 실행할 때마다 삭제되므로, 다시 실행하려면 다시 업로드하세요.
  • 병합은 레코드의 필드를 설정하고 나머지는 그대로 둡니다. 레코드의 빈 하위 도큐먼트는 저장된 내용을 바꾸지 않으며 새 도큐먼트에서만 만들어집니다. "업데이트만"은 업서트와 병합 모두에 적용됩니다.
  • 거부된 레코드는 원본의 형식과 구분 기호로 돌아오며, 텍스트가 아니었던 바이트는 �로 표시되어 행을 찾아 수정할 수 있습니다.

한도와 안전

  • 파일은 서버에 24시간 동안 보관되며 사용자별 저장 용량 한도가 있습니다. 관리자가 둘 다 변경할 수 있습니다(배포 참조).
  • 안전을 위해 거부되는 항목: 매크로가 포함된 통합 문서와 비밀번호로 보호된 통합 문서, 오래된 .xls 파일, 압축을 풀 때 지나치게 커지는 파일, DTD가 있는 XML, $로 시작하거나 점을 포함하거나 __proto__라는 이름의 필드 이름(특이한 이름을 허용하지 않는 한). gzip으로 압축된 통합 문서는 처음 읽을 때 한 번 압축이 풀리며 이후 통합 문서의 크기를 갖습니다. 내용은 일반 통합 문서보다 더 많이 늘어날 수 없습니다.
  • 개인 데이터를 볼 수 없는 사용자는 개인 값 대신 ***가 들어간 파일을 내보내고, 개인 필드를 매핑하거나 그 필드로 일치시킬 수 없으며, 개인 필드가 있는 곳에서는 도큐먼트 전체를 교체할 수 없습니다. 개인 필드 규칙이 바뀌기 전에 만든 파일은 더 이상 내려받을 수 없으므로 다시 내보내세요.
  • 뷰어는 관리자가 해당 연결에 허용한 경우에만 내보낼 수 있습니다.
  • 가져오기 및 내보내기 작업은 본인과 관리자에게만 표시됩니다. 미리 보기에서는 긴 값이 잘려 표시되며, 매우 넓은 파일은 더 적은 행으로 샘플링됩니다.
