변경 사항 감시

감시 섹션에서는 MongoDB가 데이터에 가하는 변경 사항을 발생하는 즉시 볼 수 있습니다. 모든 삽입, 업데이트, 교체, 삭제가 표시되며, 요청하면 새 인덱스 같은 스키마 변경도 표시됩니다. MongoDB의 변경 스트림을 사용합니다. 저장되는 것은 없습니다. 피드는 열었을 때 시작되며 그 시점부터 발생하는 일을 보여 줍니다.

위치

  • 컬렉션 탭 → 감시: 해당 컬렉션의 변경 사항.
  • 데이터베이스 탭 → 감시: 데이터베이스에 있는 모든 컬렉션의 변경 사항.
  • 연결 탭 → 감시: 연결에 있는 모든 데이터베이스의 변경 사항.
  • 명령 팔레트(Ctrl+K): "Watch changes…"를 선택하면 현재 탭의 감시 섹션이 열립니다.

변경 스트림에는 레플리카 세트, 샤드 클러스터 또는 로드 밸런싱 배포가 필요합니다(MongoDB Atlas는 항상 이 중 하나입니다). 독립 실행형 서버는 감시할 수 없으며, 섹션에 그렇게 표시됩니다. 개발용으로는 단일 노드 레플리카 세트로 충분합니다. mongod --replSet rs0을 시작하고 rs.initiate()를 한 번 실행하세요. 뷰는 감시할 수 없습니다. 뷰의 감시 섹션에서는 뷰가 읽는 원본 컬렉션을 감시할 수 있습니다. 아직 존재하지 않는 컬렉션도 감시할 수 있으며, 컬렉션이 생성되면 변경 사항이 표시됩니다.

감시할 수 있는 사용자

연결에서 도큐먼트를 읽을 수 있는 사용자는 모든 범위에서 해당 연결을 감시할 수 있습니다. 연결의 데이터베이스 사용자에게는 감시 대상에 대한 changeStream 및 find 권한이 필요합니다(기본 제공 read 역할에는 둘 다 있습니다). system.users 같은 자격 증명 컬렉션은 해당 연결의 관리자에게만 표시됩니다.

피드

피드 위의 막대에는 피드 상태가 표시됩니다. 실시간, 일시 중지됨, 지연(2초 넘게 뒤처진 경우, 뒤처진 정도 포함), 다시 연결 중 또는 종료됨이며, 도착한 변경 건수와 속도도 표시됩니다. 최신 변경 사항이 맨 위에 있습니다. 각 행에는 변경 유형(글자와 색상), 데이터베이스 및 연결 피드에서는 컬렉션, 도큐먼트의 _id, 업데이트의 경우 변경된 필드 이름, 변경이 발생한 후 경과 시간(마우스를 올리면 정확한 시각)이 표시됩니다. 아래로 스크롤하면 새 변경 사항은 읽고 있는 내용을 밀어내지 않고 "새 이벤트" 버튼 뒤에서 대기합니다. 최근 변경 2,000건이 유지되며, 그보다 오래된 변경은 목록에서 사라집니다.

변경을 선택하면 오른쪽에 상세 내용이 표시됩니다. 변경된 필드, 삽입 및 교체의 경우 전체 도큐먼트, 또는 JSON 형식의 이벤트입니다. "도큐먼트 열기"를 선택하면 해당 도큐먼트의 _id로 필터링된 컬렉션의 도큐먼트 섹션이 열립니다. "EJSON으로 복사"는 변경을 Extended JSON으로 복사합니다.

일시 중지, 재개, 재연결

일시 중지하면 현재 위치를 잃지 않고 목록이 멈춥니다. MongoDB가 서버 쪽에 변경 사항을 계속 보관하기 때문입니다. "따라잡기"로 재개하면 일시 중지 중에 발생한 일을 볼 수 있고, "지금부터"로 재개하면 그 내용을 건너뜁니다. 피드 도구 모음에서 Space를 누르면 일시 중지와 재개가 전환됩니다. 일시 중지된 피드는 섹션이나 탭을 전환해도 탭을 닫을 때까지 일시 중지 상태로 유지됩니다. 실행 중인 피드는 해당 섹션을 떠나고 몇 초 뒤에 중지됩니다.

앱과의 연결이 끊기면 피드가 스스로 다시 연결합니다. 2분 이내에는 브라우저가 마지막으로 받은 변경 바로 다음부터 누락이나 중복 없이 재개하며, 그 사실을 알려 줍니다. 일시 중지된 피드는 일시 중지된 상태로 돌아옵니다. 그 위치에서 더 이상 재개할 수 없는 경우(매우 큰 폭주 이후)에는 서버가 있던 위치에서 재개하며 일부 변경이 누락되었을 수 있다고 알려 줍니다. 2분이 지나면 지금부터 다시 시작하며 그렇게 알려 줍니다. 피드가 재개하는 위치(MongoDB의 재개 토큰)는 서버에 남아 있습니다.

필터

칩으로 변경 유형(삽입, 업데이트, 교체, 삭제)을 선택합니다. "스키마 변경 포함"을 켜면 컬렉션 및 인덱스의 생성이나 삭제, 옵션 변경 같은 변경도 포함됩니다. "업데이트 후 전체 도큐먼트 표시"는 업데이트할 때마다 그 후의 도큐먼트를 읽으며, 업데이트당 읽기 한 번의 비용이 듭니다.

"필터 편집"에서는 각 변경 이벤트에 적용할 $match를 쿼리처럼 작성합니다. 예:

  • { 'updateDescription.updatedFields.status': 'paid' }: 상태를 paid로 설정하는 업데이트.
  • { 'fullDocument.total': { $gt: 1000 } }: 큰 금액 주문의 삽입 및 교체.
  • { 'documentKey._id': ObjectId('…') }: 도큐먼트 하나.
  • { 'ns.coll': 'orders' }: 데이터베이스 또는 연결 피드에서 컬렉션 하나.

필터는 최대 12KB, 중첩 깊이 20단계까지 가능합니다. 서버에서 JavaScript를 실행하는 연산자 ($where, $function, $accumulator)는 허용되지 않습니다. 필터를 하나라도 변경하면 피드가 지금부터 다시 시작되며, 피드가 그렇게 알려 줍니다.

변경 전 값 확인

MongoDB는 업데이트가 변경한 필드와 그 새 값을 알려 줍니다. 변경 전 값도 보려면 컬렉션의 사전 이미지를 켜세요. 그러면 피드에 업데이트의 변경 전후 전체 비교와 삭제된 도큐먼트의 이전 모습이 표시됩니다. 컬렉션의 감시 페이지에서 컬렉션 옵션(예: 유효성 검사 규칙)을 변경할 수 있는 사용자는 사전 이미지가 꺼져 있는 동안 사전 및 사후 이미지 켜기가 표시됩니다. 이 버튼은 비용을 설명한 뒤 같은 명령을 실행합니다(감사됨). 셸에서 직접 실행할 수도 있습니다. 

db.runCommand({ collMod: 'orders', changeStreamPreAndPostImages: { enabled: true } })

사전 이미지는 서버의 변경 스트림 설정에 따른 기간 동안 서버 스토리지에 보관되므로, 사용량이 많은 컬렉션에서는 디스크 공간을 차지합니다. 사전 이미지가 없으면 피드에는 업데이트된 값, 제거된 필드 이름, 배열이 줄어든 방식이 표시됩니다.

녹화, 재생, 알림

파일로 녹화(필터에 있으며, 연결에서 내보낼 수 있는 사용자용)는 피드의 이벤트를 전송된 그대로 (마스킹된 부분은 마스킹된 채로) 한 줄에 이벤트 하나씩 서버에 보관합니다. 녹화는 사용자 본인의 전송 파일이며, 전송 공간을 차지하고, 최대 64MB까지 담을 수 있으며(초과하면 녹화는 멈추고 피드는 계속되며, 감시 페이지에 그렇게 표시됩니다), 피드가 끝난 뒤 전송 파일 보관 기간 동안 유지됩니다. 재연결하면서 녹화하는 경우 새 파일이 시작됩니다. 서버를 다시 시작하면 녹화가 종료되며, 디스크에 기록된 내용은 완료된 녹화로 보관됩니다. 파일에는 이벤트가 전송된 방식에 따라 마스킹 여부가 표시됩니다. 피드 도중 마스킹 설정이 바뀌면(개인 값이 지금부터 숨겨지거나 더 이상 숨겨지지 않거나 규칙이 변경된 경우) 파일은 그 시점에서 끝나고 새 표시로 새 파일이 시작되며, 녹화 목록에 둘 다 표시됩니다. 도구 모음의 녹화에는 이 연결에 대한 본인의 녹화가 나열됩니다. 재생은 실시간 피드 대신 녹화를 그 자리에서 보여 주며(같은 목록과 상세 내용), 처음 500개 이벤트를 표시하고 이벤트 더 불러오기를 선택할 때마다 500개씩 더 표시하여 최대 5,000개까지 볼 수 있습니다(나머지는 파일에 있습니다). 다운로드는 파일(NDJSON)을 제공하며, 녹화는 삭제할 수 있습니다. 관리자를 포함해 다른 누구도 읽을 수 없습니다. 녹화 당시 마스킹되지 않았는데 연결에서 개인 값이 사용자에게 숨겨진 경우, 또는 녹화 당시 마스킹되었는데 규칙이 변경된 경우에는 녹화가 제공되지 않습니다.

일치 시 알림 발생은 이벤트가 피드의 필터를 통과했음을 앱의 알림(watch.matched 이벤트)에 알립니다. 최대 10초마다 한 번, 건수와 마지막 이벤트의 유형만 전달하며 값은 절대 전달하지 않습니다. 피드가 실행되는 동안 작동합니다.

개인 데이터

개인 데이터를 볼 수 없는 사용자에게는 모든 변경이 개인 필드를 ***로 표시하여 보여 줍니다. 도큐먼트, 키, 변경 전 값, 업데이트된 값이 필드 경로별로(배열 위치 포함) 가려집니다. 숨겨진 필드에 대한 필터는 거부되며, 데이터베이스 및 연결 피드에서 이런 사용자는 변경 유형, 네임스페이스, 시간으로만 필터링할 수 있습니다. 피드를 내보내면 표시된 내용이 그대로 들어가며, 숨겨진 값도 ***로 포함됩니다.

제한 및 설정

  • 브라우저 창당 실시간 피드 3개, 사용자당 5개, 서버 전체 50개(MM_WATCH_MAX_FEEDS).
  • 256KB보다 큰 도큐먼트는 피드로 전송되지 않으며, "도큐먼트 열기"에서 볼 수 있습니다.
  • 피드당 브라우저에 도달하는 변경은 초당 최대 200건이며, 그보다 많이 발생하면 피드에 뒤처진 정도가 표시되고 따라잡습니다.
  • MM_WATCH=0은 서버에서 감시를 끕니다.
  • 피드의 시작과 중지는 필터의 지문과 함께 감사 로그에 기록되며, 필터의 값은 기록되지 않습니다.

피드가 종료되는 경우

  • 컬렉션이 삭제되었거나 이름이 변경됨: 피드가 종료됩니다. "지금부터 다시 시작"을 선택하면 같은 이름의 컬렉션을 다시 감시합니다.
  • 서버의 기록(oplog)이 피드의 위치까지 더 이상 닿지 않음(예: 오랫동안 자리를 비운 경우): 지금부터 다시 시작하세요.
  • 사용자의 접근 권한, 연결 또는 연결 설정이 변경됨: 피드가 종료되며 그 이유를 알려 줍니다.
