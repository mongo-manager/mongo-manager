はじめに

インストール

次のいずれかの方法を使用します。各リリースには、エアギャップ環境のマシン向けに、すべてのファイルの SHA-256 チェックサムも付属しています。

  • npm（Node.js 24 以降）: npx @mongo-manager/app
  • オフライン npm: npm install --global ./mongo-manager-<version>.tgz
  • スタンドアロンバイナリ: お使いのシステム用のファイルをダウンロードして実行します。Node.js は不要です。
  • Docker: docker compose -f deploy/docker-compose.yml up -d

サポートする MongoDB は 6.0 以降です。それより古いサーバーは、接続時にその旨のメッセージとともに拒否されます。

初回起動

ローカルモード（デフォルト）は、1 台のコンピューターで 1 人が使うためのモードです。Mongo Manager は 127.0.0.1:4321 で待ち受け、ブラウザーを開きます。サインインはなく、1 回限りのリンクから開きます。ターミナルで起動した場合は、アドレスの次の行にリンクが表示されます。それ以外（サービス、コンテナー、ログ）の場合は、開くためのファイルのパスが表示され、そのファイルはあなたのアカウントだけが読み取れます。その後、ブラウザーがこのサイトのデータを保持している間は、サインインした状態が続きます（最後の使用から最大 6 か月。Safari は、1 週間アクセスがないと削除します）。インストールしたアプリも同様です。ただし Mac の Safari の Web アプリは独自のデータを保持し、リンクを渡せないため、そこでは Safari のタブで Mongo Manager を使用してください。コンピューター上の他のプログラムやアカウントがそのアドレスを開いても、開き方を説明するページが表示されるだけです。リンクが使用済みになった場合や、ブラウザーが忘れた場合は、mongo-manager open を実行して新しいリンクを取得します。ターミナルではリンクも表示されるため、ファイルを開けないブラウザー（Linux の snap や Flatpak のブラウザー）でも使えます。共有しているコンピューターでは、チームモードを使用してください。 

mongo-manager
mongo-manager open             # a new link for a running Mongo Manager (--no-open prints it)

チームモードでは、ユーザー、ロール、二要素サインインが追加されます。最初の起動時に、1 回限りのセットアップトークンがターミナルに表示されます（サービスやコンテナーとして実行した場合は、データフォルダーの setup-token にあります）。ページを開いてそれを入力し、最初の管理者を作成します。 

mongo-manager --auth

最初の接続

  1. 接続を追加を選び、最初のフィールドに接続文字列を貼り付けるか入力します。たとえば localhost:27017 や mongodb+srv:// のアドレスです（mongodb:// は省略できます）。フォームは自動的に入力されます。フィールドの下の行には解釈された内容が表示され、名前は、自分で入力するまでホスト名に追従します。サーバー、認証、TLS、SSH などは詳細オプションにあります。保存して接続を選ぶと、接続を保存して開きます。
  2. 接続をテストを選びます。MongoDB のバージョンとトポロジーが表示されます。
  3. 保存します。接続が左側のツリーに表示されます。

サインイン方法

ユーザー名とパスワード（SCRAM）のほかに、接続は X.509 証明書、LDAP（PLAIN）、AWS IAM キー、OIDC、Kerberos でサインインできます。方法は詳細オプション → 認証で選択します。

  • MONGODB-OIDC（MongoDB Atlas、Enterprise）: 各自が、サーバーが指定する ID プロバイダーでサインインします。パスワードは保存されません。接続を初めて開くと、ダイアログにサインインが表示されます。プロバイダーのページがこのタブで開き、完了すると戻ってきます。そのリダイレクトが Mongo Manager に届かない環境では、代わりにコードを使用を選び、プロバイダーに表示されたコードを入力します。このサーバーの …/oidc/callback アドレスをプロバイダーに登録するか、リダイレクトアドレスに別のアドレスを指定します。許可するホストは、サインインの送信先として許可されるホストです（空の場合は Atlas とこのコンピューター）。接続のページには、サインインしているかどうかが表示され、そこからサインアウトできます。ワークロード ID（Azure、GCP、Kubernetes）は、代わりに Mongo Manager が動作しているマシンとしてサインインします。チームモードでは、管理者が許可した場合のみ使用できます。
  • Kerberos（GSSAPI）: プリンシパルを指定し、サーバーで必要な場合はサービス名、レルム、ホスト名の正規化も指定します。Mongo Manager が実行されているアカウントの Kerberos チケットでサインインします。自分のコンピューターではあなたのもの、チームモードではサーバーのものです。チームモードでは、管理者が許可しない限りオフです。npm パッケージのオプションの kerberos パッケージが必要です（デプロイを参照）。

クライアント側の暗号化

詳細オプション → 暗号化で、接続はクライアント側フィールドレベル暗号化（CSFLE）または Queryable Encryption を使用できます。npm パッケージのオプションの mongodb-client-encryption パッケージが必要です。

  • キープロバイダー: ローカルの 96 バイトのマスターキー（新しいキーを生成で作成されます。コピーを保管してください。ないとデータを復号できません）、AWS KMS、Azure Key Vault、Google Cloud KMS、または KMIP。それらの認証情報は封印された状態で保存され、再び表示されることはありません。キーボールトは、データキーが保存されるコレクションです（デフォルトは encryption.__keyVault）。
  • モード: 読み取りと書き込みは、読み取りを復号し、書き込みを暗号化します（MongoDB Enterprise または Atlas）。復号のみは、暗号化された値を復号して読み取り、ドキュメントは書き込みません（MongoDB Community）。クエリ分析には、crypt_shared ライブラリ（そのパス、チームモードではサーバーのもの）またはこのコンピューター上の mongocryptd を使用します。
  • 暗号化されたフィールドは、接続が独自のマップを指定しない限り、サーバーのコレクションオプション（Queryable Encryption の encryptedFields、CSFLE の $jsonSchema 検証ルール）から決まります。ドキュメントビューでは、暗号化されたフィールドに鍵のマークが付きます。
  • 接続の暗号化セクション（その管理者向け）には、データキーの一覧があり、新しいキーの作成とローテーション（マスターキーでの再ラップ）、および Queryable Encryption コレクションの作成を行えます。各フィールドについて、型と、等価またはレンジでクエリできるかどうかを指定し、それぞれにデータキーが作成されます。
  • 個人データが非表示になっているユーザーには、暗号化された値が保存されたままの状態で表示され、そのような接続ではドキュメントを書き込めません。コピーでは、暗号化された値が保存されたまま移動します。Queryable Encryption のコレクションはコピーできません。

ホームと次のステップ

ホームは、ダッシュボードをカスタマイズでウィジェットを追加、削除、サイズ変更、移動できるダッシュボードで、あなた用にサーバーに保存されます。次のステップウィジェットは、最近の作業からアプリ自身が判断して、最大 5 つの作業を提案します。発火中のアラート、直近 1 日で失敗したジョブ、対応が必要なライブ同期とスケジュールバックアップ、最後に使ったデータベースに対して提案されるインデックス（そのサーバーを監視できる場合に、スロークエリから導出されます）、そして最近開いたもののいま開いていない場所です。それぞれが、その作業を実行するリンクになっています。インデックスの場合は、キーが入力された通常の「インデックスを作成」ダイアログが開き、そこで確認するまで何も構築されません。✕ で非表示にできます（「元に戻す」で戻ります）。非表示にした内容はダッシュボードとともに保存され、同じ種類の新しいイベントは新しいステップとして再び表示されます。ウィジェットのメニューにある非表示にしたステップを再表示で、すべてが戻ります。

AI プロバイダーが設定されている場合、ウィジェットのメニューにAI で並べ替えが表示されます。これはオンにするまでオフです。オンにすると、AI がステップを並べ替え、タイトルの文言を整えます。使うのは事実のみで、各ステップの種類、名前（接続、データベース、コレクション、インデックスのフィールド名）、件数であり、値、ドキュメント、エラーテキストは決して使いません。接続の AI ポリシーが「オフ」、または「ローカルのみ」でプロバイダーがローカルネットワークから応答することが分かっていない場合、そのステップは送信されず、元の位置のままです。AI はステップを追加したり、ステップの動作を変更したりすることはできません。AI が付けた各タイトルの下には、そのステップが何をするかがアプリ自身の言葉で表示され、タイトルには数字が含まれません（件数は古くなるため。件数はアプリの行に表示されます）。ステップが再び並べ替えられるのは、ステップが変わったとき（別の種類のステップ、別の場所）、またはAI で並べ替え直すを選んだときだけで、件数が変動したり時間が経過したりしただけでは並べ替えられません。並べ替えのたびに、AI 履歴（「次のステップ」として、文言なし）と監査ログ（ステップの数のみで、名前は記録されません）にカウントされます。提案されたインデックスは、インデックスを作成できる場所にのみ提示されます。

クエリ

コレクションを開き、{ status: 'A', qty: { $lt: 30 } } のようなフィルターを入力して、Enter を押します。オプションでは、プロジェクション、ソート、スキップ、制限、照合順序、ヒント、時間制限を追加できます。最近のクエリには、そのコレクションで実行したクエリが一覧表示され、星印を付けると、名前とタグを付けてお気に入りとして保存できます。

コレクションは最新のドキュメントを先頭にして開きます。並び順 { _id: -1 } はオプションと _id 列に表示され、そこで変更や解除ができます。リセットボタンでこの並び順に戻ります。ビューと時系列コレクションは元の順序のままです。保存順で開くには、環境設定で「コレクションを開いたときに最新のドキュメントを先頭に表示する」をオフにします。

バーの中の値はパラメーターにでき、{{name}} と書きます。例: { status: {{status}}, qty: { $gte: {{min}} } }。それぞれに対するフィールドがバーの下に表示され、検索は、そこで指定した値でクエリを実行します。18 は数値、"18" は文字列、ISODate("2026-01-01") は日付で、それ以外のテキストは入力されたままの文字列です。バーから保存したお気に入りはパラメーターを保持し、指定した値がデフォルト値になります。開くと、それらが入力されて実行されます。値のないパラメーターがある場合は、値の入力を待ちます。引用符、正規表現、コメントの内部では、{{name}} は単なるテキストです。接続の個人データを閲覧できないユーザーが、他のユーザーのデフォルト値を取得することはありません。

バーの下のチップは条件を提案します。コレクションで最近実行した条件と、そのコレクションの小さなサンプルから導き出される条件（status = "paid" のような一般的な値、または多くのドキュメントにないフィールド）です。1 つ選ぶとフィルターに追加されて実行されます。サンプルは、ページがアイドル状態になったとき、またはバーが使われたときに 1 回取得され、ビューでは取得されません（ビューのパイプラインが実行されてしまうため）。結果の上には、使用中のフィルターの各条件が個別のチップとして表示されます。それを削除すると（×、またはチップ上で Delete）、その条件なしでフィルターが実行され、元に戻すで戻せます。バーのテキストは、それが使用中のフィルターである間だけ追従します。まだ編集中のフィルターは、そのままにされます。バーの下のパネルには、使用中のクエリが部分ごとに表示されます。その実行で再度実行でき、星印でお気に入りとして保存できます。

テーブルでは、列の名前をクリックしてソートします。昇順、降順、ソートなしの順に切り替わります。Shift + クリックで、その列がソートに追加されます。ソートはオプションに書き込まれ、バーのフィルターとともに実行されるため、バーには常に実行される内容が表示されます。列の端をドラッグする（またはフォーカスして矢印キーを使う）と幅を変更でき、端をダブルクリックすると列が自動的にサイズ調整されます。幅は、コレクションごとに、あなたのために、このブラウザーに保存されます。列のメニューでは、その列のソート、名前のコピー、非表示を行えます。値があなたに対して非表示になっている列（個人データ）は、ソートされません。

テーブル、カード、JSON と並ぶチャートは、クエリの結果を棒、折れ線、点、円で描画します。X 軸に使うフィールド、数値フィールドのカウント、合計、または平均、および結果を系列に分けるフィールドを選択します。一致する最初の 1,000 件までのドキュメント（描画に使うフィールドのみ）を読み取り、それ以上ある場合はその旨が表示されます。同じ数値のテーブルがスクリーンリーダー向けに用意されています。あなたに対して非表示のフィールドは選択肢に表示されず、チャートに描画されることもありません。データベース、コレクション、列のメニューと、スキーマ内のフィールドの横にある名前をコピーは、そのままの名前をコピーします。

表の各行の先頭には編集、削除（確認のあと）と ⋮ メニューがあり、行の _id からはドキュメントを読むために開けます。カードと JSON リストでは各ドキュメントに編集と削除が表示されます。行を右クリックするとその行のすべての操作が、セルを右クリックするとセル自体の操作（値のコピー、その値で絞り込み）も表示されます（キーボードでは Shift + F10 で同じメニューを開きます）。ドキュメントは結果の代わりにページとして開きます。結果に戻る（または Escape）で元の位置の結果に戻り、最後に開いたドキュメントに印が付きます。前のドキュメントと次のドキュメント（Alt + ↑ / ↓）でクエリの結果を順にたどり、ページの端では次または前のページに進みます。保存によってクエリに一致しなくなったドキュメントもその位置を保ち、ページにその旨が表示されます。

ページではドキュメントをツリー、JSON、エディターで表示します。ドキュメント内を検索（ページにフォーカスがあるときは Ctrl / ⌘ + F）は、キー、値、またはその両方を検索します。一致の数を数え、Enter と Shift + Enter で一致の間を移動し、一致を含む枝が開いて残りは薄く表示されます。次のドキュメントに移っても検索はそのまま残ります。ツリーの上のバーには選択したフィールドの位置（payments › 2 › amount）が表示され、パスをコピーで payments.2.amount としてコピーできます。射影のあるクエリの行はドキュメントの一部にすぎないため、ページはドキュメント全体を読み込んで表示・編集し、その旨を表示します。

書き込み権限がある場所では、ツリーでその場で編集できます。Enter またはダブルクリックで値を変更し、型を保つか別の型にできます。F2 でフィールド名を変更、Delete で削除し、フィールドのメニューからフィールドや要素を追加します。ツリーとテキストは 1 つの下書きで、元に戻す履歴も 1 つです（Ctrl / ⌘ + Z, Ctrl / ⌘ + Shift + Z）。確認して保存では、書き込む前にどのフィールドが変わるかを正確に表示し、それらだけを開いたバージョンに対して保存します。サーバー上のより新しいコピーを上書きすることはありません。_id と非表示の値は変更されず、検索が非表示の値を見つけることもありません。表では値をダブルクリック（またはその上で Enter）するとその場で編集でき、型は保たれます。行のそれ以外の場所をダブルクリックすると、ドキュメントを編集用に開きます。

複数のドキュメントを更新と複数のドキュメントを削除は、実行前にプレビューを表示します。一致するドキュメントの数と、そのいくつかです。更新の場合、各サンプルには、その中で何が変わるかが表示されます。これは MongoDB が何も書き込まない読み取りで計算します。更新が失敗するドキュメント（テキストに対する $inc、配列を通るパス）には印が付きます。位置指定パス（$[]）、配列インデックス、条件付きの $pull はサンプルではプレビューされず、プレビューにその旨が表示されます。個人データの値は、前後ともサンプル内でマスクされたままです。

コレクション

新しいコレクションでは、コレクション、キャップ付きまたは時系列コレクション、ビューに対して、デフォルトの照合順序（言語、強度、数値順序、MongoDB のその他のオプション）を設定できます。MongoDB はこれを作成時に固定します。コレクションまたはキャップ付きコレクションは、最初からチェンジストリームの変更前後イメージを保持することもできます。後からは、コレクションのメニューのコレクションを編集でそれらのイメージをオンまたはオフにでき（名前を指定した確認の後）、照合順序が表示され、ルールが保持される検証タブに移動できます。コレクションのヘッダーには、その照合順序とイメージが保持されているかどうかが表示されます。

パフォーマンス

接続のパフォーマンスタブは、サーバーをライブでチャート化します。1 秒あたりの操作数、接続数、ネットワーク、メモリが、タブを開いている間 2 秒ごとにサンプリングされます。その下には、実行中の最も遅い操作（データベースまたはコレクション、種類、実行時間、ロックの待機、アイドル接続でフィルターでき、一時停止もできます）と、最も時間がかかったコレクションが表示されます。編集者と管理者が開くことができます。操作の「…」メニューにはそのコマンドが表示され、接続の管理者には、確認が表示される操作を強制終了があります。MongoDB 自体が、そのアカウントにサーバーステータスの読み取りを許可している必要があります。clusterMonitor ロールを付与してください。不足している場合は、タブにその旨が表示されます。

プロファイラーセクションには、各データベースのプロファイラーレベル、slowms、サンプルレートが表示されます。接続の管理者は、データベースの行の鉛筆アイコンから変更できます。レベル 2（すべての操作）では先に確認が表示され、30 分後に自動的に前の設定に戻ります。スロークエリには、プロファイラーとサーバー自身のログ（プロファイラーがオフでも動作します）からの遅い操作が新しい順に一覧表示され、プラン、調べられたキーとドキュメント、コマンドが表示されます。返す件数よりはるかに多くのドキュメントを読み取るものには印が付き、実行計画の確認で開くで、そのコレクションで開けます。

接続の個人データタブでは、接続の管理者が、個人データを保持するフィールドを一覧にできます（たとえば crm.users.email や *.*.**.phone）。コレクション自身の個人データタブには、そのコレクションのフィールドだけが一覧表示され、追加できます（新しいフィールドに必要なのはフィールド名だけです）。また、そのコレクションに及ぶ、接続のより広いルールも表示されます。個人データを表示できないを付与されたユーザーには、プロファイラー、スロークエリ、操作での値が *** として表示され、シェルを使用できません。ローカルモード（アカウントなし）では、ルールは、ドキュメント、エクスポート、AI のコンテキストなど、あらゆる場所であなた自身に対しても値を非表示にし、非表示の間はシェルが閉じたままになります。接続のタブにある自分に対しても非表示にするをオフにすると、その接続ではこれが解除されます。

インデックスの提案は、データベースのスロークエリを読み取り、スキャンが発生した各クエリに対して、等価・ソート・レンジの規則でインデックスを提案します（すでにそれを満たすインデックスがある場合を除く）。また、サーバーの起動以降に使用されていないインデックス、または別のインデックスの先頭部分にあたるインデックスも一覧表示します。使用されるのはフィールド名だけです。インデックスを作成を選ぶと、キーが入力された通常のダイアログが開きます。そこで確認するまで何も構築されません。

パフォーマンスを開いている間、接続のヘッダーで、ライブ（直近 5 分間）または保存済みの 1 時間、24 時間、7 日間の期間を選べます。接続の管理者は、その隣のメトリクス履歴メニューでメトリクス履歴を記録をオンにします（同じメニューで、確認の後、保存済みのものを削除できます）。オンにすると、サーバーがその接続を 1 分に 1 回サンプリングし、7 日間保持します（数値のみ）。オフの間、サーバーがその接続へ自発的に接続することはありません。mongos では、タブにシャーディングの概要が表示されます。シャード、バランサー、ルーター、各シャーディングされたコレクションのキーとチャンクの分布が表示され、サイズとジャンボチャンクはオンデマンドで取得されます。そこでの操作がクラスターを変更することはありません。

レプリカセットでは、同じタブにすべてのメンバーが一覧表示されます。どれがプライマリか、どれがダウンしているか、各セカンダリがプライマリから何秒遅れているか（10 秒を超えると黄色、60 秒を超えると赤）、過半数コミットの遅延、oplog ウィンドウが表示され、直近数分間の遅延のチャートも表示されます。プライマリのないセットは赤で表示されます。プライマリが選出されるまで、書き込みを受け付けられません。

集計

コレクションの集計タブでは、パイプラインをステージごとに構築します。ステージを追加し、その演算子を選び（演算子のフィールドに入力すると、名前や機能でステージを検索できます。たとえば「join」で $lookup が見つかります。矢印キーと Enter で選択します。一覧の横には、そのステージの機能と値の例が表示されます。各ステージはテンプレートから始まり、MongoDB マニュアルへのリンクがあります）、その値を編集します。入力している間、各ステージの出力が、コレクションのサンプル（最初の 1000 件のドキュメント、またはランダムサンプル）でプレビューされます。ステージは、無効にしたり、ドラッグアンドドロップまたは Alt+Up と Alt+Down で並べ替えたり、テキストとしてまとめて編集したりできます。

実行は、停止ボタンとともに結果全体（最大 10 000 ドキュメント）をストリーミングします。合計の計算は、要求されたときにのみ件数を数えます。$out または $merge で終わるパイプラインは、プレビューされません。ターゲットを示す確認の後に 1 回だけ実行され、コレクションの置き換えでは、その名前の入力が求められます。パイプラインは、コレクションとともに保存でき（チームモードでは、任意で共有）、Node.js、Python、Java、Go、C#、PHP、Ruby、Rust のプログラムとしてエクスポートできます（接続文字列は MONGODB_URI から読み取られ、コードに書き込まれることはありません）。また、ビューに変換することもできます。

ビューのパイプラインも同じ方法で変更します。ビューのパイプラインを編集（その概要またはメニュー）を選ぶと、ビューが読み取るコレクションの集計タブでそのパイプラインがビューのものとして印が付いた状態で開き、各ステージのプレビューが表示されます。ビューを更新は、有効なステージをビューに書き戻します。ビューの名前を示す確認が表示されます。ビルダーが読み取れないステージを含むパイプラインは開かれません（保存するとそのステージが失われるため）。個人データが非表示になっているユーザーは、定義がマスクされて表示されるビューを変更できません。

クエリ

クエリページ（サイドバーの「クエリ」、コマンドパレット、または Ctrl / ⌘ + Shift + L。アドレスは /library）では、接続のお気に入り、保存済みパイプライン、シェルのスニペット、クエリ履歴を、名前、タグ、クエリのテキスト、種類、コレクションで検索できます。作業中の接続で開き、なければ最初の接続で開き、戻ってきたときには検索内容が保持されています。項目を開くと、そのコレクションに移動します。検索はドキュメントで実行され、パイプラインは集計カードに入力されます（タブにすでに何かある場合は、確認の後）。履歴には、実行した検索と集計が、コレクションごとに最新の 200 件、合計で 2000 件まで保持され、それぞれ 1 回だけ、使用回数とともに記録されます。エントリーは 1 件ずつ削除したり、クリアしたりできます。お気に入りと保存済みパイプラインは、クエリページから名前の変更、タグの付け直し、共有、削除、ピン留めができます。ピン留めしたクエリはあなただけのもので（接続ごとに最大 50 件）、クエリページとホームのクエリウィジェットで先頭に表示されます。コマンドパレットには、タブで開いているすべての接続のお気に入り、保存済みパイプライン、シェルのスニペットが、接続ごとにその名前の下に一覧表示され、作業中の接続が先頭に表示されます。チームモードが開始されると、ローカルモードの履歴は削除されます（チームのユーザーが閲覧もクリアもできないため）。ログには、削除されたエントリーの数が表示されます。ローカルモードのお気に入りと保存済みパイプラインは、接続の管理者のために残ります。

高度なシェル

接続のシェルタブは本物の mongosh を実行し、そのターミナルでコードを入力します。データベースの使用、検索と集計の実行、スクリプトの記述を行えます。Enter はコードが完結したときに実行します。括弧、文字列、ステートメントが開いている間（.、演算子、if (…) の後）は、... の後の次の行に続き、Shift+Enter は常に行を追加します。Ctrl+Enter は、そのままコードを実行します。複数行のコードをターミナルに貼り付けることができます。1 行ずつ表示され、Enter を押したときにのみ実行されます。スクリプトは、mongosh が入力されたものを実行するのと同じように実行されます。use、show、it はそれぞれ単独で、その後に各ステートメントが順番に実行されます。エラーが発生するとそこで停止し、実行されなかったステートメントの数が表示されます。print() と printjson() はターミナルに書き込みます。cls はターミナルと結果をクリアし、exit はシェルを終了します。

上下キーは、入力した内容の行間を移動し、次に履歴を移動します。Ctrl+R は履歴を検索します（もう一度 Ctrl+R でさらに古い一致、Escape で終了）。Ctrl+C は、実行中のコマンドを停止するか、行をクリアします。出力が選択されている場合はコピーします。Alt+B と Alt+F（または Ctrl+左と Ctrl+右）は単語単位で移動します。各ユーザーの履歴は、接続ごとに暗号化されて保持され、クリアできます。

シェルは、接続の管理者と、管理者から許可された編集者が使用できます。認証情報を持たず、接続自身のサーバーにのみ到達できるサンドボックスで動作します。読み取り専用の接続では書き込みが拒否され、管理者以外はクラスター管理やユーザー管理を実行できません。

シェルページには、実行場所（接続と、シェルがいるデータベース。use に追従します）と、その状態（接続中、接続済み、実行中（実行時間付き）、閉じた）が表示されます。そのヘッダーには、コマンドの実行中は停止、画面と結果のクリア（Ctrl+L。コマンドの実行中も有効、または cls。通知でその旨が表示され、その元に戻す、または空の結果カードの「結果を元に戻す」で結果が戻ります）があり、またメニューでは、入力した内容（または最後に実行したコード）をスニペットとして保存、履歴のクリア（結果も一緒に消えます）、シェルの再起動（セッションが終了して新しいものが始まります。変数と表示中の結果は失われます）を行えます。ターミナルは、アプリのライトまたはダークテーマ、または独自のテーマのいずれかを使用し、コードに色を付けます。下部のバーには、キーの一覧が表示されます。シェルは、そのページが開いている限り、使用されない時間がどれだけ長くても開いたままです。シェルが閉じたとき（サインインが終了した、またはサーバーが設定するアイドルまたは有効期間の上限を超えた）は、ページにその理由が表示されます。Enter で新しいものが開きます。接続が切れたときに実行中だったコマンドは、接続が戻ると画面上で完了します。

入力中は、Tab で補完候補が表示されます。db. の後はデータベースのコレクション（シェルで作成したものも含む）、チェーンが返すものに対するメソッド、$ の後は演算子、コレクションからサンプリングしたフィールド名です。Shift+Tab、または Escape の後に Tab で、ターミナルから出ます。

ターミナルの横の結果カードには、最後の結果が、テーブル、ツリー、またはテキストとして表示されます。「さらに表示」はカーソルの次のバッチを取得し、ヘッダーの結果履歴では、以前の結果を選択できます。各結果は、元になったコマンドの名前で表示されます（メモリ内にのみ保持されます）。クリアはカードを空にします。通知の元に戻す、または空のカードの「結果を元に戻す」で、シェルが再起動するか履歴がクリアされるまで、結果が戻ります。カードは広げることができ、狭い画面ではターミナルと結果が 2 つのタブになります。複数のシェルタブを同時に開くことができ、それぞれ独自のセッションを持ちます。単純な検索または集計のカーソルは、そのコレクションビューで開きます。検索はそのスキップ位置から始まり、その制限がページサイズになります。表示されているドキュメントは、JSON または CSV としてエクスポートできます。

コードは、スニペットとして保存できます。非公開、またはチームと共有で、パラメーターは {{name}} と書きます。スニペットを開く（クエリページまたはコマンドパレットから）と、そのパラメーターの入力が求められ、入力されたコードがターミナルに置かれます。Enter を押すまで何も実行されません。自分のスニペットは、クエリページで編集します。名前、タグ、コード、パラメーター（入力に合わせて、各 {{name}} の行が追加されます）で、新しいスニペットと同じ検査が行われます。共有スニペットは共有されたままで、監査ログにはそのコードが変更されたことが記録されますが、コード自体は記録されません。

ターミナルはスクリーンリーダーで動作します。スクリーンリーダーモードはデフォルトでオンで、アカウント → 環境設定でオフまたは再びオンにでき、開いているシェルにも反映されます。

実行計画の確認

ドキュメントまたは集計の「なぜ遅いのか」を選ぶと、そのクエリまたはパイプラインの実行計画の確認セクションが開きます。MongoDB が選択したプランがツリーとして表示され（矢印キーで移動できます）、各ステージが読み取った内容と返した内容、却下されたプラン、そして言葉による警告が表示されます。コレクション全体のスキャン、メモリ内で行われたソート、返す件数よりはるかに多くを読み取るフィルター、インデックスのないフィールドでの結合などです。インデックスが有効な場合は、実行計画の確認がインデックスを提案し（等価フィールド、次にソート、次にレンジ）、「このインデックスを作成」でバックグラウンドで構築されます。書き込みを行うパイプラインは、確認すると実行されてしまうため、実行計画の確認は行われません。

検証

検証セクションでは、挿入または更新されるすべてのドキュメントが従うべきルールを、検証レベルとアクションとともに編集します。「サンプルから生成」は、コレクションのドキュメントから $jsonSchema を作成します。「既存のドキュメントに対してテスト」は、保存する前に、どれだけのドキュメントが失敗するかを例とともにカウントします。保存する前には確認が表示され、ルールに違反するドキュメントの更新が拒否される場合はその旨が表示されます。「以前のルールを復元」は、タブを開いている間、最後の保存で置き換えられた内容を元に戻します。ルールに拒否された書き込みでは、満たされなかったルール（フィールドの欠落、型の誤り、最小値）が示され、インポートやコピーのレポートでも同様です。失敗した値が繰り返し表示されることはありません。

スキーマ

コレクションのスキーマタブは、ランダムサンプル（100、1,000、または 10,000 ドキュメント）を分析します。各フィールドについて、出現頻度、型、ヒストグラムまたは最も一般的な値が表示されます。エクスポート は、分析結果を Mongoose スキーマ、MongoDB JSON Schema 検証ルール、または TypeScript インターフェースに変換し、コピーまたはダウンロードできます。サンプリングされたすべてのドキュメントにあるフィールドは、必須として扱われます。

フィールドのバー（範囲と最も一般的な値）と型はボタンになっています。1 つ選ぶと、その条件がコレクションのドキュメントのフィルターに追加され（すでに入力されている条件と並べて、フィールドにすでに条件がある場合は $and で）、実行されてドキュメントが表示されます。分析で途中までしか取得されなかった値は表示されますが、選択できません。場所を保持するフィールド（GeoJSON ポイント、または location や coords のような名前の座標ペア）は、ネットワークを使わずに描画される地図に表示されます（世界の輪郭は、パブリックドメインの Natural Earth）。ドラッグまたは矢印キーで移動し、Ctrl とホイール、2 本指、または + と − でズームします。場所はテーブルとしても一覧表示され、この範囲でフィルターは、表示中の範囲の $geoWithin を追加します。個人データのフィールドは描画されません。

データモデル

データベースのモデルセクションは、そのコレクションと、それらの間の参照を描画します。モデルを読み取るは、各コレクションをサンプリングして（100 から 1,000 ドキュメント、最大 50 コレクション）そのフィールドを調べます。最上位とその 1 つ下のレベルのフィールドで、それより深いものは、参照のように見える場合のみです。参照は 3 つの方法で見つけられます。コレクションにちなんだ名前のフィールド（userId または user_id → users、tagIds → tags）、別のコレクションの _id として見つかったサンプリングされた ObjectId 値（フィールドあたり最大 10 個の値、小さなカウントは合計 60 回まで）、そして、ビューと、あなたが開ける保存済みパイプラインの $lookup および $graphLookup ステージです。実線は名前または値によって、破線は $lookup のみによって見つかったもので、点線はビューとそのソースを結びます。線は、参照を保持するフィールド側では鳥の足（「多」）で終わり（多くのドキュメントが同じ ID を保持することがあります）、参照先のコレクション側ではバー（「一」）で終わります。参照の配列の場合は、そこも鳥の足になります。フィールドには、PK（キー、_id）、UQ（そのフィールドのみの一意インデックス）、IX（インデックスに含まれる）の印が付きます。インデックスは、そのキーの名前のみから読み取られます。

図をドラッグするか矢印キーで移動し、+ と − でズーム、0 で全体表示にします。ホイールは、図にフォーカスが移るまで（クリックするか Tab で移動）ページをスクロールし、フォーカス後は、ホイールで図が移動し、Ctrl / ⌘ とホイールでズームします（Shift とホイールは、いつでも移動します）。コレクションをクリックするか、Tab で移動して Enter を押すと、そのリンクが表示され、開くことができます。リストビューは、同じモデルをリストとして表示します。各コレクションを開くとそのフィールドとリンクが表示され、リンクからは参照先のコレクションに移動します。エクスポートは、図を PNG または SVG として（使用中のテーマの色とあなたの言語で）、モデルを JSON として、そしてモデルを Mermaid の erDiagram として（.mmd として保存、またはコピー）保存します。これは、図を描画する README、Wiki、プルリクエストで使えます。Mermaid の命名に従い、一意のフィールドは UK と書かれます。表示されるのは名前、型、件数のみで、値がサーバーから出ることはありません。ドキュメントを読み取れる人は、モデルを読み取れます。個人データとしてあなたに対して非表示のフィールドは、名前のみが表示され、その値は読み取られません。一部のコレクションのみを許可された MongoDB ユーザーには、それらが表示されます。

モデルの読み取りには、コレクションごとに 1 回のサンプリングがサーバーに負荷として発生します。最大 50 コレクションにサンプルサイズを掛けた量に、最大 60 回の小さなカウントが加わります。サーバーは、1 つのモデルが全体で読み取るドキュメント数に上限を設けています（MM_MODEL_MAX_DOCS、デフォルトは 20,000）。コレクションが多い場合は各サンプルが小さくなり、セクションにその旨が表示されます。負荷の高い本番データベースでは、サーバーが空いているときや、サンプルを小さくして読み取ってください。

検索インデックス

MongoDB Atlas、または検索プロセス（mongot）を備えた MongoDB 8.0 以降では、インデックスタブに、コレクションの Atlas Search と Vector Search のインデックスも一覧表示されます。それぞれの種類、状態（保留中、構築中、準備完了、失敗とその理由）、対象が表示され、構築中のものがある間は数秒ごとに再確認されます。検索インデックスを作成では、定義を JSON で指定するか、ベクトルインデックスの場合はガイド付きフォームで指定します。埋め込みを保持するフィールド、その次元と類似度、フィルターに使うフィールドです。定義は編集でき、インデックスはドロップできます（名前を示す確認の後）。それ以外の環境では、検索に何が必要かがタブに表示されます。

バックグラウンドジョブ

インデックスの構築とコレクションの複製はバックグラウンドで実行されるため、長時間かかってもタイムアウトに遭遇しません。実行中に、ページを離れたりタブを閉じたりしても構いません。上部バーのバックグラウンドジョブボタンには、各ジョブが表示されます。MongoDB が進捗を報告する場合（インデックスの構築）はバーと数値が、そうでない場合（コピー）は実行中とこれまでの時間が表示されます。自分のジョブが終了すると通知され、そこでキャンセルすることもできます。

コピーの最中にサーバーが再起動した場合、そのコピーは破棄され、作成途中のコレクションは削除されます。ターゲットが中途半端に埋まったままになることはありません。インデックスの構築は MongoDB 内で続行されることがあり、インデックスタブにそれが表示されます。
