インポートとエクスポート

コンピューターとコレクションの間のファイルの移動は、バックグラウンドジョブとして実行されます。ダイアログを閉じても、ジョブ一覧で進捗を確認できます。ジョブは、コレクションのツールバー、サイドバーのコレクションのメニュー、またはコマンドパレットから開きます。SQL ダンプは別扱いで、ファイルとデータベース全体の間で移動し、専用のページで行います（SQL のインポートとエクスポートを参照）。

形式

  • CSV と TSV（区切り文字はカンマ、セミコロン、タブ、パイプ。文字エンコーディングは UTF-8、UTF-16、Latin-1、Windows-1252、Windows-1254、ISO-8859-9）。
  • JSON: ドキュメントの配列 1 つ、または 1 つのドキュメント。
  • NDJSON: 1 行に 1 ドキュメント。Extended JSON 形式なので、すべての BSON 型が元のまま復元されます。
  • Excel ブック（.xlsx）。一度に 1 シートずつ。
  • 上記のいずれかを gzip（.gz）で圧縮したもの。

インポート

  1. ファイルを選択するか、ダイアログにドロップするか、テキストを貼り付けます。
  2. 読み取り方法を確認します。形式、区切り文字、エンコーディング、先頭行がフィールド名かどうか、ブックのシートです。ファイルは、バイトオーダーマークが別の指定をしているか、別のエンコーディングを選んだ場合を除き、UTF-8 として読み取られます。そのエンコーディングではバイト列がテキストにならない場合は、それらしいエンコーディングが提案され（バイトオーダーマークのない UTF-16、トルコ語の文字なら Windows-1254、それ以外は Windows-1252）、1 クリックでそのエンコーディングで再読み込みできます。推測が自動で適用されることはありません。間違った推測では誤った文字が書き込まれてしまうためです。選択したエンコーディングでもテキストにならない行は拒否され、置換文字で書き込まれることはありません。
  3. フィールドをマッピングします。各フィールドの書き込み先（a.b はネスト、a[0] は配列要素）、型、空の値や変換できない値をどうするかを指定します。型は最初の 1,000 件のレコードから提案されます。先頭に 0 や + が付いた値はテキストのままになるため、コードや電話番号がそのまま保持されます。この規則は以降のすべてのレコード、選択した型、定数にも同様に適用されます。コードが数値として読み取られることも、別の数値になってしまう double として数値が読み取られることもありません（0.30000000000000004 は double ですが、12345678901234567 は double ではありません）。そのような値は、変換できない値として扱われます。タイムゾーンのない日付は UTC として読み取られます。ヘッダーよりフィールド数が多い、または少ない CSV の行（フィールド内の引用符なしのカンマなど）は行エラーとなり、元のままの形で拒否レコードのファイルに出力されます。スペースだけの行はレコードとして扱われません。各フィールドの下には、選択した型で書き込まれる場合の最初のサンプルが表示されます。書き込めない場合は、その理由が表示されます。
  4. 必要に応じて、定数フィールドを追加します。すべてのドキュメントに同じ値を入れるもので、インポート時刻、または文字列、数値（Int32、Int64、Double、Decimal128）、日付、ObjectId、ブール値、JSON、null として指定できます。定数は、ファイルの値と同じ規則で変換され、変換できない場合はインポートの開始前に拒否されます。
  5. モードを選び、必要に応じて先にドライランを実行します。アップサートとマージでは、キーフィールドのいずれかで始まるインデックスがない場合、ダイアログが警告します。その場合、各レコードはコレクションをスキャンして検索されることになります。

モード

  • 挿入: すべてのレコードが新しいドキュメントになります。_id がすでに存在するレコードは失敗します。
  • アップサート: 同じキーフィールド（デフォルトは _id）を持つドキュメントはレコードで置き換えられ、なければレコードが挿入されます。
  • マージ: レコードのフィールドが、同じキーフィールドを持つドキュメントに書き込まれます。レコードにないフィールドは、サブドキュメント内も含めて保持されます。「更新のみ」にすると、どれにも一致しないレコードは除外されます。名前にドットを含む、または $ で始まるフィールド名を持つレコードはマージできません（パスとして解釈されてしまうため）。その場合はアップサートを使用してください。

「スキップして続行」では、失敗したレコードはカウントされて一覧表示されます。「インポートを停止」では、最初の失敗より前のレコードが書き込まれ、そこでインポートが停止します。ドライランは、ファイル全体を読み取り、変換し、検証しますが、何も書き込みません。レポートには、結果の件数、マッピングしたフィールドごとに変換できた値とできなかった値の数、最初の失敗の一覧が表示され、拒否されたレコードは元の形式のファイルとして提供されるので、修正して再度インポートできます。そのファイルがストレージの上限を超える場合は保持されず、レポートにその旨が表示されます。キーフィールドは値として照合され、$ で始めることはできません。

エクスポート

適用したクエリ、コレクション全体、またはパイプラインの結果をエクスポートできます。CSV と Excel では、選択して並べ替えた列が使われます。サイドバー、コマンドパレット、またはドキュメントが表示されていないコレクションから開いた場合、ダイアログは 100 件のドキュメントのサンプルから列を提案します（個人データのフィールドには印が付き、それを閲覧できないユーザーには *** として書き込まれます）。配列は、JSON テキストとして、要素ごとに 1 列（tags.0、tags.1…。最初のドキュメントのうち最も長い配列の長さまで、ただし設定した数が上限。それを超える要素はレポートに記載されます）として、または選択した区切り文字で連結した要素として書き込まれます。いずれも選択しない場合は、最初のドキュメント（最大 1,000 件または 8 MiB、列は最大 500）のフィールドが列になり、あるドキュメントでは値、別のドキュメントではサブドキュメントであるフィールドは、値全体を保持する 1 つの列になります。どの列にも含まれないものは、そのパスとともにレポートに記載されます。スペースを除いた先頭が =、+、-、@、タブ、または改行で始まる CSV テキストには、スプレッドシートが数式として実行しないよう先頭に ' が付加されます。別のプログラムが読み込むファイルや、再インポートするファイルでは、これをオフにしてください。JSON と NDJSON では、すべてのフィールドとすべての型が保持されます。Excel は最大 1,048,575 行、1 セルあたり 32,767 文字までです。それより長いセルは切り詰められてレポートにカウントされ、それより大きなエクスポートは、CSV または NDJSON の使用を提案して拒否されます。ジョブが完了したら、ジョブ一覧からファイルをダウンロードします。ファイルの保持期限が表示されます（デフォルトは 24 時間、MM_TRANSFER_TTL_HOURS）。期限が切れた後は、エクスポートをもう一度実行する必要があります。

SQL のインポートとエクスポート

SQL のインポートとエクスポートは、同梱の SQL → MongoDB プラグインの機能です。管理者がプラグインで承認して有効にするまで、このページ、サイドバーの項目、コマンドパレットのコマンド、以下のデータベースメニューの項目は表示されず、サーバーも SQL のインポートとエクスポートを拒否します。コレクションの SQL エクスポートやアシスタントによる SQL エクスポートも同様です。

SQL のインポートとエクスポートは、コレクションからは行いません。ドキュメントのツールバーにも、コレクションのエクスポートダイアログにも表示されません。専用のページ、サイドバーの SQL ↔ MongoDB があります。このページには、作業対象の接続とデータベースが常に表示されます。どちらも上部で選択し、ページのアドレス（/sql/import/<connection>/<database> または /sql/export/…）に保持されるため、再読み込みや共有リンクで同じ場所が開きます。サイドバーのツリーでは、データベースのメニューに「SQL ダンプをインポート…」と「SQL としてエクスポート…」があり、そのデータベースでページが開きます。コマンドパレットでは、「SQL ↔ MongoDB」で前回の位置のままページが開き、「SQL としてエクスポート」で、現在のタブのデータベースのエクスポートが開きます。インポートもエクスポートも、一度に 1 つのデータベースで動作します。他のタブやこのページの別の部分を見ている間もページは開いたままで、準備中のファイルや実行中のジョブは失われず、実行中のエクスポートは戻ってきたときに再び表示されます。ファイルを準備している間やインポートが実行中の間にページを閉じたりアプリを離れたりしようとすると、先に確認されます。ジョブの進捗がページ上に表示されている間は、その終了結果もそこに表示され、別途通知は出ません。

SQL ダンプのインポート（SQL → MongoDB）

  1. MySQL（mysqldump）、PostgreSQL（pg_dump）、SQLite（.dump）のファイルを、そのままのもの、または gzip（.gz）で圧縮したものを選択またはドロップします。読み取られるのはテーブル定義と行だけで、ファイル内のものが実行されることはありません。その他のステートメントは、スキップされたものとして一覧表示されます。
  2. ダンプに含まれるテーブルを確認します。各テーブルには、列、行数、主キー、いくつかのサンプル行が表示されます。インポートするテーブルを選び、それぞれの取り込み先のコレクション名を指定します。名前には、新規か既存かの印が付きます。挿入の場合は、複数のテーブルを 1 つのコレクションにまとめられます。アップサートとマージでは、同じキーを持つ 2 つのテーブルの行が互いを置き換えてしまうため、各テーブルは別々のコレクションに入ります。
  3. オプションを選びます。「主キーを _id にする」にすると、単一列の主キーがドキュメントの _id になります。複合キーはフィールドのままです。モードは、ファイルの場合と同様に挿入、アップサート、マージのいずれかです（アップサートとマージは _id で照合するため、単一列の主キーを持たないテーブルでは使用できません）。行を書き込めない場合は、「スキップして続行」または「インポートを停止」を選びます。
  4. 必要に応じてドライランを実行します。選択したすべての行を読み取って検証しますが、何も書き込みません。その後、インポートを開始します。インポートはバックグラウンドジョブとして実行され、フォームとは別の専用ページで進捗と、続いてレポートを確認できます。「停止」で終了します。停止、失敗、または中断されたインポートは、その旨と、終了するまでに書き込んだ内容がレポートされます。

インポート先は、既存のデータベース、またはページで名前を指定した新しいデータベースで、admin、local、config には決して書き込まれません。既存のデータベースと大文字小文字だけが異なる新しい名前は、MongoDB が拒否するのと同様に拒否されます。別のデータベースを選んでも、準備中のファイルは保持されます（ドライランは、実行したデータベースについての結果であるため破棄されます）。別の接続を選ぶ場合は、どのような方法で要求しても（一覧、ツリー、パレット、プラグイン、ブラウザーの「戻る」）先に確認されます。読み取ったファイルは接続に属しているためで、辞退するとページはそのままです。接続でドキュメントを書き込む権限とバックグラウンドジョブを実行する権限が必要で、接続とサーバーが読み取り専用であってはなりません。

インポートもエクスポートも、1 つの長いページではなく、1 ステップずつ進みます。上部のステップ（インポートは「ファイル」「テーブル」「オプション」「進捗」、エクスポートは「コレクション」「オプション」「進捗」）で現在位置が分かります。ファイルの後に通過したステップには、選択内容を保持したまま戻れます。「別のファイルを選択」を選ぶと、別のファイルで最初からやり直します。ドライランは、確認した内容についての結果です。テーブル、コレクション、オプション、またはデータベースを変更すると破棄されます（実行中のドライランは停止されます）。インポートが実行されると、渡された内容は変更できません。終了するまでそのページが表示され、その後「別のファイルをインポート」で最初からやり直せます。

SQL としてエクスポート（MongoDB → SQL）

データベースを選び（admin、local、config は選べません）、エクスポートするコレクション、ビュー、時系列コレクションを選びます。最初はすべてが選択されており、最大 500 までです。1 つのバックグラウンドジョブが、それらを 1 つの SQL ファイルに書き込み、それぞれに CREATE TABLE とその INSERT を出力します。ファイルはデータベースやスキーマ自体は作成しないため、選択したデータベースに読み込まれます。2 つのテーブル名が衝突する場合（たとえば大文字小文字だけが異なる名前）は、一方が一意な名前になり、レポートにその旨が表示されます。オプションは、ダイアレクト（PostgreSQL、MySQL、SQLite）、INSERT あたりの行数（1 から 1000）、テーブルごとに 1 つのトランザクション、gzip 圧縮です。MySQL では、phpMyAdmin 4.7 より前のような古いツール向けに、ネストされた値を JSON ではなく LONGTEXT（同じ JSON テキスト）として書き込めます。MySQL の decimal 列は、最初のドキュメントの値が書き込まれている小数桁数を採用します（234.20 は 2 桁。末尾の 0 が 2 つを超える分はパディングなので、DECIMAL(65,30) 列から読み戻した値は自身の小数桁数を保ちます）。すべての金額に 30 個の 0 が付くことはありません。後の値の小数桁数がそれより多い場合は、ALTER TABLE … MODIFY で列が広げられます（MySQL はその前の行をコミットするため、その後トランザクションが改めて開始されます）。それまでの値と合わせてどの decimal 列にも保持できない値（小数が 30 桁を超える、または全体で 65 桁を超える）は、丸められることなく NULL として書き込まれ、カウントされます。列は各コレクションの最初のドキュメントから決まります。後のドキュメントにのみ現れるフィールドは含まれず、レポートにテーブルごとに一覧表示されます。大きすぎる、または SQL の型でないために NULL として書き込まれた値も同様です。このアプリが書き出したファイルは、保持していたドキュメントとしてインポートし直せます。CHAR(24) 列は ObjectId に、"sub.a" 列はネストされたフィールドに（そこにある NULL は、ドキュメントに存在しなかったフィールドとして）、バイト列はバイナリに戻ります。進捗、レポート、ダウンロードは専用のページに表示されます。「停止」で実行中のエクスポートを終了し、「もう一度エクスポート」でオプションに戻ります。

SQL としてエクスポートするには、接続のエクスポート権限が必要です。個人データを閲覧できないユーザーには、他のエクスポートと同様に、値が非表示の箇所に *** が書き込まれます。

コピー、比較、同期

コレクション（コレクション全体、適用したクエリ、コピーダイアログで入力したフィルター、またはパイプラインの結果。集計ビルダーの「結果をコピー…」）、またはデータベースの選択したコレクションを、同じ接続または別の接続にコピーします。最初のステップでは、ソースの推定サイズが表示されます。ターゲットを選択または入力すると、ダイアログがすぐにそれを確認します。存在するかどうかとドキュメント数、選択したモードがターゲットに与える影響、そこでのあなたのロール、そしてコピーが拒否する内容です。データベースのコピーの実行中は、ジョブ一覧に各コレクションがそれぞれの進捗とともに表示されます。挿入、アップサート、マージはインポートと同様に動作し、失敗するまでに書き込まれた内容は保持されます。「ターゲットを置き換え」は、ステージング用のコレクションにコピーを構築し、すべてのドキュメントが書き込まれたときにのみ所定の場所に入れ替えます。拒否されたドキュメント、失敗、キャンセルがあった場合、ターゲットは元のままです。検証ルールは、MongoDB 自身のコピーと同様に、ドキュメントの読み込み後に設定されるため、それより前に保存されたドキュメントもコピーされます。ただし、ターゲットのユーザーが検証ルールを変更できない場合（readWrite ロール）は、先に設定され、レポートにその旨が表示されます。インデックス、検証ルール、コレクションオプション（キャップ付き、照合順序、時系列、クラスター化）もコピーできます。データベースのコピーでは、ビューは依存関係の順に最後に作成され、ビューは 1 つずつ選択できます。暗号化された（Queryable Encryption）コレクションとそのメタデータコレクションはコピーされません。マスクするものがない同一の接続内では、MongoDB が自身でコピーし（$out または $merge）、データが Mongo Manager を通過することはありません。

Mongo Manager を通過するコピーでは、各ドキュメントが Node.js 用 MongoDB ドライバーが読み取るとおりに書き込まれます。非推奨の BSON 型である undefined と DBPointer は、それぞれ null と DBRef ドキュメントとして届きます。MongoDB が自身で行うコピーでは、これらが保持されます。

サマリーには、何かが書き込まれる前に、各ターゲット、それが存在するかどうか、どのようにコピーされるかが表示されます。ターゲットのドキュメントを削除する TTL インデックスには、確認が必要です。ソースに個人データのフィールドのルールがあり、ターゲットにない場合、コピーには、個人データの値がそこで表示されることの確認が必要です。ターゲットの管理者であれば、代わりにルールを追加できます。個人データのフィールドは、クエリが見つける場合と同じ方法で、ビューや、パイプラインが移動または参照するフィールドを通じて見つけられます。ソースで個人データのフィールドがあなたに対して非表示になっている場合、コピーではその箇所に *** が保持され、常に匿名になります。「匿名コピー」では、全員に対して *** が書き込まれます。個人データの _id はマスクしてコピーできません。ターゲットをソースと区別できない場合は、サマリーにソース自身である可能性がある旨が表示されます。

比較は、両側を _id の順に読み取り、ソースのみにある、ターゲットのみにある、異なる、同一のドキュメントの数をカウントし、サンプルとフィールド単位の差分を表示します。フィルターは両側に適用され、選択したフィールドを無視することもできます。どちらかの側で個人データのフィールドが非表示になっている場合は、両側が *** として比較され、個人データの _id は比較できません。同期は、完了した比較を適用します。不足しているドキュメントを挿入し、異なるものを置き換えますが、読み取った後に変更されたドキュメントを上書きすることはありません。コピーと同様に、ターゲットにソースの個人データのフィールドのルールがない場合は確認が必要です。ターゲットの余分なドキュメントの削除はデフォルトでオフで、ターゲットの名前の入力が必要で、ソースからドキュメントが読み取れない場合は拒否され、比較で見つかった数に余裕分（その数の 10%、最低 100）を加えた数を超えて削除しようとすると停止します。フィルターを使用した場合、ソースにまだ存在しても、もうフィルターに一致しないターゲットのドキュメントは、削除されずに保持され、レポートにカウントされます。個人データのフィールドのルールが変更されたとき、どちらかの接続へのアクセスを失ったとき、または個人データのフィールドがあなたに対して非表示になったときは、レポートは取り下げられます。

保存済みの設定

マッピング、エクスポート設定、コピー設定は、名前を付けて保存し、このコレクションでも別のコレクションでも再度読み込めます。保存済みクエリと同様に、暗号化されて保存されます。

ファイルに保持されるもの、保持できないもの

  • CSV と Excel が保持できるのは、テキスト、数値、ブール値、日付です。それ以外のドキュメントの型（ObjectId、Long、Decimal128、バイナリ、ネストされたドキュメントと配列）は、テキストまたは Extended JSON として出力され、CSV を読み戻すと、マッピングで指定した型になります。正確に元へ戻るファイルが必要な場合は、JSON または NDJSON（Extended JSON）でエクスポートしてください。
  • SQL エクスポートはドキュメントを列に平坦化します。このアプリが作成したダンプは、ObjectId、ネストされたフィールド、バイナリ値とともに読み戻され、他で作成されたダンプは、その列が示す型で読み込まれます。
  • 日付は、MongoDB と同様にミリ秒を保持します。SQL ダンプのマイクロ秒は切り捨てられます。MySQL の 0000-00-00（「日付なし」）は null として読み取られます。SQL ダンプの整数のうち Decimal128 が保持できる桁数（34 桁）より長いものは、テキストとして正確に保持されます。
  • Excel では、日付を表示しているセルは、その日付と時刻が書かれたとおりに UTC として読み取られます（セルにはタイムゾーンがないため）。時刻のみを表示しているセルは、テキストの HH:MM:SS（形式が表示する秒未満の部分を含む）として読み取られ、日付も保持している場合は日時として読み取られます。経過時間（[h]:mm）はテキストとして読み取られ、時間は 1 日を超えて数えられます。
  • エクスポートは、ある時点のスナップショットではなく、進行しながらコレクションを読み取ります。その間に書き込まれたドキュメントは、含まれることも含まれないこともあります。
  • 停止、失敗、またはキャンセルされたインポートは、それまでに書き込んだ内容を保持します。レポートにその件数が表示されます。挿入で再度実行すると、それらのレコードは二重に書き込まれます。キーを指定してアップサートまたはマージを使用するか、先にそれらを削除してください。アップロードされたファイルは、実行のたびに削除されます。再度実行するには、もう一度アップロードしてください。
  • マージはレコードのフィールドを設定し、その他は残します。レコード内の空のサブドキュメントは、保存済みの内容を何も変更せず、新しいドキュメントの場合にのみ作成されます。「更新のみ」は、アップサートとマージのどちらにも適用されます。
  • 拒否されたレコードは、ソースの形式と区切り文字で返されます。テキストでなかったバイト列は � として表示されるため、その行を見つけて修正できます。

上限と安全性

  • ファイルはサーバー上に 24 時間保持され、ユーザーごとのストレージ上限があります。どちらも管理者が変更できます（デプロイを参照）。
  • 安全のために拒否されるもの: マクロ有効のブックとパスワード保護されたブック、古い .xls ファイル、展開すると大きくなりすぎるファイル、DTD を含む XML、および $ で始まる、ドットを含む、または __proto__ という名前のフィールド名（珍しい名前を許可した場合を除く）。gzip 圧縮されたブックは、最初に読み取られるときに一度だけ展開され、その後はブックのサイズとして扱われます。その内容は、通常のブックを超えて展開されてはなりません。
  • 個人データを閲覧できないユーザーは、個人データの値の代わりに *** が入ったファイルをエクスポートします。個人データのフィールドをマッピングしたり照合に使ったりすることはできず、個人データのフィールドがあるドキュメントを丸ごと置き換えることもできません。個人データのフィールドのルールが変更される前に作成されたファイルは、もうダウンロードできません。もう一度エクスポートしてください。
  • 閲覧者がエクスポートできるのは、その接続について管理者が許可した場合のみです。
  • インポートとエクスポートのジョブは、あなた自身と管理者にのみ表示されます。プレビューでは長い値は切り詰めて表示され、非常に幅の広いファイルは、より少ない行でサンプリングされます。
