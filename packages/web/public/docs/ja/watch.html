変更の監視

「監視」セクションでは、MongoDB がデータに加える変更をリアルタイムで確認できます。挿入、更新、置換、削除のすべてに加え、必要に応じて新しいインデックスの作成などのスキーマの変更も表示されます。この機能には MongoDB のチェンジストリームを使用します。何も保存されません。フィードは開いた時点から始まり、それ以降に起きたことを表示します。

場所

  • コレクションのタブ → 監視: そのコレクションの変更。
  • データベースのタブ → 監視: データベース内のすべてのコレクションの変更。
  • 接続のタブ → 監視: 接続内のすべてのデータベースの変更。
  • コマンドパレット (Ctrl+K): 「変更を監視…」で、現在のタブの監視セクションが開きます。

チェンジストリームには、レプリカセット、シャーディングされたクラスター、またはロードバランサー対応のデプロイメントが必要です (MongoDB Atlas は常にいずれかに該当します)。スタンドアロンサーバーは監視できません。その場合はセクションにその旨が表示されます。開発用には単一ノードのレプリカセットで十分です。mongod --replSet rs0 を起動し、rs.initiate() を一度実行してください。ビューは監視できません。ビューの監視セクションでは、そのビューの読み取り元のコレクションが提示されます。まだ存在しないコレクションも監視でき、作成された時点から変更が表示されます。

監視できるユーザー

接続のドキュメントを読み取れるユーザーは、どのスコープでもその接続を監視できます。接続のデータベースユーザーには、監視対象に対する changeStream 権限と find 権限が必要です (組み込みの read ロールには両方が含まれます)。system.users などの認証情報のコレクションは、その接続の管理者にのみ表示されます。

フィード

フィードの上のバーには状態が表示されます。ライブ、一時停止中、遅延 (2 秒以上遅れている場合。遅れの大きさも表示)、再接続中、終了のいずれかと、届いた変更の件数と速度です。新しい変更が一番上に表示されます。各行には、変更の種類 (文字と色で表示)、データベースフィードと接続フィードではコレクション、ドキュメントの _id、更新では変更されたフィールド名、そして経過時間 (正確な時刻はマウスオーバーで表示) が表示されます。下にスクロールしている間は、読んでいる位置が動かないよう、新しい変更は「新しいイベント」ボタンの背後に待機します。直近の 2,000 件の変更が保持され、それより古いものはリストから消えます。

変更を選択すると、右側に詳細が表示されます。変更されたフィールド、挿入と置換ではドキュメント全体、またはイベントの JSON です。「ドキュメントを開く」を選ぶと、そのドキュメントの _id で絞り込んだコレクションのドキュメントセクションが開きます。「EJSON としてコピー」は、変更を Extended JSON でコピーします。

一時停止、再開、再接続

一時停止すると、現在位置を失うことなくリストの更新が止まります。MongoDB はサーバー側で変更を保持し続けます。再開するときは、「追い付く」で一時停止中に起きたことを確認するか、「現在から」でそれを飛ばします。フィードのツールバーでは Space キーで一時停止と再開を切り替えられます。一時停止中のフィードは、セクションやタブを切り替えても、そのタブを閉じるまで一時停止のままです。実行中のフィードは、そのセクションを離れてから数秒後に停止します。

アプリとの接続が切れると、フィードは自動的に再接続します。2 分以内であれば、ブラウザーが最後に受け取った変更の直後から、取りこぼしも重複もなく再開し、その旨が表示されます。一時停止中のフィードは一時停止の状態で戻ります。そこから再開できなくなった場合 (非常に大量の変更が続いた後など) は、サーバーがあった位置から再開し、一部の変更が欠けている可能性があることが表示されます。2 分を過ぎた場合は現在から開始し、その旨が表示されます。フィードの再開位置 (MongoDB のレジュームトークン) はサーバーに保持されます。

フィルター

チップで変更の種類 (挿入、更新、置換、削除) を選びます。「スキーマの変更を含める」を選ぶと、コレクションやインデックスの作成と削除、オプションの変更などが加わります。「更新後のドキュメント全体を表示」は、更新のたびに更新後のドキュメントを読み取ります。そのため更新ごとに 1 回の読み取りが発生します。

「フィルターを編集」では、各変更イベントに対する $match を、クエリと同じ書き方で指定できます。例:

  • { 'updateDescription.updatedFields.status': 'paid' }: ステータスを paid に設定した更新。
  • { 'fullDocument.total': { $gt: 1000 } }: 高額な注文の挿入と置換。
  • { 'documentKey._id': ObjectId('…') }: 特定の 1 件のドキュメント。
  • { 'ns.coll': 'orders' }: データベースフィードまたは接続フィードでの 1 つのコレクション。

フィルターのサイズは 12 KB まで、ネストは 20 階層までです。サーバー上で JavaScript を実行する演算子 ($where、$function、$accumulator) は一切受け付けられません。フィルターを変更すると、フィードは現在から再開され、その旨が表示されます。

変更前の値を確認する

MongoDB は、更新で変更されたフィールドとその新しい値を報告します。変更前の値も確認するには、コレクションで変更前イメージをオンにします。オンにすると、フィードに更新の変更前と変更後の完全な比較と、削除では削除前のドキュメントが表示されます。コレクションの監視ページでは、そのコレクションのオプション (検証ルールなど) を変更できるユーザーに、イメージがオフの間 変更前・変更後イメージをオンにする が表示されます。必要なコストが説明され、その後に同じコマンドが実行されます (監査対象)。シェルから実行することもできます。 

db.runCommand({ collMod: 'orders', changeStreamPreAndPostImages: { enabled: true } })

変更前イメージは、サーバーのチェンジストリーム設定で定められた期間、サーバーのストレージに保持されます。そのため、負荷の高いコレクションではディスク容量を消費します。イメージがない場合、フィードには更新後の値、削除されたフィールド名、配列がどのように短くなったかが表示されます。

記録、再生、アラート

ファイルに記録 (フィルター内。接続からエクスポートできるユーザー向け) は、フィードのイベントを、送信されたとおりに (マスクされたものはマスクしたまま) 1 行に 1 イベントでサーバーに保持します。記録はご自身の転送ファイルです。転送領域の容量に含まれ、最大 64 MB まで保存でき (上限に達すると記録は止まり、フィードは続行され、監視ページにその旨が表示されます)、フィードの終了後は転送ファイルの保持期間だけ保持されます。再接続時に記録している場合は新しいファイルが始まります。サーバーを再起動すると記録は終了し、ディスクに届いた分は完了した記録として保持されます。ファイルには、イベントが送信されたときのとおりにマスク済みかどうかが記されます。フィードの途中でマスクの状態が変わった場合 (個人データがあなたに対して非表示になった、または表示されるようになった、あるいはルールが変更された場合) は、そこでファイルが終了し、新しい状態で新しいファイルが始まります。記録の一覧には両方が表示されます。ツールバーの 録画 には、この接続のご自身の記録が一覧表示されます。再生 は、ライブフィードの代わりに記録を同じ一覧と詳細で表示します (最初の 500 イベント、その後は さらにイベントを読み込む を選ぶたびに 500 件ずつ、最大 5,000 件まで。残りはファイルに含まれています)。ダウンロード でファイル (NDJSON) を取得でき、記録は削除もできます。管理者を含め、他のユーザーは読み取れません。接続で個人データがあなたに対して非表示になった場合 (マスクなしで記録されたとき)、またはそのルールが変更された場合 (マスク付きで記録されたとき) は、その記録は提供されません。

一致したらアラートを発生 は、イベントがフィードのフィルターを通過したことを、アプリのアラート (watch.matched イベント) に通知します。通知は最大で 10 秒に 1 回で、件数と最後のイベントの種類が含まれ、値は一切含まれません。フィードの実行中に動作します。

個人データ

個人データを閲覧できないユーザーには、すべての変更で個人フィールドが *** として表示されます。対象は、ドキュメント、そのキー、変更前の値、更新後の値で、配列の位置を含めてフィールドパスで判定されます。非表示のフィールドに対するフィルターは拒否され、データベースフィードと接続フィードでは、そのようなユーザーが指定できるのは変更の種類、名前空間、時刻だけです。フィードのエクスポートには、表示された内容がそのまま含まれ、非表示の値も *** として含まれます。

制限と設定

  • ライブフィードは、ブラウザーウィンドウごとに 3 件、ユーザーごとに 5 件、サーバー全体で 50 件までです (MM_WATCH_MAX_FEEDS)。
  • 256 KB を超えるドキュメントはフィードでは送信されません。「ドキュメントを開く」で表示できます。
  • ブラウザーに届く変更は、フィードあたり 1 秒に最大 200 件です。それを超える場合、フィードは遅れの大きさを表示し、追い付きます。
  • MM_WATCH=0 を設定すると、サーバーで監視が無効になります。
  • フィードの開始と停止は監査ログに記録されます。フィルターのフィンガープリントは記録されますが、その値は記録されません。

フィードが終了するとき

  • コレクションがドロップされた、または名前が変更された: フィードは終了します。「現在からもう一度開始」で、その名前のコレクションを再び監視します。
  • サーバーの履歴 (oplog) がフィードの位置まで残っていない場合 (長時間離れていた後など): 現在から開始し直してください。
  • アクセス権、接続、またはその設定が変更された: フィードは終了し、その理由が表示されます。
