プラグインの開発

プラグインは、Mongo Manager にビュー、アクション、ページを追加します。たとえば、コレクション内の場所を示す地図、チャート、重複検出ツール、SQL からの変換ツールなどです。このガイドは、プラグインを開発する方を対象としています。プラグインを構成するファイル、プラグインがアプリに要求できるすべての操作、アプリが適用するルール、そしてパッケージ化、テスト、公開の方法を説明します。管理者は プラグイン ページでプラグインをインストールして承認します。承認モデルについては セキュリティ を参照してください。このページにはすべてのプラグインが一覧表示され、有効なもの、管理者の対応が必要なもの（承認待ち、変更あり、動作不良）、無効なものに絞り込めるほか、ソースでの絞り込みや、名前、説明、ID、バージョン、要求する権限、追加する機能での検索もできます。

プラグインとは

プラグインは静的ファイルのフォルダーです。HTML ページ、そのスクリプト、スタイル、画像、フォント、そしてプラグインが追加するものと実行できる操作を記述するマニフェスト mongo-manager-plugin.json で構成されます。アプリはそのページをサンドボックス化されたフレーム内に表示し、ページはメッセージを通じてのみアプリとやり取りします。ページがドキュメントを要求すると、アプリはサインイン中のユーザーとして、そのユーザーの権限とアプリのマスクを適用して応答します。

  • サーバーコードはありません。 プラグインのコードがサーバー上で実行されることはありません。サーバーはファイルを保存し、検査し、フレームに配信するだけです。
  • ネットワークは使えません。 ページは、配信元のサーバーを含め、どのアドレスからも取得できません。Cookie もストレージもなく、アプリのページにもアクセスできません。ブラウザー側には抜け道が 2 つ残っています。WebRTC は、ポリシーの webrtc ディレクティブを適用するブラウザーでのみブロックされます。Chromium 系ブラウザー（Chrome、Edge）はバージョン 149 時点でこれを無視し、Firefox も当てにできません。そのため、これらのブラウザーでは、プラグインが読み取った内容を WebRTC で外部に送信できてしまいます。また、プリフェッチヒント（dns-prefetch、preconnect）によって名前解決を発生させることもできます。フレームはブラウザーにプリフェッチしないよう求め、スキャンはどちらも高リスクとして検出しますが、スキャンはファイルのテキストから既知のパターンを探すだけなので、回避するように書かれたコードは検出されません。信頼できるプラグインだけを承認してください。
  • 承認なしでは何も動きません。 プラグインは、管理者がそのファイルの内容そのままと、要求する権限を承認した後にのみ実行されます。ファイルを変更するたびに、新たな承認が必要です。
  • 変更はユーザーを経由します。 ドキュメントを変更できるプラグインは、確認を求めます。アプリが専用のダイアログで変更内容を表示し、ユーザーが判断します。プラグインが用意したクエリやパイプラインは、ユーザー自身のエディターに入力されるだけで、ユーザーが実行するまで何も実行されません。

Mongo Manager には、独自のプラグインがいくつか付属しています（マップ、チャート、スキーマの状態、重複検出、値の検索、参照、ドキュメントの差分、SQL から MongoDB へ、時間のヒント、バイナリのプレビュー、データディクショナリ、ローカル時刻、ログ分析、テストデータ、再構成、匿名化、検索プレイグラウンド、シャードキー分析、ストレージレポート、検証チェック、レガシー UUID、日付フィルター、インデックススクリプト、有効期限 (TTL)、個人データの検出、ドキュメントサイズ）。これらは同じサンドボックスで動作し、同じブリッジで通信し、同じ方法でスキャンされます。ただし、アプリ自身のコードであるため、承認時に ID の入力は求められません（バージョンと承認 を参照）。プラグインは MM_PLUGINS=0 でサーバー全体で無効にできます（デプロイメント を参照）。

クイックスタート

スターターテンプレートから始めます。プラグイン ページの 独自のプラグインを作成 で スターターをダウンロード (.zip) を選びます（Mongo Manager のソースコードの packages/plugins/starter フォルダーでもあります）。ビルド手順も依存関係もない、プレーンな JavaScript で書かれた完全なプラグインで、コレクションのドキュメントを一覧表示するコレクションタブとサイドバーページが含まれています。

  1. 展開するかフォルダーをコピーして、自分用の新しいリポジトリに置きます。
  2. mongo-manager-plugin.json の id、name、 author、repository を変更します。ID は一意でなければなりません。すべてのサーバーでプラグインのフォルダー名になるためです。
  3. ページを main.js と style.css に書きます。
  4. 自分のサーバーで試します。 node scripts/pack.mjs --folder ~/.mongo-manager/plugins を実行し、 プラグイン → 再スキャン を選んで、スキャン結果を確認してから承認します。 自分のサーバーでのテスト を参照してください。
  5. node scripts/pack.mjs でパッケージ化すると <id>-<version>.tgz が書き出されます。このファイルを GitHub のリリースに添付します。 GitHub での公開 を参照してください。

スターターには、AI コーディングアシスタント向けの指示ファイル（CLAUDE.md、 AGENTS.md、GEMINI.md、.github/copilot-instructions.md）も含まれています。 AI アシスタントでの開発 を参照してください。

ファイルとフォルダー構成

hello-documents/
  mongo-manager-plugin.json   the manifest (required, at the top)
  index.html                  the entry page every contribution opens
  main.js                     the page's script (an ES module)
  style.css                   the page's styles
  README.md                   shown to administrators on the plugin's details page
  README.tr.md, README.zh.md  the same in another language of the app (optional)
  scripts/pack.mjs            packaging (not part of the plugin: left out of the archive)
  CLAUDE.md, AGENTS.md, ...   AI assistant files (left out of the archive)

プラグインのファイルに対するアプリのルールは次のとおりです。

  • 合計で最大 500 ファイル、25 MB まで。マニフェストは最大 64 KB です。
  • すべてのパスは相対パスで、単純な形式でなければなりません。各部分は英字、数字、_、- のいずれかで始まり、英字、数字、.、_、- のみを含み、最大 100 文字です。階層は最大 16 段、全体で最大 240 文字です。隠しファイルや隠しフォルダー（. で始まる名前）、スペース、デバイス名（con、nul、com1...）、__proto__、constructor、prototype は使えません。
  • ファイルとフォルダーのみ使えます。リンク、ジャンクション、特殊ファイルがあると、プラグインは使用できなくなります。
  • 大文字と小文字の違いだけで区別されるパスを 2 つ置くことはできません。
  • ファイルは拡張子から決まる種類で配信されます。html、js、 mjs、css、json、map、txt、 svg、png、jpg、jpeg、gif、 webp、avif、ico、woff、woff2、 ttf、otf です。それ以外はバイト列として配信され、実行されることはありません。

マニフェスト

mongo-manager-plugin.json は厳密に検査されます。未知のフィールド、誤った型、範囲外の値があると、プラグインは使用できなくなり、プラグインページにどのフィールドが誤っているかが表示されます。人が読むテキスト（名前、タイトル、ノート）には、制御文字や、テキストを隠したり反転させたりする文字を含めることはできません。 

{
  "id": "hello-documents",
  "name": { "en": "Hello documents", "tr": "Merhaba belgeler" },
  "version": "0.1.0",
  "description": { "en": "Lists the documents of a collection.", "tr": "Bir koleksiyonun belgelerini listeler." },
  "entry": "index.html",
  "permissions": ["documents:read"],
  "contributes": {
    "collectionTabs": [{ "id": "list", "title": { "en": "Hello", "tr": "Merhaba" }, "icon": "table" }],
    "sidebarPanels": [{ "id": "page", "title": { "en": "Hello documents" }, "icon": "puzzle" }]
  },
  "settings": {},
  "author": { "name": "Your Name", "url": "https://example.com" },
  "homepage": "https://example.com/hello-documents",
  "repository": "https://github.com/your-name/hello-documents",
  "license": "MIT",
  "publishedAt": "2026-10-11",
  "changelog": [
    { "version": "0.1.0", "date": "2026-10-11", "notes": { "en": "First release.", "tr": "İlk sürüm." } }
  ]
}
フィールド 必須 ルール
id はい 小文字の英字と数字をダッシュで区切った形式（geojson-map）で、最大 64 文字です。プラグインのフォルダー名と一致している必要があります。Mongo Manager 付属のプラグインの ID や、アプリが予約している名前と読める ID（後述）は使えません。
name はい ローカライズされたテキストで、最大 60 文字です。{ "en": "...", "tr": "..." }。不可視文字（ゼロ幅文字、タグ文字、異体字セレクター。絵文字に含まれるものは可）は使えません。また、アプリ自身のメッセージと読める名前も使えません。Mongo Manager（またはそれで始まる名前）、MongoDB、System、Session、Security、Admin、Server、Update などが、アプリのどの言語でも対象で、大文字小文字、スペース、アクセント、似た文字の違いを除いた見た目で比較されます。各単語の文字は、すべてラテン文字であるか、まったくラテン文字でないかのどちらかでなければならず（ギリシャ文字とキリル文字の混在は不可）、角かっこの中に ID と読めるもの（(value-search)）を入れることはできません（(beta) は可）。アプリは、プラグインのメッセージや質問を、名前の横に ID を添えて表示します。
version はい セマンティックバージョニング: major.minor.patch。プレリリース（1.2.0-beta.1）も付けられます。最大 64 文字です。
description いいえ ローカライズされたテキストで、最大 300 文字です。
entry はい すべての拡張ポイントが開くページ。プラグイン内の .html ファイルへの単純なパスです。
permissions いいえ documents:read、documents:write、collection:read、 database:read のいずれか（各 1 回まで）。既定値はなしです。 権限 を参照してください。
contributes いいえ collectionTabs、documentActions、sidebarPanels、 cellRenderers: それぞれ最大 5 件のリストで、ID はリスト内で一意でなければなりません。 拡張ポイント を参照してください。
settings いいえ 最大 10 件。キー（英字で始まり、英数字が続く、最大 32 文字）ごとに指定します。 { "type": "url" | "text" | "boolean", "title": localized text of at most 60 }。 値は管理者が設定し、ページはコンテキストからそれを読み取ります。
author いいえ { "name": text of at most 80, "url": an https address (optional) }。
homepage、repository いいえ ホストを含む https:// アドレスで、最大 300 文字です。認証情報、スペース、バックスラッシュを含めることはできません。
license いいえ SPDX 式で、最大 40 文字です。MIT、Apache-2.0 OR MIT。
publishedAt いいえ 実在する日付を YYYY-MM-DD で指定します（1900 年から 2100 年の間）。
changelog いいえ 最大 50 件のエントリ { "version", "date": "YYYY-MM-DD", "notes": localized text of at most 1000 }。各バージョンは 1 回までで、マニフェストの version より新しいものは指定できません。

ローカライズされたテキストは、en（必須）と、必要に応じてアプリのその他の言語（tr、zh（簡体字中国語）、ja、es、 pt（ブラジルポルトガル語）、ko、de、fr、 ru）を持つオブジェクトです。閲覧者の言語がない場合は英語が表示されます。拡張ポイントは { "id", "title": localized text of at most 40, "icon" } で表します。ID は小文字の英字で始まり、小文字の英字、数字、ダッシュが続く最大 32 文字で、アイコンは map、chart、table、file、image、 globe、layers、puzzle、book、wand、 shapes、scroll、code、calendar、 hourglass、shield、fingerprint、ruler のいずれかです（アプリ自身のアイコンであり、プラグインが独自のアイコンを持ち込むことはできません）。セルレンダラーは代わりに { "id", "match" } で表し、任意で "display"（inline（既定）または tooltip）を指定できます。

url 設定は、認証情報を含まない https アドレスでなければなりません（http が使えるのはこのコンピューター、つまり localhost、127.0.0.1、[::1] に限ります）。そのスキームとホストとポートは、フレームが読み込める画像の許可対象に追加されます（地図タイルの場合、先頭の {s}. は任意のサブドメインになりますが、2 つ以上の部分からなる名前の前に限り、アドレスには適用されません）。画像のアドレスにはデータを含められます。つまり、プラグインは読み取った内容をそのサーバーに送信できるため、承認画面と設定画面にその旨が表示されます。 text 設定は最大 500 文字です。プラグインのすべてのユーザーが設定を読み取れるため、シークレットを求めてはいけません。サーバーは、他のすべての保存値と同様に、設定をサーバーのキーで暗号化して保存します。

拡張ポイント

すべての拡張ポイントは同じエントリページを開きます。ページは、どの拡張ポイントなのかを、アドレスのフラグメント #<kind>=<id>（たとえば #collectionTab=list）と、コンテキストの contribution から知ります。

種類 表示場所と開き方
collectionTabs すべてのコレクションのタブで、アプリ自身のタブの後ろに表示されます。ビューでも表示されます。フレームはタブ全体に表示されます。その place は、そのコレクションと、ユーザーが設定したドキュメントの filter です。ページはタブが表示されるたびに再読み込みされますが、ui.keepOpen で維持を要求した場合は、そのコレクションのタブの別のセクションが表示されている間も読み込まれたままになります（表示されていない間は、読み取りはできますが操作はできません: not_visible）。
documentActions ドキュメントタブの、ドキュメントのアクションメニューにあるエントリで、documents:read を承認されたプラグインにのみ表示されます。ページを表示するダイアログが開き、place.documentId はそのドキュメントの _id です。プラグインがクエリまたはパイプラインを配置すると（ui.useQuery、ui.useQueryIn、ui.useAggregation）、ダイアログは閉じます。
sidebarPanels サイドバーのエントリで、専用のページが /plugin/<id>/<contribution> のワークスペースタブとして開きます。コレクションのタブがアクティブなときにクリックすると、そのコレクションでページが開き （/plugin/<id>/<contribution>/<connection>/<db>/<collection>）、place がそれを示します。それ以外の場所からは place は null です。リンクから開かれたページは、そのコレクションを読み取る前にユーザーに確認し、ユーザーはコレクションなしで続行することもできます。ページは別のタブが表示されている間も読み込まれたままになります。表示されていない間は、読み取りはできますが操作はできません（not_visible）。
cellRenderers ドキュメントタブが値を表示するあらゆる場所（テーブル、ツリー、カード、ドキュメントインスペクター、チェンジストリームの詳細）で、値についての短いテキストを表示します。たとえば、ObjectId が作成された日付です。表示は、値の横（"display": "inline"、既定）か、そのセルや行にホバーまたはフォーカスしたときに値全体の下に表示され、プラグイン名が添えられるツールチップ（"display": "tooltip"）です。ツールチップのテキストはプレーンテキストで、tone は使われません。スクリーンリーダーは値と一緒に読み上げます。プラグインが値の横と、そのツールチップに出せるテキストはそれぞれ 1 つで、各場所で応答する最初のレンダラーが使われます。ページは非表示のフレームでプラグインごとに 1 つ実行され、documents:read を承認されたプラグインのみが対象で、自分自身を表示することはありません。match は geojson、string、number、date、 object、objectId、binary（UUID を除く）のいずれかです。 セルレンダラー を参照してください。

セルレンダラー

アプリは、表示する値について、cells.render メッセージで非表示のフレームに最大 200 件ずつまとめて問い合わせます。キットを使う場合は、client.onCells で応答します。 

client.onCells((renderer, values, locale, paths, place) =>
  values.map((v) => (typeof v?.$oid === 'string' ? { text: createdAt(v.$oid, locale), tone: 'info' } : null)),
)
  • renderer は拡張ポイントの ID、values は正規の Extended JSON 形式の値、locale はアプリの言語、paths は各値のフィールドパス（または null）、place は値の取得元のコレクション（または null）です。
  • binary 値は、全体ではなく先頭部分のみが { "$binaryHead": { "base64", "subType", "length" } } として、最初の 2,048 バイトとともに送られます。画像の種類とサイズを判別するには十分です。
  • 値ごとに 1 件ずつ、順番に応答します。{ "text", "tone" }、テキストなしを示す null、または後でもう一度問い合わせるよう求める { "retry": true } です。長さが異なるリストは無視されます。
  • テキストはプレーンテキストとして表示されます。値の横では最大 80 文字、ツールチップでは最大 200 文字で、制御文字と不可視文字は取り除かれます。 tone は neutral、info、success、 warning、danger のいずれかです。
  • 応答は 3 秒以内に返す必要があります。間に合わなかった場合は元の値がそのまま表示され、30 秒後にもう一度問い合わせます。応答は、値、言語、プラグインの設定ごとに保持されます。設定を変更すると再度問い合わせられ、1 分より古い応答は、その値が次に表示されるときにあらためて問い合わせられます（新しい応答が届くまで古い応答が残り、再度の問い合わせに失敗した場合も残ります）。binary 値の応答は、その長さ、サブタイプ、先頭部分のハッシュをキーとして保持されます。
  • レンダラーは、応答する前に読み取りを行えます（たとえば他のドキュメントへの参照）。その場合、リクエストで渡された place を { place, filter, ... } として渡し、読み取れるのはそこだけです。レンダラーのコンテキストの place は null です。

コンテキスト

context.get は、ページがどこにあり、どのように表示すべきかを返します。最初に呼び出してください。コレクションが開いている場合は、アプリがビューかどうかを確認するため、応答まで最大 3 秒かかることがあります。 

{
  "plugin": { "id": "hello-documents", "version": "0.1.0" },
  "contribution": { "kind": "collectionTab", "id": "list" },
  "locale": "en",
  "theme": "dark",
  "accent": "emerald",
  "place": {
    "connectionId": "6650...",
    "connectionName": "Production",
    "db": "shop",
    "coll": "orders",
    "view": false,
    "documentId": null,
    "filter": { "status": "open" }
  },
  "settings": { "tileUrl": "https://tile.example.org/{z}/{x}/{y}.png" }
}
  • kind は collectionTab、documentAction、 sidebarPanel、cellRenderer のいずれかです。
  • locale はアプリの言語です: en、tr、zh、ja、es、pt、ko、de、fr、ru。
  • theme は light または dark です。
  • accent はユーザーのアクセントカラーです: emerald、indigo、 violet、ocean、rose。それ以外の値は emerald として扱ってください。
  • place は、ページがコレクションなしで開かれた場合（サイドバーページ、セルレンダラー）は null です。connectionName は null になることがあります。view はビューの場合に true で、ビューは読み取りはできますが書き込みはできず、インデックスもありません。documentId は、ドキュメントアクションの場合はそのドキュメントを正規の Extended JSON で表したもの、それ以外は null です。filter は、コレクションタブの場合はドキュメントタブのフィルター、それ以外は {} です。どちらもデータです。documents:read のないプラグインには null と {} が渡されます。
  • hidden は、そのコレクションで個人データのルールによってユーザーから隠されるフィールドパスの一覧で、キーのリストとして表されます（[["contact", "phone"]]。"*" は 1 つのキー、 "**" は任意の数のキーで、どの深さでも対象）。名前のみで、documents:read を持つプラグインに渡されます。それ以外は []、アプリが時間内（3 秒）に判断できなかった場合は null です。そのようなフィールドの値は "***" として届きます。それをそのフィールドの型だと受け取らないでください。
  • settings は管理者が設定した値を保持します。設定されていない設定は含まれません。

ユーザーが言語、テーマ、アクセントカラーを変更すると、アプリは locale、theme、accent を含む context.changed を送信します（キットの client.onContext）。すぐに反映してください。ページに、もう一方のテーマや言語が表示されたままになってはいけません。ドキュメントを読み取れるプラグインには、ページが読み込まれている間にドキュメントタブのフィルターが変わった場合にも context.changed が送信されます。ui.keepOpen を呼び出したコレクションタブは、表示されていない間にユーザーが設定したすべてのフィルターを受け取ります。新しい place を取得するには、もう一度 context.get を呼び出してください。

ブリッジ API

プロトコル

ページとアプリは、postMessage でプレーンな JSON をやり取りします。キット（packages/plugins/kit/src/client.ts）とスターターの main.js がこれを実装しています。独自に実装する場合のルールは次のとおりです。

  1. event.source が window.parent で、mm が 1 のメッセージのみを読み取ります。
  2. ページが読み込まれると、アプリがあいさつを送ります: { "mm": 1, "type": "hello", "token": "..." }。最初のトークンを保持してください。それより前には何も送信しないでください。
  3. リクエストは { "mm": 1, "id": 1, "method": "documents.find", "params": { ... }, "token": "..." } の形式で、window.parent にターゲット '*' で投稿します（フレームのオリジンは不透明です）。ID は数値か最大 64 文字の文字列です。トークンのないリクエストはアプリが無視します。
  4. 応答には同じ ID が付きます: { "mm": 1, "id": 1, "result": ... } または { "mm": 1, "id": 1, "error": { "code": "...", "message": "..." } }。
  5. アプリは、ユーザーが変更するたびに { "mm": 1, "type": "context.changed", "locale", "theme", "accent" } を送信します（documents:read を持つプラグインには、ドキュメントタブのフィルターも送信します）。また、セルレンダラーには { "mm": 1, "id": "h1", "method": "cells.render", "params": { ... } } を問い合わせます。これには { "mm": 1, "id": "h1", "token", "result": [...] } で応答します。

ページは自身のアドレスから離れてはいけません。別のページを読み込む（リンク、フォーム、location の変更）と、アプリはブリッジを閉じてフレームを削除し、ユーザーはプラグインをもう一度開く必要があります。すべてを 1 つのページに収めてください。 

import { createClient, askMessage, AskError } from './kit/client'

const client = createClient()                       // requests time out after 15 s ("timeout")
client.onContext((locale, theme, accent) => restyle(locale, theme, accent))
client.onReady(async () => {
  const context = await client.ask('context.get')
  if (!context.place) return showNoCollection()
  try {
    const { documents, hasMore } = await client.ask('documents.find', { filter: context.place.filter, limit: 100 })
    show(documents, hasMore)
  } catch (e) {
    showError(askMessage(e, context.locale))         // the app's code, in the user's language
  }
})

documents.find、documents.findIn、ui.useQuery のフィルター、プロジェクション、ソート、および documents.aggregate では、演算子 $where、$function、$accumulator、 $out、$merge、$lookup、$graphLookup、 $unionWith は、どの深さにあっても拒否されます（前述の、最上位の単純な $lookup を除く）。ui.useAggregation のステージは、ユーザーが自身の権限で実行するため他のコレクションを読み取れますが、$where、 $function、$accumulator、$out、$merge を含めることはできません。読み取りは即座に実行されます。ui.useQuery と ui.useAggregation は、作業をユーザーに引き渡すだけです。

制限

  • メッセージはどちらの方向でも最大 1 MB です。それより大きい応答は too_large で失敗します。ドキュメントの件数を減らすか、プロジェクションでフィールドを絞ってください。
  • 同時に待機できるリクエストは最大 8 件です（too_many）。
  • フレームごとに、1 分あたり最大 60 回の読み取り（documents.find、.get、 .aggregate、.findIn、collections.list、 database.model）に加え、それとは別に 120 回の定義の読み取り（indexes.list、validation.get）までです。50 個のコレクションのディクショナリは、1 回のモデル取得と 100 回の定義の読み取りになります。
  • プラグインのページ内でのクリックの直後。 ui.copy、 ui.useQuery、ui.useAggregation、ui.importSql、 ui.exportSql、ui.openDocument、ui.download、 ui.importDocuments、documents.update は、プラグイン自身のページでのユーザーのクリックまたはキー操作が新しい間のみ受け付けられます。フレームにフォーカスがある必要があるため、アプリの別の場所でのクリックは数えられません。他の処理を await する前に、クリックハンドラー内で直接呼び出してください。そうしないと no_activation で失敗します。ui.copy、ui.use…、SQL ページ、ui.openDocument は、拒否された場合も含めて、試行のたびにそのメソッドの制限にカウントされます。クリックを待って何度も試行するプラグインは、その 1 分間の枠を使い切ります（too_many）。documents.update は、代わりに「一度に 1 つの質問」と「2 回の拒否」で制限されます。フレームはクリックなしでもフォーカスを得られるため、アプリの別の場所でのクリックやキー操作から 5 秒以内（ブラウザーのアクティベーションが続く時間）に要求された ui.copy、 ui.download、ui.importDocuments は、プラグインの申告だけでは実行されません。アプリは、プラグイン名と要求内容（文字数とテキストの冒頭部分（隠し文字は明示）、ファイル名とサイズ、どのコレクションに何件のドキュメントか）を示してユーザーに確認し、アプリ自身の コピー、保存、開く のクリックで実行します。プラグインへの応答はそれまで待機します（ユーザーが閉じた場合は declined、応答がない場合は unanswered、待機中は busy）。アプリがプラグインのために行うすべての質問（これらや、変更、配置されるステージ）は、ポインターが当たっていても 150 秒後に終了します。キットはこれらのリクエストを 180 秒待つため、ページが受け取るのは常にアプリの応答であり、自身のタイムアウトではありません。
  • 表示中のみ。 documents.update、ui.openDocument と上記のメソッドは、セルレンダラーから、または別のタブが表示されている間維持されているページからは、not_visible で失敗します。

権限

管理者は、プラグインが列挙する権限を、プラグインページでの名称のとおりに承認します。必要最小限の権限だけを要求してください。権限は 1 つ増えるごとに、管理者が承認を見送る理由になります。

権限 管理者に表示される内容 許可される操作
documents:read ドキュメントの読み取り documents.find、.get、.aggregate。ドキュメントアクションとセルレンダラーは、この権限がある場合にのみ提供されます。
documents:write ドキュメントの変更（変更ごとに確認） documents.update。変更ごとにユーザーが確認します。この権限の要求は、常にそれ自体が中程度のスキャン結果になります。
collection:read このコレクションのインデックスの読み取り indexes.list。
database:read 同じデータベースの他のコレクションの読み取り（名前とドキュメント） collections.list、documents.findIn、単純な $lookup。

権限のないプラグインでも、ページの表示、コンテキストと設定の読み取り、ui.* メソッドの使用は可能です。権限がユーザー自身の権限を超えることはありません。コレクションを読み取る権限のないユーザーは、プラグインを介してもそれを読み取れません。

サンドボックス

ページは sandbox="allow-scripts" を指定した iframe に、プラグイン、そのバージョン、承認されたファイル、ユーザーのセッションを示す署名付きアドレスから読み込まれます（封印されたチケット: ページは 10 分以内に読み込まれる必要があり、その他のファイルはセッションが続く間（最大 12 時間）読み込めます。別のタブでのサインインやパスワード変更によってセッションがその場で更新された場合は、それに追従します。サインアウトすると、そのアドレスは何も配信しなくなり、ブラウザーもファイルを一切保持しません）。配信されるすべてのファイルは、承認された SHA-256 と照合されます。ポリシー（Content-Security-Policy）は、X-DNS-Prefetch-Control: off とともに次のとおりです。 

default-src 'none'; script-src <its files>; style-src <its files>;
img-src <its files> data: blob: <the origins of its url settings>; font-src <its files>;
connect-src 'none'; webrtc 'block'; frame-ancestors 'self'; base-uri 'none'; form-action 'none';
sandbox allow-scripts

コードにとっての意味は次のとおりです。

  • ネットワークは一切使えません。 プラグイン自身のファイルを含め、どのアドレスにもリクエストできません。読み込む .json ファイルの代わりに、データはスクリプトモジュール（data.js）に入れてください。WebRTC やプリフェッチヒントも使わないでください。すべてのブラウザーがブロックするわけではなく、スキャンも高リスクとして検出します。
  • インラインのコードやスタイルは使えません。 スクリプトとスタイルはプラグインのファイルからのみ読み込まれます。インラインの <script>、<style> 要素、style 属性、インラインのイベントハンドラー、eval は使えません。スクリプトでプロパティを設定すること（el.style.width = '40px'）は可能です。
  • 不透明なオリジン。 Cookie、localStorage、IndexedDB は使えず、失敗します。状態はメモリに保持してください。管理者が選ぶ設定は、マニフェストの settings から渡されます。
  • ポップアップ、ダイアログ、フォーム、ダウンロードは使えません。 window.open、 alert、confirm、フォーム送信は何も行いません。コピーには ui.copy を使い、ファイルはアプリ自身のインポートとエクスポートを通じてユーザーに渡してください。
  • アプリには手を出せません。 ページは、アプリのページ、セッション、ストレージを読み取れません。アプリとはメッセージを交換するだけです。
  • フォントと画像はプラグイン自身のファイルです（または data: や blob: の画像）。

セキュリティスキャン

すべてのプラグインのファイルは、検出またはインストールされたときに、管理者が承認する前にスキャンされます。スキャンは、スクリプト（.js、.mjs、.cjs）、マークアップ（.html、.htm、.svg）、スタイル（.css）のファイルを、コメントも含めて 1 行ずつ読み取り、各結果を重大度、ルール、ファイル、行、抜粋とともに一覧表示します。マークアップファイルは全体としても読み取られるため、複数行にまたがる <script> タグやインラインハンドラーも検出されます。プラグインに同梱されたライブラリは、自分のコードと同様にスキャンされます。スキャンはヒューリスティックであり、テキストから既知のパターンを探すだけです。そのため、検出を逃れるように書かれたコード（たとえば、断片から組み立てた名前）は検出されません。スキャン結果が問題なしでも、安全の証明にはなりません。高の結果があるプラグインは、管理者がリスクを受け入れるためにその ID を入力した場合にのみ承認できます。これはサーバーが強制し、監査ログにはスキャンの件数とリスクを受け入れたかどうかが記録されます。高の結果はすべて避け、中の結果は説明できるものだけにとどめてください。

スキャンされるのはスクリプト、マークアップ、スタイルのファイルのみです。マニフェストは documents:write について読み取られます（常に中の結果になるため、プラグインがドキュメントを変更する場合にのみ要求してください）。同じルールの結果は 1 ファイルにつき最大 10 件、全体で最大 200 件（重大なものから）が一覧表示されます。件数には常にすべての結果が含まれます。すべてのパターンは線形時間で実行されるため、どんなファイルでもスキャンはすぐに終わります。スキャン自体が失敗した場合、プラグインは動作不良とは見なされません。スキャンがない状態になり、（Mongo Manager 付属のものを除き）高の結果がある場合と同様に、ID を入力した場合にのみ承認できます。Mongo Manager 付属のプラグインのスキャン結果も表示されますが、承認時に ID は求められません。

UI とテーマ

プラグインは、アプリの一部のように見えるべきです。ユーザーのテーマとアクセントカラーに合わせた、色、書体、余白です。Mongo Manager 自身のプラグインは、packages/plugins/kit のプラグインキットを使っています。

  • kit/src/ui.css: ライトとダーク、および各アクセントカラーに対応したアプリのデザイントークン（--ds-surface、 --ds-fg、--ds-accent...）と、コンポーネント（mm-btn、mm-table、mm-empty、 mm-callout...）。フォントは @fontsource パッケージのファイルです。プラグインに同梱するか、@font-face ルールを削除してシステムフォントを使ってください。
  • kit/src/ui.ts: applyLook(theme, accent) は html.dark と html[data-accent] を設定します。h(tag, props, ...children) はテキストが常にテキストとして扱われる形で要素を組み立てます。その他に icon、button、segmented、 switchControl、chip、badge、pageHeader、 emptyState、skeleton、callout、table、 valueView、describeValue、formatNumber、 statusLine、setBusy、serialAsk があります。
  • kit/src/client.ts: createClient、AskError、 askMessage。

キットは TypeScript で書かれており、バンドルして使うことを想定しています。kit/src を自分のプロジェクトにコピーし、公式プラグインの vite.config.ts のように、インラインスクリプトなしの相対パスで Vite（または別のバンドラー）を使ってビルドします: base: './'、modulePreload: { polyfill: false }、 assetsInlineLimit: 0。パッケージ化するのはソースではなくビルド出力です。スターターは、代わりにクライアントと色の短いコピーを、プレーンな JavaScript と CSS で持っています。 

import './kit/ui.css'
import { createClient } from './kit/client'
import { applyLook, h, pageHeader, emptyState, button } from './kit/ui'

const client = createClient()
client.onContext((locale, theme, accent) => applyLook(theme, accent))
client.onReady(async () => {
  const context = await client.ask('context.get')
  applyLook(context.theme, context.accent)
  document.body.append(
    h('div', { class: 'mm-page' },
      pageHeader({ icon: 'table', title: 'Hello', description: context.place?.coll ?? '' }),
      emptyState({ icon: 'search', title: 'Nothing yet', action: button({ label: 'Load', variant: 'primary' }) }),
    ),
  )
})

ページが表示される場所に合わせて設計してください。コレクションタブは広く、ドキュメントアクションはダイアログで、サイドバーページはワークスペース全体を使います。表示するものがない場合や place が null の場合は空の状態を、読み取り中はスケルトンを、拒否された場合はアプリの言葉を表示してください。ボタンなど本物のコントロールを使い、キーボードだけでページを操作できるようにしてください。

言語

アプリは英語、トルコ語、簡体字中国語、日本語、スペイン語、ブラジルポルトガル語、韓国語、ドイツ語、フランス語、ロシア語に対応しており、context.locale は en、tr、 zh、ja、es、pt、ko、de、 fr、ru のいずれかです。プラグインは、できるだけ多くの言語に対応し、英語には必ず対応してください。

  • マニフェストでは、すべてのローカライズされたテキストに、en に加えて用意した各言語を指定します。
  • ページでは、言語ごとの文言の表を保持し、context.locale で選択します（用意していない言語には英語）。document.documentElement.lang には文言が実際に書かれている言語を設定し（英語にフォールバックした場合は en。中国語とポルトガル語には zh-CN と pt-BR を使い、正しい字形が表示されるようにします）、数値も同じ言語で書式設定し、context.changed で再描画します。
  • セルレンダラーは、各バッチが問い合わせられた locale で応答します。
  • 数値と日付はその言語の形式で表示します（Intl.NumberFormat、 Intl.DateTimeFormat）。
  • 言語ごとに、README.md と並べて README.<language>.md（README.tr.md、README.zh.md、…）を追加し、リリースノートも各言語で用意します。

README とリリースノート

プラグインの最上位にある README.md は詳細ページに表示され、管理者は承認する前にそれを読みます。README.<language>.md（README.tr.md、README.ja.md、…）は、その言語でアプリを使っている人には代わりにそちらが表示されます。ローカライズされた README は、README.md も存在する場合にのみ表示されます。README は安全な Markdown として表示されます: 見出し、段落、リスト（1 階層）、太字、斜体、インラインコード、コードブロックです。リンク、画像、テーブル、HTML はプレーンテキストとして表示されます。表示されるのは最大 64 KB です。

良い README には、次の内容がこの順序で書かれています。

  1. プラグインの機能を、2、3 文で。
  2. 表示される場所: どのタブ、アクション、ページ、またはセルのテキストか。
  3. 使い方を、例を交えて手順ごとに。
  4. 各権限と、それが必要な理由。
  5. 設定がある場合はその説明。
  6. 制限: 読み取るドキュメントの件数や、対応していないこと。
  7. 残っている各スキャン結果と、それが安全である理由。

リリースノートはマニフェストの changelog に、新しいものから順に、バージョンごとに 1 エントリとして、日付とノートを英語と用意した各言語で書きます。詳細ページにはそれが表示され、更新後は、前回以降のバージョンに新着の印が付きます。

バージョンと承認

  • 承認は、正確なファイルに対するものです。そのダイジェストは、すべてのファイルのパスと SHA-256 の SHA-256 です。管理者は承認する前にこれを確認できます。
  • アップロードされたプラグインやプラグインフォルダーのどのファイルであっても変更（新しいバージョン、README の誤字修正など）があると、管理者があらためて承認するまで無効になります。リリースごとに version を上げ、changelog のエントリを追加して、管理者が何を承認するのかわかるようにしてください。
  • インストール済みの ID のプラグインをアップロードすると置き換えられます。ファイルが承認済みのものとまったく同じ場合にのみ、有効のままになります。新しいマニフェストが同じ型で設定を宣言している限り、設定は保持されます。
  • 手動で配置したプラグインフォルダーは手動で管理されます。同じ ID のアップロードは拒否され、アプリで削除してもフォルダーは削除されず、アプリが認識しなくなるだけです。
  • 更新後も承認が維持されるのは、Mongo Manager 付属のプラグインだけで、有効であり、かつ更新が新しい権限を要求しない場合に限ります。その場合、管理者には何も求められず、プラグインの詳細ページに承認が維持されたことが表示されます。管理者が手動で承認した更新には、管理者が承認した旨が表示されます。

パッケージ化

プラグインは、gzip 圧縮された tar アーカイブ（.tgz）として配布します。ファイルはアーカイブのルートに置き、mongo-manager-plugin.json もその 1 つです。すべてを含む 1 つの最上位フォルダー（npm pack の package/ のようなもの）は許容され、取り除かれます。アーカイブには通常のファイルのみを含めてください（フォルダーは暗黙的に含まれます）。リンク、デバイス、特殊なエントリ、単純でないパス、重複したパスは拒否されます。展開後で最大 500 ファイルと 25 MB、アップロードで最大 30 MB です。

スターターの scripts/pack.mjs は、Node.js だけでこれを行います。

アプリと同じようにパスと制限を検査し、プラグインに含まれないもの（隠しファイル、scripts/、node_modules/、AI アシスタントのファイル、パッケージファイル、アーカイブ。SKIP リストを編集して調整できます）を除外し、 <id>-<version>.tgz を書き出して、管理者に表示されるダイジェストを出力します。バンドラーでビルドする場合は、代わりにビルド出力フォルダーをパッケージ化し、マニフェストを最上位に置いてください。

GitHub での公開

管理者は、許可が設定されたサーバー（MM_PLUGINS_GITHUB=1。既定ではオフ）で、公開 GitHub リポジトリから直接プラグインをインストールできます。プラグインページで、次のいずれかのアドレスを貼り付けます。

  • https://github.com/<owner>/<repo>、…/releases、 …/releases/latest: 最新のリリース用。
  • https://github.com/<owner>/<repo>/releases/tag/<tag>: 特定のリリース用。 タグにはスラッシュを含められます（最大 4 つの部分）。

アドレスにそれ以外のものは含められません。クエリ、フラグメント、ポート、認証情報は不可です。名前が変更されたリポジトリには追従します。リリース自身のページアドレスが、そのリポジトリを示すためです。アプリは、そのリリースのプラグインアーカイブ、つまり名前が .tgz または .tar.gz で終わる唯一のアセットをダウンロードします。そのようなアセットがないリリースや、複数あるリリースは拒否されます。タグとアセットの名前は、表示可能な ASCII でなければなりません。アセットはそのリポジトリのリリースに属している必要があり、サイズは、宣言された値と実際に読み取った値のどちらでも、アップロードの上限（30 MB）を超えてはなりません。

アプリが通信するのは github.com、api.github.com、 objects.githubusercontent.com、release-assets.githubusercontent.com だけで、https を使い、公開アドレスのみに接続し、サーバーの情報（Cookie、トークン、認証情報）は一切送信しません。リダイレクトは、これらのホスト間に限り最大 4 回まで追従し、リリースの説明は最大 5 MB まで読み取り、インストール全体に 4 分を割り当てます。プラグインは無効の状態でスキャン結果とともにインストールされ、アップロードと同様に承認を待ちます。取得元（リポジトリ、リリース、アーカイブ）が記録され、詳細ページに表示されます。

インストールに失敗すると、プラグインページに理由が表示されます。リポジトリに公開済みのリリースがない、GitHub のレート制限に達した、GitHub に拒否された（リポジトリが公開されていない）、サーバーから GitHub に接続できない、リダイレクト先が許可されていないホストだった、リダイレクトが多すぎた、リリースにアーカイブがない・複数ある、またはアーカイブがそのリポジトリのリリースにない、のいずれかです。

  1. version を上げ、changelog のエントリを追加して、publishedAt を設定します。
  2. node scripts/pack.mjs を実行します。
  3. GitHub のリリースを作成し（たとえばタグ v0.1.0）、hello-documents-0.1.0.tgz をそのアセットとして添付します。他の .tgz や .tar.gz ファイルは添付しないでください。
  4. 最新のリリースとしてマークします。pack.mjs が出力したダイジェストをリリースノートに記載し、管理者がアプリに表示される内容と比較できるようにします。

GitHub からのインストールは、MM_PLUGINS_GITHUB=1 を設定しない限りオフです。また、サーバーが GitHub に到達できない場合や、プロキシ経由でしか外部に出られない場合もあります（インストールは GitHub に直接接続し、HTTP プロキシの設定は使いません）。その場合、管理者は .tgz をダウンロードし、プラグインをアップロード でアップロードします。

自分のサーバーでのテスト

  1. プラグインを有効にして（既定）Mongo Manager を実行し、管理者としてサインインします。データディレクトリを確認してください。MM_DATA_DIR で別の場所が指定されていない限り、~/.mongo-manager です。
  2. プラグインを <data-dir>/plugins/<id> にコピーします: node scripts/pack.mjs --folder ~/.mongo-manager/plugins。フォルダー名は ID と同じでなければならず、隠しファイルを含めることはできません（そのため、スクリプトはプラグインのファイルだけをコピーします）。~/ はどのシェルでもホームフォルダーを表します。cmd や PowerShell では ~\ を使うか、引用符で囲んでください（bash と zsh は引用符なしのバックスラッシュを取り除くため、スクリプトは残った部分を拒否します）。スクリプトが置き換えるのは、このプラグインのフォルダーで、コピーできたはずのファイルとフォルダーだけを含み（スクリプト、隠しファイル、リンク、パイプ、ソケットがない）、そこやその中にファイルシステムがマウントされていないものに限られます。新しいコピーを入れ替える方式なので、コピーが途中で止まってもフォルダーは元の状態のままです。対象がプラグイン自身のフォルダー、その内側、またはそれを含む場所である場合は、パスの指定方法（シンボリックリンク、ジャンクション、共有）にかかわらず拒否され、何も書き込まれません。
  3. プラグイン を開き、再スキャン をクリックします。使用できないプラグインには理由（マニフェストのフィールド、パス）が表示されます。詳細を開き、管理者と同じように、スキャン結果、権限、README を確認してください。
  4. 承認して有効化 をクリックしてから、コレクションを開いて、すべての拡張ポイントを試します。
  5. 変更するたびに、もう一度コピーし、再スキャン をクリックして、あらためて承認し（ファイルが変わったため）、タブ、ページ、ダイアログを開き直します。複数の言語、両方のテーマ、ビュー、ドキュメントのないコレクション、コレクションなしで開いたサイドバーページを試してください。
  6. 最後に、クリーンなサーバーで、プラグインをアップロード から .tgz 自体をアップロードします。ユーザーが行うのと同じ方法です。

ブラウザーの開発者ツールはフレーム内でも動作します。コンソールでプラグインのフレームを選ぶと、そのエラーとメッセージを確認できます。コンソールにポリシー違反が表示された場合は、ページがサンドボックスで禁止されている操作を試みたことを意味します。

AI アシスタントでの開発

スターターには、このページにあるすべての内容を AI コーディングアシスタントに教える指示ファイルが含まれています。マニフェストのルール、ブリッジのメソッドと権限、サンドボックス、スキャン、言語、README、パッケージ化、公開です。プラグインのリポジトリの最上位に置いておいてください。pack.mjs はそれらをアーカイブから除外します。プラグイン ページでは、スターターを .zip として、また各ファイルを単独で、すでにあるプラグインに追加できるよう AI アシスタント向けの指示 の下に保存できます。Copilot 用のファイルは、リポジトリの .github フォルダー用に copilot-instructions.md として保存されます。

  • CLAUDE.md: Claude Code。
  • AGENTS.md: OpenAI Codex と、AGENTS.md を読み取るその他のエージェント。
  • GEMINI.md: Gemini CLI。
  • .github/copilot-instructions.md: GitHub Copilot。

プラグインにさせたいことをアシスタントに伝えてください。スキャンと、下のチェックリストを通過するコードが返ってくるはずです。公開する前に、書かれた内容を必ず読んでください。管理者が信頼するのはあなたです。

公開前のチェックリスト

  • ID が一意で、フォルダー名と一致している。バージョンを上げ、当日の日付で changelog のエントリを追加した。
  • すべてのローカライズされたテキストに en と tr がある。ページが locale と context.changed に追従する。
  • 権限は動作する範囲で最小限であり、README が各権限の必要な理由を説明している。
  • スキャンに高の結果がなく、README がその他すべての結果を説明している。
  • テキストは textContent または h() で書き込んでいる。テキストからマークアップを組み立てていない。
  • ネットワークに接続しない（fetch、WebRTC、プリフェッチヒントを使わない）。ストレージを使わない。ポップアップを開かない。ページから離れない。
  • インラインのスクリプト、スタイル、イベントハンドラーがない。すべてのパスが相対パスである（./main.js）。
  • すべてのファイルが NUL バイトなしの UTF-8 で保存されている。
  • ページがテーマとアクセントカラーに追従し、キーボードで操作できる。
  • place が null の場合、ビュー、空のコレクション、遭遇しうる各エラーコードを処理している。
  • クリックが必要な呼び出しは、クリックハンドラー内で直接行っている。
  • 大きな読み取りに上限がある: limit、プロジェクション、パイプラインは一度に 1 つ。
  • README.md とその翻訳がプラグインを説明している。license、 author、repository が設定されている。
  • クリーンなサーバーに .tgz をアップロードし、スキャン、承認、動作確認をした。
  • GitHub のリリースにプラグインのアーカイブがちょうど 1 つあり、名前が <id>-<version>.tgz である。
