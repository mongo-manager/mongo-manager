Начало работы

Установка

Выберите любой из способов. К каждому выпуску прилагаются все файлы с контрольными суммами SHA-256 для изолированных от сети компьютеров.

  • npm (Node.js 24 или новее): npx @mongo-manager/app
  • Офлайн-установка через npm: npm install --global ./mongo-manager-<version>.tgz
  • Автономный исполняемый файл: скачайте файл для своей системы и запустите его; Node.js не нужен.
  • Docker: docker compose -f deploy/docker-compose.yml up -d

Поддерживается MongoDB 6.0 и новее. Более старые серверы отклоняются при подключении, и сообщение об этом сообщает причину.

Первый запуск

Локальный режим (по умолчанию) рассчитан на одного человека на одном компьютере: Mongo Manager слушает адрес 127.0.0.1:4321 и открывает браузер. Входа нет: приложение открывается по одноразовой ссылке. При запуске в терминале ссылка выводится в строке после адреса; в других случаях (служба, контейнер, журнал) выводится путь к файлу, который открывает приложение и который может прочитать только ваша учетная запись. После этого браузер остается в системе, пока хранит данные этого сайта (не более шести месяцев после последнего использования; Safari удаляет их через неделю без посещений), так же и установленное им приложение — кроме веб-приложения Safari на Mac: у него свои данные, и ссылку ему передать нельзя, поэтому там используйте Mongo Manager во вкладке Safari. Другая программа или учетная запись на этом компьютере, открывшая адрес, увидит лишь страницу с объяснением, как его открыть. Если ссылка использована или браузер ее забыл, выполните mongo-manager open, чтобы получить новую; в терминале эта команда также выводит ссылку — для браузера, который не может открыть файл (браузер snap или Flatpak в Linux). На компьютере, которым пользуются несколько человек, используйте командный режим. 

mongo-manager
mongo-manager open             # a new link for a running Mongo Manager (--no-open prints it)

Командный режим добавляет пользователей, роли и двухфакторный вход. При первом запуске в терминал выводится одноразовый установочный токен (если приложение работает как служба или в контейнере, он находится в файле setup-token в папке данных); откройте страницу и введите токен, чтобы создать первого администратора. 

mongo-manager --auth

Первое подключение

  1. Выберите Добавить подключение и вставьте или введите строку подключения в первое поле, например localhost:27017 или адрес mongodb+srv:// (mongodb:// можно опустить). Форма заполняется сама: строка под полем сообщает, что было распознано, а имя следует за хостом, пока вы не введете свое. Сервер, аутентификация, TLS, SSH и остальное находятся в разделе Дополнительные параметры; Сохранить и подключиться сохраняет подключение и открывает его.
  2. Выберите Проверить подключение. Будут показаны версия MongoDB и топология.
  3. Сохраните. Подключение появится в дереве слева.

Способы входа

Помимо имени пользователя и пароля (SCRAM), подключение может использовать вход по сертификату X.509, LDAP (PLAIN), ключам AWS IAM, OIDC или Kerberos. Способ выбирается в разделе Дополнительные параметры → Аутентификация.

  • MONGODB-OIDC (MongoDB Atlas, Enterprise): каждый пользователь входит через поставщика удостоверений, указанного сервером; пароль не сохраняется. При первом открытии подключения диалог предлагает Войти: страница поставщика открывается в этой вкладке и возвращает вас обратно. Если ее перенаправление не может достичь Mongo Manager, выберите Использовать код и введите код, показанный у поставщика. Зарегистрируйте адрес …/oidc/callback этого сервера у поставщика или укажите другой в поле Адрес перенаправления. Разрешенные хосты — это хосты, на которые может быть отправлен ваш вход (если пусто: Atlas и этот компьютер). На странице подключения показано, выполнен ли вход, и есть выход. Идентификатор рабочей нагрузки (Azure, GCP, Kubernetes) выполняет вход от имени машины, на которой работает Mongo Manager: в командном режиме — только там, где это разрешил администратор.
  • Kerberos (GSSAPI): укажите принципала, а также имя службы, область (realm) и канонизацию имени хоста, если они нужны вашим серверам. Вход выполняется по билету Kerberos той учетной записи, от имени которой работает Mongo Manager: на вашем компьютере это ваша запись, в командном режиме — запись сервера, и там способ отключен, пока его не разрешит администратор. Требуется необязательный пакет kerberos из npm-пакета (см. Развертывание).

Шифрование на стороне клиента

В разделе Дополнительные параметры → Шифрование подключение может использовать шифрование полей на стороне клиента (CSFLE) или Queryable Encryption. Требуется необязательный пакет mongodb-client-encryption из npm-пакета.

  • Поставщики ключей: локальный мастер-ключ длиной 96 байт (Создать новый ключ создает его; сохраните копию, иначе данные нельзя будет расшифровать), AWS KMS, Azure Key Vault, Google Cloud KMS или KMIP. Их учетные данные хранятся в защищенном виде и больше не показываются. Хранилище ключей (key vault) — это коллекция, в которой находятся ключи данных (по умолчанию encryption.__keyVault).
  • Режим: Чтение и запись расшифровывает читаемое и шифрует записываемое (MongoDB Enterprise или Atlas); Только расшифровка читает зашифрованные значения в расшифрованном виде и не записывает документы (MongoDB Community). Анализ запросов использует библиотеку crypt_shared (путь к ней или, в командном режиме, путь на сервере) либо mongocryptd на этом компьютере.
  • Зашифрованные поля берутся из параметров коллекции на сервере — для Queryable Encryption это encryptedFields, для CSFLE — валидатор $jsonSchema — если только подключение не задает собственные карты. В представлении документов зашифрованные поля отмечены замком.
  • Раздел Шифрование подключения (для его администраторов) перечисляет ключи данных, создает новые и ротирует их (перешифровывает под другим мастер-ключом), а также создает коллекции Queryable Encryption: каждое поле с его типом и признаком, можно ли запрашивать его по равенству или по диапазону, для каждого создается ключ данных.
  • Тот, от кого скрыты персональные данные, видит зашифрованные значения в том виде, в каком они хранятся, и не может записывать документы на таком подключении. Копии переносят зашифрованные значения как есть; коллекцию Queryable Encryption копировать нельзя.

Главная и следующие шаги

Главная — это панель из виджетов, которые вы добавляете, удаляете, масштабируете и перемещаете через Настроить панель; она сохраняется для вас на сервере. Виджет Следующие шаги предлагает до пяти дел, которые приложение определяет само по вашей недавней работе: сработавшие оповещения, задания, завершившиеся ошибкой за последние сутки, живые синхронизации и резервное копирование по расписанию, которым нужно ваше внимание, индекс, предложенный для базы данных, с которой вы работали последней (по ее медленным запросам, если вам разрешено следить за ее сервером), и места, которые вы недавно открывали и которые сейчас не открыты. Каждый шаг — это ссылка, выполняющая действие: индекс открывает обычный диалог «Создать индекс» с заполненным ключом, и ничего не создается, пока вы не подтвердите это там. Скройте шаг крестиком ✕ (Отменить возвращает его); скрытие сохраняется вместе с вашей панелью, а новое событие того же рода возвращается как новый шаг. Показать скрытые шаги снова в меню виджета возвращает все скрытые шаги.

Там, где настроен ИИ-провайдер, меню виджета предлагает Упорядочить с помощью ИИ; по умолчанию это выключено, пока вы не включите. Тогда ИИ расставляет шаги по порядку и формулирует их заголовки, опираясь только на факты: вид каждого шага, названия (подключение, база данных, коллекция, имена полей индекса) и количества — но никогда не значение, не документ и не текст ошибки. Шаг, у подключения которого политика ИИ равна «выключено» или «только локально» при провайдере, не известном как отвечающий из локальной сети, не отправляется и сохраняет свое место. ИИ не может добавить шаг или изменить действие шага: под каждым предложенным заголовком собственные слова приложения говорят, что шаг делает, а в заголовках нет чисел (число устарело бы; его указывает строка приложения). Шаги упорядочиваются заново только когда они меняются (другой вид шага, другое место) или когда вы выбираете Упорядочить с помощью ИИ — но не потому, что изменилось число или прошло время. Каждое упорядочение учитывается в истории ИИ (как «Следующие шаги», без его формулировок) и в журнале аудита (сколько шагов, но не их названия). Предложенный индекс показывается, только если вам разрешено создавать индексы.

Запросы

Откройте коллекцию и введите фильтр, например { status: 'A', qty: { $lt: 30 } }, затем нажмите Enter. Параметры добавляют проекцию, сортировку, пропуск, лимит, правила сортировки (collation), подсказку индекса (hint) и ограничение по времени. В списке Недавние запросы показано то, что вы выполняли для этой коллекции, а звездочка сохраняет запрос в избранное с именем и тегами.

Коллекция открывается с самыми новыми документами в начале: сортировка { _id: -1 } видна в разделе Параметры и на столбце _id, где ее можно изменить или убрать, а кнопка сброса возвращает ее. Представления и коллекции временных рядов сохраняют свой порядок. Чтобы открывать коллекции в порядке хранения, выключите «Открывать коллекции с самыми новыми документами в начале» в разделе «Предпочтения».

Значение в строке может быть параметром, записанным как {{name}}: { status: {{status}}, qty: { $gte: {{min}} } }. Под строкой для каждого параметра появляется поле, а Найти выполняет запрос с указанными там значениями: 18 — это число, "18" — строка, ISODate("2026-01-01") — дата, а любой другой текст — строка как есть. Избранный запрос, сохраненный из строки, сохраняет свои параметры, а указанные значения становятся значениями по умолчанию; при открытии он подставляет их и выполняется либо ждет значения, если у параметра его нет. Внутри кавычек, регулярного выражения или комментария {{name}} — обычный текст. Тот, кому нельзя видеть персональные данные подключения, никогда не получает значения по умолчанию другого пользователя.

Чипы под строкой предлагают условия: те, что вы недавно выполняли для коллекции, и те, что подсказывает небольшая выборка из нее (частое значение, например status = "paid", или поле, которого нет у многих документов); выбор чипа добавляет условие в фильтр и выполняет его. Выборка берется, когда страница простаивает или строка используется, и никогда — для представления (это запустило бы конвейер представления). Над результатами каждое условие используемого фильтра — отдельный чип: его удаление (крестик или Delete на чипе) выполняет фильтр без него, а Отменить возвращает его. Текст в строке следует за фильтром, только пока это используемый фильтр; фильтр, который вы еще редактируете, остается как есть. Панель под строкой показывает используемый запрос по частям; ее кнопка Выполнить запускает его снова, а звездочка сохраняет его в избранное.

В таблице щелкните имя столбца, чтобы отсортировать по нему: по возрастанию, затем по убыванию, затем без сортировки. Shift + щелчок добавляет столбец к сортировке. Сортировка записывается в Параметры и выполняется вместе с фильтром в строке, поэтому строка всегда показывает то, что выполняется. Потяните границу столбца (или сфокусируйте ее и используйте клавиши со стрелками), чтобы изменить ширину, и дважды щелкните границу, чтобы столбец снова подобрал размер сам; ширина хранится для каждой коллекции, для вас, в этом браузере. Меню столбца сортирует его, копирует его имя или скрывает его. Столбец, значения которого скрыты от вас (персональные данные), никогда не сортируется.

График рядом с «Таблица», «Карточки» и JSON рисует результаты запроса в виде столбцов, линии, точек или круговой диаграммы: выберите поле по оси X, количество, сумму или среднее числового поля и поле, которое разбивает результаты на серии. Читаются до первых 1000 подходящих документов (только рисуемые поля), и приложение сообщает, если их больше; для программ чтения с экрана есть таблица с теми же числами. Скрытые от вас поля не предлагаются и никогда не попадают на график. Копировать имя в меню баз данных, коллекций и столбцов, а также рядом с полем на вкладке «Схема» копирует простое имя.

Каждая строка таблицы начинается с Изменить, Удалить (после подтверждения) и меню ⋮; ее _id открывает документ для чтения. Карточки и список JSON показывают Изменить и Удалить у каждого документа. Щелчок правой кнопкой по строке показывает все ее действия, а по ячейке — еще и действия самой ячейки: скопировать значение, отфильтровать по нему (Shift + F10 открывает то же меню с клавиатуры). Документ открывается страницей на месте результатов. Назад к результатам (или Escape) возвращает к ним в то же место и отмечает последний открытый документ. Предыдущий документ и Следующий документ (Alt + ↑ / ↓) идут по результатам запроса, переходя на следующую или предыдущую страницу; документ, который после сохранения перестал подходить под запрос, сохраняет свое место, и страница об этом сообщает.

Страница показывает документ деревом, в виде JSON или в редакторе. Поиск в документе (Ctrl / ⌘ + F, когда фокус на странице) ищет в ключах, значениях или в том и другом: считает совпадения, Enter и Shift + Enter переходят между ними, ветви с совпадениями раскрываются, а остальное приглушается. Поиск сохраняется при переходе к следующему документу. Полоса над деревом показывает, где находится выбранное поле (payments › 2 › amount); Копировать путь копирует его как payments.2.amount. Строка запроса с проекцией — лишь часть документа: страница загружает, показывает и изменяет весь документ и сообщает об этом.

Там, где у вас есть право записи, дерево изменяется на месте: Enter или двойной щелчок меняет значение, сохраняя его тип или задавая другой; F2 переименовывает поле, Delete удаляет его, а меню поля добавляет поле или элемент. Дерево и текст — один черновик с одной историей отмены (Ctrl / ⌘ + Z, Ctrl / ⌘ + Shift + Z). Проверить и сохранить точно показывает, какие поля изменятся, до того как что-либо будет записано; сохраняются только они, относительно открытой вами версии, и более новая копия на сервере никогда не перезаписывается. _id и скрытые от вас значения никогда не изменяются, а поиск никогда не находит скрытое значение. В таблице дважды щелкните значение (или нажмите на нем Enter), чтобы изменить его на месте; тип сохраняется. Двойной щелчок в другом месте строки открывает документ для изменения.

Обновить несколько документов и Удалить несколько документов показывают предварительный просмотр перед выполнением: сколько документов подходит и несколько из них. Для обновления каждый образец показывает, что в нем изменится; это вычисляет сама MongoDB при чтении, ничего не записывая; документ, на котором обновление завершилось бы ошибкой ($inc для текста, путь через массив), отмечается. Позиционные пути ($[]), индексы массивов и $pull с условием на образцах не просматриваются, и предварительный просмотр сообщает об этом. Персональные значения в образцах остаются скрытыми — и до, и после.

Коллекции

Новая коллекция может задать правила сортировки (collation) по умолчанию (язык, уровень сравнения, числовой порядок и остальные параметры MongoDB) для коллекции, ограниченной коллекции (capped), коллекции временных рядов или представления; MongoDB фиксирует их при создании. Коллекция или ограниченная коллекция может также с самого начала хранить предыдущие и последующие версии документов потока изменений. Позже пункт меню коллекции Изменить коллекцию… включает или выключает эти версии (после подтверждения с названием коллекции), показывает ее правила сортировки и ведет на вкладку «Валидация», где остаются правила. В заголовке коллекции указаны ее правила сортировки и то, сохраняются ли версии.

Производительность

Вкладка Производительность подключения показывает в реальном времени графики сервера: операции в секунду, подключения, сеть и память; выборка делается каждые 2 секунды, пока вкладка открыта. Ниже показаны самые медленные выполняющиеся операции, которые можно фильтровать по базе данных или коллекции, виду, времени выполнения, ожиданию блокировки и простаивающим подключениям, а также приостанавливать; и коллекции, потребовавшие больше всего времени. Открыть ее могут редакторы и администраторы; меню «…» операции показывает ее команду, а администраторам подключения — еще и Прервать операцию, которое сначала запрашивает подтверждение. Сама MongoDB должна разрешать учетной записи читать состояние сервера: выдайте ей роль clusterMonitor, иначе вкладка сообщит, чего не хватает.

Раздел Профилировщик показывает уровень профилировщика, slowms и долю выборки для каждой базы данных; администратор подключения может изменить их карандашом в строке базы данных. Уровень 2 (каждая операция) сначала запрашивает подтверждение и сам возвращается к прежнему значению через 30 минут. Медленные запросы перечисляют медленные операции из профилировщика и из собственного журнала сервера (это работает даже при выключенном профилировщике), сначала новые, с планом, проверенными ключами и документами и командой; операция, которая читает намного больше документов, чем возвращает, помечается флажком, а Открыть в Explain открывает ее в своей коллекции.

На вкладке Персональные данные подключения администратор подключения может перечислить поля, содержащие персональные данные (например, crm.users.email или *.*.**.phone); собственная вкладка Персональные данные коллекции перечисляет и добавляет поля только этой коллекции — для нового поля достаточно его имени — и показывает более широкие правила подключения, которые на нее распространяются. Пользователь с правом Не видит персональные данные видит их значения как *** в профилировщике, медленных запросах и операциях и не может пользоваться оболочкой. В локальном режиме (без учетных записей) правила скрывают значения и от вас — везде: в документах, экспорте, контексте ИИ — а оболочка остается закрытой, пока значения скрыты; кнопка Скрыть их и от меня на вкладке подключения отключает это для данного подключения.

Предложения по индексам читают медленные запросы базы данных и предлагают индекс для каждого запроса, который выполнял сканирование, по правилу «равенство — сортировка — диапазон», если его еще не обслуживает какой-либо индекс; они также перечисляют индексы, которые не использовались с момента запуска сервера или являются началом другого индекса. Используются только имена полей. Создать индекс открывает обычный диалог с заполненным ключом: ничего не создается, пока вы не подтвердите это там.

В заголовке подключения, пока открыта вкладка «Производительность», выберите Сейчас (последние 5 минут) или сохраненный период в 1 час, 24 часа или 7 дней. Администратор подключения включает Записывать историю метрик в меню История метрик рядом (то же меню удаляет сохраненное после подтверждения): тогда сервер раз в минуту делает выборку по этому подключению и хранит 7 суток (только числа). Пока запись выключена, сервер сам никогда не подключается к этому подключению. На mongos вкладка показывает обзор шардирования: шарды, балансировщик, маршрутизаторы, а также ключ и распределение чанков каждой шардированной коллекции, а размеры и jumbo-чанки — по запросу. Ничто из этого не изменяет кластер.

На наборе реплик та же вкладка перечисляет всех участников: какой из них первичный, какие недоступны, насколько секунд каждый вторичный узел отстает от первичного (желтым свыше 10 с, красным свыше 60 с), отставание фиксации по большинству и окно oplog, а также график отставания за последние минуты. Набор без первичного узла показан красным: он не может принимать записи, пока не будет выбран первичный.

Агрегации

Вкладка «Агрегации» коллекции строит конвейер по стадиям. Добавьте стадию, выберите ее оператор (введите в поле оператора, чтобы найти стадию по названию или по тому, что она делает — «join» находит $lookup — и выберите клавишами со стрелками и Enter; рядом со списком показано, что делает стадия, и пример ее значения; каждая начинается с шаблона со ссылкой на руководство MongoDB) и измените ее значение; результат каждой стадии просматривается на выборке из коллекции (первые 1000 документов или случайная выборка) по мере ввода. Стадии можно отключать, переставлять перетаскиванием или клавишами Alt+вверх и Alt+вниз либо редактировать все сразу как текст.

Кнопка «Выполнить» передает потоком весь результат (до 10 000 документов) и имеет кнопку «Остановить»; «Подсчитать итог» считает количество только по запросу. Конвейер, заканчивающийся на $out или $merge, никогда не просматривается заранее: он выполняется один раз после подтверждения с названием цели, а для замены коллекции требуется ввести ее имя. Конвейеры можно сохранять вместе с коллекцией (в командном режиме — с возможностью общего доступа), экспортировать в виде программы на Node.js, Python, Java, Go, C#, PHP, Ruby или Rust (строка подключения читается из MONGODB_URI и никогда не записывается в код) либо превратить в представление.

Конвейер представления изменяется так же: Изменить конвейер у представления (в его обзоре или меню) открывает его на вкладке «Агрегации» коллекции, которую оно читает, с пометкой, что это конвейер представления, и предварительным просмотром каждой стадии. Обновить представление записывает включенные стадии обратно в представление после подтверждения с его названием. Конвейер со стадией, которую построитель не может прочитать, не открывается (сохранение потеряло бы эту стадию); пользователь, от которого скрыты персональные данные, не может изменить представление, определение которого видит скрытым.

Запросы

Страница «Запросы» (пункт «Запросы» на боковой панели, палитра команд или Ctrl / ⌘ + Shift + L; ее адрес — /library) ищет среди избранного, сохраненных конвейеров, сниппетов оболочки и истории запросов подключения по имени, тегу, тексту запроса, виду или коллекции. Она открывается на подключении, с которым вы работали, а при его отсутствии — на первом, и сохраняет то, что вы искали, когда вы возвращаетесь. Открытие элемента переходит к его коллекции: поиск выполняется на вкладке «Документы», конвейер заполняет карточки «Агрегации» (с запросом подтверждения, если на вкладке они уже есть). История хранит выполненные вами поиски и агрегации — последние 200 на коллекцию и 2000 всего, каждую один раз с числом использований; записи можно удалять по одной или очистить все. Избранное и сохраненные конвейеры можно переименовывать, менять им теги, делиться ими и удалять на странице «Запросы», а также закреплять: закрепленные запросы принадлежат только вам (до 50 на подключение), показываются первыми на странице «Запросы» и в виджете «Запросы» на Главной. Палитра команд перечисляет избранное, сохраненные конвейеры и сниппеты оболочки каждого подключения, открытого во вкладке, каждое под своим именем, а то, с которым вы работаете, — первым. При запуске командного режима история локального режима удаляется (ни один пользователь команды не смог бы ее видеть или очищать); журнал сообщает, сколько записей удалено. Избранное и сохраненные конвейеры локального режима остаются, для администраторов подключения.

Расширенная оболочка

Вкладка оболочки подключения запускает настоящий mongosh, а в ее терминале набирается код: выбор базы данных через use, поиск и агрегации, скрипты. Enter выполняет код, когда он завершен; пока скобка, строка или инструкция не закрыты (после ., оператора, if (…)), ввод продолжается на следующей строке после ..., а Shift+Enter всегда добавляет строку. Ctrl+Enter выполняет код как есть. В терминал можно вставить многострочный код: он показывается построчно и выполняется только после нажатия Enter. Скрипт выполняется так, как mongosh выполняет набранное — use, show и it каждая отдельно, затем каждая инструкция по очереди; ошибка останавливает выполнение на этом месте и сообщает, сколько инструкций не выполнено. print() и printjson() пишут в терминал; cls очищает его и результаты, а exit завершает оболочку.

Стрелки вверх и вниз перемещают между строками набираемого, затем по истории; Ctrl+R ищет по истории (повторное Ctrl+R — более старые совпадения, Escape — выйти из поиска). Ctrl+C останавливает выполняющуюся команду или очищает строку — либо копирует, если выделен вывод. Alt+B и Alt+F (или Ctrl+влево и Ctrl+вправо) перемещают по словам. История каждого пользователя хранится отдельно для каждого подключения в зашифрованном виде, и ее можно очистить.

Оболочка доступна администраторам подключения и редактору, которому администратор ее предоставил. Она работает в песочнице, где не хранится никаких учетных данных и которая может обращаться только к серверам самого подключения; на подключении «только чтение» она отклоняет записи, а не администратор не может выполнять администрирование кластера или пользователей.

Страница оболочки сообщает, где она работает — подключение и база данных, на которой находится оболочка (она следует за use), — и ее состояние: подключение, подключено, выполнение (с временем выполнения) или закрыто. В ее заголовке есть «Остановить» (пока команда выполняется), «Очистить» экран и результаты (Ctrl+L, также во время выполнения команды, или cls; уведомление сообщает об этом, а его «Отменить» или «Вернуть результаты» на пустой карточке «Результаты» возвращает их) и меню, чтобы сохранить набранное (или последний выполненный код) как сниппет, очистить историю (результаты исчезают вместе с ней) или перезапустить оболочку (сеанс завершается и начинается новый; переменные и показанные результаты теряются). Терминал использует светлую или темную тему приложения либо одну из собственных и подсвечивает код. В нижней строке перечислены клавиши. Оболочка остается открытой, пока открыта ее страница, как бы долго ею ни пользовались. Когда она закрывается (ваш вход завершен или превышен лимит простоя или времени жизни, установленный сервером), страница сообщает причину; Enter открывает новую; команда, еще выполнявшаяся при потере подключения, завершается на экране после его восстановления.

При наборе Tab предлагает варианты — коллекции базы данных после db. (в том числе созданную в оболочке), методы того, что возвращает цепочка, операторы после $ и имена полей из выборки коллекции. Shift+Tab или Escape, затем Tab выводят из терминала.

Рядом с терминалом карточка «Результаты» показывает последний результат в виде таблицы, дерева или текста; «Еще» получает следующую порцию курсора, а история результатов в заголовке позволяет выбрать более ранний результат, каждый назван командой, из которой он получен (хранится только в памяти); «Очистить» опустошает карточку; «Отменить» в уведомлении или «Вернуть результаты» на пустой карточке возвращает результаты, пока оболочка не перезапущена и ее история не очищена. Карточку можно расширить; на узком экране терминал и результаты — две вкладки. Одновременно можно открыть несколько вкладок оболочки, у каждой свой сеанс. Курсор простого поиска или агрегации открывается в представлении своей коллекции — поиск начинается со своего значения skip, а его limit служит размером страницы — а показанные документы можно экспортировать в JSON или CSV.

Код можно сохранить как сниппет — личный или общий для команды — с параметрами, записанными как {{name}}. Открытие сниппета (со страницы «Запросы» или из палитры команд) запрашивает его параметры и помещает заполненный код в терминал; ничего не выполняется, пока вы не нажмете Enter. Свои сниппеты редактируются на странице «Запросы»: имя, теги, код и параметры (строка появляется для каждого {{name}} по мере набора), проверка такая же, как у нового сниппета; общий сниппет остается общим, а журнал аудита отмечает, что его код изменился, но не сам код.

Терминал работает с программой чтения с экрана: ее режим включен по умолчанию, а Учетная запись → Предпочтения выключают или снова включают его, в том числе в уже открытых оболочках.

Explain

«Почему медленно?» в «Документах» или «Агрегациях» открывает раздел Explain для этого запроса или конвейера. Он показывает выбранный MongoDB план в виде дерева (по нему перемещаются стрелками), что прочла и вернула каждая стадия, отклоненные планы и предупреждения словами: сканирование всей коллекции, сортировка в памяти, фильтр, читающий намного больше, чем возвращает, соединение по полю без индекса. Если поможет индекс, Explain предлагает его (поля равенства, затем сортировка, затем диапазоны), а «Создать этот индекс» строит его в фоне. Конвейер, который записывает данные, не анализируется, потому что анализ выполняет его.

Валидация

Раздел «Валидация» редактирует правила, которым должен соответствовать каждый вставляемый или обновляемый документ, с уровнем и действием валидации. «Создать по выборке» формирует $jsonSchema по документам коллекции; «Проверить на существующих документах» подсчитывает, сколько из них не пройдут, с примерами, до сохранения. Сохранение сначала запрашивает подтверждение и сообщает, когда обновления документов, нарушающих правила, будут отклоняться; «Восстановить прежние правила» возвращает то, что заменило последнее сохранение, пока вкладка открыта. Запись, отклоненная правилами, сообщает, каким именно она не удовлетворила (отсутствует поле, неверный тип, минимум), и то же делает отчет об импорте или копировании; значение, не прошедшее проверку, никогда не повторяется.

Схема

Вкладка Схема коллекции анализирует случайную выборку (100, 1000 или 10 000 документов): каждое поле с частотой присутствия, его типами и гистограммой или самыми частыми значениями. Экспорт превращает анализ в схему Mongoose, валидатор MongoDB JSON Schema или интерфейс TypeScript, которые можно скопировать или скачать. Поле считается обязательным, если оно есть у каждого документа выборки.

Столбцы поля — его диапазоны и самые частые значения — и его типы являются кнопками: выбор одной из них добавляет это условие в фильтр коллекции на вкладке «Документы» (рядом с уже набранными условиями или через $and, если у поля оно уже есть), выполняет его и показывает документы. Значение, обрезанное при анализе, показывается, но не предлагается. Поле с местами — точки GeoJSON или пары координат под именем вроде location или coords — показывает их на карте, нарисованной без обращения к сети (контуры мира из Natural Earth, общественное достояние): перемещайте перетаскиванием или клавишами со стрелками; масштабируйте клавишей Ctrl и колесом, двумя пальцами или клавишами + и −; места также перечислены в таблице; а Фильтровать по этой области добавляет $geoWithin для видимой области. Поля с персональными данными никогда не отображаются.

Модель данных

Раздел Модель базы данных рисует ее коллекции и ссылки между ними. Прочитать модель берет выборку каждой коллекции (от 100 до 1000 документов, не более 50 коллекций), чтобы получить ее поля — верхний уровень и один уровень ниже, более глубокие только если они похожи на ссылки — и находит ссылки тремя способами: поле, названное по коллекции (userId или user_id → users, tagIds → tags), значения ObjectId из выборки, найденные как _id другой коллекции (не более десяти значений на поле, всего шестьдесят небольших подсчетов), и стадии $lookup и $graphLookup представлений и сохраненных конвейеров, которые вам разрешено открывать. Сплошная линия найдена по имени или значениям, пунктирная — только по $lookup, точечная соединяет представление с его источником. Линия заканчивается «вороньей лапкой» («многие») у поля, содержащего ссылку, — один и тот же идентификатор могут хранить многие документы — и чертой («один») у коллекции, на которую она указывает; для массива ссылок там тоже «вороньей лапкой». Поле помечается PK (ключ, _id), UQ (уникальный индекс только по нему) или IX (входит в индекс); индексы читаются только по именам их ключей.

Перетаскивайте диаграмму или используйте клавиши со стрелками, чтобы переместить ее, + и − — для масштаба, 0 — чтобы вписать ее. Колесо прокручивает страницу, пока диаграмма не получит фокус (щелкните ее или перейдите к ней клавишей Tab); затем колесо перемещает ее, а Ctrl / ⌘ и колесо масштабируют (Shift и колесо перемещают ее всегда). Щелкните коллекцию или перейдите к ней клавишей Tab и нажмите Enter, чтобы увидеть ее связи и открыть ее. Вид Список показывает ту же модель в виде списка: каждая коллекция раскрывает свои поля и связи, а связь переходит к коллекции, на которую указывает. Экспорт сохраняет диаграмму как PNG или SVG (в цветах используемой темы и на вашем языке), модель как JSON и модель как erDiagram Mermaid (сохраняется как .mmd или копируется) для README, вики или запроса на слияние, которые ее рисуют; уникальное поле записывается как UK, как его называет Mermaid. Показываются только имена, типы и количества; ни одно значение не покидает сервер. Кто может читать документы, тот может читать модель; поля, скрытые от вас как персональные данные, показываются только по имени, а их значения никогда не читаются. Пользователь MongoDB, которому разрешены только некоторые коллекции, видит именно их.

Чтение модели обходится серверу в одну выборку на коллекцию: до 50 коллекций, умноженных на размер выборки, плюс не более шестидесяти небольших подсчетов. Сервер ограничивает общее число документов, читаемых одной моделью (MM_MODEL_MAX_DOCS, по умолчанию 20 000): при множестве коллекций каждая выборка уменьшается, и раздел сообщает об этом. На загруженной рабочей базе данных читайте модель, когда сервер не занят, или с меньшей выборкой.

Поисковые индексы

В MongoDB Atlas или MongoDB 8.0 и новее с процессом поиска (mongot) вкладка «Индексы» также перечисляет индексы Atlas Search и Vector Search коллекции: каждый с видом, состоянием (ожидание, построение, готов, ошибка с причиной) и тем, что он охватывает; состояние проверяется каждые несколько секунд, пока строится какой-либо индекс. Создать поисковый индекс принимает определение в виде JSON, а для векторного индекса — пошаговую форму: поле с эмбеддингами, их размерность и метрика сходства, а также поля для фильтрации. Определение можно изменить, а индекс удалить после подтверждения с его названием. В других случаях вкладка сообщает, что требуется для поиска.

Фоновые задания

Построение индекса и дублирование коллекции выполняются в фоне, поэтому долгая операция никогда не упирается в тайм-аут. Пока они работают, можно уйти со страницы или закрыть вкладку. Кнопка Фоновые задания в верхней панели показывает каждое задание: с полосой и числами, когда MongoDB сообщает о ходе выполнения (построение индексов), или Еще выполняется и прошедшим временем, когда не сообщает (копии). О завершении ваших собственных заданий вам сообщают, и отменить их можно там же.

Если сервер перезапускается во время копирования, копирование прекращается, а его недоделанная коллекция удаляется; целевая коллекция никогда не остается заполненной наполовину. Построение индекса может продолжаться внутри MongoDB; вкладка «Индексы» показывает это.
